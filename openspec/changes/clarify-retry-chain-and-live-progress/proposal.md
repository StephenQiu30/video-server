# Proposal: Clarify Retry Chain And Live Progress

## Why

当前重试任务会作为新任务创建，但数据层没有显式重试关系，前端也按普通历史任务平铺展示。用户在工作台会同时看到旧失败/取消任务和新重试任务，容易误认为文件重复或重试逻辑错误。

下载进度目前依赖页面加载或手动刷新，Worker 已经写入进度，但前端无法及时反映。

## What Changes

- 为下载任务增加显式重试链字段：上一任务 ID 和尝试次数。
- 修正重试状态判断，禁止 queued/running 任务重试，禁止旧尝试重复创建新的重试任务。
- 工作台只展示每条明确重试链的最新任务，任务历史保留完整尝试记录。
- 增加任务列表 SSE 流，让前端无需手动刷新即可看到进度变化。
- 更新数据库升级脚本、测试场景和执行计划。

## Non-Goals

- 不按标题或 URL 猜测合并历史任务。
- 不删除历史任务记录。
- 不引入 WebSocket、复杂任务编排、批量任务或生产 SaaS 能力。
- 不修改下载内核、B 站解析、清晰度选择、对象存储和签名下载逻辑。
