# 009 前端体验重构需求

- 状态：Accepted
- 日期：2026-08-09
- 关联 Design：`docs/design/009-Next前端与蓝白视觉系统设计.md`

## 背景与用户问题

现有 Umi Max + Ant Design Pro 前端能够完成下载、分析和账户管理，但后台模板式导航、容器层级与产品的单一核心任务不匹配；移动端表格依赖横向滚动，页面之间的信息密度和视觉表达也不统一。接口客户端依赖 Umi 插件生成，使框架迁移与契约生成耦合。

本次重构保持业务能力不变，把“粘贴公开链接并安全完成下载”变成首屏唯一主线，同时建立适合桌面与 390px 手机的 Vercel Home 式无边框视觉系统和可持续的 OpenAPI 契约流程。当前视觉真值为用户选定的 Product Design 方案 3：`#FAFAFA` 偏白画布、Geist、72px 无边框 Header、Header/main/footer 共用的 1376px 隐形网格、80/32/16px 响应式 gutter、大尺寸编辑式 Hero、近黑主操作和无边框填充控件。页面不使用可见外壳、Card 或装饰 ring，只保留必要的发丝 Separator 与功能性焦点轮廓；并优先使用 shadcn `radix-nova` 与 Radix 组件组合。

## 用户与核心任务

- 普通用户：粘贴有权处理的公开视频链接，选择格式，查看任务进度，获取文件，并在下载完成后生成 AI 摘要与思维导图。
- 回访用户：搜索和筛选历史任务，继续查看、取消、重试或获取已经完成的文件。
- 管理员：在不离开统一产品视觉的前提下查询账号、调整他人角色与启用状态。

## 产品目标

1. 用方案 3 的大尺寸编辑式主张、大留白和无边框结构降低首次下载的理解成本。
2. 以 Next.js App Router + shadcn/ui `radix-nova` + Radix UI + Tailwind CSS 建立唯一前端实现方式。
3. 在保留 FastAPI 同源静态交付的同时覆盖全部现有路由与刷新场景。
4. 让 FastAPI OpenAPI 成为唯一接口契约，并由 `@umijs/openapi` 生成类型安全客户端。
5. 在 390px 视口、键盘操作和屏幕阅读器下完成核心流程，不把无障碍作为视觉后的补丁。
6. 用官方 shadcn/Radix 组件承载内容、数据和覆盖层交互，减少页面级自制外壳与不一致交互。

## 非目标

- 不新增下载平台、认证方式、AI 模型、支付或分享能力；主题切换只消费现有语义 token，不扩大业务范围。
- 不改变后端任务状态、权限规则、幂等、取消、取件与分析语义。
- 不运行 Next.js 服务端，不引入 SSR、Server Actions、Middleware 或独立前端容器。
- 不保留 Umi/Ant Design 页面作为备用入口或兼容层。

## 功能需求

### FR-009-01 唯一前端栈

前端必须使用 Next.js App Router、React、shadcn/ui `radix-nova`、Radix UI、Tailwind CSS 和 `@umijs/openapi`。shadcn 组件作为项目内源码使用，不构成第二个运行时 UI 框架。交付时移除 Umi Max、Ant Design、Ant Design Pro、Less 及其配置、入口、类型和依赖；不得同时维护两套路由或组件系统。

### FR-009-02 路由等价迁移

必须保留 `/`、`/history`、`/account`、`/admin/users`、`/user/login`、`/user/register` 和 404 能力。下载详情 canonical 地址改为 `/downloads/detail?jobId=<id>`；旧 `/downloads/{jobId}` 由 FastAPI 以 308 重定向，所有新内部链接直接使用 canonical 地址。

桌面 Header 使用可读的“帧取”品牌首页链接和“下载记录”链接；账户和主题操作位于右侧。移动端保留品牌首页链接，其他导航与账户操作收入 Radix Sheet。当前路由对应的导航链接使用 `aria-current="page"`，所有导航与覆盖层都必须可用键盘聚焦和激活。

### FR-009-03 首页下载主流程

用户可以输入、清除并提交公开 HTTP(S) 视频地址；页面校验输入、显示解析状态和错误，成功后展示真实媒体信息与所有语义格式。用户可以用单选控件选择格式并幂等创建下载任务，成功后进入该任务详情。

首页不再展示旧的“链接 → 格式 → 下载”三步导航/进度 UI，而是用“01 / 解析媒体”流程眉题、大尺寸主张、输入区和解析结果的自然阅读顺序表达任务。合法使用与隐私提示持续可见；契约未提供解析耗时，界面不得伪造。URL 无效、平台不支持、没有格式、网络失败与重复提交必须有可恢复反馈。格式选择必须使用 Radix `RadioGroup` 直接表达 API 返回的真实 `MediaFormat`；不得伪造画质预设，不增加未由契约支持的字幕/容器控件，也不在静态封面上放置伪播放按钮。

### FR-009-04 下载历史

用户可以按标题搜索、按状态筛选、刷新和分页浏览自己的任务。每项必须展示视频、格式、状态/进度和创建时间；成功任务可获取文件，其他任务可进入详情。桌面与 390px 均使用 Item/ItemGroup 语义任务列表，桌面通过宽布局展示更完整元数据，移动端重排为单列而不横向滚动。

### FR-009-05 下载与分析详情

页面从查询参数读取 `jobId`，显示加载、无效参数、无权限/不存在、任务错误和正常状态。活跃下载可取消，成功下载可获取文件并启动 AI 分析；分析支持语言/模板选择、取消、重试，并展示摘要、关键观点、章节和思维导图。轮询在终态、离开页面或认证失效后停止。

### FR-009-06 认证与账户

登录、注册、会话恢复、一次 Refresh 轮换和退出行为保持可用。未登录用户访问受保护地址时携带安全站内 `redirect` 前往登录；登录后返回原目标。个人资料支持修改用户名并立即更新导航显示，邮箱与角色只读。

### FR-009-07 管理员用户管理

管理员可以按用户名/邮箱、角色和启用状态查询用户，并修改他人的角色与启用状态。普通用户不得看到入口或访问页面；管理员不能降级或停用自己。390px 下不得依赖横向表格才能完成管理。

### FR-009-08 静态导出与同源服务

Next.js 必须输出可由 FastAPI 直接托管的 `frontend/out/`，覆盖所有有限页面、静态资源和 404。生产镜像不启动 Next Node 进程。页面、API、健康检查与 OpenAPI 文档继续使用同一源；API 404 不得返回页面 HTML。

### FR-009-09 OpenAPI 唯一契约

所有前端 API 类型和调用函数由 `@umijs/openapi` 直接根据 FastAPI `/openapi.json` 生成。后端公开操作必须拥有唯一稳定 `operationId`。生成目录禁止手改，CI 重新生成后必须无差异；不得提交第二份人工维护的 OpenAPI 或重复 DTO。

### FR-009-10 视觉一致性

首页必须遵循方案 3 的布局与内容优先级；其他页面沿用同一轻量导航、中性 token、短文案、必要的发丝分隔和大留白。Header、main 与 footer 统一使用 `.content-shell = min(calc(100% - 160px), 1376px)`；641–1023px 的内容 gutter 各 32px，640px 及以下 gutter 为 16px。认证双栏可使用更宽的 `.page-shell`，表单等窄内容只能在网格内二次收窄。页面统一使用 `#FAFAFA` 画布、72px 无边框 Header、Geist 排版、`#0A0A0A` 前景和 `#111111` 主操作；首页 H1 使用流动的大尺寸编辑式标题，内页使用响应式层级，不强制旧的固定页标尺寸。所有关键交互必须覆盖 hover、focus、disabled、loading、selected、empty、error 和 success 状态。

页面和区块标题上方只允许承载真实流程序号的中性 mono eyebrow，不得显示彩色装饰性 kicker、无语义英文标签或与 H1 重复的说明。页面根、标题区、筛选区、列表区和表单区不显示可见 PageShell/Card 外壳、装饰 ring、阴影或装饰性大边框。输入、选择器与按钮优先使用无边框实心填充面；内容分组只保留必要的 1px Separator。键盘焦点轮廓、错误边界以及 Dialog、Sheet、Popover 等 Radix 覆盖层的表面、遮罩、焦点圈定与 Escape/焦点恢复必须保留。

数据列表、移动导航、提示、用户身份、表单、结果项、空态、分页、破坏性确认、媒体比例和格式选择必须优先由 shadcn `radix-nova` 的 Table、Sheet、Tooltip、Avatar、Field、InputGroup、Item、Empty、Pagination、AlertDialog、AspectRatio、Separator 和 RadioGroup 组合；不得为相同语义重复实现页面级自制原语。认证页使用无外壳表单，历史使用 Item/ItemGroup，管理员桌面列表使用 Table，下载详情使用连续内容区与 Separator，AlertDialog 仅用于取消下载/分析任务的确认。所有业务图标继续使用项目已有的 Phosphor 图标库。

### FR-009-11 响应式与无障碍

全部页面在 390×844 无页面级横向溢出，核心控件触控区域至少 44×44px。管理员数据在桌面端使用 Table、390px 下切换为 Item 列表；历史在两类视口均使用 Item/ItemGroup；移动导航使用 Sheet，不把横向滚动作为核心信息的唯一通道。产品达到 WCAG 2.2 AA：语义结构、可见标签、键盘全流程、可见焦点、对比度、状态播报、错误关联、200% 缩放和减少动态效果均须验收。Radix 覆盖层必须保留官方的焦点圈定、Escape 关闭、触发器焦点恢复与 WAI-ARIA 属性。

### FR-009-12 设计 QA

首页解析成功态必须在方案 3 参考图原始 1487×1058 视口进行同图对比。全部路由在桌面和 390×844 检查关键状态，并逐页核对 72px Header、Header/main/footer 共用的 1376px 隐形网格与 80/32/16px 响应式 gutter、响应式标题阶梯、无可见页面外壳/Card/ring、填充控件与发丝 Separator；修复 P0/P1/P2 后，根目录 `design-qa.md` 必须记录 `final result: passed`。

## 非功能需求

- NFR-009-01：生产静态 HTML 不包含用户资料、访问凭据、任务数据或环境 Secret。
- NFR-009-02：认证刷新并发合并，失败后只跳转一次；轮询请求在卸载时取消或失效。
- NFR-009-03：构建产物中的脚本和样式使用内容哈希；HTML 可重新验证，静态资源可长期缓存。
- NFR-009-04：用户可见错误使用稳定中文说明与恢复动作，不直接展示后端堆栈或不受控异常文本。
- NFR-009-05：核心页面不能因缩略图加载失败、长标题、空字段或慢接口发生布局坍塌。

## 验收标准

- AC-009-01：依赖、目录和构建入口只保留 Next App Router + shadcn `radix-nova`/Radix UI + Tailwind CSS + `@umijs/openapi`，不存在 Umi/Ant Design/Less 运行时代码。
- AC-009-02：全部现有页面能力均有 App Router 对应页面；受保护路由、管理员路由、认证页和 404 权限行为正确；Header 中有可读且可键盘激活的品牌首页链接和“下载记录”链接，移动 Sheet 中的导航/账户操作与 `aria-current="page"` 正确。
- AC-009-03：首页可以从有效链接完成“解析 → 选择格式 → 创建任务 → 进入详情”，并覆盖规定的加载、错误和空状态。
- AC-009-04：历史、详情、AI 分析、个人资料和用户管理的现有功能与权限不回退。
- AC-009-05：`npm run build` 产出 `frontend/out/`，所有有限路由可直接刷新；生产运行时无 Next 服务。
- AC-009-06：旧 `/downloads/{jobId}` 返回 308 并安全指向 canonical 查询参数地址，后端 API 与文档路径不受静态回退影响。
- AC-009-07：`npm run openapi` 可重现生成客户端，所有 `operationId` 唯一，`npm run openapi:check` 无漂移。
- AC-009-08：首页在 1487×1058 达到方案 3 的结构和视觉层级；全部页面统一使用 `#FAFAFA` 画布、72px 无边框 Header、Header/main/footer 共用的 1376px 隐形网格、80/32/16px 响应式 gutter、Geist、`#0A0A0A` 前景、`#111111` 主操作、无边框填充控件和必要的发丝 Separator。首页使用流动大尺寸编辑式 Hero；页面级内容没有可见 PageShell/Card 外壳、装饰 ring、阴影或大边框。
- AC-009-09：首页的真实格式 RadioGroup、历史 Item/ItemGroup、管理员桌面 Table 和下载详情 Separator 信息层级清晰；首页无旧三步 UI、伪画质预设、伪字幕/容器控件或伪播放按钮。所有路由在 390×844 无横向滚动，首页输入、结果、Item 列表、表单、分页与 Sheet/AlertDialog 完成移动布局。
- AC-009-10：自动化 axe 无 serious/critical 问题，键盘可以完成登录、解析、格式选择、创建下载、筛选历史、返回首页和用户编辑；桌面导航以及移动 Sheet 内的路由入口可聚焦和激活，RadioGroup、Tooltip、Sheet、AlertDialog 和菜单的键盘与焦点行为符合 Radix 规范。
- AC-009-11：前端单元/集成测试、生产构建、后端静态服务测试、统一镜像构建和 Compose 解析通过。
- AC-009-12：根目录 `design-qa.md` 记录方案 3 与实现在相同视口/状态的比较，并包含 72px Header、导航/主体统一网格与响应式 gutter、响应式排版、无 PageShell/Card/ring 可见外壳、真实格式 RadioGroup、Phosphor 图标、山景演示资产与发丝 Separator 证据；P0/P1/P2 清零并写明 `final result: passed`。

## 发布成功信号

- 用户无需打开菜单即可识别首页唯一主任务，并能从粘贴链接连续完成到任务详情。
- 用户进入下载历史后，可以通过有可读名称的品牌首页链接返回解析主流程，不依赖浏览器后退。
- 390px 下完成核心任务不需要横向滚动或缩小页面。
- 接口变更若未重新生成客户端会在 CI 明确失败，而不是在运行时暴露类型漂移。
- 生产镜像继续只暴露 FastAPI 服务，同时页面刷新、旧详情链接和 API 404 行为稳定。

## 官方规范依据

- [Vercel 首页](https://vercel.com/home) 与 [Geist 排版](https://vercel.com/geist/typography)：偏白画布、近黑前景/主操作、无边框填充控件、发丝 Separator、大尺寸编辑式排版、网格和留白节奏。
- [shadcn/ui Components](https://ui.shadcn.com/docs/components)：官方 registry 组件的结构、状态和组合方式。
- [Radix Accessibility](https://www.radix-ui.com/primitives/docs/overview/accessibility) 与 [Composition](https://www.radix-ui.com/primitives/docs/guides/composition)：WAI-ARIA、键盘导航、焦点管理和 `asChild` 组合约束。
