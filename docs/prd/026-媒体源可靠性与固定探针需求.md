# 026 媒体源可靠性与固定探针需求

- 状态：Accepted
- 日期：2026-08-17

## 目标

用户提交受支持的公开单视频或官方单集分享后，系统应稳定显示私有封面、创建和
重试下载任务，并把平台、会话、格式漂移与本项目运行故障区分为可操作稳定错误。
运维需要一套覆盖所有注册 Provider 的固定 metadata/media 矩阵，持续证明当前
版本而不是依赖静态“已验证”日期。

## 必须满足

1. 私有封面读取复用现有 Access/Refresh 登录态，刷新后无需用户重新登录或输入。
2. 封面 Blob 可被 CSP 显示，失败与加载中状态明确，object URL 及时释放。
3. 旧下载规格消失时，终态任务重试不要求用户重新选择格式；自动选择同画幅、同
   媒体契约的最接近当前规格，并在新任务中保存真实语义计划。
4. Cookie 不进入 API、DB、队列或日志；本地可信环境可持续同步当前 Chrome 的
   YouTube/TikTok 最小域登录态，生产继续使用不可变专用会话版本。
5. 配置声明的每个 Runner 都进入 readiness；缺失 Operator 不能伪装成就绪。
6. 每个注册 Provider 有固定 metadata 和完整 media 样本，结果持久化并使用稳定
   错误码；没有当前证据时不显示为 verified。

## 非目标

- 不保证第三方平台、账号或 Cookie 永不变化。
- 不绕过 DRM、付费、私密、会员、地域或平台授权边界。
- 公开诊断成功不替代项目自有/授权生产 canary 和完整 AI 分析验收。
