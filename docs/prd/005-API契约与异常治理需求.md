# PRD 005 API 契约与异常治理需求

## 文档状态

- 状态：Accepted for Planning（2026-07-19）。
- 上游：[Design 005](../design/005-API契约与异常处理设计.md)。
- 输入：下载、任务、AI 功能及 Ant Design Pro OpenAPI 消费要求。
- 输出：版本化 API、DTO/VO、统一响应、Swagger 和异常验收需求。
- 下游：[Plan 005](../plans/005-API契约与异常治理计划.md)。

## 1. 背景与价值

前后端是独立仓库。若请求、响应、状态和错误依赖手写同步，功能会迅速漂移。服务端必须以 OpenAPI 提供可生成、可测试、可稳定演进的唯一契约。

## 2. 产品目标

1. 所有业务 API 位于 `/api/v1`，使用明确 Request DTO 和 Response VO。
2. 所有业务 JSON 使用 `code/message/data` 统一结构和真实 HTTP 状态。
3. Swagger、OpenAPI、ReDoc 完整描述正式接口和错误。
4. 全局异常不泄露 URL、文件路径、SQL、外部响应或密钥。
5. Web 能从 `/openapi.json` 生成 TypeScript Service，无需手写 DTO。

## 3. 非目标

- 不提供 GraphQL、WebSocket、SSE、用户、管理、字幕、取消或列表 API。
- 不包装 MinIO 文件、Swagger、OpenAPI 或 ReDoc 静态响应。

## 4. 业务规则

- 成功 envelope：`{"code":"SUCCESS","message":"success","data":...}`。
- 错误 envelope：`code` 为稳定机器码，`message` 可展示，`data` 通常为 null。
- HTTP 400/404/409/422/429/500/503 保持语义，禁止全 200。
- Entity 不直接返回；Service 不传播无类型 dict。
- operation ID 必须稳定唯一，生成 Service 名称可预测。
- 未知异常只记录服务端堆栈并返回 `INTERNAL_ERROR`。

## 5. 首版验收门禁

- `S005-AC-01`：Design 005 中全部正式路径、方法和 HTTP 状态出现在 OpenAPI。
- `S005-AC-02`：每个接口声明 Request DTO、Response VO、tags、operation ID 和错误示例。
- `S005-AC-03`：成功和失败均满足统一 envelope，且不存在 `request_id` 字段。
- `S005-AC-04`：校验、业务、HTTP、依赖和未知异常分别被全局处理。
- `S005-AC-05`：错误响应与日志不泄露敏感实现信息。
- `S005-AC-06`：`/docs`、`/openapi.json`、`/redoc` 可用，Schema 可生成 Web Service。
- `S005-AC-07`：Liveness 不访问重依赖，Readiness 正确检查 PostgreSQL、RabbitMQ、MinIO。

## 6. 前后端边界

OpenAPI 是唯一传输契约。任何路径、字段、状态或业务 code 的破坏性变化，必须先更新对应 Design/PRD，再重新生成 Web Service；不得用 `any` 或双轨响应隐藏变化。

## 7. 待确认问题

无。鉴权加入后需扩展本 PRD，当前 401/403 仅保留基础处理能力。
