# PRD06 视频源接入与适配器扩展

## 1. 背景

当前 `download_adapter.py` 已实现 `PlatformAdapter`、`AdapterRegistry`、`YtDlpAdapter`、`BilibiliAdapter`、`DomesticShortVideoAdapter` 等适配器类，但缺少产品层规范：新增平台时应遵循什么契约、何时使用专用适配器 vs 通用回退、失败语义如何统一。PRD06 将这些行为提升为产品边界，确保未来扩展不破坏现有 `/api/parse` 契约和任务创建主流程。

## 2. 目标

1. 新增视频源平台时，只需注册 `PlatformProfile` 和对应的 `PlatformAdapter`，不修改 parse router 或任务创建主流程。
2. 所有视频源共享统一的 `ParseResponse` 契约和错误码体系。
3. 未知平台通过 `YtDlpAdapter` best-effort 处理，不承诺正式支持。

```gherkin
Given 开发者需要新增一个视频源平台
When 开发者注册平台画像和适配器
Then 系统自动将该平台纳入解析和下载流程
And 不修改 parse router、任务创建主流程或错误码体系
```

```gherkin
Given 用户提交一个已注册平台的视频 URL
When 系统通过 AdapterRegistry 匹配适配器
Then 适配器返回统一的 ParseResponse
And 失败时返回统一的错误码
```

## 3. 非目标

- 不承诺 `yt-dlp` 支持的所有站点都成为正式支持平台。
- 不设计动态插件市场或远程第三方 adapter 加载机制。
- 不主动去水印或绕过平台风控。
- 不支持 DRM、会员、付费或需登录态的内容绕过。
- 不在本 PRD 中定义 Worker 下载执行或 MinIO 归档逻辑。

## 4. 核心内容

### 4.1 用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 开发者 | 新增一个视频源平台 | 只需添加 PlatformProfile 和 PlatformAdapter，不修改 router 或主流程 |
| 开发者 | 为已有平台定制解析逻辑 | 通过继承 PlatformAdapter 并覆写 parse/map_parse_error 实现 |
| 用户 | 提交已注册平台的 URL | 系统返回统一格式的 ParseResponse |
| 用户 | 提交未知平台的 URL | 系统通过 YtDlpAdapter best-effort 处理，不承诺成功 |
| 用户 | 提交受限内容 URL | 系统返回统一的平台受限错误码 |

### 4.2 适配器接入规则

1. 每个正式支持平台 MUST 有对应的 `PlatformAdapter` 子类。
2. `PlatformAdapter` MUST 实现 `supports()`、`parse()`、`map_parse_error()` 三个方法。
3. `AdapterRegistry` 按注册顺序匹配适配器，第一个 `supports()` 返回 `True` 的适配器被选中。
4. `YtDlpAdapter` 作为最终回退，处理所有未被专用适配器匹配的 URL。

### 4.3 注册中心规则

1. `AdapterRegistry` 在应用启动时初始化，运行期间不动态增删适配器。
2. 新增适配器通过修改 `AdapterRegistry.__init__` 的默认适配器列表实现。
3. 适配器注册顺序 MUST 保证专用适配器在通用回退之前。

### 4.4 失败语义

所有适配器 MUST 使用统一的错误码体系：

| 错误码 | 含义 | HTTP 状态码 |
| --- | --- | --- |
| `parse_failed` | 解析失败或平台暂不支持 | 422 |
| `platform_restricted` | 平台受限（登录/会员/付费/DRM/版权/地区） | 403 |
| `platform_rate_limited` | 平台限流或风控 | 429 |
| `unsupported_platform` | 不支持的平台 | 422 |
| `platform_unavailable` | 平台暂时不可访问或网络超时 | 503 |
| `engine_unavailable` | 下载内核未安装 | 503 |

### 4.5 格式模型

1. 所有适配器 MUST 返回 `ParseResponse`，包含 `formats` 列表。
2. `formats` MUST 包含至少一个推荐格式（`kind=recommended`）。
3. 格式分为：`recommended`（推荐下载）、`video`（分辨率预设）、`raw`（原始格式）。

### 4.6 合规边界

1. 所有适配器的 `compliance_note` MUST 遵守 PRD02 §4.2 合规要求。
2. 不得在解析结果中承诺绕过登录、验证码、会员、付费、DRM、版权或地区限制。
3. 水印提示 MUST 诚实标注，不得承诺去水印能力。

## 6. 验收门禁

- 新增平台只需添加 PlatformProfile 和 PlatformAdapter，不修改 router 或主流程。
- 所有适配器共享统一的 ParseResponse 契约和错误码体系。
- YtDlpAdapter 作为最终回退处理未知平台。
- 合规提示不承诺绕过任何平台限制。

## 7. 风险与边界

1. 平台页面结构和 yt-dlp extractor 策略会变动，适配器需要定期维护。
2. 过度依赖 `YtDlpAdapter` 回退可能导致用户对未知平台产生不切实际的期望。
3. 适配器注册顺序影响匹配结果，需要有明确的优先级规则。

## 8. 待确认问题

- 是否需要为每个适配器定义独立的超时策略。
- 是否需要适配器级别的缓存机制。
