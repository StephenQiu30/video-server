# 链接解析与平台识别 PRD

## 1. 背景

万能视频下载器的第一步是让用户粘贴一个公开视频链接，并获得可行动的解析结果。当前后端已有 URL 规范化、平台画像、yt-dlp 解析适配器和基本错误分类，本需求用于固化首版解析入口边界，避免将“万能”误解为绕过平台限制。

## 2. 目标

1. 用户粘贴公开视频链接后，系统能识别已知主流平台并返回平台名称、类别和合规提示。
2. 系统能拒绝无效 URL、内网地址、本机地址和明显不可公开访问的链接。
3. 解析失败时返回可理解错误码，不把平台限制、限流、暂不支持和普通解析失败混为一类。

```gherkin
Given 用户已登录并粘贴一个公开视频链接
When 用户提交解析请求
Then 系统返回平台识别信息、标题、封面、时长和可选格式
And 响应中包含该平台的合规提示
```

## 3. 非目标

- 不承诺所有网站永久可解析。
- 不绕过登录、验证码、地区限制、DRM、付费墙、会员或私密内容。
- 不做频道批量抓取、播放列表批量下载或自动同步。
- 不在 SaaS 页面中托管或上传用户 Cookie。

## 4. 核心用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 普通用户 | 粘贴 B 站、YouTube、TikTok 等公开视频链接 | 能看到平台名称、视频基础信息和格式列表 |
| 自部署用户 | 粘贴 yt-dlp 支持但未显式画像的平台链接 | 系统可 best-effort 尝试解析，失败时提示暂不支持或解析失败 |
| 管理员 | 控制高风险链接输入 | 内网、本地、保留地址和明显无效 URL 被拒绝 |

## 5. 用户体验原则

1. 解析入口只要求用户粘贴链接，不要求先选择平台。
2. 平台识别是辅助信息，不等同于承诺可下载所有内容。
3. 错误提示必须能指导用户下一步操作，例如换公开视频链接、稍后重试或确认平台限制。

## 6. 数据与权限边界

- 解析请求必须经过登录鉴权和限流。
- 日志不得保存完整敏感链接参数。
- 解析阶段不保存下载产物。
- 自部署 Cookie 只通过本机环境配置读取，不作为用户上传数据。

## 7. 状态模型

| 状态 | 含义 |
| --- | --- |
| `parse_ready` | URL 合法，平台可尝试解析 |
| `unsupported_platform` | 链接无效、受限或不适合作为公开视频解析 |
| `platform_restricted` | 平台要求登录、权限、会员或其他访问条件 |
| `platform_rate_limited` | 平台限流、验证码或临时风控 |
| `parse_failed` | 公开视频解析失败，保留人工排查空间 |

## 8. 首版验收门禁

- 至少覆盖国内短视频、长视频、海外公开视频三类样例平台。
- 已知平台返回 `platform_id`、`platform_category` 和 `compliance_note`。
- 保留 yt-dlp best-effort 兜底，但文案不承诺所有平台。
- 无效、本机、内网和保留地址被拒绝。

## 9. 风险与边界

平台页面结构、风控策略和 yt-dlp 支持范围会变化，验收应绑定公开样例和错误语义，不应绑定“所有链接都成功”。
