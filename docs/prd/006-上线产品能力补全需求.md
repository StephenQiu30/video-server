# 006 上线产品能力补全需求

- 状态：Draft
- 日期：2026-08-08
- 关联 Design：`docs/design/006-上线产品能力补全设计.md`
- 目标版本：Public Beta → Stable v1

## 背景

项目已经具备 URL 解析、语义格式选择、异步下载、对象存储交付、下载历史以及 AI 摘要/思维导图的 MVP。当前缺口主要位于公网滥用防护、运行时隔离、数据生命周期、升级恢复、可观测性和真实可靠性证据；同时缺少用户普遍预期的音频、字幕、受限批量、删除与重试能力。

本需求将“能下载一个受控样本”和“可持续运营的上线产品”区分开。Public Beta 只有在所有 P0 验收项通过后才能发布。

## 用户与场景

### 注册用户

- 下载自己有权处理的公开、非 DRM 媒体。
- 使用邮箱登录，在不理解 yt-dlp 参数的情况下选择清晰度、音频或字幕。
- 查看任务进度、失败原因、保留时间，并取消、重试或删除。

- 跨设备访问历史；配额、API key 和通知仍是后续能力。

### 运营与支持

- 查看 Provider、队列、存储、AI 成本和错误聚合。
- 暂停高风险 Provider、封禁滥用主体、处理删除/投诉和故障。
- 不接触用户完整 URL query、Cookie、transcript 或模型原始响应。

### 运维与开发

- 安全升级 schema 和镜像、执行备份恢复、定位跨进程任务。
- 通过可重复的 E2E、canary 和故障注入证明发布质量。

## Public Beta P0 需求

### FR-001 运行时最小权限

1. 每个服务只能获得其职责需要的环境变量和 Secret。
2. Media Runner 不得获得数据库、消息、MinIO 或 AI 凭据。
3. Media Runner 不得有默认公网路由，只能通过无凭据 egress proxy 访问媒体公网。
4. 网络策略必须阻止 Runner 横向连接 PostgreSQL、RabbitMQ、MinIO 和 Valkey。
5. CI 必须有容器级可见性和可达性测试，不能只检查 Pydantic 字段。

### FR-002 公网滥用防护

1. inspect、create download、create analysis 分别配置 IP/owner/API key 限流。
2. 系统限制单 owner 活跃下载数、活跃分析数、每日任务数、下载字节和 AI 音频分钟。
3. 幂等重放不得重复扣减配额。
4. 超限返回稳定 `429`、Problem Details、`Retry-After` 和剩余/重置提示（可公开时）。
5. 支持全局暂停新高成本任务，查询、取消、删除和已完成文件获取仍可用。
6. 官方公网部署支持 bot challenge 或等价防自动化能力；API 客户端使用受控 API key。

### FR-003 制品与隐私生命周期

1. 到期 artifact 在没有分析锁时自动删除 MinIO 对象并标记数据库状态。
2. 删除失败可重试、可告警、可人工恢复。
3. 用户可删除自己的任务/制品；跨 owner 始终返回 404。
4. 系统每日对账对象存储与数据库，处理孤儿对象和缺失对象。
5. 公开页面和 API 明确展示制品保留时间与删除状态。

### FR-004 数据库升级与灾难恢复

1. 所有 schema 变更使用版本化 migration；新环境和已存在环境走同一 revision 图。
2. 发布前验证 migration dry-run 和兼容窗口。
3. PostgreSQL、MinIO 具备加密备份、保留和恢复手册。
4. 至少完成一次空环境恢复和一次带真实受控制品的恢复演练。
5. 达到已批准的 RPO/RTO 后才能发布 Stable v1。

### FR-005 可观测性与运营

1. API、Outbox、Workers、Runner 输出统一脱敏 JSON 日志和 correlation id。
2. 暴露内部 Prometheus metrics，覆盖请求、任务、队列、Provider、存储、GC 和 AI。
3. 提供 Provider 最近验证状态和错误分类；前端不再把静态 extractor 清单等同于可用性。
4. P0 告警至少覆盖：API error budget、队列堆积、无 consumer、outbox lag、lease recovery 激增、磁盘不足、GC backlog、Provider 集体失败和 AI 成本异常。
5. 每个 P0 告警都有 owner、阈值和 runbook。

### FR-006 可靠性与发布门禁

1. 固定受控样本完成 inspect → download → verify → MinIO → browser E2E。
2. 覆盖 muxed 与分离音视频流、格式漂移、重定向、取消、超时和磁盘上限。
3. 故障注入覆盖 Worker 崩溃、重复 delivery、RabbitMQ/MinIO 暂停、Runner 重启和孤儿对象。
4. AI 用真实 ASR + LLM 对受控短视频完成 evidence E2E，或在 Public Beta 明确关闭 AI 功能。
5. 定时 Provider canary 与普通 PR CI 分离；canary 失败不阻断代码合并，但必须触发状态降级/告警。
6. 后端 lint/format/type/test、前端 lint/format/test/build、Compose config、镜像 build、依赖/镜像/Secret 扫描全部通过。

### FR-007 生产入口

1. 只有受支持的 ingress 对公网开放，内部依赖不发布宿主机端口。
2. TLS、HSTS、CSP、Referrer-Policy、Permissions-Policy、MIME sniffing、请求体/header/超时限制有版本化配置。
3. 只信任已配置代理的 forwarded headers；限流不能使用任意客户端伪造的 IP header。
4. 健康、metrics、Swagger/Redoc 的公网暴露策略明确；生产文档不默认暴露管理面。

### FR-008 治理与合规入口

1. 用户提交前确认只处理有权下载的公开、非 DRM 内容。
2. 提供隐私、服务条款、保留/删除策略和投诉/下架渠道。
3. 建立安全事件、滥用、Provider 下线、数据删除和发布回滚流程。
4. 产品文案不得承诺“所有平台永久可用”或暗示可绕过访问控制。

## Stable v1 P1 需求

### FR-101 音频下载

- inspect 返回 `audio_only` 选项，展示 codec、container、语言和质量档。
- 原生 M4A/Opus 优先；MP3 为显式转码选项并受 CPU/大小/时长配额限制。
- 产物使用准确 Content-Type、扩展名、SHA-256 和 ffprobe 验证。

### FR-102 字幕

- 展示可用字幕的语言、人工/自动和格式。
- 支持单独下载；嵌入/烧录只允许服务端白名单 preset。
- AI transcript 与平台字幕在 API/UI 中明确区分。

### FR-103 受限批量与多媒体帖子

- 支持播放列表/多条目页面的预览和用户确认。
- 每批条目数、总时长、估算字节和并发有硬限制；默认最多 20 条。
- 每个条目有独立任务和错误；父任务支持部分成功、整体取消和汇总。
- 不支持无限频道抓取或后台订阅。

### FR-104 任务恢复操作

- 用户可以从失败/取消/过期任务创建新的重试任务。
- 用户可以删除历史与制品，并看到异步删除状态。
- 重试继续使用语义计划并重新 inspect，不能复用过期 Provider format id 作为唯一依据。

### FR-105 实时状态

- 下载和 AI 任务使用 owner-scoped SSE 推送状态。
- 支持 Last-Event-ID、断线重连、心跳和慢客户端限制。
- SSE 不可用时使用带指数退避和 jitter 的轮询降级。

### FR-106 Provider 状态体验

- 首页、解析页和系统状态页展示 `verified/degraded/access_required/unsupported/unknown`。
- 展示最近验证时间和用户可采取的合法操作，不展示 Cookie 上传或绕过提示。

### FR-107 AI 完整闭环

- 真实受控视频生成摘要、观点、行动项、章节和 evidence 导图。
- 提供 JSON/Markdown 导出和分析历史。
- 可选 faster-whisper adapter 与托管 ASR 使用相同 transcript contract。

## P2 候选需求

- 频道/播放列表订阅、归档规则和自动清理。
- Apprise/邮件/Webhook 通知。
- 浏览器扩展、书签脚本和移动分享入口。
- 团队、API keys、套餐和计费。
- 媒体中心元数据、RSS、SponsorBlock、章节切割。

P2 必须单独建立 Design/PRD，不从本需求自动获得实施授权。

## 非功能需求

### 安全

- 不接受 Cookie、账号凭据、私网 URL、任意命令或原始 yt-dlp 参数。
- URL 只加密持久化；日志、消息、metrics、异常和前端不出现完整 query。
- Secret 轮换不要求同时清空全部任务或数据。
- 所有外部操作有时长、大小、并发、重试和取消上限。

### 性能与容量

- P95 查询 API < 500ms，P95 创建任务 API < 1s（不含媒体 inspect）。
- 系统在目标并发下不超过已定义 CPU、内存、磁盘和队列水位。
- 下载速度不作为平台无关 SLO；必须度量排队时间、Runner 时间和 Provider 时间。

### 可用性

- 查询 API 月可用性目标 99.9%。
- 单 Provider 降级不应使 API readiness 失败。
- PostgreSQL 是事实源；RabbitMQ 丢失后可依赖 outbox 和 recovery 恢复待执行任务。

### 可维护性

- OpenAPI 仍是前后端唯一契约；新接口有稳定 operationId。
- 源码文件遵循现有职责边界和约 200 行原则。
- 所有新增第三方依赖记录用途、许可证、固定版本、更新策略和移除方案。

## 发布范围

### Public Beta

必须完成所有 P0；可以只提供现有视频下载和已验证 Provider。若真实 AI E2E 未通过，则生产 UI/API 暂时关闭 AI 创建入口。

### Stable v1

必须保持 P0 持续通过，并至少完成 P1 的音频、字幕、删除/重试、Provider 状态和 SSE；批量可根据容量结果独立延后，但不得以不受限 playlist 代替。

## 成功指标

- 100% P0 验收项有自动化或演练证据。
- 0 个服务收到超出职责的生产 Secret；Runner 直连公网/业务依赖测试全部失败（预期阻断）。
- artifact 到期后一小时内删除成功率 ≥ 99%。
- Provider 状态展示与 canary 最近结果一致。
- 连续 14 天 beta 无 P0 安全事件、无不可恢复数据丢失、错误预算未耗尽。
- 用户可理解的错误分类覆盖至少 95% 的 inspect/download 失败，不以泛化 500/502 替代。

## 依赖与决策

- 引入 migration 需要修改 `AGENTS.md` 当前数据库规则。
- Valkey、ingress 和 metrics 后端是否纳入同一 Compose，取决于单机或托管部署决策。
- 账户、MP3 转码、批量上限和官方部署地域需要产品/法律/成本共同确认。
