# 内容创作与平台发布需求

- 日期：2026-09-15；状态：既有证据回看和报告交互缺陷已修复，新增创作/发布功能待实施；分项证据见验收。
- 上游：[调研](../research/023-内容创作与平台发布能力调研.md)、[设计](../design/036-内容创作与平台发布设计.md)；下游：[计划](../plans/036-内容创作与平台发布计划.md)、[验收](../acceptance/036-内容创作与平台发布验收.md)。

## 1. 用户与目标

首先服务已有视频/文稿的个人创作者和小规模内容运营者：把取得的素材加工成文章或小红书图文，检查依据、编辑、配图、保存和投递。采用单用户拥有作品、单用户管理其发布连接的模型；暂不加入团队审批、跨租户共享账号和批量运营。

成功的业务结果是“能找到并使用成品”，不是生成一次 JSON、安装 Skill 或收到工具 success。媒体下载继续是独立核心能力，不得要求用户先连接发布账号才能下载或写作。

## 3. 页面与交互要求

### 入口与作品列表

已有媒体详情/报告提供“制作文章”“制作小红书图文”；独立作品页允许文字创建。列表展示标题、内容类型、保存时间和真实状态，支持打开、按标题检索和删除。沿用现有分页/owner scope，不首期做全站语义搜索。

### 编辑页

桌面以正文为主，来源/图片/平台预览按需切换；移动端保留正文、保存状态和主操作，其他区使用现有 Sheet/Tabs。沿用 BasicLayout 和无边框 Vercel/Geist 视觉，不增加三步向导或高密度后台面板。操作常用语是“查看依据”“改写这段”“更换图片”“下载内容包”“存入草稿箱”。

未保存、保存中、保存失败、版本冲突、生成中、生成失败、素材失效都必须可见且可恢复。自动保存不抢焦点，不打断中文输入；生成失败保留已有正文。向外部平台提交前提供完整内容预览，标明账号、动作和可见范围。

### 发布记录

清楚呈现本地内容版本、目标账号、远端草稿、提交受理、审核结果、最终链接；未知结果显示“正在核实发布结果，请先查看平台记录”，主操作为核对。不能给未知结果一个语义模糊的“重试”按钮再次发帖。

## 4. 数据、内容和配额要求

- 用户有权处理的内容才可导入；网页摘要与引用不能自动变成全文转载，素材来源/署名/使用说明随版本保存。
- AI 不编造采访、口播、产品功效、数据或引用；机器字幕允许校对。平台原创/商业声明由用户明确选择，不能模型默认勾选。
- 用户自写观点允许保留；事实来源不充分时显示待复核，不把 schema 合格当事实成立。
- 生成前说明预估消耗；服务端限制尝试、转录分钟、图片和存储。模型/图片失败不丢失已完成部分，重放同一请求不重复扣额度。
- 本地删除与平台删帖是不同操作；首版不自动删除外部内容。作品删除时正确解除资产引用和在途任务关系。

## 5. 可用性与质量目标

下列是**拟议验收目标**，尚未达到的生产 SLO 不写为已实现：

- A05 的重开/断网/冲突场景中，已确认保存内容丢失数为 0；并发更新不静默覆盖。
- A16/A17 的重复消息、响应丢失及提交后崩溃场景中，无系统自动重复写入平台的行为；无法判断时允许保持未知。
- 在约定目标环境、20 个并发编辑客户端、每份正文不超过 100 KB 的测试下，保存接口 P95 ≤ 1 秒、错误率 < 1%；测量另记 DB/网络条件，不把它泛化为整站容量。
- 首轮至少 12 份来源样本：口播、教程、无声/视觉、图文资料各 3 份；每份生成文章和小红书稿，共 24 份产物。量表为事实忠实、读者价值、结构、渠道适配、可读性各 1–5 分；至少 90% 产物平均 ≥ 4 分，伪造关键事实/引用为 0；中文卡片文字与确认稿不一致为 0。
- 390×844、1280px 和现行桌面基准；键盘、中文输入、保存/错误状态、焦点恢复和横向溢出按现有前端规范验收。
- 不制定“全平台永远成功”承诺；以平台、内容类型、账号权限和最近验收日期给出真实支持范围。平台投稿失败仍可导出成品。

## 6. 本期非目标与依赖

不将批量账号自动运营、自动评论/点赞、定时发帖、团队协作审批、商业数据看板、全平台发帖纳入首个闭环。Tiptap/doocs/ASR/生图需要各自适配验证，不因为候选存在就安装到生产。

M1 不依赖真实发布账号；M3 的实际账号权限、M4 的官方接入与真实授权影响相应外部验收，不能据此阻塞已有草稿/导出开发。功能上线与原下载故障关闭分别按 036/035 记录。
