# 014 WebSocket 任务状态同步需求

- 状态：Accepted
- 日期：2026-08-10
- 关联 Design：`docs/design/archive/014-WebSocket任务状态同步设计.md`

## 1. 用户价值

用户需要在下载和分析任务运行时及时看到阶段、进度、错误、重试代次和报告可用状态，而不依赖高频刷新。网络切换、标签页休眠或服务重启后，页面必须自动恢复到数据库最新事实，不能因为漏掉一条实时消息永久显示旧状态。

## 2. 用户流程

1. 已登录用户打开任务页面，浏览器建立一个同源认证 WebSocket 连接。
2. 页面订阅当前用户拥有的下载或分析任务，并携带本地已知版本。
3. 服务端主动推送状态变化，页面按任务版本更新且不回退。
4. 连接短暂中断时页面显示重连状态，不把连接故障误报为任务失败。
5. 重连后系统有限重放缺失事件或返回当前快照；实时通道长期不可用时才启用有退避的低频 HTTP 恢复查询。

## 3. 产品规则

- WebSocket 只同步公开任务投影和报告可用性；创建、重试、取消、下载和报告正文继续使用 HTTP。
- 浏览器会话使用同源 HttpOnly Cookie 认证，生产只允许 `wss`；JWT、签名 URL和 API key 不进入 query string。
- 握手与每次订阅都校验账户状态、Origin 和 owner；知道任务 UUID 不代表有权订阅。
- 每个任务具有严格递增 `version`。客户端丢弃旧消息，发现版本缺口时必须 resync。
- PostgreSQL 和持久任务事件是恢复事实；RabbitMQ 实时消息允许重复或丢失，不能作为历史存储。
- 订阅恢复必须避免“快照完成、实时接管前”的丢事件窗口。
- 单用户连接数、单连接订阅数、消息速率、帧大小和发送队列都有硬上限。
- 中间进度可按任务合并；终态、失败、取消和报告可用事件不能静默丢弃。
- WebSocket 或 RabbitMQ 故障只触发带退避的低频 HTTP 降级，恢复后必须停止降级查询。
- 页面显示连接状态、重连和手动刷新入口，并通过节流的 `aria-live` 播报重要变化。

## 4. 产品验收标准（AC）

- AC-014-01：正常路径由 WebSocket 主动同步下载与分析状态，页面不执行固定周期高频轮询。
- AC-014-02：未登录、禁用账户、错误 Origin 和跨 owner 订阅均失败且不泄露任务存在性。
- AC-014-03：重复、乱序或延迟消息不能使页面状态、run 或报告状态回退。
- AC-014-04：断线、标签页休眠、网络切换和 Gateway 重启后，页面可通过重放或快照恢复到最新版本。
- AC-014-05：恢复与实时流切换期间发生的新事件不会丢失；检测到版本缺口时强制 resync。
- AC-014-06：慢消费者的资源使用有界，中间进度可合并但终态、错误、取消和报告可用性不丢失。
- AC-014-07：RabbitMQ/WebSocket 暂时不可用时页面进入明确降级状态并低频恢复查询，服务恢复后自动回到实时模式。
- AC-014-08：一个 owner 会话复用单例连接；多页面和多任务订阅不会为每个组件创建独立 socket。
- AC-014-09：事件、URL、日志和指标不包含 Cookie、JWT、owner hash、Prompt、报告正文、对象键或签名 URL。
- AC-014-10：桌面和 390×844 移动端均提供可访问的连接、重连、失败和手动刷新状态，任务状态不只靠颜色表达。

## 5. 非目标

首期不通过 WebSocket 创建或修改任务、不传输报告正文或媒体文件、不向浏览器暴露 RabbitMQ、不提供任意频道订阅、不保证无限历史重放，也不把在线状态当作任务事实源。
