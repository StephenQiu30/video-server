# 002 安全视频下载闭环需求

- 状态：Accepted
- 关联 Design：`docs/design/archive/002-安全视频下载闭环设计.md`

## 目标用户流程

1. 用户粘贴有权处理的公开视频 URL。
2. 系统展示标题、时长、来源和可下载清晰度/兼容性选项。
3. 用户选择一个选项创建任务并看到真实阶段、进度和失败原因。
4. 失败或取消后，用户可以从原任务页面发起一次新的下载尝试。
5. 成功后用户获得经过验证、默认保留 7 天的文件；每次获取文件时签发短时有效的下载地址。

## 必须满足

- 当前 MVP 仅接受公开 HTTP(S) 单视频，不支持 DRM、Provider Cookie、账号、直播、播放列表和批量；受控会话按 005 独立设计和验收。
- 下载前重新解析，按语义计划匹配格式；不允许静默降级分辨率。
- 单文件与兼容的分离音视频流均可正确处理，最终文件必须通过 ffprobe 和 SHA-256 验证。
- 创建、消息投递、重试与 Worker 重投递必须幂等；Worker 崩溃后任务可收敛。
- 用户可取消 queued/running 任务；总超时和取消都必须终止子进程并清理临时文件。
- 用户可对 failed/cancelled 终态任务手动重试；重试必须保留原任务并创建新任务，请求必须幂等。原 inspection 过期时不得使用陈旧来源参数，应要求用户重新解析。
- 用户 URL 不得进入普通日志，存储时加密并按 TTL 删除。
- Runner 不持有业务凭据，所有媒体出网请求经过拒绝私网的代理。
- MinIO 对象保留期与预签名 URL 有效期必须分离：对象默认保留 7 天，部署可显式配置为 30 天；下载 URL 默认只在 5 分钟内有效，过期后可在对象保留期内重新签发。

## 成功指标

- 受控样例端到端成功率 100%，重复任务不产生重复业务制品。
- 进度单调且与真实阶段一致；失联任务在一个 lease 窗口内被回收。
- SSRF canary、私网重定向和 DNS rebinding 用例全部被阻断。
- 任务终态后无不可解释的临时文件或 MinIO 孤儿。
