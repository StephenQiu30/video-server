# 027 开场钩子审查 Skill 需求

- 状态：Implemented / Provider Validated
- 日期：2026-08-30
- 对应设计：`docs/design/archive/027-开场钩子审查Skill设计.md`

## 1. 用户价值

创作者可以在现有 AI 分析入口选择“开场钩子审查”，得到前 3 秒、5 秒和 15 秒的
可见证据审查，并知道哪些分镜应保留、前移、简化、放大或重组。结果要能回到
真实时间轴，不使用笼统的“不够吸引人”或虚构平台指标。

## 2. 功能需求

### FR-027-01 Skill 目录

- `GET /api/analysis-skills?input_kind=video` 动态返回 `opening-hook-review`。
- Skill 显示名为“开场钩子审查”，带可编辑默认提示词。
- 现有 Web 配置器自动展示新 Skill，不新增硬编码前端分支。

### FR-027-02 完整时间轴

- 分析必须仍生成从 0 到权威时长的连续 `shots`。
- `scenes` 必须按顺序覆盖全部分镜一次。
- 前 15 秒是重点而非唯一观察范围，必须用后续可见画面检查开场承诺是否兑现。

### FR-027-03 开场审查

- 区分 0–3 秒的首个可见注意力锚点、0–5 秒的内容承诺和 0–15 秒的视觉进展。
- 检查主体、动作、构图、文字、镜头变化、状态变化和进入正文的衔接。
- 节奏判断同时考虑无变化、无目的变化和信息过载，不把更多 Cut 自动判为更好。
- 画面文字只在真实可辨认时评价文案和可读性；看不清时记录局限。

### FR-027-04 证据化建议

- 摘要、高光和优先制作建议必须引用存在的 `shot.id`。
- 建议说明观察、影响和期望修订结果，不代替创作者自动修改原视频。
- 无成立高光候选时允许 `highlights` 为空，不为满足数量编造优势。

### FR-027-05 边界声明

- 没有可靠音频证据时，不评价开场台词、语速、音乐卡点、音效或情绪语气。
- 不声称预测真实停留、留存、完播、点击或转化。
- 极短闪切或 Provider 未采样到的画面必须保留不确定性。

## 3. 非功能需求

- Skill 只包含 `SKILL.md` 和一层 Markdown reference，不包含脚本、链接资产或任意文件访问。
- 不放宽现有 Prompt Injection、输出大小、时间轴、证据引用或人物敏感属性限制。
- Skill 指令和 SHA-256 参与任务幂等指纹，更新后不改写旧任务。
- 不新增前端包、后端依赖、数据库迁移或 Provider Secret。

## 4. 验收指标

- 内置目录顺序、输入类型、结果契约、reference 编译和 SHA-256 测试通过。
- 静态行为测试证明 Skill 同时要求全片覆盖、开场时间窗口、可见证据和非平台指标边界。
- 后端 Ruff、MyPy 和相关 Pytest 通过。
- 至少一次受控视频的真实 Provider canary 通过后，才可宣称该 Skill 完成真实视觉验收。
