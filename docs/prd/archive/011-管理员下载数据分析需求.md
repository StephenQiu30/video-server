# 011 管理员下载数据分析需求

- 状态：Accepted
- 日期：2026-08-10
- 关联 Design：`docs/design/archive/011-管理员下载数据分析设计.md`

## 1. 用户价值

管理员需要在产品内快速理解近期下载使用情况：下载量是否上升，哪些视频来源占比最高，成功、失败、进行中和取消任务分别有多少。这些数据帮助进行产品运营和问题定位，但不应暴露用户的原始链接、单任务内部信息或个人身份。

## 2. 管理员流程

1. 管理员从桌面账户菜单或移动导航进入“下载分析”。
2. 页面默认读取近 30 天数据，显示总量、状态摘要、去重用户数、制品总字节、平均视频时长和成功率。
3. 管理员查看每日下载趋势与按视频来源聚合的下载量/成功率。
4. 管理员可在界面切换 7、30、90 天统计周期；API 对 `days` 保留 7–365 的参数校验边界。
5. 管理员可手动刷新当前窗口，请求失败时保留明确重试入口。

## 3. 产品规则

- 仅启用中的管理员可读取该页和 API；普通用户不显示入口，直接调用返回 403。
- 统计来自 PostgreSQL 的 `download_jobs` 当前事实。视频来源已在 `media_inspections` 中持久化，原始 URL 使用密文包保存，下载任务通过 `inspection_id` 外键关联，不再建重复来源列。
- 窗口从第一个统计日 UTC 00:00 开始，到请求当前时刻结束，两端均包含；以任务创建时间归属窗口和 UTC 日分桶。
- 成功率为 `成功 / (成功 + 失败) * 100`，是 0–100 的百分比；无终态样本时显示 0%。进行中和取消任务不进入分母。
- 来源为空或无法归类时显示“其他来源”，页面不伪造平台名称。
- 产品不显示 URL、`owner_hash`、Provider format hint、内部错误原文、用户邮箱或对象存储信息。
- 统计页是业务使用视图，不用 Provider 健康、队列或 SLO 运维指标代替下载任务计数。

## 4. 产品验收标准（AC）

- AC-011-01：管理员在桌面和移动导航中可见“下载分析”；普通用户不可见且接口返回 403。
- AC-011-02：页面默认展示近 30 天，并可在 7/30/90 天之间切换；API 拒绝小于 7 或大于 365 的 `days`。
- AC-011-03：首屏展示总量、成功、失败、进行中、已取消、去重用户数、制品总字节、平均视频时长和 0–100% 成功率，数值与后端口径一致。
- AC-011-04：页面以可视化方式展示每日趋势和各视频来源的下载量/成功率，同时有等价的文本或表格信息。
- AC-011-05：统计对幂等重放不重复计数，日边界、空白日、空数据和成功率零分母均有确定结果。
- AC-011-06：不新建冗余来源列或分析事实表；来源由 `download_jobs.inspection_id` 关联现有持久化解析记录。
- AC-011-07：API 和页面不包含 URL、`owner_hash`、`provider_hints`、`error_message` 或其他用户/单任务内部信息。
- AC-011-08：加载、空数据、失败重试、刷新和快速切换窗口都有稳定可访问状态，旧响应不覆盖新选择。
- AC-011-09：页面符合 009 无边框视觉系统，在 1280px 和 390×844 无横向溢出，不只靠颜色表达数据，键盘与屏幕阅读器可获得等价数值。
- AC-011-10：接口具有稳定唯一的 `operationId`/tag，前端只使用 OpenAPI 生成类型和请求服务。

## 5. 非目标

首期不提供原始 URL 导出、用户级明细或排名、自定义日期时区、CSV/报表导出、实时推送、删除/重试任务或操作性监控仪表盘。
