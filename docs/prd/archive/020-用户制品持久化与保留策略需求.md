# 020 用户制品持久化与保留策略需求

- 状态：Accepted
- 日期：2026-08-13
- 关联 Design：`docs/design/archive/020-用户制品持久化与保留策略设计.md`

## 1. 用户价值

用户完成下载或视频分析后，需要有足够时间跨设备、跨会话再次获取视频和报告。一天内必须下载完文件不符合常规使用预期，但无限期保留大视频又会造成不可控的存储成本。

## 2. 产品规则

1. 下载视频、Markdown 报告和 DOCX 报告默认保留 7 天。
2. 需要更长使用窗口且容量充足的部署可以通过统一配置延长为 30 天，不允许低于 7 天或高于 30 天作为常规产品策略。
3. 页面必须显示每个文件的实际到期时间，不根据固定天数自行推算。
4. MinIO bucket 保持私有；每次获取文件只签发默认 5 分钟的短时地址，地址到期后只要文件仍在保留期内即可重新获取。
5. 到期文件由有界、可重试的 GC 删除；下载历史和任务事实继续保留，用户可从过期任务重新下载。
6. 仍未删除的旧一天对象在升级时延长至创建后 7 天；已经删除的文件不承诺恢复。
7. 下载制品和报告保留配置必须由实际创建对象的 Worker 接收，不能只写在 `.env` 而未进入容器。

## 3. 验收标准

- AC-020-01：默认配置下，新视频和报告的 `expires_at` 为完成时间后 7 天。
- AC-020-02：配置 `2592000` 后，新视频和报告的 `expires_at` 为完成时间后 30 天。
- AC-020-03：连续两次获取同一有效文件可得到短时地址，文件的真实到期时间不被改变。
- AC-020-04：任务详情和历史显示实际保留截止时间，过期后显示不可用和重新下载入口。
- AC-020-05：数据库初始化可重复执行，旧一天对象只延长一次，不覆盖已有 7 天或更长策略。
- AC-020-06：GC 只删除真实到期且无分析锁的对象，删除失败可重试且不伪造成功。
- AC-020-07：Compose 开发与生产配置均把保留参数传给 Download Worker 和 Report Worker，把短时 URL 参数传给 API。

## 4. 非目标

本需求不提供永久保存、用户自选保留天数、公开分享链接、归档冷存储、计费套餐或恢复已经从 MinIO 删除的对象。
