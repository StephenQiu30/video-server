# 013 AI 分析原任务重试需求

- 状态：Accepted
- 日期：2026-08-10
- 关联 Design：`docs/design/archive/013-AI分析原任务重试设计.md`

## 1. 用户价值

用户需要在分析失败、取消或希望重新分析时继续使用原任务页面和链接，不应得到多个语义相同、难以辨认的任务。系统必须保留每次执行历史、失败原因和上一成功报告，同时防止重复点击、响应丢失或延迟消息创建多个活跃执行。

## 2. 用户流程

1. 用户在失败或取消任务上选择“重试”，在成功任务上选择“重新分析”。
2. 系统校验任务归属、终态、输入制品和重试额度，并为同一任务创建下一执行代次。
3. 页面保留原 `analysisId`、URL 和实时订阅，立即展示新的代次与排队状态。
4. 系统在当前代次内自行处理有上限的技术重试；用户看到的执行次数与技术 attempt 分开展示。
5. 新代次成功后更新当前报告；失败或取消时保留上一成功报告与全部历史摘要。

## 3. 产品规则

- 手动重试必须保持 `analysis_jobs.id` 不变，并创建单调递增的 `run_no`；自动技术重试只增加当前 run 的 `attempt`。
- 失败、取消和成功终态允许创建新 run；排队、执行、等待重试或报告发布中的任务返回稳定冲突错误。
- 重试沿用原视频制品、Skill 指令快照、输出语言、自定义提示词和 Provider 策略；请求不能携带改变分析语义的字段。
- 重试请求必须使用 `Idempotency-Key`。同一个 key 的重放返回同一 run，不重复发布消息、创建记录或计费。
- 不同 key 的并发重试、重试与取消并发时，最多只能存在一个活跃 run。
- 源 artifact 不可用、任务删除中、超出 run 数量或频率限制时，系统拒绝重试且不创建新任务。
- 新 run 启动时不清除当前成功报告；新报告发布完成后才切换当前报告。
- 上一代次、重复或 lease 失效的异步消息不得覆盖当前 run、任务状态或报告。
- 手动新 run 计入新的 AI 执行额度；报告发布重试不计 AI 额度。
- 页面必须准确区分“第 N 次执行”和“本次第 N 个技术 attempt”。

## 4. 产品验收标准（AC）

- AC-013-01：手动重试或重新分析后任务 ID、页面 URL 和订阅目标不变，`run_no` 恰好增加 1。
- AC-013-02：同一 run 的自动恢复只增加 `attempt`，不增加 `run_no` 或创建新任务。
- AC-013-03：重试 API 不接受 Skill、提示词、语言、Provider 或模型字段，并复用原语义快照。
- AC-013-04：相同 `Idempotency-Key` 重放返回同一 run；响应丢失后重试不会重复计费或发消息。
- AC-013-05：并发重试以及重试/取消竞争时最多有一个活跃 run，失败事务不遗留半成品状态。
- AC-013-06：旧代次、重复投递或过期 lease 不能覆盖当前状态、进度、错误或当前报告。
- AC-013-07：新代次运行期间上一成功报告仍可下载；新代次失败或取消时报告指针不变。
- AC-013-08：artifact 不可用、任务非终态、任务删除中或超过限额时返回稳定错误且不生成新 run。
- AC-013-09：成功响应使用 `201 Created`、同一任务 `Location` 和最新状态投影，客户端无需额外创建资源才能继续展示。
- AC-013-10：页面可访问地展示执行代次、技术 attempt、失败原因、可重试窗口和上一报告状态。

## 5. 非目标

重试不用于修改分析配置、切换 Provider/模型、恢复已删除视频、并行比较多个模型、复制任务或无限延长 artifact 保留期。需要改变语义输入时必须创建新分析任务。
