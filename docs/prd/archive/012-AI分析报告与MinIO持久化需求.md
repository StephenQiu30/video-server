# 012 AI 分析报告与 MinIO 持久化需求

- 状态：Accepted
- 日期：2026-08-10
- 关联 Design：`docs/design/archive/012-AI分析报告与MinIO持久化设计.md`

## 1. 用户价值

用户需要在分析完成后稳定地查看和下载同一份报告。服务重启、页面刷新或重复下载都不能重新调用 AI，也不能生成内容不同的临时报表；报告发布暂时失败时，已经完成的视频分析结果和上一版成功报告仍应可恢复。

## 2. 用户流程

1. 用户启动视频分析，任务完成结构化结果校验后进入报告发布阶段。
2. 系统从同一份规范 Markdown 生成 Markdown 与 DOCX 两种文件并持久化。
3. 两个文件均通过完整性检查后，任务才显示成功并开放下载。
4. 用户再次打开任务时看到当前报告状态、发布时间、格式和大小，并下载已发布对象。
5. 用户重新分析同一任务时，上一成功报告继续可用；新报告完整发布后再成为当前版本。

## 3. 产品规则

- PostgreSQL 是报告语义、版本、归属和发布状态的事实源；MinIO 只保存私有、不可变的报告对象。
- 每次执行至多产生一个规范报告版本，Markdown 与 DOCX 必须来自同一 Markdown 快照。
- 任务只有在两个必需对象均可读且大小、SHA-256 与数据库记录一致后才能进入 `succeeded`。
- 报告发布失败只重试渲染与上传，不重新运行 AI，不增加 AI 技术重试次数。
- 报告发布和下载必须先执行 owner 授权；公开响应不得包含 bucket、object key、凭据或长期有效的签名 URL。
- 新执行开始时不删除上一成功报告；新执行失败或取消不得改变当前报告指针。
- 数据库记录可用但对象缺失时必须显式报错并告警，不允许即时重建来掩盖损坏。
- 用户删除任务、报告到期和孤儿对象清理必须最终一致、幂等且可审计。
- Markdown 预览按不可信内容处理；DOCX 不包含宏、远程关系、用户本机路径或外部资源。
- Markdown 与 DOCX 默认保留 7 天，部署可显式配置为 30 天；报告对象保留期与每次下载的短时授权有效期相互独立。

## 4. 产品验收标准（AC）

- AC-012-01：分析成功后，页面刷新和服务重启不改变报告内容，下载不触发新的 AI 执行。
- AC-012-02：每个可用报告恰有一份 Markdown 和一份 DOCX，且两者可证明来自同一 Markdown 快照。
- AC-012-03：报告发布期间任务展示明确状态；只有两个对象都通过完整性校验后才显示成功与下载入口。
- AC-012-04：重复消息、Publisher 重启和上传后数据库提交失败均可幂等恢复，不产生重复版本或内容冲突。
- AC-012-05：未登录、非 owner 和跨用户 UUID 下载都失败且不泄露报告是否存在。
- AC-012-06：报告未就绪返回稳定冲突错误；数据库与对象存储不一致返回稳定不可用错误并触发告警。
- AC-012-07：重新分析期间上一成功报告仍可下载；新报告完整发布后原子切换，失败时保持旧版本。
- AC-012-08：删除、TTL 与孤儿对象清理可重复执行，最终不留下可访问的失效对象。
- AC-012-09：API、WebSocket、普通日志和指标不暴露报告正文、对象键、签名参数、Prompt、模型原始输出或 Secret。
- AC-012-10：Markdown/DOCX 下载具备正确文件名、媒体类型、大小和短时授权行为，并覆盖桌面与移动端状态展示。

## 5. 非目标

首期不提供在线富文本编辑、用户自定义 DOCX 模板、公开分享链接、报告协作评论、PDF 导出、对象存储直公开或历史报告内容合并。
