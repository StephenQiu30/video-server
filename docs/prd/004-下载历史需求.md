# 004 下载历史需求

- 状态：Accepted
- 日期：2026-08-07
- 关联 Design：`docs/design/004-下载历史设计.md`

## 1. 用户价值

用户完成一次视频下载后，即使离开任务页，也能回到“下载历史”找到最近记录，判断任务是否成功，并继续打开任务或获取已完成文件。

## 2. 用户流程

1. 用户在“新建下载”完成解析并开始下载。
2. 系统将任务和选中的媒体信息写入 PostgreSQL。
3. 用户打开“下载历史”，看到当前账户的任务列表和成功/处理中/失败统计。
4. 用户可按标题搜索、按状态筛选、翻页。
5. 用户点击“查看任务”进入现有任务页；成功记录可点击“获取文件”。

## 3. 产品规则

- 历史只属于当前登录账户；换设备登录同一账户仍可查看，其他账户不可见。
- 新任务立即进入历史，状态随数据库任务状态变化。
- 标题为空时显示“未命名视频”；没有封面时使用现有默认封面。
- 失败记录显示稳定错误码；不展示后端错误详情。
- 文件对象默认保留 7 天，需要更长窗口的部署可显式配置为 30 天；页面显示数据库记录的实际到期时间。文件对象过期时历史仍保留，并明确显示“文件已过期”；有效制品可重新签发短时下载地址，过期制品可从原任务重新下载。

## 4. 产品验收标准（AC）

- AC-004-01：导航中有“下载历史”，且不影响“新建下载”和任务详情路由。
- AC-004-02：历史页首屏展示记录数、成功数、处理中数和失败数。
- AC-004-03：用户能完成关键词搜索、状态筛选和分页，筛选条件变化回到第一页。
- AC-004-04：每条记录显示封面、标题、格式、状态、创建时间和可用操作。
- AC-004-05：无记录时给出回到“新建下载”的明确入口。
- AC-004-06：请求失败时保留重试入口；加载中使用骨架屏；移动端不出现横向溢出。
- AC-004-07：历史列表不会显示 URL、Cookie、密钥或内部对象信息。
