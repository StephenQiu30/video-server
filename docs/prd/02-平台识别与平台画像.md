# PRD02 平台识别与平台画像

## 1. 背景

"万能视频下载器"容易被误解为对所有网站都做出成功承诺。首版必须清楚区分"正式支持的平台"和"理论上可能被 yt-dlp best-effort 处理的平台"，避免产品边界失控。

当前代码已实现 10 个正式支持平台的画像注册和识别，本 PRD 以此为准进行规范化。

## 2. 目标

1. 系统在接收合法 URL 后，能识别其来源平台。
2. 首版明确 10 个正式支持平台，每个平台均有稳定画像。
3. API 对外返回统一的 `platform_id`、`platform_category` 和 `compliance_note` 字段。
4. 合规提示不承诺绕过登录、验证码、会员或私密访问限制。

```gherkin
Given 用户提交一个合法的公开视频 URL
When 系统完成平台识别
Then 系统返回统一的 platform_id、platform_category 和 compliance_note
And 正式支持平台有明确合规提示
```

## 3. 非目标

- 不承诺 yt-dlp 支持的所有网站都进入正式支持清单。
- 不在本 PRD 中定义任务执行或对象存储。
- 不做私密内容、会员内容或 DRM 内容的支持声明。
- X（Twitter）和 Instagram 暂不列入首版正式支持清单。
- 不承诺主动去水印或绕过平台水印标记。

## 4. 核心内容

### 4.1 正式支持平台

首版正式支持 10 个平台，分为三类：

#### 长视频平台（long_video）

| platform_id | display_name | hosts | compliance_note |
| --- | --- | --- | --- |
| `bilibili` | B 站 | bilibili.com, b23.tv | 仅支持公开视频；番剧、会员、付费、版权受限或需登录内容不会绕过。 |
| `youtube` | YouTube | youtube.com, youtu.be, youtube-nocookie.com | 仅支持公开可访问内容；不支持 DRM、会员、付费或需登录内容。 |
| `vimeo` | Vimeo | vimeo.com | 仅支持公开可访问内容；不支持 DRM、会员、付费或需登录内容。 |
| `dailymotion` | Dailymotion | dailymotion.com, dai.ly | 仅支持公开可访问内容；不支持 DRM、会员、付费或需登录内容。 |

#### 国内短视频平台（domestic_short_video）

| platform_id | display_name | hosts | compliance_note |
| --- | --- | --- | --- |
| `douyin` | 抖音 | douyin.com, iesdouyin.com | 仅支持公开视频链接；平台风控、私密作品、登录态内容和付费内容不会绕过。 |
| `kuaishou` | 快手 | kuaishou.com | 仅支持公开视频链接；平台风控、私密作品、登录态内容和付费内容不会绕过。 |
| `xiaohongshu` | 小红书 | xiaohongshu.com, xhslink.com | 仅支持公开视频链接；平台风控、私密作品、登录态内容和付费内容不会绕过。 |
| `ixigua` | 西瓜视频 | ixigua.com | 仅支持公开视频链接；平台风控、私密作品、登录态内容和付费内容不会绕过。 |
| `weibo` | 微博 | weibo.com, weibo.cn | 仅支持公开视频链接；平台风控、私密作品、登录态内容和付费内容不会绕过。 |

#### 海外短视频平台（short_video）

| platform_id | display_name | hosts | compliance_note |
| --- | --- | --- | --- |
| `tiktok` | TikTok | tiktok.com | 仅支持公开可访问内容；不支持 DRM、会员、付费或需登录内容。 |

### 4.2 平台画像要求

每个平台画像必须包含以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 机器可读的平台标识，例如 `douyin`、`bilibili` |
| `display_name` | string | 用户可读的平台名称，例如 `抖音`、`B 站` |
| `category` | string | 平台分类：`long_video`、`domestic_short_video`、`short_video` |
| `hosts` | tuple[string] | 该平台的域名列表，用于 URL 匹配 |
| `requires_public_access` | bool | 是否要求公开可访问（默认 `true`） |
| `supports_public_parse` | bool | 是否支持公开解析（默认 `true`） |
| `compliance_note` | string | 合规提示文案 |

### 4.3 API 返回字段

`POST /api/parse` 返回的 `ParseResponse` 中，以下平台相关字段由平台画像填充：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `platform_id` | string \| null | 匹配到正式平台时返回平台 ID，否则为 `null` |
| `platform_category` | string \| null | 匹配到正式平台时返回平台分类，否则为 `null` |
| `compliance_note` | string \| null | 匹配到正式平台时返回合规提示，否则为 `null` |
| `source_site` | string \| null | 平台展示名称 |
| `watermark_hint` | string \| null | 水印提示：含平台水印 / 优先可用源 / 不可确认 |

### 4.4 水印提示规则

| 水印分类 | 平台 | 提示文案 |
| --- | --- | --- |
| 默认含水印 | douyin, kuaishou, tiktok | "可能含平台水印" |
| 默认无水印 | bilibili, youtube, vimeo, dailymotion | "优先可用源" |
| 不可确认 | 其他平台 | "不可确认" |

### 4.5 产品边界

1. 平台识别成功不等于下载一定成功。
2. 对未列入首版清单的平台，允许 yt-dlp best-effort 处理，但不做正式承诺。
3. 产品文案不得表达规避平台限制或主动去水印能力。
4. 合规提示明确声明不绕过登录、验证码、会员、付费、DRM、版权或地区限制。

## 6. 验收门禁

- 10 个正式支持平台均有稳定平台画像，字段完整。
- API 对外返回统一的 `platform_id`、`platform_category`、`compliance_note` 字段。
- 合规提示不承诺绕过登录、验证码、会员或私密访问限制。
- 平台画像注册表（`PLATFORM_PROFILES`）与本文档平台列表一致。

## 7. 风险与边界

平台页面结构和策略会变动，平台画像要绑定首版声明，不要把产品支持范围和第三方工具能力混为一谈。

## 8. 待确认问题

- X（Twitter）和 Instagram 是否在后续版本加入正式支持清单。
- 是否需要支持用户自定义平台画像扩展。
