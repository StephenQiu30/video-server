# PRD 003 异步任务与数据持久化需求

## 文档状态

- 状态：Accepted for Planning（2026-07-19）。
- 上游：[Design 003](../design/003-异步任务与数据存储设计.md)。
- 输入：两类长任务、六张表、24 小时结果和 7 天墓碑。
- 输出：任务状态、数据一致性、重试、过期和恢复需求。
- 下游：[Plan 003](../plans/003-异步任务与数据持久化计划.md)。

## 1. 背景与价值

下载与 AI 任务不能依赖 HTTP 连接或进程内状态。用户需要在刷新页面、Worker 重启和临时依赖故障后仍能得到准确、可恢复的任务状态。

## 2. 产品目标

1. PostgreSQL 保存来源、格式、任务、文件和 AI 结果。
2. RabbitMQ/Celery 分发下载与 AI 任务，但不承担最终状态。
3. 任务提供 queued、running、succeeded、failed、expired 和 0–100 进度。
4. Worker 可安全处理重复投递并有限重试瞬时故障。
5. 结果到期可解释、可清理，不无限增长。

## 3. 非目标

- 不提供暂停、取消、原任务重试、优先级、批量任务或用户任务列表。
- 不使用 Redis、第三条业务队列、复杂工作流引擎或事件溯源。

## 4. 业务规则

- RabbitMQ 消息只含 job ID；Worker 从 PostgreSQL读取输入。
- `download` 和 `ai` 是唯一业务队列，Worker 分开消费。
- 任务发布失败必须落为明确失败状态，不能永久停在未知状态。
- succeeded/expired 任务不重复执行；外部写入按 job ID 校验幂等。
- 进度最多每秒或每增加 1% 写一次数据库。
- 结果 24 小时后 expired；墓碑保留 7 天；Scheduler 每小时触发清理。
- Alembic 是唯一 schema 迁移入口，运行时不自动迁移。

## 5. 状态场景

- 正常：`queued → running → succeeded → expired`。
- 业务失败：`queued/running → failed`，不自动重试。
- 瞬时失败：任务有限重试，最终只能 succeeded 或 failed。
- 重复消息：已有终态时直接确认，不生成重复 Artifact 或 AI Result。

## 6. 首版验收门禁

- `S003-AC-01`：六张表、外键、唯一约束、CHECK 和必要索引符合 Design。
- `S003-AC-02`：两条队列正确路由，消息不包含 URL、密钥、大文本或文件。
- `S003-AC-03`：API/Worker 重启后任务状态仍可查询，PostgreSQL 为最终事实。
- `S003-AC-04`：同一 job 重复投递不会产生重复最终结果。
- `S003-AC-05`：瞬时错误有限退避，业务错误不重试。
- `S003-AC-06`：24 小时到期、expired 展示和 7 天删除可验证。
- `S003-AC-07`：迁移可从空数据库前向执行，应用不自动改 schema。

## 7. 风险与约束

- 初始 RabbitMQ 单节点不保证高可用；持久化、发布确认和恢复步骤必须存在。
- 数据库高频进度更新可能造成压力，因此必须节流。

## 8. 待确认问题

无。优先级、取消和多租户任务隔离不属于首版。
