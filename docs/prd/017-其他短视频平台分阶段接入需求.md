# 017 其他短视频平台分阶段接入需求

- 状态：已实现代码能力；真实平台证据持续验收
- 日期：2026-08-11
- 对应设计：`docs/design/017-其他短视频平台分阶段接入设计.md`

## 1. 用户目标

用户提交其有权处理的公开、非 DRM 单视频后，系统应安全下载完整音视频，并由 Agent 基于完整视频生成连续分镜、高光和视觉资产报告。平台状态页必须准确区分“已登记”“下载探针通过”和“完整分析已验证”。

## 2. 功能需求

### FR-1 平台入口

1. AcFun 只接受公开 `/v/ac{id}` 单视频。
2. Rutube 只接受公开 video/embed 单视频，不接受 private、live、频道和 query 扩展入口。
3. VK 只接受直接 `video{owner}_{id}` / `clip{owner}_{id}`，不接受 feed、账号页、embed 或带 list 的入口。
4. PeerTube 只接受 `PEERTUBE_ALLOWED_INSTANCES` 中精确 DNS hostname 的 watch/embed/short URL；禁止通配符、IP、自定义 scheme/端口和任意实例。
5. 未取得新鲜样本或安全会话方案的平台保持 `unknown/unsupported`，不得复用相似平台 Profile 冒充支持。

### FR-2 下载探针

1. 运维目标仅来自 Secret 类型 JSON 配置，默认空列表。
2. 目标必须是 HTTPS、无 URL credentials、Provider 与路径匹配。
3. metadata 与 media 分开调度；media 必须走正常 re-inspect、完整下载、ffprobe、轨道、大小和 SHA-256 合同。
4. 探针表不得存 URL、Cookie、异常文本或其他凭据。

### FR-3 完整视频分析证明

1. analysis 证明必须引用已经成功的同一 `analysis_job`，不能由下载探针模拟。
2. 输入制品哈希、大小、时长、容器必须与严格分析结果一致。
3. 当前 Agent run、数据库报告、MinIO 原视频/Markdown/DOCX 和 WebSocket 恢复事件必须全部成功且未过期；证明服务使用独立只读对象存储身份复核对象存在和大小。
4. 加密源 URL 只允许在证明进程内解密，与授权 canary URL 精确比对，不能输出。
5. analysis 失败只持久化稳定错误码。

### FR-4 状态与发布

1. 下载层窗口至少最近 5 次中 4 次成功，最近 2 次连续成功。
2. 必须存在 6 小时内 metadata、26 小时内 media 和 7 天内 analysis 成功证明。
3. 新平台还必须存在 `PROVIDER_VERIFIED_KEYS` 显式批准；单独批准或单独探针均不能提升。
4. access、rate、永久失败和短暂失败继续按既有迟滞规则降级。

### FR-5 异步、持久化和重试

1. 完整视频通过 MinIO 交给 RabbitMQ Analysis Worker，Agent 读取完整文件；固定抽帧不能替代输入。
2. 报告持久化到数据库，Markdown 与 DOCX 上传 MinIO 并可下载。
3. WebSocket 持续同步，断线后可从数据库事件恢复。
4. 手动重试复用原 `analysis_job`，仅追加 run，并保持原 task/WebSocket 主题。

### FR-6 文档归档

只有范围内全部平台真实为 `verified`、Acceptance 有授权样本与 CI 证据时，017 文档才可归档；任一平台 pending 时保持当前文档。

## 3. 非功能需求

- 所有 URL 与凭据遵循加密、脱敏、SSRF 和最小权限边界。
- 不使用公共解析 API、MITM、账号自动化、私有签名、DRM/地域/权益绕过。
- 桌面与移动 Provider 页面共享容器边界、无横向溢出并与 Header 对齐。
- 后端/前端质量门禁、Compose 配置、浏览器验收和 GitHub Actions 必须通过。

## 4. 不在本期

- 西瓜视频受控会话、Snapchat 新鲜样本验证。
- Likee、Threads、好看视频、Kwai 等可信插件。
- carousel、多视频帖子、直播、播放列表和付费/private 内容。
- 未经授权的第三方真实平台访问。
