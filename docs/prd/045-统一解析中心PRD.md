# 045 统一解析中心 PRD

日期：2026-09-24。状态：目标规格，待实现与验收。关联：[Design](../design/045-统一解析中心设计.md) · [Plan](../plan/045-统一解析中心Plan.md)。

## 1. 问题与产品目标

用户希望从一个入口找回链接解析、视频 AI 智能分析、剧本解析及其结果，而不必记住任务从首页、下载详情还是剧本文档详情发起。

源码基线 0435b13c：解析记录已经联合查询链接意图与视频分析，但不包含剧本文档与剧本 AI；因此“只有链接”是用户观察，不能据此断言当前源码完全没有视频分析历史。部署版本、用户数据和实际接口返回仍需实施前核对。

本期目标：所有持久化处理任务可发现、可区分、可定位原结果、可安全继续操作。下载记录仍管理文件交付；剧本文档仍管理源文件与正文。解析中心管理处理过程与分析产出。

## 2. 范围和记录粒度

| 类型 | 用户名称 | 一条记录的含义 | 结果 |
| --- | --- | --- | --- |
| parse | 链接解析 | 一个持久解析意图 | 媒体信息、可用格式或失败原因 |
| video_analysis | 视频 AI 分析 | 一个 AnalysisJob | 导演拉片、高光、视觉资产、文章等对应 Skill 产出 |
| document_parse | 剧本基础解析 | 一个 Document 导入生命周期 | 规范化正文、目录、场景与基础统计 |
| screenplay_analysis | 剧本 AI 分析 | 一个 screenplay AnalysisJob | 审稿、专项分析或改写报告；以 result_contract 区分 |

FR-01：四类记录全部入列；剧本基础解析与 AI 审稿必须分开，上传完成不等于 AI 已完成。本地视频上传本身仍归文件导入，不伪造一条链接解析；其 AI 任务必须入列。

FR-02：每个任务一行。自动 attempt 和同参数手动 retry 不新增列表行；改 Skill、语言或提示词创建新任务、新行。剧本改写是剧本 AI 子类型，不为每个 Skill 建新记录类型。不以素材去重吞掉用户的多次分析。

FR-03：新建请求持久化成功后即可找回，包含排队、处理中、等待重试、待操作、失败、取消和过期；不只展示成功项。请求尚未被服务端接纳的格式校验错误保留表单反馈，不造历史。

## 3. 页面与交互

FR-04：导航和页面统一命名“解析中心”，沿用现有解析记录页面 URL；默认“全部”，并提供“链接解析 / 视频 AI / 剧本解析”页签，剧本页签内按“基础解析 / AI 分析 / AI 改写”筛选。

FR-05：支持服务端筛选：类型、状态组、创建时间范围、标题关键词；AI 类增加 Skill，来源详情可带 document_id 或 download_id 查看关联记录。关键词仅检索可安全展示的标题，不搜索原始 Prompt、正文或带凭据 URL。日期按用户时区转换到 UTC 左闭右开区间。

列表使用无边框内容行，桌面列为“内容与类型 / 状态 / 提交时间 / 操作”；移动端合并为纵向信息块。首屏不设置全量统计面板。主操作“新建解析”提供粘贴链接、上传视频、上传剧本三个入口，视频分析仍在媒体准备完成后发起。

单行信息：标题、类型、AI Skill、输出语言、精确状态、真实阶段、提交时间；详情补充开始/结束时间、错误原因、运行次数、源资源和结果。未知进度显示阶段/不定进度，不编造百分比。标题缺失使用安全来源标签与短 ID，Skill 下线仍显示保存的名称或原 ID。

FR-06：打开历史、刷新和返回仅执行读取，不重新提交解析、不重新运行 AI、不新增计费。AI 历史以 analysis_id 精确定位；带 ID 时不存在就展示已删除/不可用，绝不降级为 latest。素材详情的“最近分析”保留，同时新增“查看全部分析”。

FR-07：取消请求被接收显示“正在取消”，以服务端终态为准。失败或已取消后“重试”复用参数并创建新 run；成功任务“重新运行”同样需要显式点击。修改配置显示“新建分析”，不得覆盖历史输入与报告。源文件不满足运行条件时保留报告查看，禁止重跑并给出原因。

FR-08：任务执行状态与资源可用性分别展示。例如“分析已完成 · 源文件已删除”不能变为“分析失败”；“链接解析完成 · 格式已过期”不能显示仍可直接下载。AI 失败不改下载/文档成功状态。

FR-09：沿用领域删除规则，不提供统一批量删除。列表第一期只读入口；取消、重试和删除在领域详情执行。删除分析不删除源文件；删除源文件不隐式删除其他分析报告。受运行锁保护的源文件按现有规则拒绝删除。已删除分析退出列表，旧地址不再返回报告。原料删除导致无法重新运行时明确解释。

FR-10：列表显示当前页码、上一页/下一页及已可到达的页码，不以“更早的记录”代替分页。筛选和游标写入 URL，返回恢复同一页；筛选变化清空游标。服务端未提供总数时不虚构总页数，也不提供跳转到未知页的入口。首次加载失败使用错误页，首次为空与筛选无匹配分开，已有数据刷新失败保留数据并提示。仅存在活跃任务且页面可见时轮询，账号变化取消请求并清除旧数据，迟到响应不得回填。

## 4. 状态口径

统一 status_group 只用于筛选，不替换原始 status。

| 状态组 | 链接意图 | 视频/剧本 AI | 剧本基础解析 |
| --- | --- | --- | --- |
| processing | queued/preparing/resolving/retry_wait | queued/running/retry_wait | uploading/verifying |
| action_required | action_required | 无；取消请求为附加状态 | 无 |
| completed | ready/handed_off | succeeded | ready |
| failed | failed | failed | failed |
| cancelled | cancelled | cancelled | cancelled |
| expired | expired | 无 | expired |

ready 的“已完成”指信息解析就绪；handed_off 显示“已创建下载”，不代表下载完成。源文件/报告不可用不计入 expired 任务组。取消意图不能仅靠前端改状态。

## 5. 非功能目标

NFR-01：所有联合查询分支、关联资源、报告和操作均 owner-scoped；匿名/访客上下文沿用既有认证规则，不合并不同身份历史。返回与日志不包含 owner_hash、原始链接认证参数、对象路径或完整提示词。

NFR-02：单页默认 20、最多 50；分页稳定处理同时间和跨类型相同 ID。列表不读取对象存储、不读取完整正文/报告、不调用模型或解析 Provider。

NFR-03：性能目标为固定测试环境单 owner 十万混合记录、10 并发列表读取，p95 ≤ 500ms；记录 SQL 次数和执行计划。此为待验证目标，不能作为当前容量承诺。按实际索引计划优化，不先引入搜索集群或历史事件表。

NFR-04：Web 桌面和 390px、明暗主题、键盘焦点、状态播报通过真实浏览器验证。App 单独排期、契约生成与设备验收，Web 完成不等于 App 完成。

## 6. 验收标准

| 编号 | 可判定验收 |
| --- | --- |
| AC-01 | 同账号创建四类任务，全部在中心出现；新 Skill、同素材不同配置均独立可见 |
| AC-02 | 同剧本连续两次 AI 分析，分别从列表进入都命中原 analysis_id，刷新/返回不变成 latest |
| AC-03 | 排队、重试等待、待操作、失败、取消、过期均可找回，映射与原始状态一致 |
| AC-04 | 自动重试与手动同参数重跑不增加任务行；新配置新增一行；幂等重发不重复运行 |
| AC-05 | 同时间、跨类型相同 UUID、至少三页混合数据无重复遗漏；新任务插入后旧游标稳定 |
| AC-06 | 类型/状态/时间/关键词/Skill/来源组合筛选有效；换筛选重置分页，返回恢复条件 |
| AC-07 | 访问历史、刷新、分享给本人另一浏览器只产生 GET，不触发下载/解析/AI POST |
| AC-08 | A/B 账号列表、详情、报告、运行历史及操作隔离；切换账号时延迟响应不泄露旧数据 |
| AC-09 | 源文件删除后可用报告仍可查看；失效源不能重跑；删除分析后列表与旧链接一致 |
| AC-10 | 刷新失败保留数据，首次错误不显示空列表；全部活跃类型更新、终态停止轮询 |
| AC-11 | 已有数据库记录直接可见，无重复回填、无重新调用模型；缺历史元数据明确显示未知 |
| AC-12 | 性能、OpenAPI 生成、后端/前端回归和四种浏览器组合有证据，App 验收另列 |

## 7. 不在本期

不重构 AI Worker/Prompt/Skill 执行；不改变报告质量标准；不加入统一任务调度器、自动二次分析、批量删除、协作分享、全文搜索或报告版本对比编辑器。历史 run 可查看元信息；每个历史 run 的报告导出若没有可用契约，单独列为后续需求，不让 UI 暗示可读。
