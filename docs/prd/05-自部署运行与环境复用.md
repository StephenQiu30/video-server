# PRD05 自部署运行与环境复用

## 1. 背景

这个项目的目标用户是个人自部署用户。相比 SaaS，首版更重要的是“容易启动、容易调试、容易复用已有 Redis/Postgres/MinIO 环境”，而不是多租户或团队协作。

## 2. 目标

1. 支持本机开发模式。
2. 支持以 Docker Compose 为主的一键部署模式。
3. 优先复用部署者已有的 Redis、Postgres、MinIO 环境。

```gherkin
Given 部署者已有或没有基础依赖服务
When 选择本机开发或 Docker Compose 方式启动
Then 系统都能给出稳定的运行路径和健康检查方式
```

## 3. 非目标

- 不做 Kubernetes、云原生多集群或 SaaS 运维设计。
- 不做浏览器端 Cookie 上传、托管或共享。
- 不在本 PRD 中定义业务接口细节。

## 4. 核心内容

### 4.1 运行方式

1. 本机开发：复用已有 Redis、Postgres、MinIO，启动 API 和 Worker。
2. Docker Compose：拉起完整依赖和服务进程。

### 4.2 产品边界

1. 本机开发路径优先考虑研发调试体验。
2. Docker Compose 是推荐的个人自部署交付路径。
3. 所有环境变量必须有明确来源和默认行为。

### 4.3 可观测性要求

1. 提供健康检查接口。
2. 启动失败时能定位是 API、Redis、Postgres 还是 MinIO 问题。
3. 对缺失依赖给出可操作提示。

## 6. 验收门禁

- 本机开发路径能复用已有依赖启动。
- Docker Compose 路径能一键启动完整系统。
- 健康检查和启动说明完整可验证。

## 7. 风险与边界

运行文档不清晰会导致“功能其实存在，但用户跑不起来”。本 PRD 的验收必须包含真实启动路径。

## 8. 待确认问题

- 是否需要为 MinIO、Redis、Postgres 增加启动前探测脚本。
- 是否为 Docker Compose 提供最小和完整两套 profile。
