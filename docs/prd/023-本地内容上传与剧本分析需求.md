# 023 本地内容上传与剧本分析需求

- 状态：实现中，Phase A 当前态契约已完成
- 日期：2026-08-14
- 对应设计：`docs/design/023-本地内容上传与剧本分析设计.md`
- 对应调研：`docs/research/012-本地内容上传与剧本Skill调研.md`

## 1. 背景与用户问题

当前用户只能粘贴公开视频链接、选择格式并等待下载成功后创建视频分析。用户已经持有本地视频或剧本文件时，必须先寻找额外托管地址，无法直接进入项目的拉片、报告和任务闭环；现有 Analysis 又只接受视频 Artifact，不能准确处理剧本文档。

产品需要增加浏览器本地上传，并将能力严格限定为：

1. 上传本地 MP4 后执行现有导演拉片等视频视觉分析。
2. 上传剧本文档后执行剧本分析、结构审阅或中文/英文改写。

## 2. 目标用户与核心任务

目标用户是拥有视频或剧本文档处理权、使用本项目 Web 服务和已配置 Analysis Agent 的本地部署用户。

核心任务：

1. 用户在首页选择本地上传并选择一个文件。
2. 系统不经过 API 完整文件中转，将文件上传到私有隔离区。
3. 系统重新验证真实文件并生成可审计输入。
4. 视频进入现有下载详情和视频 Skill；剧本进入文档详情和剧本 Skill。
5. 用户查看任务状态、结构化结果、报告，并可取消、重试、删除或导出。

## 3. 产品目标

- 本地 MP4 与远程下载视频使用同等可信的 Artifact 和视频分析入口。
- 文档不污染下载领域，不伪造 URL inspection、格式、时长或媒体轨道。
- 视频与剧本共享成熟的异步任务、Provider、报告、重试和 WebSocket 基础设施。
- 剧本分析与改写有严格、可验证、可引用场景证据的结果契约。
- GitHub Skill 经过固定版本、许可证和内容审查后才能成为内置选择。
- 上传、解析和 AI 执行均有大小、时间、权限、保留期与 Prompt Injection 边界。

## 4. 非目标

- 通用文档摘要、问答、知识库、向量检索、办公文档助手或任意文件聊天。
- OCR、扫描 PDF、图片/音频转剧本、字幕提取或视频自动生成剧本。
- 用户自定义 Skill、Skill 市场、从 GitHub/URL 动态安装或第三方脚本执行。
- 多文件、文件夹、压缩包、批量剧本、协作编辑、批注、修订历史和版本合并。
- 首期 FDX、EPUB、PPTX、XLSX、网页和云盘导入。
- Edge Agent、微信视频号、红果 Adapter 和平台会话；这些由 `019` 负责。

## 5. 功能需求

### FR-023-01 入口与文件选择

1. 首页必须提供“链接解析”和“本地上传”两个明确入口，现有链接下载行为保持不变。
2. 本地上传首期一次只接受一个文件，允许 MP4、DOCX、PDF、TXT、Markdown 和 Fountain。
3. 选择后必须显示清洗后的真实文件名、字节大小、识别类型、支持范围、隐私披露和版本化内容权利声明。
4. 类型必须由服务端依据文件内容重新判断，浏览器 `accept`、扩展名和 MIME 只能用于交互提示。
5. 未登录、未接受权利声明、类型不支持或大小超限时不得创建上传会话。

### FR-023-02 直传与隔离

1. 浏览器必须通过短期、单资源、确定 object key 的 multipart 会话直传 MinIO quarantine；API 不缓存完整文件。
2. 浏览器不得获得 MinIO 通用凭据、任意 bucket/key、任意 S3 参数或可扩权的签名能力。
3. 上传会话必须绑定 owner、资源、attempt、声明大小、part 预算和过期时间。
4. `complete` 必须先核对 part 和对象 HEAD，再在同一 PostgreSQL 事务更新资源并写入 `content.import.verify.requested` outbox。
5. 重复创建、complete、消息投递和 Worker 恢复必须幂等，不得产生第二个最终制品。
6. 取消、失败、过期和中断必须有界清理 multipart、quarantine、最终孤儿和本地工作区。

### FR-023-03 本地视频导入

1. 本地视频必须创建 `download_job(source_kind=browser_import)`；导入任务不得伪造 inspection 或远程 format。
2. 服务端必须重新计算实际大小与 SHA-256，并验证 MP4/BMFF、至少一条视频轨、正时长、codec、尺寸和配置上限。
3. 首期允许无音频 MP4，不执行转码、修复、重新编码或容器改写。
4. 假扩展名、损坏容器、外部引用、多文件、playlist、无视频轨、超限和哈希不一致必须 fail closed。
5. 验证成功后必须生成现有 `artifacts`，进入现有下载详情、历史、保留期、取消和视频 Analysis API。
6. 来源显示必须为“本地视频上传”，不得写入 Provider canary 或宣称来自某个平台下载。

### FR-023-04 剧本文档导入

1. 剧本文档必须使用独立 Document 资源，不进入 `download_jobs` 和视频 `artifacts`。
2. 首期格式为 DOCX、未加密且可提取文字的 PDF、TXT、Markdown 和 Fountain。
3. DOCX 必须限制 ZIP 条目、解压大小、压缩比和路径，拒绝宏、路径穿越和不允许的外部关系。
4. PDF 必须拒绝加密、附件、无有效文字或提取质量低于配置门槛的文件；不得执行 JavaScript、外部资源或自动 OCR。
5. 文本格式必须限制编码、NUL、控制字符、最长行、字符数和规范化膨胀。
6. 系统必须保存原始私有对象与规范化 UTF-8 文本对象，分别记录大小、SHA-256、状态和保留期。
7. 文档资源创建后不可变；修订稿必须创建新资源。

### FR-023-05 剧本规范化与预览

1. 所有支持格式必须规范化为 UTF-8、LF 换行和稳定尾部换行。
2. 系统必须确定性识别场景标题、动作、人物、括注和对白，并为源场景生成稳定 ID。
3. 正文存在但没有可识别场景时可退化为单场景并返回质量警告；空文本、乱码超限或无法安全解析时必须失败。
4. 创建分析前，文档详情必须显示格式、字符数、场景数、检测语言、质量警告和有界纯文本预览。
5. API、日志、WebSocket 和指标不得包含完整正文或规范化文本。

### FR-023-06 Analysis 联合输入

1. Analysis 必须支持 `video` 与 `screenplay` 两种输入，并通过数据库约束保证每个任务只引用一种输入。
2. 视频任务继续锁定视频 Artifact；剧本任务必须锁定不可变 Document 和规范化文本 SHA-256。
3. 创建任务时必须固定 Skill 指令快照、指令 SHA-256、结果契约、输出语言、输入 SHA-256、Provider 解析时机和重试截止时间。
4. 视频和剧本必须共享现有 lease、heartbeat、取消、retry wait、原任务重试、报告持久化、删除和 WebSocket 语义。
5. 输入过期、已删除或哈希漂移时必须返回稳定错误，不能读取其他版本或部分结果。
6. AI 失败不得改变视频下载成功或文档 ready 状态。

### FR-023-07 Skill 清单与选择

1. `GET /api/analysis-skills` 必须按 `input_kind` 返回可用 Skill；视频详情不得显示剧本 Skill，文档详情不得显示视频 Skill。
2. 首批剧本 Skill 固定为 `screenplay-analysis`、`screenplay-structure-review` 和 `screenplay-rewrite`，不使用版本后缀。
3. 每个 Skill 必须声明允许的输入类型和服务端预注册结果契约，不能由用户或 Skill 正文指定任意 Schema/工具。
4. 现有视频 Skill 必须一次性迁移到当前标准格式并声明 `video-visual-analysis`；不保留 legacy loader。
5. `custom_prompt` 继续限制为 4000 字符，只能改变分析重点或表达，不能改变输入、工具、安全边界、目标契约或文件访问。

### FR-023-08 GitHub Skill 供应链

1. 生产 API 和界面不得提供上传、URL 安装、GitHub 搜索、自动更新或执行第三方 Skill 的能力。
2. 外部 Skill 内容必须经过许可证、来源、Prompt Injection、工具、脚本和引用路径审查后，改写为项目内置 Skill。
3. 仓库必须保存来源 URL、固定 commit、许可证/NOTICE 和本地修改说明；升级必须重新审查和验收。
4. Registry 只读取允许的 `SKILL.md` 和一层 references，拒绝符号链接、路径穿越、绝对路径、未知输入类型和未知结果契约。
5. 外部 `scripts/`、`allowed-tools`、MCP、插件和网络要求不得进入 Analysis 子进程。

### FR-023-09 剧本分析

1. `screenplay-analysis` 必须返回 logline、synopsis、结构/转折/节奏、人物目标/冲突/弧光、场景分析、对白发现、优点和优先修改项。
2. `screenplay-structure-review` 使用同一结果契约，但重点覆盖节拍、场景推进、转折、连续性和节奏。
3. 所有人物、场景、对白与修改建议必须引用存在的源场景 ID；不得用模型生成的新场景作为证据。
4. 服务端必须验证字段、字符串、数组、scene ID、引用、数量和 JSON 总字节；非法结果不得保存部分成功。
5. 超过单次安全文本预算时，可信 Worker 必须按源场景分块，先获得场景级结果，再用受控摘要生成全局结论；模型不得自行创建 subagent。

### FR-023-10 剧本中英文改写

1. `screenplay-rewrite` 的 `output_language` 只允许 `zh-CN` 或 `en-US`；与源语言不同表示跨语言改写，相同表示同语言润色。
2. Worker 必须先生成受 schema 校验的角色名、地点、专有名词、称谓和保留术语 glossary。
3. 改写必须按完整场景边界分块；单场景超限时才能按动作/对白段落细分，并保留 scene ID 与 part 序号。
4. 每块必须返回源 scene ID、part、源 SHA-256、目标语言和改写正文。
5. 合并前必须验证块一一对应、没有遗漏/重复、源哈希一致、目标语言正确和保留术语一致。
6. 任一块失败或覆盖不完整时整个任务失败，不发布部分改写；重试必须遵守原任务输入、Skill 和输出语言。
7. 完整改写正文必须只由服务端按源顺序确定性合并一次，形成 canonical Markdown，并生成 DOCX；公开 JSON 不重复承载第二份全文。

### FR-023-11 执行权限与 Prompt Injection

1. 视频继续使用当前受限 ffprobe/ffmpeg 工具；剧本执行器不得获得 FFmpeg、通用 Shell、网络、Home、仓库、其他任务、MCP、插件、浏览器或 subagent。
2. 文档正文、metadata、文件名、剧中文字和用户 Prompt 必须被标记为不可信输入。
3. CLI 子进程只接收当前任务只读输入、应用生成的 policy、受控工作目录和必要认证环境；数据库、队列、对象存储与无关 Secret 必须剔除。
4. 成功、失败、取消、lease 丢失、超时和 Agent shutdown 都必须终止完整进程组并清理工作区。
5. 模型输出只能作为数据解析，不得执行其中的命令、路径、代码、URL 或后续指令。

### FR-023-12 API、界面与报告

1. 视频导入、Document、上传会话和剧本 Analysis 创建接口必须有唯一 operationId、严格 OpenAPI、幂等键及 `201 + Location`。
2. 新增 `/documents` 列表和文档详情；MP4 成功后进入现有下载详情。
3. 剧本分析结果必须展示结构、人物、场景、对白和优先修改项；剧本改写展示正文预览、术语表、修改摘要和下载。
4. Markdown 预览、Markdown 下载和 DOCX 必须消费同一 canonical Markdown，不维护第二套内容映射。
5. 页面必须覆盖上传、解析、校验、Agent 离线、加载、空、失败、取消、重试、成功和过期状态。
6. 所有正文和模型文字按纯文本或现有安全 Markdown renderer 呈现，不执行 HTML、脚本或链接指令。

## 6. 非功能需求

### NFR-023-01 安全与隐私

- quarantine、最终原文件、规范化文本和报告均为私有对象，使用最小权限与短期下载 URL。
- 未公开剧本可能高度敏感；创建 AI 任务前必须披露正文和必要上下文会发送给活动云端模型 Provider。
- 日志、指标、任务事件和消息不得包含正文、完整 Prompt、预签名 URL、模型原始输出、人物名或场景内容。
- 删除和过期覆盖 multipart、quarantine、原文件、规范化文件、临时块、结果与报告，并受任务锁保护。

### NFR-023-02 可靠性

- PostgreSQL 是状态事实来源；上传完成与验证请求使用 transactional outbox。
- Import Worker 与 Analysis Worker 支持至少一次投递、幂等、lease、heartbeat、恢复扫描、DLQ 和有界回灌。
- 存储复制、数据库提交和清理任一位置崩溃均不得产生重复最终对象、假成功或永久可读孤儿。

### NFR-023-03 容量

- 视频/文档大小、PDF 页数、ZIP 膨胀、文本字符、场景、行长、chunk、模型输入/输出、报告、工作区、并发和 wall-clock 均使用类型化硬上限。
- 首期 Analysis Agent 总并发继续为 1；长剧本通过确定性分块收敛，不用无界上下文或无界并行降级。

### NFR-023-04 兼容与维护

- 现有 URL inspection、下载、历史、五个视频 Skill、视频结果、报告、重试和 WebSocket 不得发生行为回归。
- OpenAPI 是前后端唯一契约；SQL 只维护 `backend/sql/schema.sql` 当前态并在空/已有数据卷幂等通过。
- Domain/Application 不导入 MinIO、RabbitMQ、解析器、CLI 或框架；格式解析和 Skill loader 放在 Infrastructure。
- 单个长期源码文件按职责拆分，不建立平行前端、平行任务系统或 legacy 兼容层。

### NFR-023-05 可访问性与体验

- 遵循现有无边框视觉系统、语义 token、Radix/shadcn、Phosphor 图标和清晰返回路径。
- 满足 WCAG 2.2 AA、键盘操作、可见焦点、44×44 触控目标和 `aria-live` 节流。
- 390×844、1024px 和 1280px 不产生页面级横向滚动；长文件名、错误、术语和改写正文必须安全换行或局部滚动。

## 7. 验收标准

- `AC-023-01`：有效本地 MP4 经直传、quarantine、服务端复验和 Artifact 晋升后完成现有导演拉片与 MD/DOCX 报告。
- `AC-023-02`：假扩展名、损坏 MP4、无视频轨、超限、哈希不一致和重复 complete 均稳定收敛且无可读孤儿。
- `AC-023-03`：DOCX、文本 PDF、TXT、Markdown、Fountain 各有中/英文有效 fixture；扫描/加密 PDF、ZIP bomb、路径穿越和宏文档被拒绝。
- `AC-023-04`：规范化文本 SHA-256 稳定，同一输入重复处理得到相同场景顺序和 scene ID。
- `AC-023-05`：视频/剧本 Skill 过滤正确，未知输入类型、结果契约、路径引用、符号链接和外部脚本 fail closed。
- `AC-023-06`：中文和英文剧本各完成一次 `screenplay-analysis`，所有结论只引用有效源场景。
- `AC-023-07`：完成中→英、英→中和至少一次同语言润色；scene/chunk 覆盖 100%，无缺失/重复，glossary 保留词一致。
- `AC-023-08`：正文 Prompt Injection 无法联网、读 Home/仓库/相邻任务/Secret 或扩大工具权限。
- `AC-023-09`：取消、超时、lease 丢失、Worker shutdown 和崩溃恢复无孤儿进程、临时块或永久 multipart。
- `AC-023-10`：API/OpenAPI/前端、WebSocket、日志和数据库公开字段不泄漏正文、Prompt、预签名 URL或模型原始响应。
- `AC-023-11`：现有 URL 下载和全部视频分析回归通过；AI 失败不改变输入资源成功状态。
- `AC-023-12`：桌面和 390×844 完成上传、文档详情、Skill 选择、结果、导出、取消与重试，满足键盘和无障碍门禁。

## 8. 发布成功信号

- 用户无需外部托管即可把本地 MP4 送入现有完整视频拉片闭环。
- 用户可以从一个中/英文剧本文档得到可追溯到源场景的分析结果。
- 全剧本中英文改写没有场景遗漏、顺序漂移和人物/术语随机变化。
- GitHub 来源只以经过审查、固定 commit、带许可证记录的内置 Skill 进入生产。
- 新入口关闭或失败时，现有链接下载和视频分析保持可用。
