# PRD01 解析入口与 URL 安全

## 1. 背景

个人自部署万能视频下载器的第一步不是下载，而是安全地接收一个公开视频 URL。首版必须先把输入边界定义清楚，避免系统把本机、内网、保留地址或明显非法链接当成合法下载请求处理。

## 2. 目标

1. 用户只需提交一个公开视频 URL，就能获得明确的接收结果。
2. 系统在进入下载链路前拒绝危险、不合法或不适合作为公开视频解析的链接。
3. 错误反馈面向用户可理解，日志面向研发可排障，但不泄露敏感参数。

```gherkin
Given 用户提交一个公开视频 URL
When 系统接收并校验该 URL
Then 系统只允许安全、合法且可公开访问的链接进入后续流程
And 系统对被拒绝的链接返回明确错误语义
```

## 3. 非目标

- 不在本 PRD 中定义平台识别规则。
- 不在本 PRD 中定义任务队列、下载执行和对象存储。
- 不支持批量 URL、播放列表或频道级入口。

## 4. 核心内容

### 4.1 用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 自部署用户 | 提交一个公开视频链接 | 系统返回“已接收”或明确拒绝原因 |
| 自部署用户 | 粘贴格式错误的链接 | 系统返回可理解的错误提示 |
| 部署者 | 防止 SSRF 风险 | 本机、内网、保留地址链接被拒绝 |

### 4.2 接收规则

1. 仅接受 `http` 和 `https`。
2. URL 必须包含有效主机名。
3. 拒绝 `localhost`、`127.0.0.1`、内网 IP、保留地址和明显伪造主机。
4. 拒绝空字符串、非 URL 文本和不完整协议地址。

### 4.3 反馈原则

1. 接收失败时优先返回业务语义，不直接暴露底层异常。
2. 错误文案应指导用户下一步，例如“请改用公开视频链接”。
3. 日志中不得直接打印完整敏感查询参数。

## 6. 验收门禁

- 非法 URL、本机地址、内网地址和保留地址均被拒绝。
- 错误反馈覆盖格式错误、危险地址和不支持的接收场景。
- 日志脱敏规则可验证。

## 7. 风险与边界

URL 校验过严会误伤真实公开视频链接，过松会带来 SSRF 风险，验收时需要同时覆盖正反样例。

## 8. 待确认问题

- 首版是否需要兼容短链接自动展开。
- 是否允许通过配置添加自定义信任域名。
