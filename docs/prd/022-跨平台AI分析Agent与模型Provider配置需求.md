# 022 跨平台 AI 分析 Agent 与模型 Provider 配置需求

- 状态：In Progress（内部实现与自动化契约已通过；真实 API Key、macOS、Linux 实机待验收）

- 日期：2026-08-13
- 目标用户：本地部署用户、管理员、运维人员

## 1. 背景

文档和视频制品可以正常保留，但 AI 分析依赖一个手工启动的宿主机 Worker。进程退出或机器重启后心跳过期，页面只显示“AI 分析服务暂时不可用”。此外，项目在 Codex 桌面环境中可以直接复用 ChatGPT 登录，却没有面向其他模型服务的安全配置入口。

## 2. 用户故事

1. 作为本地 Codex 用户，我希望无需填写 API Key，直接使用已登录的 ChatGPT/Codex 环境。
2. 作为管理员，我希望只填写名称、Endpoint、模型与 Key 就能接入兼容服务。
3. 作为 macOS、Windows 或 Linux 用户，我希望机器登录后 Agent 自动启动，异常后自动恢复。
4. 作为管理员，我希望区分“配置已存在”和“Agent 真正在线”，快速定位分析不可用原因。
5. 作为安全负责人，我希望 Key 不被回显、不进入日志，也不污染用户全局 CLI 配置。

## 3. 功能需求

### P0

- 默认提供本机 Codex 登录 Profile。
- 支持本机 Codex、Claude 登录与自定义 API Key Profile。
- Profile 可新增、编辑、启用和删除；只允许一个活动项。
- Key 加密保存，API 只返回是否已配置。
- Worker 下一任务自动使用最新活动 Profile。
- 管理页显示 Agent 在线状态、当前执行链路、模型与认证方式。
- 提供三平台当前用户服务的 install/status/doctor/uninstall 命令。
- Worker 内部组件异常自动退避重启，进程异常由系统服务拉起。

### P1

- 内置常用 Provider 预设，只填写 Key。
- Agent 侧连接测试、模型发现与稳定诊断码。
- 管理页展示 CLI 版本、最后心跳与最后成功任务。

### P2

- 多 Provider 优先级、熔断、自动故障转移、用量与预算。
- 团队级 AI Gateway 与外部 Secret Manager。

## 4. 安全与体验要求

- 非管理员访问管理接口返回 403。
- API Key 不得出现在 GET/PATCH/POST 响应、日志、命令行参数和任务结果中。
- 公网 Endpoint 必须 HTTPS；本机回环地址允许 HTTP。
- 切换 Provider 不要求重启 API 或手工编辑 `.env`。
- 在 390×844 视口可完成查看、新增、编辑和启用操作，无横向滚动。
- 错误文案必须说明是 Agent 离线、配置不完整还是任务执行失败，不使用笼统“操作未完成”替代可行动信息。

## 5. 成功指标

- 重启系统并登录用户后，Agent 在 60 秒内恢复有效心跳。
- 活动 Profile 切换后，下一个新任务使用新 `provider/model` 记录。
- 任何管理 API 响应与正常日志均无法检索到测试 Key。
- 本机 Codex 登录路径不要求新增 Key。
- 三个平台的生成服务定义具备自动启动与失败重启配置。
