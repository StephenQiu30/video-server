# 001 服务基座与运行配置需求

## 文档状态

- 状态：Accepted for Planning（2026-07-20）；由已确认总需求等价拆分，尚未授权实现。
- 设计依据：[001 服务边界与总体架构](../design/001-服务边界与总体架构设计.md)。
- 对应 Plan：[001 服务基座与运行配置计划](../plans/001-服务基座与运行配置计划.md)。

## 1. 背景与价值

MVP 需要一套可重复启动、可诊断且没有隐藏基础设施的服务基座，使后续解析和下载能力在开发、测试与部署环境保持一致。运维人员应能只通过环境配置启动 API、Worker、PostgreSQL、RabbitMQ 和 MinIO，不修改源码或镜像。

## 2. 必须能力

1. API 与 Download Worker 是独立进程，使用同一锁定依赖和统一 Settings。
2. PostgreSQL、RabbitMQ、MinIO 是唯一数据库、消息队列和对象存储；不存在候选实现或通用适配层。
3. 源码直接位于 `src/`；配置、日志、数据库连接和外部客户端职责清晰。
4. 开发部署值来自根目录 `.env`，生产由同名环境变量覆盖；缺失、类型错误或越界时启动失败。
5. `alembic/env.py` 从统一 Settings 读取 `DATABASE_URL`；数据库凭据不进入 `alembic.ini`、源码、Compose 或镜像。
6. Compose 明确提供 `api`、`worker-download`、`postgres`、`rabbitmq`、`minio` 五个部署单元及必要持久卷。
7. 依赖版本、yt-dlp/FFmpeg/JS runtime 来源、许可证和构建结果可追踪、可复现、可回滚。

## 3. 明确不做

- 不增加 Redis、Celery、第二套 broker、本地文件交付或存储适配器。
- 不拆微服务、不引入 Kubernetes，不实现账号、AI、字幕、批量或历史。
- 本需求不定义视频解析算法、任务状态机或 HTTP 业务模型，它们由后续 PRD 负责。

## 4. 配置与安全规则

- `.env.example` 必须列出全部业务配置键和非敏感开发示例，真实 `.env` 永不提交。
- API、Worker、Alembic、housekeeping 不得分别维护环境读取或业务默认值。
- 日志只允许输出脱敏后的运行状态，不输出 Secret、含凭据连接串、视频 URL query 或预签名地址。
- API 路径、状态枚举、消息 schema 和数据库约束是产品契约，不作为可变部署配置。

## 5. Product Acceptance Criteria

| 编号 | 验收行为 |
| --- | --- |
| `S001-AC-01` | 冷环境能以锁文件和 Compose 重复构建并启动五个确定部署单元 |
| `S001-AC-02` | API 与 Worker 独立运行，API 不执行长下载，二者只使用 PostgreSQL、RabbitMQ、MinIO |
| `S001-AC-03` | 缺少、非法或越界配置会在启动阶段失败，合法环境变量可覆盖 `.env` |
| `S001-AC-04` | API、Worker、Alembic 共用 Settings，源码、迁移、Compose、镜像与日志无硬编码凭据、地址和资源阈值 |
| `S001-AC-05` | 依赖、许可证、FFmpeg 构建选项、版本和 checksum 可追踪且冷构建可重复 |
| `S001-AC-06` | 目录和依赖中不存在非 MVP 能力、候选基础设施、通用适配层或复制的 AGPL 参考源码 |

## 6. 冻结决策

1. Python、FastAPI、SQLAlchemy、Alembic、Pydantic Settings 为服务基座。
2. PostgreSQL、RabbitMQ、MinIO 为唯一基础设施。
3. 源码直接位于 `src/`，Alembic 位于仓库根级 `alembic/`。
4. 本 PRD 通过只表示可进入 Plan，不表示已实现。
