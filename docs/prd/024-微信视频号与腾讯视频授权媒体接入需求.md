## 1. 背景与产品判断

用户希望把微信视频号、腾讯视频以及自己腾讯云 VOD 中的媒体导入现有下载、Artifact 和完整视频分析闭环。当前系统能识别部分腾讯视频 URL，也已具备安全的本地 MP4 导入，但仍存在三类问题：

1. 视频号社区实现依赖登录会话、未公开接口、本地代理/证书或受保护媒体转换，不能作为本产品的默认采集能力。
2. 当前匿名权益检查会漏过 private/premium/member 等限制，固定 Tencent extractor 又缺少公开免费正向证据，不能继续静态标为 `verified`。
3. 腾讯视频消费会员与腾讯云 VOD 资产所有者能力被混淆；前者通常只有官方播放/缓存权，后者才有官方媒资导出 API。

产品必须把“URL 可识别”“公开元数据可解析”“平台可播放”“允许导出”和“已生成完整可分析制品”拆成不同结果。正确解析受限内容并返回不可下载原因，也是成功的产品结果。

## 2. 目标用户与核心任务

### 2.1 目标用户

- 拥有视频号原文件或合法导出文件、希望进行拉片分析的创作者/权利方。
- 希望判断腾讯视频 URL 是否公开可下载，或为什么只能官方播放的普通用户。
- 在自己腾讯云 VOD 账号/子应用中拥有媒资，并需要把 clear 源文件或处理输出导入本项目的团队。
- 负责 Provider、Secret、权限、审计和真实 canary 的管理员。

### 2.2 核心任务

1. 输入文章/视频链接或选择官方资产后，立即得到来源、权益、保护状态、可执行动作和稳定原因；公众号多视频文章可先发现再选择。
2. 导入自有视频号 MP4，生成现有 Artifact 并继续完整视频分析。
3. 对腾讯 VIP、购买、试看、private、地域或 DRM 内容得到准确限制，而不是假成功或试看文件。
4. 连接当前租户自己的腾讯云 VOD 子应用，选择明确 `FileId` 并安全导出未加密制品。
5. 在历史、任务详情和 Provider 页面看见真实来源及当前能力证据。

## 3. 产品范围

| 来源 | 首期产品行为 |
| --- | --- |
| 微信公众号公开文章 | 作为多资产 discovery 容器，分别列出公众号原生、腾讯视频、视频号和未知 embed；原生 clear 项仅在身份映射唯一且全部门禁通过后下载 |
| 微信视频号分享 URL | 识别为 `wechat_channels`，返回 `export_required`，引导自有/合法导出文件上传 |
| 视频号自有或合法导出 MP4 | 复用 023 的 quarantine、Import Worker、Artifact 和 Analysis |
| 腾讯视频公开单视频 | 当前先降级；只有接口机制获批、公开免费正向证据和真实 E2E 全部通过后才开放 clear 下载 |
| 腾讯 VIP/购买/试看/DRM | 可解析公开元数据和限制；无下载格式，只提供官方播放/缓存行动 |
| 租户自有腾讯云 VOD | 通过独立官方连接器导出 clear 源文件/处理输出；加密输出保持受限 |
| 未来微信正式 API | 取得书面许可或正式合作 API 后另行启用独立官方连接器 |

## 4. 功能需求

### FR-024-01 来源识别与准入

1. 系统必须区分微信公众号文章容器/原生视频、微信视频号、腾讯视频消费站和腾讯云 VOD，已识别但未批准的来源不得落入 Generic Provider。
2. 视频号首期只识别经审查的单作品分享形态；主页、搜索、评论、直播、回放和批量入口不得创建下载格式。
3. 腾讯视频只允许 `/x/page/{vid}.html` 与 `/x/cover/{series_id}/{vid}.html` 单视频/单集形态；剧集首页、频道、搜索、直播、playlist、未知 query 和跨形态重定向必须拒绝。
4. 每次重定向和下载前重解析都必须重新执行 host/path、DNS/IP、来源身份和权益检查。

### FR-024-02 统一解析决策

1. Inspection 必须返回 `downloadable/playback_only/export_required/blocked/unsupported` 之一，并分别返回 `entitlement_state`、`identity_state`、`protection_state` 和低基数 `restriction_reason`。
2. 只有 `downloadable` 可以返回 `formats` 并创建下载；其他状态的 `formats` 必须为空。
3. private、需要登录、VIP、会员、购买、试看、地域、encrypted、DRM 和 unknown 对所有 access mode 一律 fail closed。
4. 可下载结果必须具有 `public_free` 或正式 `official_download_grant` 正向证据；缺少限制字段不构成公开免费证据。
5. 用户权利声明只形成审计记录，不能覆盖平台权益或保护结果。

### FR-024-03 微信公众号文章 discovery 与原生视频

1. `mp.weixin.qq.com` 文章必须使用独立 `wechat_official_account_article`，不能识别成 `wechat_channels`；首期只接受公开 `/s/...` 和严格参数 allowlist。
2. Adapter 只用有界标准 HTTP 与静态解析，不执行 JavaScript，不使用 Cookie、stealth 浏览器、验证码绕过或第三方文章解析 API。
3. 文章内零个、一个或多个 item 必须作为 discovery 返回；多项和单项都由用户明确选择 opaque item ref 后再创建 inspection。
4. item 必须分类为 `official_account_native/tencent_video/wechat_channels/unknown` 并路由相应门禁；未知项不进入 Generic。
5. 公众号原生项只有在 `mpvid/media id/representation` 一一绑定、CDN host/path 批准、无需登录、权益为 public-free、保护为 clear 且 RightsBasis 有效时才可下载。
6. DOM 顺序猜测、数量错配、重复 id、挑战/登录/关注/付费/验证码或 schema 不明一律 fail closed；不产生媒体正文。
7. inline MP4/CDN URL 和 query 视为 Secret，只在一次 resolve/attempt 内使用；discovery、日志、错误、DB、MQ 和 Artifact 只保存 opaque ref/hash。
8. 下载前重新获取文章并验证 article/item/media identity；删除、变更、过期或映射漂移不得复用旧 URL。
9. 原生项使用独立 `article_native` execution/source kind、`article_media.requested` 和 Article Media Worker；消息只含内部 id，Worker 写 quarantine 后必须经共享 Import Intake 和无外网 Import Worker 复验，不得进入 Generic 或现有 Download Worker。

### FR-024-04 微信视频号文件导入

1. 视频号 URL 当前不得调用元宝 Cookie、finder 私有接口、公共 Worker、代理、CA、页面注入、客户端拦截、`decodeKey` 或受保护前缀转换。
2. 用户可以上传其自有原文件或合法取得的标准 MP4；系统必须沿用 023 的隔离上传和完整媒体验证。
3. 导入保存版本化权利声明、脱敏来源和不可逆文件指纹，不保存平台 URL、作品 id、会话、token、媒体 URL 或响应原文。
4. 成功结果显示为“用户提供的视频号来源文件”，不得显示为平台下载成功，也不得写视频号 Provider canary。
5. 若使用 Edge Agent，它只能传输用户显式选择的明文文件，不能读取微信网络、进程、浏览器 profile、缓存或系统代理。

### FR-024-05 腾讯公开视频候选能力

1. 当前 `qqvideo-public-video-v1` 必须先从静态 `verified` 降为 `unknown/disabled`，不得继续生成生产下载格式。
2. 恢复前必须完成未公开接口/`cKey` 机制的法务与安全审批；产品不得复刻或扩展签名、接入外部签名服务或会员 Cookie。
3. Provider classifier 必须正向证明公开免费、非试看且 clear，并绑定页面 id、上游 id 和最终媒体身份。
4. 下载前必须重新分类；若内容变为受限，不得换账号、降级到试看或复用旧媒体 URL。
5. 公开视频能力只有完整下载、Artifact、Analysis 和全部受限负例门禁通过后才可标为 `verified`。

### FR-024-06 腾讯 VIP、购买与受保护内容

1. 产品不得提供腾讯视频登录、Cookie 上传、VIP MP4 导出、官方缓存导出或 DRM 解密入口。
2. 能安全取得时可展示公开标题、时长、封面和限制原因；不得把片花/试看当作完整视频。
3. VIP/会员/购买返回 `playback_only`，DRM/encrypted/geo/unknown 返回 `blocked`。权益负例不得请求媒体 payload；直连 BMFF 保护状态只能在身份和权益正向证明后做固定预算的 head/tail range 探针。所有负例均不得留下 quarantine、对象或 Artifact。
4. UI 只提供受控的“在腾讯视频中打开/使用官方离线能力”行动，不暴露播放 token 或媒体 URL。

### FR-024-07 腾讯云 VOD 官方连接

1. 用户必须建立 owner-scoped、不可回读、可验证、可轮换和可撤销的腾讯云 VOD 连接；推荐每租户独立 `SubAppId`。
2. 明文 Secret 只从浏览器提交到 Broker/Vault 边界内的独立一次性 Secret Ingress；FastAPI 只创建 intent 并接收 opaque secret version ref。业务 API、数据库业务列、MQ、日志、对象 metadata 和前端持久存储均不得获得明文 Secret。
3. 首期只接受连接内确定的 `FileId`；`v.qq.com` 的 `vid/cid` 不能作为 VOD 资产 id。
4. 连接器必须重新验证 `SubAppId/FileId`、连接版本、资产归属、导出依据、表示身份和保护状态。
5. 只允许未加密源 MP4、未加密 MP4 转码和经保护扫描的 clear HLS；DASH、encrypted HLS、私有加密、DRM 和 unknown 拒绝。
6. 短时签名 URL 只能存在于一次 attempt 内；过期最多有界重解析一次，不得持久化或记录。

### FR-024-08 执行隔离与制品验证

1. `remote_provider`、`article_native`、`browser_import/edge_import` 和 `official_connector` 使用独立消息、claim 条件和状态机，不得跨来源回退。
2. 现有 Download Worker 只处理 `remote_provider`；Article/Official Worker 写 quarantine 后，必须通过共享内部 Import Intake 原子创建 `media_imports/media_import_attempts`，再由无外网 Import Worker 独立复验并晋升 Artifact。
3. HLS key/session-key、DASH ContentProtection、BMFF `pssh/encv/enca/sinf` 和未知保护必须在 inspection、重解析及晋升阶段拒绝。
4. 成功必须完成容器、轨道、时长、大小、保护状态、SHA-256、持久对象和唯一 Artifact 验证；HTTP 200、M3U8 或片段成功不算完成。

### FR-024-09 状态、历史与审计

1. Provider API 必须分别展示 URL 识别、Public Runner、文件导入、官方连接器及 metadata/download/media/analysis 状态。
2. Canary 证据至少按 Provider、执行器版本、`execution_mode`、`access_partition` 和 client profile 分区，不能互相掩盖；非 Runner 的 `access_partition=not_applicable`。
3. 普通用户设备、用户文件和真实用户资产不得作为 canary；平台声明导入不能写平台 canary。
4. 历史和详情必须显示 `source_origin/provider_key/acquired_by`，并支持投诉、撤销和制品删除审计。

## 5. 用户体验与稳定错误

- `article_video_selection_required`：列出文章内可识别视频，要求用户选择，不默认第一项。
- `article_access_restricted`：说明文章需要验证、登录或付费，本产品不会启动浏览器绕过；可导入自有文件。
- `article_video_identity_unverified`：说明无法可靠绑定嵌入项与媒体表示，已安全停止，不返回 CDN URL。
- `export_required`：说明当前不支持视频号链接下载，并直接提供自有文件上传入口。
- `playback_only`：说明内容需要登录/VIP/购买，只提供官方打开动作。
- `drm/encrypted`：说明内容受保护，本产品不解密或导出。
- `preview_only`：明确提示只识别到试看/片花，不创建下载。
- `content_entitlement_unknown`：说明无法证明公开可下载，默认关闭，不建议用户换 Cookie。
- `official_connection_required/expired/revoked`：引导创建、验证或轮换当前租户的官方连接。
- `official_asset_not_exportable`：说明该 `FileId` 没有 clear 可导出表示，请权利方在 VOD 生成未加密输出或提供原文件。

能够安全完成分类的限制结果必须返回 `200/201` Inspection 成功资源、低基数 `restriction_reason` 和 `formats=[]`；不能形成 Inspection 的无效请求、资源/owner/连接错误才使用 RFC 9457 稳定 Problem type。两者都不得把上游响应、Secret、URL query 或异常原文返回客户端。

## 6. 非功能需求

### 6.1 安全与隐私

- 所有外部 URL 执行 SSRF、DNS rebinding、重定向和 host/path allowlist 防护。
- 公众号文章只允许标准 HTTP 静态解析，signed CDN URL/文章 ticket/inline data 均按 Secret 脱敏；不运行浏览器绕过。
- Official Connector 使用独立 workload identity、网络、Vault policy 和 quarantine 写权限。
- DB、MQ、日志、指标、对象 metadata 和公开 API 通过 Secret 字段扫描。
- 连接、inspection、download/import、Artifact 和 Analysis 全部 owner 隔离；跨 owner 统一 404。

### 6.2 可靠性与性能

- 解析和下载有统一超时、大小、时长、segment、重定向、重试和并发预算。
- 每个 attempt 幂等；重复消息、Worker 崩溃、连接撤销和短时 URL 过期不能产生重复 Artifact 或假成功。
- 权益、身份和 manifest 声明保护的受限判定必须发生在任何媒体 payload 前；直连 BMFF 只允许固定总预算的 head/tail range 探针，扫描不完整即 `protection=unknown`。负例不得产生 quarantine/object/Artifact 残留。

### 6.3 可观测性与供应链

- 指标只使用低基数 Provider/执行模式/状态/稳定错误，不使用 owner、URL、标题、FileId 或 connection id 标签。
- 固定 yt-dlp、腾讯云 SDK 和所有 vendor 版本，生成 SBOM/NOTICE；运行时不得下载 GitHub 脚本、插件、DLL/WASM 或 CA。

## 7. 非目标

- 任意视频号分享链接、直播/回放或批量作者归档的直接下载。
- 微信公众号挑战、付费、登录/关注文章的绕过，以及批量文章抓取、正文归档或第三方解析中转。
- 腾讯视频 VIP、购买、private、地域或 DRM 内容的明文导出。
- 微信/元宝/腾讯消费端 Cookie、Token、私有签名、公共解析站或外部签名服务。
- DRM license/key、HLS key、`decodeKey`、受保护缓存或前缀转换。
- 把用户权利声明当作技术解锁或法律授权判断。

## 8. 发布定义

核心范围可发布必须同时满足：Phase 0 安全加固、公众号原生 clear 单/多视频 discovery/选择/下载 E2E 及受限负例、视频号自有文件真实导入与 Analysis、腾讯受限内容无字节负例、腾讯云 VOD owner clear 资产真实 E2E、Provider 状态真实性以及安全/租户/Secret 门禁。

腾讯公开视频下载是独立条件能力：审批或正向权益证据任一缺失时保持 `unknown/disabled`，不阻塞其他核心能力发布，也不得被宣传为已支持。未来视频号正式连接器不属于本期完成条件。
