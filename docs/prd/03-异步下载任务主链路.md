# PRD03 异步下载任务主链路

## 1. 背景

视频下载天然存在耗时长、失败面多、依赖外部平台变化快的特点。首版如果采用同步接口直出文件，会让用户体验和系统稳定性都很差，因此必须先定义异步任务模型。

## 2. 目标

1. 用户提交合法 URL 后，系统创建异步任务并返回任务 ID。
2. 用户可查询任务状态，并在任务成功后获取下载结果。
3. 系统对失败、取消、重试给出稳定语义。

```gherkin
Given 用户提交一个合法且可识别的平台 URL
When 系统创建下载任务
Then 系统返回 queued 状态和任务 ID
And Worker 异步执行下载并持续回写状态
```

## 3. 非目标

- 不支持批量下载、播放列表和频道同步。
- 不支持实时流式回传视频文件。
- 不在首版中强制实现 SSE 订阅。

## 4. 核心内容

### 4.1 状态模型

任务状态固定为 5 个，与 Design01 §4.6 对齐：

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| `queued` | 任务已创建并等待 Worker | 否 |
| `running` | 正在下载、抽取元数据或上传产物 | 否 |
| `succeeded` | 主视频已成功归档 | 是 |
| `failed` | 主视频下载或上传失败 | 是 |
| `canceled` | 用户主动取消 | 是 |

**产物过期处理**：不引入独立的 `expired` 状态。过期后任务保持 `succeeded`，通过 `failure_code = "retention_expired"` 和 `object_key = NULL` 标识产物已清理。这与 Design01 §4.6 和 PRD04 §4.2 一致。

#### 4.1.1 状态流转规则

| 前置状态 | 目标状态 | 触发角色 | 约束条件 |
| --- | --- | --- | --- |
| `queued` | `running` | Worker | Worker 拾取任务后自动流转 |
| `queued` | `failed` | 系统 | 队列不可用或任务超时未被拾取 |
| `queued` | `canceled` | 用户 | 用户主动取消 |
| `running` | `succeeded` | Worker | 主视频下载、探查和上传均成功 |
| `running` | `failed` | Worker | 下载、探查或上传过程中发生错误 |
| `running` | `canceled` | 用户 | 用户主动取消 |

**约束**：
1. 只有 Worker 可以把任务从 `queued` 推进到 `running`。
2. 只有主视频成功归档后才能进入 `succeeded`。
3. 终态（`succeeded`、`failed`、`canceled`）不可再流转，但 `succeeded` 的产物可过期清理。

### 4.2 API 契约

#### 4.2.1 创建任务

```
POST /api/tasks
Authorization: Bearer <token>
Content-Type: application/json

{
  "url": "https://www.bilibili.com/video/BV1xx411c7d",
  "format_id": "best",         // 可选，默认 "best"
  "title": null,               // 可选，用户自定义标题
  "cover_url": null,           // 可选
  "duration_seconds": null,    // 可选
  "format_label": "推荐下载"   // 可选，格式显示名
}
```

响应 `201 Created`：
```json
{
  "id": "uuid-string",
  "state": "queued",
  "progress": 0,
  "attempt_no": 1,
  "is_latest_attempt": true,
  "source_url": "https://www.bilibili.com/video/BV1xx411c7d",
  "created_at": "2026-06-10T12:00:00Z",
  "updated_at": "2026-06-10T12:00:00Z"
}
```

#### 4.2.2 任务列表

```
GET /api/tasks?state=succeeded&limit=20
Authorization: Bearer <token>
```

响应 `200 OK`：`TaskRead[]`，按 `created_at` 降序。

#### 4.2.3 任务详情

```
GET /api/tasks/{task_id}
Authorization: Bearer <token>
```

响应 `200 OK`：`TaskRead`，包含 `state`、`progress`、`failure_code`、`failure_reason`、`output_filename`、`object_size`、`expires_at` 等。

#### 4.2.4 取消任务

```
POST /api/tasks/{task_id}/cancel
Authorization: Bearer <token>
```

响应 `200 OK`：`TaskRead`，`state = "canceled"`。

#### 4.2.5 重试任务

```
POST /api/tasks/{task_id}/retry
Authorization: Bearer <token>
```

响应 `201 Created`：新 `TaskRead`，`state = "queued"`，`attempt_no = 原任务 + 1`，`retry_of_task_id = 原任务 ID`。

#### 4.2.6 任务事件

```
GET /api/tasks/{task_id}/events
Authorization: Bearer <token>
```

响应 `200 OK`：`TaskEventRead[]`，按 `created_at` 升序，每条包含 `state`、`message`、`created_at`。

#### 4.2.7 下载链接

```
GET /api/tasks/{task_id}/download-link
Authorization: Bearer <token>
```

响应 `200 OK`：
```json
{
  "url": "https://minio.example.com/bucket/key?X-Amz-Signature=...",
  "expires_in_seconds": 900
}
```

错误响应：
- `409 invalid_state`：任务非 `succeeded` 状态
- `410 retention_expired`：产物已过期清理

### 4.3 错误码目录

#### API 错误码（AppError）

| 错误码 | HTTP 状态码 | 含义 | 触发场景 |
| --- | --- | --- | --- |
| `not_found` | 404 | 任务不存在或不属于当前用户 | 查询、取消、重试、下载链接 |
| `invalid_state` | 409 | 当前状态不允许该操作 | 取消非活跃任务、重试非终态任务、下载非成功任务 |
| `invalid_url` | 422 | URL 校验失败 | 格式错误、本机地址、内网地址 |
| `rate_limited` | 429 | 请求限流 | 创建任务频率超限 |
| `limit_exceeded` | 429 | 配额超限 | 日额度、存储额度、并发数 |
| `retention_expired` | 410 | 产物已过期清理 | 下载链接请求时产物已过期 |
| `retry_superseded` | 409 | 任务已有新的重试 | 重复重试同一任务 |
| `queue_unavailable` | 503 | Redis 队列不可用 | 入队失败 |

#### Worker 失败码（WorkerFailureCode）

| 错误码 | 可重试 | 含义 |
| --- | --- | --- |
| `download_failed` | 是 | 通用下载错误 |
| `format_unavailable` | 否 | 所选格式不可用 |
| `file_too_large` | 否 | 文件超过大小限制 |
| `media_tools_missing` | 否 | ffmpeg/ffprobe 不可用 |
| `ffprobe_failed` | 否 | 媒体探查失败 |
| `storage_failed` | 是 | MinIO/S3 上传失败 |
| `task_timeout` | 是 | 任务超过最大运行时长 |
| `task_canceled` | 否 | 用户取消 |
| `platform_restricted` | 否 | 平台限制下载 |
| `platform_rate_limited` | 是 | 平台限流 |
| `unsupported_platform` | 否 | 不支持的平台 |
| `browser_cookies_unavailable` | 否 | 浏览器 Cookie 读取失败 |

### 4.4 进度语义

`progress` 字段为整数，范围 0-100：

| 阶段 | 进度值 | 含义 |
| --- | --- | --- |
| 创建 | 0 | 任务已入队 |
| 开始处理 | 5 | Worker 已拾取，开始下载 |
| 下载中 | 5-95 | 下载进度（由 Worker 回写） |
| 完成 | 100 | 主视频已成功归档 |

**约束**：
1. `progress` 只在 `running` 状态下由 Worker 更新。
2. `succeeded` 状态的 `progress` 必须为 100。
3. `failed`/`canceled` 状态的 `progress` 保持最后值，不超过 99。

### 4.5 取消与重试边界

#### 取消规则

| 当前状态 | 允许取消 | 说明 |
| --- | --- | --- |
| `queued` | 是 | 任务尚未开始执行 |
| `running` | 是 | Worker 需检查取消标志 |
| `succeeded` | 否 | 终态，返回 `invalid_state` |
| `failed` | 否 | 终态，应使用重试 |
| `canceled` | 否 | 已取消，返回 `invalid_state` |

取消语义：
- `state` 设为 `canceled`
- `failure_reason` 设为 "用户已取消任务"
- 写入 `task_events` 记录

#### 重试规则

| 当前状态 | 允许重试 | 说明 |
| --- | --- | --- |
| `queued` | 否 | 任务尚未完成，返回 `invalid_state` |
| `running` | 否 | 任务正在执行，返回 `invalid_state` |
| `succeeded` | 条件允许 | 仅当产物已过期（`failure_code = "retention_expired"` 或 `expires_at` 已过） |
| `failed` | 是 | 创建新任务 |
| `canceled` | 是 | 创建新任务 |

重试语义：
- 创建新任务（`retry_of_task_id` 指向原任务）
- `attempt_no = 原任务.attempt_no + 1`
- 保留 `source_url`、`title`、`cover_url`、`duration_seconds`、`format_id`、`format_label`
- 新任务 `state = queued`，`progress = 0`
- 原任务 `is_latest_attempt` 变为 `false`

### 4.6 事件流要求

关键状态流转必须写入 `task_events` 表：

| 事件触发 | 必写 | 示例消息 |
| --- | --- | --- |
| 任务创建 | 是 | "任务已创建，等待下载" |
| Worker 开始处理 | 是 | "开始下载" |
| 状态流转 | 是 | "下载完成，开始上传" |
| 任务成功 | 是 | "任务完成" |
| 任务失败 | 是 | 失败原因摘要 |
| 用户取消 | 是 | "用户已取消任务" |
| 重试创建 | 是 | "第 2 次尝试已创建，等待下载" |
| 产物过期清理 | 是 | "过期文件已清理，历史记录已保留" |

**约束**：
1. 每条事件包含 `task_id`、`state`、`message`、`created_at`。
2. 事件按 `created_at` 升序排列，不可修改。
3. 事件写入失败不应回滚主事务（尽力写入）。

### 4.7 用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 自部署用户 | 创建下载任务 | 返回任务 ID 和初始状态 |
| 自部署用户 | 查询任务详情 | 可看到状态、进度和失败原因 |
| 自部署用户 | 失败后重试 | 系统允许对失败任务发起重试 |

### 4.8 产品边界

1. 任务成功的必要条件是主视频成功归档。
2. 元数据或封面缺失不应把主视频任务回退为失败。
3. 用户轮询是首版正式支持的结果获取方式。

## 6. 验收门禁

- 支持任务创建、详情、列表、取消和重试。
- 主视频成功后状态为 `succeeded` 且进度为 100。
- 失败原因可映射到稳定错误码。
- 状态流转规则与 Design01 §4.6 一致（5 状态）。
- 过期产物通过 `SUCCEEDED + retention_expired` 标识，不引入独立状态。
- API 契约、错误码目录、进度语义、取消重试边界和事件流要求均有明确定义。

## 7. 风险与边界

队列积压、第三方限流、FFmpeg 缺失和上传失败都会影响主链路，验收必须覆盖异常路径。

## 8. 待确认问题

- 是否在首版暴露任务事件列表接口。
- 是否给重试任务保留原任务 ID 还是创建新任务。
