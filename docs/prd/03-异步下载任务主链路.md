# PRD03 异步下载任务主链路

## 1. 背景

视频下载天然存在耗时长、失败面多、依赖外部平台变化快的特点。首版如果采用同步接口直出文件，会让用户体验和系统稳定性都很差，因此必须先定义异步任务模型。

## 2. 目标

1. 用户提交合法 URL 后，系统创建异步任务并返回任务 ID。
2. 用户可查询任务状态，并在任务成功后获取下载结果。
3. 系统对失败、取消、重试给出稳定语义。

```gherkin
Given 用户提交一个合法且可识别的平台 URL
When 系统创建下载任务
Then 系统返回 queued 状态和任务 ID
And Worker 异步执行下载并持续回写状态
```

## 3. 非目标

- 不支持批量下载、播放列表和频道同步。
- 不支持实时流式回传视频文件。
- 不在首版中强制实现 SSE 订阅。

## 4. 核心内容

### 4.1 状态模型

任务生命周期包含 6 个状态：

| 状态 | 含义 |
| --- | --- |
| `queued` | 任务已创建并等待 Worker |
| `running` | 正在下载、抽取元数据或上传产物 |
| `succeeded` | 主视频已成功归档 |
| `failed` | 主视频下载或上传失败 |
| `canceled` | 用户主动取消 |
| `expired` | 任务成功过，但产物已过期清理 |

#### 4.1.1 状态流转规则

| 当前状态 | 目标状态 | 触发角色 | 约束条件 |
| --- | --- | --- | --- |
| `queued` | `running` | Worker | 仅 Worker 消费时可触发 |
| `queued` | `canceled` | 用户 | 用户主动取消 |
| `running` | `succeeded` | Worker | 主视频已成功归档至 MinIO |
| `running` | `failed` | Worker | 主视频下载或上传失败 |
| `running` | `canceled` | 用户 | 用户主动取消；Worker 需检测并中止 |
| `failed` | `queued` | 用户 | 用户发起重试，创建新任务 |
| `succeeded` | `expired` | 系统 | 产物过期清理后自动流转 |

**约束规则：**

1. 只有 Worker 可以将任务从 `queued` 推进到 `running`。
2. 只有主视频成功归档后，任务才能进入 `succeeded`。
3. `expired` 不代表下载失败，仅表示产物已被清理。
4. 终态（`succeeded`、`failed`、`canceled`、`expired`）之间不可互相流转。
5. 只有 `failed` 状态的任务可被用户重试。

### 4.2 API 契约

#### 4.2.1 创建任务

```
POST /api/tasks
```

**请求体：**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `url` | string | 是 | 公开视频 URL，须通过 PRD01 安全校验 |

**成功响应（201 Created）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (uuid) | 任务 ID |
| `status` | string | 初始状态，固定为 `queued` |
| `created_at` | string (ISO 8601) | 创建时间 |

**错误响应：** 见 §4.3 错误码目录。

#### 4.2.2 查询任务详情

```
GET /api/tasks/{task_id}
```

**成功响应（200 OK）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (uuid) | 任务 ID |
| `source_url` | string | 原始提交 URL |
| `platform_id` | string | 识别出的平台 ID |
| `status` | string | 当前状态 |
| `progress` | integer (0-100) | 进度百分比，见 §4.4 |
| `title` | string \| null | 视频标题 |
| `author` | string \| null | 视频作者 |
| `duration_seconds` | integer \| null | 视频时长（秒） |
| `error_code` | string \| null | 失败时的错误码 |
| `error_message` | string \| null | 失败时的用户可读错误信息 |
| `created_at` | string (ISO 8601) | 创建时间 |
| `started_at` | string (ISO 8601) \| null | Worker 开始执行时间 |
| `finished_at` | string (ISO 8601) \| null | 任务完成（成功或失败）时间 |

#### 4.2.3 查询任务列表

```
GET /api/tasks
```

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 否 | 按状态过滤 |
| `limit` | integer | 否 | 返回数量，默认 20，最大 100 |
| `offset` | integer | 否 | 分页偏移量，默认 0 |

**成功响应（200 OK）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | array | 任务列表，每项结构同详情响应 |
| `total` | integer | 符合条件的总任务数 |

#### 4.2.4 取消任务

```
POST /api/tasks/{task_id}/cancel
```

**成功响应（200 OK）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (uuid) | 任务 ID |
| `status` | string | 更新后的状态，固定为 `canceled` |

**错误响应：** 仅 `queued` 和 `running` 状态可取消，其他状态返回 `TASK_ALREADY_FINISHED`。

#### 4.2.5 重试任务

```
POST /api/tasks/{task_id}/retry
```

**成功响应（201 Created）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string (uuid) | 新任务 ID |
| `status` | string | 新任务状态，固定为 `queued` |

**约束：** 仅 `failed` 状态可重试。重试创建新任务，保留 `source_url` 和 `platform_id`，`retry_count` 在原任务基础上 +1。

#### 4.2.6 获取下载链接

```
GET /api/tasks/{task_id}/download
```

**成功响应（200 OK）：**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `url` | string | 短期有效的预签名下载链接 |
| `expires_in` | integer | 链接有效期（秒） |

**错误响应：** 仅 `succeeded` 状态可获取下载链接。`expired` 状态返回 `TASK_ARTIFACTS_EXPIRED`。

### 4.3 错误码目录

| 错误码 | HTTP 状态 | 业务语义 | 触发场景 |
| --- | --- | --- | --- |
| `INVALID_URL` | 400 | URL 格式不合法 | 空字符串、非 URL 文本、缺少协议 |
| `UNSAFE_URL` | 400 | URL 不安全 | localhost、内网 IP、保留地址 |
| `UNSUPPORTED_PLATFORM` | 400 | 不支持的平台 | URL 不属于首版 5 个正式支持平台 |
| `PLATFORM_RESTRICTED` | 403 | 平台受限 | 平台对当前内容有访问限制 |
| `PLATFORM_RATE_LIMITED` | 429 | 平台限流 | 第三方平台触发频率限制 |
| `DOWNLOAD_FAILED` | 500 | 下载失败 | yt-dlp 下载主视频失败 |
| `STORAGE_UPLOAD_FAILED` | 500 | 存储上传失败 | MinIO 上传产物失败 |
| `TASK_NOT_FOUND` | 404 | 任务不存在 | 查询的任务 ID 无对应记录 |
| `TASK_ALREADY_FINISHED` | 409 | 任务已完成 | 对终态任务执行取消或重试 |
| `TASK_ARTIFACTS_EXPIRED` | 410 | 产物已过期 | 尝试下载已过期任务的产物 |

### 4.4 进度语义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `progress` | integer (0-100) | 任务完成百分比 |

**更新规则：**

1. 任务创建时 `progress` 为 `0`。
2. Worker 开始执行时 `progress` 可更新为 `10`（表示已开始）。
3. 主视频下载完成时 `progress` 更新为 `80`。
4. 主视频上传至 MinIO 完成时 `progress` 更新为 `100`。
5. 仅 `running` 状态下 Worker 可更新 `progress`。
6. `succeeded` 状态的 `progress` 必须为 `100`。

### 4.5 取消与重试边界

#### 4.5.1 取消规则

| 当前状态 | 可取消 | 说明 |
| --- | --- | --- |
| `queued` | 是 | 直接标记为 `canceled` |
| `running` | 是 | Worker 需检测取消信号并中止 |
| `succeeded` | 否 | 返回 `TASK_ALREADY_FINISHED` |
| `failed` | 否 | 返回 `TASK_ALREADY_FINISHED` |
| `canceled` | 否 | 返回 `TASK_ALREADY_FINISHED` |
| `expired` | 否 | 返回 `TASK_ALREADY_FINISHED` |

#### 4.5.2 重试规则

| 当前状态 | 可重试 | 说明 |
| --- | --- | --- |
| `failed` | 是 | 创建新任务，保留 `source_url` 和 `platform_id` |
| 其他状态 | 否 | 返回 `TASK_ALREADY_FINISHED` |

**重试语义：**

1. 重试创建新任务，不复用原任务 ID。
2. 新任务保留 `source_url` 和 `platform_id`。
3. 新任务的 `retry_count` 为原任务 `retry_count + 1`。
4. 原任务状态不变，仍为 `failed`。
5. 新任务入队后走完整的 `queued -> running -> succeeded/failed` 流程。

### 4.6 事件流要求

关键状态流转必须写入 `task_events` 表，用于过程追踪和排障。

**必写事件类型：**

| event_type | 触发时机 | from_status | to_status |
| --- | --- | --- | --- |
| `task.created` | 任务创建 | - | `queued` |
| `task.started` | Worker 开始执行 | `queued` | `running` |
| `task.succeeded` | 主视频归档完成 | `running` | `succeeded` |
| `task.failed` | 主视频下载或上传失败 | `running` | `failed` |
| `task.canceled` | 用户取消 | `queued`/`running` | `canceled` |
| `task.retried` | 用户重试 | `failed` | `queued`（新任务） |
| `task.expired` | 产物过期清理 | `succeeded` | `expired` |

**事件记录要求：**

1. 每次状态流转必须产生一条事件记录。
2. 事件记录包含 `task_id`、`event_type`、`from_status`、`to_status`、`created_at`。
3. `message` 字段可选，用于记录失败原因摘要。
4. `payload_json` 字段可选，用于记录扩展数据（如重试来源任务 ID）。

### 4.7 用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 自部署用户 | 创建下载任务 | 返回任务 ID 和初始状态 |
| 自部署用户 | 查询任务详情 | 可看到状态、进度和失败原因 |
| 自部署用户 | 查询任务列表 | 可看到所有任务的状态概览 |
| 自部署用户 | 取消进行中的任务 | 任务状态变为 `canceled` |
| 自部署用户 | 失败后重试 | 系统创建新任务并重新执行 |
| 自部署用户 | 成功后下载 | 获取短期有效的预签名链接 |

### 4.8 产品边界

1. 任务成功的必要条件是主视频成功归档。
2. 元数据或封面缺失不应把主视频任务回退为失败。
3. 用户轮询是首版正式支持的结果获取方式。
4. 重试创建新任务，不复用原任务 ID。
5. 取消操作是异步的，`running` 状态的任务取消后 Worker 需检测并中止。

## 6. 验收门禁

- 支持任务创建、详情、列表、取消和重试。
- 主视频成功后状态为 `succeeded` 且进度为 100。
- 失败原因可映射到稳定错误码。
- 状态流转规则可验证：仅 Worker 推进 `queued -> running`，仅 `failed` 可重试，仅 `queued`/`running` 可取消。
- 事件流完整：每次状态流转产生一条 `task_events` 记录。
- API 契约明确：6 个端点的请求/响应 schema 可用于实现和测试。

## 7. 风险与边界

队列积压、第三方限流、FFmpeg 缺失和上传失败都会影响主链路，验收必须覆盖异常路径。取消操作的异步性质意味着 `running` 任务取消后可能存在短暂的竞态窗口，Worker 侧需做好幂等处理。

## 8. 待确认问题

- 是否在首版暴露任务事件列表接口。
- 重试任务是否需要在 API 响应中返回 `retry_of` 字段以关联原任务。
