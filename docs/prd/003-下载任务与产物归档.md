# PRD003 下载任务与产物归档

## 1. 背景

万能视频下载器 MVP 的核心用户路径是：提交 URL → 选择格式 → 下载视频 → 获取文件。当前代码库已实现完整的下载任务模型（`DownloadTask`）、Worker 流程（`jobs.py`）、对象存储（`artifact_storage.py`）和失败分类（`failures.py`），但缺少一份统一的产品需求文档来规范：

- 任务从创建到终态的完整生命周期；
- 主视频文件（必要产物）与增强产物（字幕、封面、元数据、AI 摘要）的归属关系；
- 对象存储保留策略和过期清理边界；
- 增强产物不可用时的降级行为。

本文档对齐现有实现，为后续子计划提供产品级约束。

## 2. 目标

```gherkin
Given 用户提交一个合法的视频下载 URL
When Worker 完成下载、校验和上传
Then 任务状态为 succeeded，progress=100，主视频文件可通过预签名 URL 下载
And 字幕、封面、元数据等增强产物可用时随任务归档
And 增强产物不可用时仅记录原因，不回退主任务状态
```

### 2.1 核心目标

1. **任务生命周期明确**：定义 `queued → running → succeeded / failed / canceled` 五态模型，每个状态转换有且仅有一个触发条件。
2. **主视频为必要产物**：主视频文件下载、校验、上传全部成功是任务 `succeeded` 的充要条件。
3. **增强产物为可选**：字幕、封面、元数据、AI 摘要不可用时记录失败原因，不改变主任务终态。
4. **存储保留可配置**：基于用户配额（`file_retention_hours`）自动过期，过期后清理对象存储并标记任务。
5. **下载链接安全**：仅任务拥有者可获取短期预签名 URL（默认 15 分钟 TTL）。

## 3. 非目标

- 不处理视频编辑、转码或格式转换（仅下载原始格式或用户选择的格式）。
- 不实现多文件批量下载（单任务单文件）。
- 不处理 DRM 加密内容的解密。
- 不实现跨用户文件分享（仅任务拥有者可下载）。
- 不在本文档中定义 AI 摘要的详细产品逻辑（由 AI Intelligence Suite 独立 PRD 覆盖）。

## 4. 核心内容

### 4.1 任务生命周期

| 状态 | 触发条件 | 可逆性 |
|------|----------|--------|
| `queued` | 用户提交下载请求，任务入队 | 可 → `running` / `canceled` |
| `running` | Worker 开始处理任务 | 可 → `succeeded` / `failed` / `canceled` |
| `succeeded` | 主视频下载+校验+上传全部成功 | 终态 |
| `failed` | 任意主链路步骤异常 | 终态（可 retry 创建新 attempt） |
| `canceled` | 用户主动取消 | 终态（可 retry 创建新 attempt） |

**进度语义**：`progress` 字段范围 0-100，其中 0-5 为初始化，5-95 为下载阶段（按 `downloaded/total` 线性映射），95-100 为校验+上传阶段。

### 4.2 产物分类

#### 4.2.1 必要产物（主视频）

| 字段 | 说明 |
|------|------|
| `object_key` | S3 对象键，格式 `users/{user_id}/tasks/{task_id}/{filename}` |
| `object_size` | 文件字节数 |
| `output_filename` | 原始文件名 |
| `expires_at` | 过期时间，基于 `user.file_retention_hours` |

主视频是任务 `succeeded` 的必要条件。缺少 `object_key` 的任务不能标记为成功。

#### 4.2.2 增强产物

| 产物 | 存储方式 | 失败行为 |
|------|----------|----------|
| 字幕 | 内嵌于视频或独立文件（由 yt-dlp 提取） | 不可用时跳过，不阻塞主任务 |
| 封面 | `cover_url` 字段存储远程 URL（客户端展示） | 不可用时字段为空 |
| 元数据 | `title`、`duration_seconds`、`format_label` | 解析失败时使用默认值 |
| AI 摘要 | `ai_summary`、`ai_mindmap` 字段 | `ai_status=FAILED`，记录 `ai_error` |

**关键边界**：增强产物的任何失败都不应将已 `succeeded` 的主任务回退为 `failed`。AI 流水线在主任务成功后异步执行，其状态独立于任务状态。

### 4.3 失败分类

| 失败码 | 含义 | 可重试 | 阶段 |
|--------|------|--------|------|
| `download_failed` | 通用下载失败 | ✓ | DOWNLOAD |
| `format_unavailable` | 所选格式不可用 | ✗ | DOWNLOAD |
| `file_too_large` | 超出文件大小限制 | ✗ | DOWNLOAD |
| `media_tools_missing` | ffmpeg/ffprobe 缺失 | ✗ | START |
| `ffprobe_failed` | 媒体校验失败 | ✗ | PROBE |
| `storage_failed` | S3 上传失败 | ✓ | UPLOAD |
| `task_timeout` | 超过最大运行时间 | ✓ | DOWNLOAD |
| `task_canceled` | 用户取消 | ✗ | — |
| `platform_restricted` | 登录/DRM/地域限制 | ✗ | DOWNLOAD |
| `platform_rate_limited` | 429/验证码 | ✓ | DOWNLOAD |
| `unsupported_platform` | 不支持的平台 | ✗ | DOWNLOAD |
| `browser_cookies_unavailable` | Cookie 提取失败 | ✗ | DOWNLOAD |
| `retention_expired` | 存储已过期 | ✗ | — |

每个失败任务必须包含 `failure_code` 和 `failure_reason`（用户友好的中文描述，URL 自动脱敏）。

### 4.4 存储保留策略

1. **保留时长**：基于用户配额 `file_retention_hours`（默认 72 小时）。
2. **过期清理**：在任务列表和下载链接请求时惰性触发 `cleanup_expired_task_outputs()`。
3. **清理行为**：删除 S3 对象 → 清空 `object_key` → 设置 `failure_code="retention_expired"`。
4. **对象键模式**：`users/{user_id}/tasks/{task_id}/{filename}`，确保用户隔离。

### 4.5 下载链接安全

1. **权限校验**：仅任务拥有者（`user_id` 匹配）可请求下载链接。
2. **前置条件**：任务必须为 `succeeded` 且 `object_key` 存在且未过期。
3. **URL 类型**：S3 预签名 GET 请求，默认 TTL 900 秒（15 分钟）。
4. **跨用户隔离**：不同用户的任务 ID 不可互相访问。

### 4.6 重试机制

1. **触发条件**：对 `failed`、`canceled` 或 `retention_expired` 的任务发起 retry。
2. **实现方式**：创建新 `DownloadTask`，`retry_of_task_id` 指向原任务，`attempt_no` 递增。
3. **限制**：已有活跃子任务（`queued`/`running`）或已有更新 attempt 时拒绝重试。
4. **查询优化**：`is_latest_attempt` 运行时注解确保列表只显示最新 attempt。

## 7. 风险与边界

1. **yt-dlp 平台兼容性**：不同视频平台的反爬策略可能导致下载失败，需要持续维护平台白名单和 Cookie 策略。
2. **ffmpeg 依赖**：Worker 环境必须预装 ffmpeg/ffprobe，否则所有下载任务将失败（`media_tools_missing`）。
3. **S3 存储成本**：大量用户同时下载大文件可能产生显著存储成本，需要监控 `storage_quota_bytes`。
4. **AI 流水线独立性**：AI 摘要依赖外部 API（Groq/DeepSeek），其可用性不影响主任务，但会影响用户体验。
