# 下载任务与产物归档 PRD

## 1. 背景

下载器的核心价值不是只返回一个临时文件，而是完成可追踪的任务闭环。当前系统已有任务创建、队列、Worker 下载、进度、取消、重试、对象存储和过期清理。本需求将主视频与增强产物的职责拆清楚。

## 2. 目标

1. 用户选择格式后创建下载任务，并能查看排队、运行、成功、失败、取消状态。
2. Worker 下载主视频并上传到私有对象存储，生成短期有效下载链接。
3. 字幕、封面和元数据作为增强产物保存；不可得时记录原因，不影响主视频成功。

```gherkin
Given 用户已完成解析并选择一个格式
When 用户创建下载任务
Then 系统创建排队任务并异步下载
And 下载成功后提供主视频下载链接
And 增强产物可用时随任务归档
```

## 3. 非目标

- 不做批量任务、播放列表或频道同步。
- 不做长期公共文件托管。
- 不保证所有平台都有字幕、封面或完整元数据。
- 不在主任务失败后继续执行 AI 或 PDF 增强。

## 4. 核心用户故事

| 用户 | 场景 | 验收标准 |
| --- | --- | --- |
| 普通用户 | 创建下载任务 | 可看到任务状态、进度和失败原因 |
| 内容创作者 | 归档素材 | 成功任务至少包含主视频文件和基础元数据 |
| 自部署用户 | 控制成本 | 文件有保留时间，过期后下载链接失效 |

## 5. 产物规则

1. 主视频文件是任务成功的必要产物。
2. 封面、字幕和元数据是增强产物，可用则保存，不可用则记录事件。
3. 对象存储中的产物必须绑定任务和用户权限。
4. 下载链接必须使用短期预签名 URL。
5. 文件过期清理后保留任务历史和失败/过期说明。

## 6. 状态模型

| 状态 | 含义 |
| --- | --- |
| `queued` | 任务已创建，等待 Worker |
| `running` | Worker 正在下载、校验或上传 |
| `succeeded` | 主视频已成功保存 |
| `failed` | 主视频下载或上传失败 |
| `canceled` | 用户取消任务 |

## 7. 首版验收门禁

- 任务支持创建、列表、详情、事件、取消、重试和下载链接。
- 主视频成功后进度为 100，并写入对象 key、大小和过期时间。
- 增强产物失败不导致主视频任务回退失败。
- 过期文件被清理后，用户看到明确过期说明。

## 8. 风险与边界

平台下载速度、分片失败、FFmpeg 缺失和对象存储不可用都会影响主链路。测试计划必须覆盖这些失败语义，而不是只测成功路径。
