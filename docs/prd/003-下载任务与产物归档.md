# PRD003 下载任务与产物归档

更新时间：2026-06-02
关联 Issue：STE-51
子计划：STE-58（下载主链路）、STE-59（字幕封面元数据归档）

## 1. 背景

当前 MVP 已实现基础下载任务生命周期：解析 → 创建 → 排队 → 下载 → 校验 → 上传 → 完成。需要将任务生命周期、主视频文件、增强产物（字幕、封面、元数据）和对象存储保留边界形成正式 PRD，为后续迭代提供明确的契约基础。

## 2. 核心原则

- **主视频是任务成功的必要产物**：没有主视频文件，任务不可标记为 succeeded。
- **字幕、封面、元数据是增强产物**：不可用时记录失败原因，不回退主任务状态。
- **对象存储有保留期限**：过期文件自动清理，历史记录保留。

## 3. 下载任务生命周期

### 3.1 状态定义

| 状态 | 值 | 含义 |
|---|---|---|
| QUEUED | `queued` | 任务已创建，等待 Worker 处理 |
| RUNNING | `running` | Worker 正在执行下载/校验/上传 |
| SUCCEEDED | `succeeded` | 主视频文件已上传到对象存储 |
| FAILED | `failed` | 主视频下载或上传失败 |
| CANCELED | `canceled` | 用户主动取消任务 |

### 3.2 状态流转

```
QUEUED → RUNNING → SUCCEEDED
                  → FAILED
         → CANCELED（用户取消）
         → FAILED（超时自动标记）
```

### 3.3 事件记录

每次状态变更都必须通过 `TaskEvent` 记录，包含：
- `state`：变更后的状态
- `message`：中文描述变更原因
- `created_at`：事件时间戳

### 3.4 重试链路

- 失败或取消的任务可以创建重试任务
- 重试任务通过 `retry_of_task_id` 和 `attempt_no` 建立链路
- 禁止对 queued/running 状态的任务发起重试
- 工作台只展示每条重试链的最新任务

## 4. 主视频产物（必要）

### 4.1 定义

主视频文件是下载任务的必要产物。任务必须拥有一个有效的主视频文件才能标记为 `succeeded`。

### 4.2 成功条件

- Worker 通过 yt-dlp 下载源文件到本地工作目录
- FFmpeg 合并视频/音频流（如需要）
- ffprobe 校验输出文件有效性
- 文件大小不超过用户和系统限制
- 文件上传到私有对象存储 bucket
- 任务记录 `object_key`、`object_size`、`expires_at`

### 4.3 存储规范

- 对象 key 格式：`users/{user_id}/tasks/{task_id}/{filename}`
- 文件保留期限：`file_retention_hours`（默认 24 小时）
- 过期后自动清理对象文件，保留数据库历史记录
- 过期任务显示 `failure_code=retention_expired`，提供重试路径

## 5. 增强产物（可选）

### 5.1 定义

增强产物包括：
- **字幕**（subtitles）：视频内嵌或外挂字幕文件
- **封面**（thumbnail）：视频封面图
- **元数据**（metadata）：视频描述、标签、上传者等结构化信息

### 5.2 成功条件

- 增强产物随主视频一起归档到对象存储
- 增强产物归属、过期和权限与主视频一致
- 增强产物信息可在任务详情 API 中展示

### 5.3 失败边界

- **增强产物不可用时，不回退主任务状态**
- 增强产物失败只记录事件或独立的增强状态字段
- 每种增强产物独立尝试，一种失败不影响其他
- 失败原因记录在任务事件中，供用户参考

### 5.4 增强状态字段

任务模型增加增强状态字段：
- `enhanced_status`：`pending` / `processing` / `completed` / `partial` / `failed`
- `enhanced_error`：增强产物失败的汇总原因
- 各增强产物独立字段：`subtitle_key`、`thumbnail_key`、`metadata_json`

## 6. 对象存储保留边界

### 6.1 保留策略

| 产物类型 | 保留期限 | 过期行为 |
|---|---|---|
| 主视频 | `file_retention_hours`（默认 24h） | 清理对象，保留历史 |
| 字幕 | 同主视频 | 随主视频一起清理 |
| 封面 | 同主视频 | 随主视频一起清理 |
| 元数据 | 永久（数据库存储） | 不过期 |

### 6.2 清理机制

- 定时任务扫描过期的 succeeded 任务
- 删除对象存储中的文件
- 清空任务的 `object_key`
- 设置 `failure_code=retention_expired`
- 历史记录保留，提供重试路径

### 6.3 存储配额

- 每个用户有存储配额限制（`storage_quota_bytes`）
- 达到配额时拒绝创建新任务
- 过期清理后释放配额空间
