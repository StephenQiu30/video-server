# 验收标准

更新时间：2026-05-03

## MVP 验收标准

| 模块 | 标准 |
| --- | --- |
| 链接解析 | 至少 3 个公开可访问视频样例能解析出标题、封面、时长和格式 |
| 任务创建 | 用户能选择格式并创建下载任务 |
| 任务状态 | 支持 queued、running、succeeded、failed、canceled |
| 下载结果 | 至少 1 个样例能完成下载、合并、上传和后端签名代理文件获取 |
| B 站本机链路 | 本机单用户模式下，B 站链接能解析出整数时长、推荐下载格式，并由本机 Worker 完成下载或返回可诊断中文失败原因 |
| 错误反馈 | 不支持平台、网络失败、格式不可用、文件过大、超时均有明确提示 |
| 前端交互 | URL 输入自动 trim，无协议域名链接自动补 `https://`；解析、创建、下载、重试、取消均有 loading 和中文错误提示 |
| 前端展示 | 工作台使用 Ant Design Pro 蓝白单列下载器布局，不使用左右分栏或大块绿色成功面板 |
| 合规提示 | 下载前和错误提示中体现授权和合法使用边界 |
| 安全 | URL、日志、文件名做基础脱敏和清洗 |
| 清理 | 下载文件有保留期限和清理策略 |
| 本地访问 | M1 阶段默认单用户本地使用，不要求注册登录即可完成核心流程 |

## 技术验收标准

- 关键技术栈已由项目负责人确认。
- 下载内核通过适配层调用。
- Worker 只能写入受控目录。
- 公网部署前必须启用鉴权、限流和任务配额。
- 测试样例不得使用付费、会员、隐私或盗版链接。

## M1 放行标准

M1 不能只看代码存在，必须满足以下放行条件：

- M1 本地单用户模式下，可以不登录完成解析、创建任务、查看任务和获取下载链接。
- 工作台输入无协议链接或非法文本时必须有明确反馈，不能出现点击后无响应。
- 工作台主要内容必须是单列下载器布局；合规页允许/禁止边界必须上下排列，不使用左右分栏。
- 上线级 SaaS 前必须重新设计并启用 JWT、用户隔离和管理员兜底验收。
- 解析接口必须通过下载内核适配层调用 yt-dlp，不允许绕过适配层。
- 任务必须覆盖 queued、running、succeeded、failed、canceled 状态。
- 下载成功后文件必须进入私有 MinIO / S3 bucket。
- 下载链接必须由后端校验任务归属后生成短期签名代理 URL，不向前端暴露 MinIO / S3 内部地址。
- 过期清理只删除对象存储文件，不删除任务历史；历史中必须能看到文件过期原因并可重试。
- `/ready` 必须能同时证明 PostgreSQL、Redis、MinIO / S3、FFmpeg / ffprobe 在本地可用。
- 至少 3 个公开视频样例能解析成功。
- 至少 1 个小文件样例能完成下载、上传、后端代理文件获取，并补充 ffprobe 媒体校验证据。
- 本机 B 站链路必须能解析真实链接并使用推荐格式创建任务；需要登录态时只允许本机 Worker 读取 Chrome 登录态，不允许 Cookie 托管、上传、入库或日志输出。
- DRM、付费墙、会员内容、私密链接、Cookie 托管和平台专用绕过不得作为 M1 能力出现。
- 本地开发默认复用已有 Python、PostgreSQL、Redis、MinIO / S3；上线容器验收后续单独规划。
