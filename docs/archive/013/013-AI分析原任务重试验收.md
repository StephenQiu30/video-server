## 1. 冻结前置条件

- [x] 测试数据至少包含首次失败、首次取消、首次成功且有报告、artifact 过期和删除中的分析任务。
- [x] 可控制 RabbitMQ 重复/延迟投递、Worker lease 过期、API 响应丢失和并发事务。
- [x] 配额、最大 run 数、最短间隔和可重试窗口使用确定测试值。
- [x] 所有验收从当前态 schema 启动，不创建 migration 或旧模型兼容数据。

## 2. 逐项验收

- [x] A1：失败、取消和成功任务重试后 `analysis_jobs.id`、页面 URL 与 Location 不变，创建的新 run_no 恰好为上一最大值加 1。
- [x] A2：成功重试响应为 `201 Created`，包含最新任务/run 投影和同一任务 Location；API 请求生命周期不运行 AI。
- [x] A3：同一 run 的限流、临时失败或超时恢复只增加 attempt 并进入有界 `retry_wait`，不创建新 run/job。
- [x] A4：retry 请求不接受 Skill、prompt、语言、Provider 或模型字段；新 run 的 artifact SHA-256 与全部语义快照等于原任务。
- [x] A5：相同 `Idempotency-Key` 串行、并发和响应丢失重放均返回同一 run，只产生一个 task event、Outbox 与计费记录。
- [x] A6：不同 key 并发重试，以及 retry/cancel 并发时最多一个活跃 run；失败事务没有残留 run、事件、额度或错误 active_run_id。
- [x] A7：上一 run 的延迟/重复消息、过期 lease Worker 和旧结果发布均 ACK no-op，不能修改当前 run、任务 version、错误或报告。
- [x] A8：新 run 排队/执行/发布时上一成功报告仍可下载；新 run 失败/取消时指针不变，成功发布后才原子切换。
- [x] A9：active、artifact 不可用/哈希错误、删除中、超过 run/频率/额度限制分别返回稳定 409/429，且不创建任何新事实。
- [x] A10：前端重试调用 retry API 并复用原 Idempotency-Key，不清空任务、不调用 create API、不更换路由或 WebSocket 订阅。
- [x] A11：页面区分“第 N 次执行”和 attempt，展示失败原因、上一报告与可重试窗口；1280px/390×844、键盘、加载和错误恢复可用。
- [x] A12：PostgreSQL 并发、RabbitMQ 重投、lease 恢复、真实 Worker、OpenAPI、前后端全量门禁与 Compose 解析结果已记录并通过。

## 4. 验收证据

2026-08-10 已完成真实 Codex 重试：同一 job `aea255ac-5930-4866-bb09-1a202d99bce7` 从 run 1 进入 run 2，Location/job ID 不变；旧报告在 queued/running/publishing 全程可用，新报告完成后原子切换。重复 Idempotency-Key 返回同一 run，可变 body 返回 422，旧 run/version/lease fencing、active conflict 与前端同路由重试均有覆盖。

隔离 PostgreSQL 真并发矩阵通过：同 key 两请求返回 `[created=false, created=true]` 且 run_id 相同；不同 key 同时重试只有 1 个成功、另 1 个 `PersistenceActiveRun`；retry/cancel 竞态后活跃 run 为 0；run 上限返回稳定限制错误，run/operation/Outbox 计数前后相等，受控事实已清理。频率、每日额度、artifact 状态/哈希及无副作用分支由全量 repository/API 测试覆盖。

工程门禁为后端 446 tests、前端 101 tests、OpenAPI 29 operations、生产构建、空库 schema 两次幂等、已有库收敛与服务/完整环境/生产 Compose 解析全部通过。
