# 020 用户制品持久化与保留策略设计

- 状态：Accepted
- 日期：2026-08-13
- 关联设计：`002`、`004`、`006`、`012`

## 1. 问题与目标

当前下载视频和分析报告虽然已写入 MinIO 持久卷，但 Worker 在数据库中固定写入一天后的 `expires_at`，Lifecycle Worker 到期后会删除真实对象。页面显示的“保留至次日”因此不是临时链接到期，而是文件实际只有一天保留期。与此同时，Compose 没有把保留期配置传给负责创建对象的 Worker，运维修改 `.env` 也不能生效。

目标是在不公开 bucket、不延长访问凭据、不取消容量回收的前提下，将用户制品默认保留期从一天提高到 7 天，并允许需要更长使用窗口的部署显式配置为 30 天。

## 2. 生命周期模型

```text
下载/报告完成
      │
      ├─ PostgreSQL 记录 expires_at = 完成时间 + retention
      ├─ MinIO 私有不可变对象持续存在
      └─ 用户点击获取文件时签发 5 分钟 URL
                              │
                              └─ URL 到期后可再次签发

retention 到期且无分析锁 → GC 删除 MinIO 对象 → deleted_at
```

对象保留期和访问授权期是两个独立概念：

- `ARTIFACT_TTL_SECONDS`：下载视频真实保留期，默认 `604800`（7 天），可配置 `2592000`（30 天）。
- `ANALYSIS_REPORT_TTL_SECONDS`：Markdown/DOCX 真实保留期，使用相同默认值与可选值。
- `ARTIFACT_DOWNLOAD_URL_TTL_SECONDS`：每次签发的访问 URL，默认 `300` 秒，不得因对象保留期增长而增长。

## 3. 配置与职责

- Download Worker 是下载对象 `expires_at` 的唯一写入者，Compose 必须只向该角色传入下载制品保留与 GC 配置。
- Report Worker 是报告对象 `expires_at` 的唯一写入者，Compose 必须只向该角色传入报告保留与 GC 配置。
- API 只接收短时 URL TTL，用当前时间与对象剩余时间的较小值签发 URL。
- PostgreSQL 是对象是否可交付、何时到期和是否已删除的事实源；MinIO 不配置早于应用 TTL 的独立 lifecycle。

## 4. 旧数据升级

当前态 Schema 在重复执行时识别仍未删除且 `expires_at` 不晚于 `created_at + 25 小时` 的旧对象，并把它们延长为 `created_at + 7 天`。该条件只覆盖旧的一天默认值：已经配置为 7 天或 30 天的对象不会被覆盖；已经被 GC 删除的对象无法恢复，也不会伪造为可用。

## 5. 容量与清理

- 默认 7 天是产品基线；需要更长使用窗口且 MinIO 容量充足的部署可改为 30 天，但必须同时修改下载与报告配置并重建对应 Worker。
- GC 保持有界批次、删除超时、分析锁保护和幂等删除。签名 URL 到期不触发 GC。
- 历史记录继续长期保留任务事实；文件到期后明确显示不可用并提供重新下载入口。
- 运维至少监控对象字节数、预计 7/30 天增长、GC backlog、删除失败和 MinIO 剩余容量。

## 6. 安全与体验

- bucket 继续保持私有，前端和 API 不返回 object key 或存储凭据。
- 7 天或 30 天保留不意味着同等时长的 URL；刷新页面或重新点击只获得新的短时签名。
- 任务详情与历史使用 API 返回的实际 `file_expires_at`，不在前端硬编码保留天数。
- 下载任务详情独立返回从源记录保留的标题、封面、时长、平台和所选语义格式；解析资源到期只终止重新选择格式的能力，不得让仍可交付的任务详情丢失封面或基础媒体信息。
- 时区展示使用用户本地时区，服务端事实统一为 UTC。

## 7. 设计验收标准

- DAC-020-01：新下载视频与新分析报告默认到期时间均为完成后 7 天。
- DAC-020-02：配置 `2592000` 后新对象到期时间为完成后 30 天。
- DAC-020-03：对象保留 7 天或 30 天时，下载 URL 仍不超过 5 分钟且可重复签发。
- DAC-020-04：Compose 将配置传给正确 Worker，修改 `.env` 后实际生效。
- DAC-020-05：旧的一天有效对象升级为 7 天，显式 7 天或 30 天策略不被覆盖。
- DAC-020-06：到期 GC、分析锁保护、历史保留和过期后重试行为保持有效。
