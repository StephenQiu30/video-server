# API 与任务状态契约设计

## 1. 契约原则

1. `video-server` 的 OpenAPI 3.1 是跨仓唯一 HTTP 事实来源；字段使用 `snake_case`。
2. Plan 001 的创建返回 `202 Accepted`、`Location`、resolution ID、Job ID 和初始状态。
3. 创建请求必须有 `Idempotency-Key`；Job、resolution 和 Source 是不同资源。
4. API 只暴露 opaque ID，不返回源站媒体 URL、selector、存储 key 或密文。
5. Plan 001 只提供小型 JSON 和 SSE；后续大文件不经过 API 或 Next.js。
6. CSRF bootstrap、注册、验证、登录、找回和健康检查不要求数据库会话；所有 unsafe endpoint 仍要求 CSRF 与同源门禁。除此之外，业务端点都要求已验证邮箱用户的有效数据库会话；`owner_id` 只从 `users.id UUID` 注入，不出现在创建请求。
7. `REQ-CONTRACT-001` 要求身份、会话、资产与错误 schema 先在 server OpenAPI 中可重复生成并通过 Acceptance 002；video-web 只能消费该 accepted artifact。

## 2. 身份与浏览器会话

| 动作 | API | 成功 |
| --- | --- | --- |
| 获取 CSRF 配对值 | `GET /api/v1/auth/csrf` | 200 + `Cache-Control: no-store` + `Set-Cookie` |
| 注册 | `POST /api/v1/auth/register` | 202 generic response |
| 重发验证 | `POST /api/v1/auth/verification/request` | 202 generic response |
| 验证邮箱 | `POST /api/v1/auth/verify` | 204 |
| 登录 | `POST /api/v1/auth/login` | 204 + `Set-Cookie` |
| 注销 | `POST /api/v1/auth/logout` | 204 + clear cookie |
| 请求找回 | `POST /api/v1/auth/password/forgot` | 202 generic response |
| 重置密码 | `POST /api/v1/auth/password/reset` | 204 |
| 当前用户 | `GET /api/v1/users/me` | 200 |

`GET /auth/csrf` 是无账户语义的安全引导端点：响应正文只含 raw `csrf_token`，同时设置 HttpOnly 签名配对 Cookie，不读取或返回用户状态，并禁止缓存。注册、重发验证和找回无论邮箱是否已存在都返回同形 202，避免账户枚举。登录、验证、重置凭据与会话使用 FastAPI Users 的成熟流程，但 JSON facade、错误和 Cookie 由本项目 OpenAPI 冻结；不暴露库默认 form login。邮箱校验使用 `check_deliverability=false`，真实性由 1 小时有效的验证邮件证明；重置 token 有效 30 分钟。逐端点 schema 与状态见 Design 005 第 4 节。

FastAPI Users 的用户创建 transaction 先 commit，post-commit callback 再写 mail outbox，不能宣称二者同一事务；注册 callback 丢失由未验证用户扫描补建验证意图。重发验证与找回密码对命中的用户必须先提交 PostgreSQL `auth_mail_intents` generation，再在该 intent 上下文调用 FastAPI Users；callback 以 intent ID 在单一事务原子写加密 token/outbox 并置 `ENQUEUED`，不存在“outbox 已提交、intent 未更新”的合法状态。callback 崩溃时 reconciler 对同一 PENDING intent 重新调用库流程并生成新 token，不能靠未验证用户扫描推断已验证用户的重置请求。verify/reset 使用项目 facade 和 PostgreSQL command，分别把验证状态/intent/审计及 password hash/全部 DatabaseStrategy token 撤销/intent/审计放入单一事务，避免库 post-commit hook 窗口。该内部恢复不得改变 register/request/forgot 的 generic 202 wire response；新 generation 会使旧的未完成或未消费 generation 失效。

生产会话 Cookie 固定为 `__Host-video_session`，包含 `Secure; HttpOnly; SameSite=Lax; Path=/` 且无 `Domain`；只有显式 loopback development profile 可改为 `video_session_dev`，该 profile 在非 loopback 地址必须拒绝启动。mutation 必须携带 bootstrap 返回的 raw `X-CSRF-Token` 及其 fastapi-csrf-protect 签名 Cookie，并通过 1 小时 token 有效期和 exact Host/Origin/Fetch Metadata gate。签名配对不宣称与数据库会话天然绑定；登录、注销、密码重置和会话轮换必须清除旧配对值，客户端重新引导后才能发起下一次 mutation，旧 header 与缺失、过期或新 Cookie 配对必然失败。

## 3. Plan 001 端点

| 动作 | API | 成功 |
| --- | --- | --- |
| 当前权利声明 | `GET /api/v1/rights-statements/current?locale={locale}` | 200 + 冻结的 RightsStatement JSON |
| 创建解析 | `POST /api/v1/source-resolutions` | 202 + `Location: /api/v1/source-resolutions/{resolution_id}` |
| 查询解析 | `GET /api/v1/source-resolutions/{resolution_id}` | 200 |
| 查询来源 | `GET /api/v1/sources/{source_id}` | 200；格式快照到期为 410 |
| 任务事件 | `GET /api/v1/jobs/{job_id}/events` | `text/event-stream` |

下载、AI、PDF 与资产端点只在对应 Plan 冻结后加入。

## 4. 创建与解析快照

`locale` 是必填、大小写敏感的 BCP 47 catalog key；Plan 001 初始只支持 `zh-CN` 和 `en-US`。缺失 query 返回 400 `RIGHTS_LOCALE_REQUIRED`，未支持 locale 返回 406 `RIGHTS_LOCALE_UNSUPPORTED`，当前声明配置损坏或没有有效条目返回 503 `RIGHTS_STATEMENT_UNAVAILABLE`。200 正文固定为：

```json
{"version":"rights-2026-07-18.1","locale":"zh-CN","statement":"我确认：…","statement_sha256":"cf7fa670727050ffa2edb508f5adb6bb48907f2c374e375fb2253447a74da15f","effective_at":"2026-07-18T00:00:00Z","expires_at":null}
```

六个字段全部 required；时间是 UTC RFC 3339 string，`expires_at` 可为 null，其余不可空。hash 是 `statement` 精确 UTF-8 字节（不做 Unicode/换行规范化）的 lowercase hex SHA-256；完整正文与 catalog 见 `config/rights-statements.json`，wire schema 见 `schemas/rights-statement.schema.json`。

请求正文：

```json
{"url":"https://media.example/video","rights_confirmed":true,"rights_statement_version":"rights-2026-07-18.1","rights_statement_locale":"zh-CN"}
```

`url` 只接受公开 HTTPS；明文 HTTP、重定向协议降级以及任何非 HTTPS 协议均失败。该限制同时约束同步规范化、policy scope 与 worker 的每一跳出站检查。

缺少/false 权利确认返回 422 `RIGHTS_CONFIRMATION_REQUIRED` 且不创建 Job。version/locale 必须等于提交时该 locale 的 current、已生效且未过期条目；未知、locale 不匹配或已被取代的已知版本返回 409 `RIGHTS_STATEMENT_STALE` 与 `refresh_rights_statement` action，同样不创建 Job。语法、协议、userinfo、IP literal 或端口可在同步边界确定时返回 422；DNS、policy、auth、DRM、download-disabled、extractor 和上游网络结果进入异步 Job。

创建响应：

```json
{"resolution_id":"res_01...","job_id":"job_01...","status":"QUEUED","stage":"VALIDATING_URL","created_at":"2026-07-18T00:00:00Z"}
```

`GET source-resolutions/{resolution_id}` 固定返回：

```json
{"resolution_id":"res_01...","job_id":"job_01...","status":"SUCCEEDED","stage":"READY","attempt":1,"progress":100,"source_id":"src_01...","error":null,"created_at":"...","updated_at":"..."}
```

非成功时 `source_id=null`；异步失败时 `error` 使用第 7 节安全字段，但 GET 仍为 200。`progress` 为 null 或 0–100 整数，同一 Job 单调不减；QUEUED 可空，SUCCEEDED 必为 100，FAILED 保留最后值。未认证或会话失效返回 401；已认证用户跨 owner 与资源不存在统一返回 404。

## 5. Source 与格式响应

Source 必含 `source_id`、`platform`、`title`、可空 `duration_seconds`、`policy`、`formats`、`resolved_at`、`expires_at`。Plan 001 不返回第三方缩略图，避免浏览器向源站泄露访问。快照到期后 GET Source 返回 410 `SOURCE_SNAPSHOT_EXPIRED` 和 `create_new_resolution` action；原 Job/Resolution 仍保持 SUCCEEDED，客户端必须新建 Resolution，不能继续使用旧 key。

`policy` 含 `decision`、`permitted_operations[]`、`name`、可空 HTTPS `official_url` 与 `user_actions[]`；Plan 001 成功只证明 `probe`，不把 `download` 缺失解释为错误，也不承诺可下载。动作仅允许 `view_supported_sources` 或签名 dossier 中经过验证的 HTTPS `open_official`，不承诺尚未实现的上传。

格式项：

```json
{"format_key":"fmt_01...","label":"1080p · MP4","width":1920,"height":1080,"fps":30,"dynamic_range":"SDR","container":"mp4","video_codec":"h264","audio_codec":"aac","has_audio":true,"has_video":true,"requires_merge":false,"estimated_bytes":120000000,"size_is_estimate":false,"recommended":true}
```

宽高、FPS、动态范围、容器、codec 和预计大小允许 `null`；五个布尔值不可空。排序、组合、TTL 与 key 语义见 Design 004。

## 6. 状态机

| 当前 | 允许下一状态 | 规则 |
| --- | --- | --- |
| `QUEUED` | `RUNNING`, `FAILED` | 开始 attempt 1，或投递失败 |
| `RUNNING` | `RETRY_WAIT`, `SUCCEEDED`, `FAILED` | stage 只前进；失败保留最后 stage |
| `RETRY_WAIT` | `RUNNING`, `FAILED` | 重试时 attempt +1；耗尽失败 |
| `SUCCEEDED`, `FAILED` | 无 | Plan 001 终态不可逆 |

Plan 001 不实现取消或 Job `EXPIRED`；只有格式快照到期，Job 历史保持终态。每次状态变化与错误都在同一事务追加 `job_events`。阶段为 `VALIDATING_URL → CHECKING_POLICY → EXTRACTING_METADATA → NORMALIZING_FORMATS → READY`。

## 7. 错误契约

同步 HTTP 错误使用 `application/problem+json` 并返回 `X-Request-ID`。异步 `error` 与失败事件固定含九个字段：`code/title/detail/retryable/correlation_id` required 且不可空，`field/policy/actions/retry_after_seconds` required 但值可为 null；不含 HTTP `status/type/request_id`。`actions` 非空时是 string array，`retry_after_seconds` 非空时是非负整数。

`field` 非空时是最长 128 字符的 RFC 6901 JSON Pointer。`policy` 非空时是唯一 `PolicyView`：`{decision,permitted_operations,name,official_url,user_actions}`，五字段 required；decision=`allow|block`，operations 只含 `probe|download`，official URL 为 null 或经过验证的 HTTPS，user actions 只含 `view_supported_sources|open_official`。`actions` 非空时去重且只含 `refresh_rights_statement|create_new_resolution|retry_resolution|view_supported_sources|open_official`；`open_official` 必须同时有非空 policy.official_url。Source 响应复用同一 `PolicyView` schema。

| Code | 同步 HTTP / 异步 | 重试 |
| --- | --- | --- |
| `AUTHENTICATION_REQUIRED` | 401 | 否 |

| `AUTH_EMAIL_NOT_VERIFIED` | 403 | 否 |

| `AUTH_RATE_LIMITED` | 429 | 是 |
| `AUTH_EMAIL_INVALID`, `AUTH_PASSWORD_INVALID` | 422 | 否 |
| `AUTH_PROTECTION_UNAVAILABLE` | 503 | 是 |
| `REQUEST_CSRF_REJECTED` | 403 | 否 |
| `REQUEST_ORIGIN_REJECTED` | 403 | 否 |
| `LOCALE_UNSUPPORTED` | 406 | 否 |
| `EMAIL_DELIVERY_UNAVAILABLE` | 503；只用于健康/管理边界 | 是 |
| `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_KEY_INVALID` | 400 | 否 |
| `CONTENT_TYPE_UNSUPPORTED` | 415 | 否 |
| `RESOURCE_NOT_FOUND` | 404 | 否 |

## 8. 幂等

key 必须是 16–128 个可见 ASCII 字符。范围为 `users.id UUID + operation + key digest`，至少保留 24 小时。规范化摘要覆盖 URL、rights boolean/version/locale：相同 key/摘要返回原 202 或当前资源；相同 key/不同摘要返回 409。幂等命中必须先于 current rights 复核：合法创建后，即使其声明随后被取代，同 key/同摘要仍返回原资源，同 key/异摘要仍返回 409；只有真正的新建才校验 current rights。并发由 Design 004 的数据库唯一约束收敛。快照 410 或用户显式重试必须使用新 key；同一 key 在不同用户之间互不命中。

## 9. SSE wire contract

响应为 `text/event-stream; charset=utf-8`。数据事件名 `job-event`，wire `id:` 与 JSON `id` 都是数据库 `GENERATED ALWAYS` 正数 bigint identity 的十进制 string；调用方不能显式覆盖，允许事务回滚产生间隙但保持全局单调。JSON 另含 `job_id/status/stage/progress/attempt/error/occurred_at`。`Last-Event-ID` 过旧返回事件 `stream-reset` 后关闭，客户端重新 GET 快照；心跳使用 comment，不改变 cursor。

服务端按“先订阅、DB 回放、周期 tail”的算法消除 replay/live 与丢 wake 缺口。客户端须用任意精度无符号十进制整数比较（JavaScript 使用 `BigInt`），丢弃 `event_id <= cursor` 的重复/乱序事件；空、负数、带符号或非十进制 cursor 返回 400 `INVALID_EVENT_CURSOR`。终态后重新 GET resolution。

## 10. 验证

- OpenAPI 生成物与 server-owned 响应 fixture 一致且重复生成无 diff；前端一致性由 Web Plan 验收。
- 状态迁移属性测试覆盖所有允许和禁止路径。
- 同步与异步错误、幂等冲突、owner 404、PolicyView/action enum 和字段 nullability 有契约测试。
- SSE 覆盖回放、重复、乱序、丢 wake、Redis 重启、stream reset 与终态刷新。
- 身份契约覆盖 CSRF bootstrap/no-store、generic 202 防枚举、验证后登录、数据库会话撤销/过期、跨 UUID owner 404、Cookie 属性、登录/注销后的 CSRF 配对轮换、origin gate 和 Redis 丢失后会话仍以 PostgreSQL 为准。
- 邮件投递分别覆盖注册 post-commit callback 崩溃后的未验证用户扫描，以及重发/找回在 durable intent 提交后 callback 崩溃的同 intent 恢复；还需覆盖 generation 失效、PostgreSQL mail outbox、SMTP 暂时/永久失败与有限重试。generic 202 响应不随投递结果或邮箱是否存在而变化。
- OpenAPI 连续生成两次无 diff，身份/资产 fixture 逐字段通过后，`AC-CONTRACT-001` 才可 passed。
