# 003 异步任务与数据存储设计

- 上游：[001 总体架构](001-服务边界与总体架构设计.md)。

- 输出：任务状态、队列、数据表、保留、幂等和迁移契约。

## 1. 状态模型

下载和 AI 任务统一状态：`queued → running → succeeded | failed`；可用结果到期后变为 `expired`。不设计暂停、取消或原任务重试接口。

- `progress` 为 0–100。
- `stage` 表示 downloading、merging、uploading、transcribing、analyzing 等当前阶段。
- Worker 最多每秒或每增加 1% 更新一次 PostgreSQL。
- PostgreSQL 是唯一最终状态；Celery task ID 仅用于运维关联。

## 2. 数据表

| 表 | 关键字段与约束 |
| --- | --- |
| `media_sources` | UUID PK、原始 URL、平台、外部 ID、标题、时长、缩略图、过期时间 |
| `media_formats` | UUID PK、source FK、内部 selector、容器、尺寸、编解码、估算大小、是否合并 |
| `download_jobs` | UUID PK、source/format FK、status、stage、progress、错误、各阶段时间、过期时间 |
| `artifacts` | UUID PK、唯一 download job FK、唯一 object key、文件名、MIME、大小、校验值、过期时间 |
| `ai_jobs` | UUID PK、download job FK、status、stage、progress、模型、错误、各阶段时间、过期时间 |
| `ai_results` | UUID PK、唯一 ai job FK、内部转写、语言、摘要、要点 JSONB、章节 JSONB、过期时间 |

状态使用字符串加 CHECK 约束，避免 PostgreSQL Enum 迁移负担。外键、状态和 `expires_at` 建索引；Artifact 和 AI Result 通过唯一外键保证一个任务只有一个最终结果。

## 3. RabbitMQ 与 Celery

- 业务队列只有 `download` 和 `ai`。
- RabbitMQ 消息只包含 `job_id`，不得携带 URL、密钥、大文本或文件。
- 队列与消息持久化，发布启用确认；Celery Result Backend 不作为业务存储。
- 初始部署使用单 RabbitMQ 持久卷，不建设集群、Quorum Queue 或独立死信平台。
- Download Worker 与 AI Worker 分开限制并发，避免 CPU/GPU 任务阻塞下载。

任务发布顺序：先提交数据库任务，再发布消息；发布失败时将任务标记 failed 并返回明确错误。Worker 必须从 PostgreSQL 重新加载任务和输入，不信任消息负载。

## 4. 幂等与重试

- Worker 通过 job ID 锁定任务；已 succeeded/expired 的任务不重复执行。
- 已存在 Artifact 或 AI Result 时必须校验归属，禁止覆盖未知对象。
- 只对网络、Broker、MinIO 和模型 429/5xx 等瞬时错误进行有限指数退避。
- Worker 异常退出后任务允许再次投递，因此所有外部写入必须可重复检查。
- 业务失败记录安全错误码与消息，不保存完整外部响应或密钥。

## 5. 保留与清理

- 下载文件和 AI 结果默认可用 24 小时。
- 到期后 Scheduler 每小时发布清理任务，由 `download` 队列标记结果 `expired`。
- MinIO 生命周期负责对象删除兜底；应用清理临时文件和过期数据库内容。
- expired 任务墓碑保留 7 天供页面恢复和错误解释，之后删除。
- 临时音频在 AI 成功或失败后立即删除。

Scheduler 只负责定时发布，不创建第三条业务队列。

## 6. 数据迁移与恢复

- Alembic 是唯一 schema 迁移入口，运行时不自动迁移。
- 迁移必须前向兼容当前 API 与 Worker；破坏性迁移另行设计。
- 回滚应用时不回滚已经执行的数据迁移。
- Worker 停止消费后 queued 任务保留，兼容版本恢复后继续处理。
- PostgreSQL、RabbitMQ 和 MinIO 都使用持久卷并纳入部署备份范围。

## 7. 执行验收标准

| 编号 | 必须证明 | 验证与证据 |
| --- | --- | --- |
| `S003-DAC-01` | 第一份 Alembic migration 可在空 PostgreSQL 一次建成六张表、约束、外键和索引 | 空库迁移命令、revision、schema/索引检查及重复执行结果 |
| `S003-DAC-02` | 只允许设计中的状态转换，非法转换并发下也不能写入 | 全状态矩阵、数据库约束和并发事务测试 |
| `S003-DAC-03` | 消息只含 job ID，download/ai 路由固定，发布失败不会留下永久 queued | 消息捕获、队列检查和 Broker 故障注入证据 |
| `S003-DAC-04` | 重复投递、Worker 崩溃和网络重试不会产生重复 Artifact、AI Result 或未知覆盖 | 重复/并发/崩溃注入及数据库、MinIO 最终状态比对 |
| `S003-DAC-05` | API、Worker、RabbitMQ 和主机重启后 PostgreSQL 状态仍为唯一事实且任务可恢复 | 真实进程与容器重启、恢复查询和继续消费记录 |
| `S003-DAC-06` | 24 小时过期、每小时清理、7 天墓碑和临时文件清理准确且可重复 | 可控时间测试、Scheduler/Worker 记录、数据库和对象检查 |
| `S003-DAC-07` | 只对瞬时错误有限退避，认证、校验、永久业务错误不重试 | 错误分类矩阵、Celery retry 计数和最终状态 |
| `S003-DAC-08` | 持久化可恢复，不以“配置了卷”替代恢复证明 | PostgreSQL 备份恢复、RabbitMQ/MinIO 重启持久性演练记录 |
