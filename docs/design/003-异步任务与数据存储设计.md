## 1. 状态模型

下载任务状态固定为：

`queued → running → succeeded | failed`，以及 `succeeded → expired`。

- `stage` 只在运行过程表达 `downloading | merging | verifying | uploading`。
- `progress_percent` 为 0–100 或 null；上游总量未知时不伪造百分比。
- failed、expired 为终态；MVP 不提供暂停、取消、原任务重试或状态回退。
- Worker 每增加 1% 或达到 `PROGRESS_UPDATE_INTERVAL_SECONDS` 时更新数据库；MVP 配置基线为 1 秒，避免高频写入。

## 2. RabbitMQ 最小拓扑

直接使用 RabbitMQ 和 aio-pika，不引入 Celery、Result Backend 或自定义消息框架：

| 项目 | 配置来源 | MVP 基线/契约 |
| --- | --- | --- |
| direct exchange | `RABBITMQ_EXCHANGE` | `video.download`，durable |
| queue | `RABBITMQ_QUEUE` | `video.download`，durable |
| routing key | `RABBITMQ_ROUTING_KEY` | `download` |
| message | 代码契约 | 持久 JSON，仅 `{"job_id":"<uuid>"}` |
| consumer | `RABBITMQ_PREFETCH_COUNT` | manual ack，prefetch 等于 Worker 并发上限 |

Exchange、Queue 和 routing key 从统一 Settings 读取；direct、durable、persistent message、manual ack 和消息字段属于所有实例必须一致的队列契约，不允许通过环境变量改变。

API 先提交 queued job，再使用 publisher confirm 发布并写 `published_at`。发布失败则将 job 标记 failed。为覆盖“数据库已提交、进程在发布前退出”的窗口，Worker 按 `HOUSEKEEPING_INTERVAL_SECONDS` 扫描 `queued AND published_at IS NULL` 的任务并补发，MVP 配置基线为 30 秒；重复消息由数据库状态机和唯一约束消化。

Worker 取得消息后按 job ID 锁行：终态直接 ack；queued 切 running；running 重投递不并行执行并直接 ack。执行期间更新 heartbeat；进程崩溃后，`worker.py` 启动检查或同进程 housekeeping 将超时 running 标记 failed，用户可重新提交。MVP 不建重试队列、延迟队列或死信业务流程。

## 3. 关系模型

```text
media_sources 1 ── n media_formats
media_sources 1 ── 0..1 download_jobs
media_formats 1 ── 0..n download_jobs
download_jobs 1 ── 0..1 artifacts
```

只建 4 张业务表，不建用户、平台、站点配置、下载历史、事件、队列任务或通用附件表。

## 4. `media_sources`

| 字段 | 类型 | 约束/含义 |
| --- | --- | --- |
| `id` | UUID | PK |
| `owner_token_hash` | CHAR(64) | 非空；匿名会话随机 token 的 SHA-256 |
| `source_url` | TEXT | 可空；只供 Worker 使用，任务终态后擦除 |
| `source_host` | VARCHAR(253) | 非空；日志只允许记录此字段 |
| `extractor_key` | VARCHAR(100) | 非空；yt-dlp 具名 extractor |
| `external_id` | VARCHAR(255) | 可空；平台媒体 ID |
| `title` | VARCHAR(500) | 非空；不可信展示文本 |
| `thumbnail_url` | TEXT | 可空；不得含私有地址 |
| `duration_seconds` | INTEGER | 可空，CHECK >= 0 |
| `inspect_expires_at` | TIMESTAMPTZ | 非空；默认 created + 15 分钟 |
| `created_at` | TIMESTAMPTZ | 非空，UTC |

唯一约束：`(owner_token_hash, id)`；索引：`(owner_token_hash, inspect_expires_at)`、`inspect_expires_at`。不按 URL 去重，避免不同匿名会话共享来源记录。

## 5. `media_formats`

| 字段 | 类型 | 约束/含义 |
| --- | --- | --- |
| `id` | UUID | PK，对外唯一格式 ID |
| `source_id` | UUID | FK `media_sources(id)` ON DELETE CASCADE |
| `video_format_id` | VARCHAR(100) | 非空；yt-dlp 返回值，不由用户提交 |
| `audio_format_id` | VARCHAR(100) | 可空；分离音频流 ID |
| `label` | VARCHAR(50) | 非空，如 `1080p` |
| `width`,`height` | INTEGER | 可空，CHECK > 0 |
| `fps` | NUMERIC(6,2) | 可空，CHECK > 0 |
| `container` | VARCHAR(20) | 非空 |
| `video_codec`,`audio_codec` | VARCHAR(100) | 非空 |
| `estimated_size_bytes` | BIGINT | 可空，CHECK >= 0 |
| `requires_merge` | BOOLEAN | 非空 |
| `sort_order` | SMALLINT | 非空，CHECK >= 0 |
| `created_at` | TIMESTAMPTZ | 非空，UTC |

唯一约束：`(source_id, sort_order)`、`(source_id, id)`；索引：`source_id`。客户端只能看到本表 UUID 和展示字段，不能看到 provider format IDs。

## 6. `download_jobs`

| 字段 | 类型 | 约束/含义 |
| --- | --- | --- |
| `id` | UUID | PK |
| `owner_token_hash` | CHAR(64) | 非空，所有查询必须匹配 |
| `client_request_id` | UUID | 非空；客户端幂等键 |
| `source_id`,`format_id` | UUID | 非空；使用下述组合 FK 保证会话/source/format 归属 |
| `status` | VARCHAR(20) | CHECK `queued/running/succeeded/failed/expired` |
| `stage` | VARCHAR(20) | 可空，CHECK 固定阶段集合 |
| `progress_percent` | SMALLINT | 可空，CHECK 0–100 |
| `downloaded_bytes`,`total_bytes` | BIGINT | 可空，CHECK >= 0 |
| `error_code` | VARCHAR(80) | 可空；稳定机器码 |
| `error_message` | VARCHAR(500) | 可空；安全中文提示 |
| `published_at`,`started_at`,`heartbeat_at`,`finished_at` | TIMESTAMPTZ | 可空 |
| `created_at`,`updated_at` | TIMESTAMPTZ | 非空，UTC |
| `version` | INTEGER | 非空；乐观锁，CHECK >= 0 |

唯一约束：`source_id`（一次 inspect 只创建一个 job）、`(owner_token_hash, client_request_id)`。组合 FK：`(owner_token_hash, source_id) → media_sources(owner_token_hash,id)`、`(source_id,format_id) → media_formats(source_id,id)`。索引：`(status,published_at)`、`format_id`、`created_at`。状态更新使用 `WHERE status=:expected AND version=:version`，与 CHECK 一起阻止并发覆盖和非法终态回退。

## 7. `artifacts`

| 字段 | 类型 | 约束/含义 |
| --- | --- | --- |
| `id` | UUID | PK |
| `download_job_id` | UUID | UNIQUE FK `download_jobs(id)` ON DELETE CASCADE |
| `object_key` | VARCHAR(500) | UNIQUE；MinIO 私有对象键 |
| `file_name` | VARCHAR(500) | 非空；净化后的下载名 |
| `content_type` | VARCHAR(100) | 非空 |
| `size_bytes` | BIGINT | 非空，CHECK > 0 |
| `sha256` | CHAR(64) | 非空 |
| `expires_at` | TIMESTAMPTZ | 非空；默认成功后 24 小时 |
| `created_at`,`deleted_at` | TIMESTAMPTZ | created 非空，deleted 可空 |

索引：`expires_at`、`deleted_at`。Artifact 写入与 job succeeded 在一个数据库事务中完成；MinIO 已上传但事务失败时，Worker 删除孤儿对象。

## 8. 保留与迁移

- Inspect 过期后不能新建任务；无 job 的 source/format 可清理。
- job 终态后立即把 `source_url` 置 null；产物 24 小时整禁止签发 URL。
- `worker.py` 内的单一轻量 housekeeping 按 `HOUSEKEEPING_INTERVAL_SECONDS` 运行：超过 `RUNNING_STALE_AFTER_SECONDS` 的失联 running 收敛为 failed，删除已经到期的 MinIO 对象并标记 job expired；MinIO lifecycle 为物理删除兜底，不增加 scheduler 服务。
- 终态 job、source、format、artifact 元数据保留 7 天后删除，不作为用户历史功能。
- Alembic 是唯一 schema 入口；首个 migration 一次创建 4 表、约束和索引，运行时不自动建表。

## 9. Design Acceptance Criteria

| 编号 | 必须证明 | 实现后证据 |
| --- | --- | --- |
| `S003-DAC-01` | 空 PostgreSQL 经单一 Alembic migration 创建且仅创建 4 张业务表 | migration 命令、schema/约束/索引快照 |
| `S003-DAC-02` | 状态转换、会话归属、幂等键和一任务一产物在并发下仍成立 | 状态矩阵与并发事务测试 |
| `S003-DAC-03` | RabbitMQ 只有本文 exchange/queue/routing key，消息仅含 job_id | broker 声明、消息捕获和依赖扫描 |
| `S003-DAC-04` | 发布失败、发布前崩溃、重复消息和 Worker 崩溃都不会形成永久 queued/running 或重复产物 | 故障注入、补发、heartbeat 超时与重投递记录 |
| `S003-DAC-05` | 无 Celery、Result Backend、重试/DLQ 业务框架或第二套队列状态 | 依赖、配置、源码和 broker 扫描 |
| `S003-DAC-06` | URL 擦除、24 小时产物期限、MinIO 删除和 7 天元数据清理准确 | 可控时间测试与 DB/MinIO 对照 |
| `S003-DAC-07` | 数据库始终是业务状态来源，RabbitMQ/MinIO 重启后任务与对象可恢复 | 真实依赖重启与恢复记录 |
