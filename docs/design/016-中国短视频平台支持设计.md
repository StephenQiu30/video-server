# 016 中国短视频平台支持设计

- 状态：Phase 1 已实施；持续 canary 待自动化
- 日期：2026-08-11
- 前置设计：`docs/design/005-多平台Provider策略设计.md`、`docs/design/010-Codex与Claude CLI视频分析设计.md`
- 调研：`docs/research/004-GitHub短视频提取方案调研.md`
- 验收：`docs/acceptance/016-中国短视频平台支持验收.md`

## 1. 决策摘要

抖音当前已经由仓库内 `douyin_share.py` 可信插件支持：插件覆盖 yt-dlp 的 `DouyinIE`，优先读取第一方公开分享页 `window._ROUTER_DATA`，验证作品 ID 和可播放格式后才回退上游 extractor。官方开放平台是否提供下载 API，不决定这条公开分享页能力是否存在，也不得把已验证能力降级为“不支持”。

本阶段沿用同一模式实现快手公开视频：

1. 只请求快手第一方公开分享页，不调用公共解析 API。
2. 桌面 `short-video/{id}` 规范化到移动分享页 `fw/photo/{id}`；短链由插件解析第一方重定向。
3. 使用固定 `Chrome-131:Android-14` impersonation 读取 `window.INIT_STATE`。
4. 作品身份、内容类型和格式必须同时通过校验；图集不伪装成单视频。
5. 返回完整 MP4 格式，后续仍执行下载前 re-inspect、FFmpeg/ffprobe、大小/时长和哈希校验。
6. 下载完成的完整视频交给现有 AI Agent 分析分镜、高光和视觉资产；本设计不改为抽帧分析。

快手插件代码为本仓库独立实现。社区项目仅用于确认公开页面形态、维护风险和测试样本，没有复制 GPL、PolyForm Noncommercial 或授权不清的源码。

## 2. 范围

### 2.1 本阶段实现

- 抖音：保留现有 `Douyin + share_page` 插件和真实回归状态。
- 快手：新增 `KuaishouPublicIE`、`kuaishou-public-v1` Profile、来源分类、错误映射和状态页数据。
- 支持快手入口：
  - `www.kuaishou.com/short-video/{id}`
  - `kuaishou.cn/short-video/{id}`
  - `v.kuaishou.com/{share-code}`
  - `www.kuaishou.com/f/{share-code}`
  - 第一方 `chenzhongtech.com` / `gifshow.com` 移动分享详情页
- 支持视频 manifest 中多个 H.264/HEVC MP4 表示；缺少 manifest 时回退第一方 `mainMvUrls`。

### 2.2 不在范围

- DRM、会员、购买、private、follow-only、地域绕过和账号自动化。
- 用户上传原始 Cookie、Authorization、任意 yt-dlp 参数或浏览器 Profile。
- 微信视频号抓包、MITM、客户端签名逆向或登录态劫持。
- 红果 App 的签名、密钥提取或 DRM 解密。
- 把第三方影视聚合镜像或公共“去水印 API”作为 Provider。
- 把图集、轮播或多视频帖子静默截断成单个条目。

## 3. 当前调用链

```text
POST /api/inspections
  → InspectMedia
  → Media Runner
  → ProviderRegistry(kuaishou-public-v1)
  → yt-dlp --plugin-dirs app/runner
  → KuaishouPublicIE
  → 第一方公开分享页 window.INIT_STATE
  → 标准 yt-dlp info/formats
  → 语义格式选择
  → 下载前 re-inspect
  → 完整媒体下载 + FFmpeg/remux + ffprobe + SHA-256
  → MinIO 制品
  → RabbitMQ 异步 AI Agent 完整视频分析
```

AI Agent 获得的是完整视频文件和受限解码工具。连续分镜、高光、时间轴与证据仍由 010/012/015 定义的异步分析链路生成并持久化；Provider 只负责可靠交付完整媒体，不替代分析，也不把“抽几张图片”当作视频理解。

## 4. 快手提取器设计

### 4.1 URL 与重定向

- 已含作品 ID 的桌面地址在进入 yt-dlp 前规范化为固定移动分享页。
- 短链必须由固定 Android client 解析；最终 URL 必须同时满足：
  - hostname 等于或从属于 `kuaishou.com`、`kuaishou.cn`、`chenzhongtech.com` 或 `gifshow.com`；
  - path 符合 `/fw/photo/{id}` 或 `/short-video/{id}`。
- 跳转到其他域、首页、缺失作品 ID 或过期页面统一返回 `provider_link_unavailable`。
- 网络层仍由 egress proxy 阻断私网；插件域名校验是额外的应用层收敛，不替代网络隔离。

### 4.2 状态与身份校验

移动分享页包含 `window.INIT_STATE`。顶层 key 可能混淆，插件不依赖 key 名，而是检查每个顶层对象的 `photo`：

1. `share_info.photoId` 必须等于最终 URL 的作品 ID；
2. `photoType` 必须为 `VIDEO`；
3. 至少存在一个 HTTPS MP4 表示；
4. 时长必须为正数，后续还要满足 Runner 最大时长。

任一条件失败均不返回“成功但空格式”。图片/图集返回稳定 `provider_unsupported`，失效或身份不匹配返回 `provider_link_unavailable`。

### 4.3 格式映射

`manifest.adaptationSet[].representation[]` 映射为标准 yt-dlp format：

| 快手字段 | yt-dlp 字段 |
| --- | --- |
| `videoCodec=avc/hevc` | `vcodec=h264/hevc` |
| `qualityType` + `id` | 稳定 `format_id` |
| `width` / `height` / `frameRate` | 尺寸与帧率 |
| `avgBitrate` / `fileSize` | `tbr` / `filesize` |
| `url`，其次 `backupUrl[0]` | HTTPS 媒体 URL |
| MP4 内音轨 | `acodec=aac`，并由真实 ffprobe 校验 |

媒体 URL 具有短 TTL，不持久化为长期事实。下载任务必须按原 URL 和同一 Provider Profile re-inspect，重新获得新 URL 和相同语义格式。

### 4.4 访问上下文

快手 Profile 固定：

- `version=kuaishou-public-v1`
- `access_mode=anonymous`
- `client_profile_id=chrome-131-android-14`
- `command_args=--impersonate Chrome-131:Android-14`
- `canary_suite=kuaishou-public-share-page`
- 不允许 Provider Cookie、账号或公共解析服务

## 5. 状态与错误

| 场景 | 稳定码 | HTTP | 是否重试 |
| --- | --- | --- | --- |
| 公开作品视频可解析 | 成功 | 200 | 不适用 |
| 短链过期、跳首页、身份不匹配 | `provider_link_unavailable` | 422 | 否 |
| 图集/图片帖子 | `provider_unsupported` | 422 | 否 |
| 页面 schema 改变 | `extractor_regression` | 502 | 由 canary 降级，不在单请求放大重试 |
| TLS/出口挑战 | `egress_challenged` 或 inspection failure | 422/502 | 受统一预算限制 |
| DRM/受限内容 | 既有 DRM/权益错误 | 422/403 | 否 |

`GET /api/providers` 当前将快手标记为 `registered=true`、`extractor_exists=true`、`verified`，证据基线日期为 2026-08-11。该状态表示本固定版本在授权公开样本上通过 metadata 与媒体验证，不是对所有用户链接的永久承诺。自动 canary 聚合仍按 005 的 H1 门禁继续实施。

## 6. 平台决策矩阵

| 平台 | 当前实现 | 决策 |
| --- | --- | --- |
| 抖音 | 项目 `Douyin + share_page` 插件 | 保留并持续真实 canary，不因官方 Open API 缺下载接口而降级 |
| 快手 | 项目 `KuaishouPublicIE` | 本阶段新增；只处理第一方公开视频 |
| 小红书 | 固定 yt-dlp `XiaoHongShu` | 仅视频笔记；图文不冒充视频 |
| 微博 | 固定 yt-dlp `Weibo` | 保持 `unknown`，补授权 canary 后再提升 |
| Bilibili/TikTok | 固定 yt-dlp | 保留现有状态与 canary |
| 微信视频号 | 无安全、稳定、匿名公开 extractor | 维持 `unsupported` |
| 红果短剧 App | DRM/客户端签名路径 | 永久排除，不修订仓库非 DRM 硬边界 |
| 公共解析站/影视镜像 | 第三方中转 | 不接入，不发送用户 URL，不承诺来源合法性或稳定性 |

芒果TV、爱奇艺、搜狐和 WeTV 等长视频站点虽有 yt-dlp extractor，但应作为独立 Provider 批次完成授权样本、权益/DRM 负例和下载 canary，不能仅因 extractor 名称存在就标记为 verified。

## 7. 验证门禁

每个新增短视频 Provider 至少需要：

1. 插件加载、URL 匹配、身份一致、格式映射和 fallback 单元测试；
2. 不可信重定向、图集、失效链接、无格式和 schema 缺失负例；
3. Provider 规范化、固定 client、来源统计和 API 状态契约测试；
4. 真实公开样本 metadata；
5. 至少一个完整 MP4 下载并由 ffprobe 验证视频、音频、时长和容器；
6. 下载前 re-inspect 后格式 ID 稳定；
7. 浏览器状态页显示与 API 一致，桌面/移动布局无横向溢出；
8. 后端全量 lint、format、mypy、pytest 与 CI 通过。

真实 canary 只使用项目自有、明确授权或公开测试样本；验收记录不保存完整签名 URL、Cookie、用户内容或原始页面响应。

## 8. 后续演进

- 将静态 verified 基线升级为 005 定义的持久化 canary 聚合与恢复迟滞。
- 为短链重定向补充 Provider control-plane 级重新 admission；当前插件已做第一方域名收敛，Generic 的跨 Provider redirect 仍是 005 B3。
- 图片/轮播在领域模型支持多资产 manifest、总量上限和部分失败语义后另立设计；在此之前继续 fail closed。
- 其他平台优先采用“固定版本上游 extractor → 仓库可信插件 → 明确 unsupported”的顺序，不引入浏览器常驻、公共解析服务或不兼容许可证代码。
