# 016 中国短视频平台支持设计

- 状态：调研完成，实施待启动
- 日期：2026-08-11
- 前置调研：`docs/research/003-多平台下载会话与GitHub适配调研.md`、`docs/design/005-多平台Provider策略设计.md`
- 结论：红果短剧（hongguo）官方在线播放仅限 App 且为 CENC AES-128-CTR DRM + X-Gorgon 签名，与本仓库 SECURITY.md「只处理公开、非 DRM 内容」边界直接冲突；本次仅完成调研与方案设计，实施路径按「补全已有 extractor → 非 DRM 自研 → 受控 DRM 隔离 Runner」分阶段推进，安全边界修订需单独评审。

## 1. 目标

在保持现有 Provider Registry + yt-dlp 主链架构不变的前提下，让「万能视频下载器」覆盖全部主流中国社交媒体/视频平台的视频下载与 inspect（自省→格式选择）能力：

1. **补全已具备 yt-dlp extractor 但未注册的平台**：芒果TV（MangoTV）、爱奇艺（iqiyi）、搜狐视频（Sohu/SohuV）、腾讯视频（VQQ，含国际版 WeTv）。
2. **自研缺失 extractor 的平台**：快手（kuaishou）、微信视频号（wechat_channels）、红果短剧（hongguo）。
3. **验证并修复现有 17 个注册源的真实状态**：用真实 canary 把「已登记域名」「extractor 存在」「真实可下载」「需会话」「不支持」分层，落到 `GET /api/providers` 与前端状态页。
4. **明确 DRM 边界**：红果 App 路径的 DRM 解密组件与现有非 DRM 边界的关系、隔离方案与风险。

## 2. 非目标

- 不绕过 DRM、会员/购买权益、private/follow-only 权限或平台地域限制（除非 016 §7 的受控 DRM 路径经正式安全评审后单独授权）。
- 不自动化账号密码、验证码、2FA、设备注册或账号养号。
- 不在 inspection/download JSON 中直接上传 Cookie、Authorization、PO Token 或原始浏览器 profile。
- 不开放任意 yt-dlp 参数、输出模板、插件、外部 downloader、shell 或文件路径。
- 不通过高频代理轮换、伪造平台签名或安装 MITM 根证书规避访问控制。
- 不承诺「无水印」「原始母版」或受限内容可用；不把聚合镜像站（macCMS）当作官方能力承诺。

## 3. 当前基线与实测数据

本节全部数据来自 2026-08-11 的真实验证：使用 agent-browser 打开平台页面确认可达性/反爬状态，使用仓库固定 yt-dlp（commit `5d6b8c8`，版本 `2026.07.04`）配合项目自带 douyin/mediatrack 插件做 extractor 识别与 inspect 提取。

### 3.1 调用链（现有，无需改动）

```text
POST /api/inspections
  → InspectMedia
  → MediaRunnerHttpClient
  → POST /internal/v1/inspect
  → MediaRunnerService.inspect
  → MediaCommands.inspect（--plugin-dirs app/runner，--dump-single-json）
  → yt-dlp
```

下载前会重新 inspect，再执行双流 + probe。因此 inspect 流程本身对新增平台是通用的：**任何 yt-dlp 认识的 URL 都会自动走「检查→返回格式→选择→下载」**。新增平台不需要重写 `inspect_media.py`，只需在 Provider Registry 登记域名/Profile，并在需要时提供 extractor 插件。

## 4. 红果短剧专项调研

红果短剧是字节跳动（ByteDance）旗下免费短剧 App（包名 `com.phoenix.read`，复用番茄小说 `com.dragon.read` 的部分能力）。本次通过 GitHub 调研确认了三条可能的接入路径，性质完全不同。

### 4.1 路径 A：官方 web（`hongguoduanju.com`）—— 仅元数据，无播放 URL

- `novelquickapp.com` 是红果 web 前端，实测 301 重定向到 `hongguoduanju.com`。
- 详情页 URL 格式：`https://hongguoduanju.com/detail?series_id={数字ID}`。
- 页面嵌入 `window._ROUTER_DATA`，结构为 `loaderData.detail_page.seriesDetail` / `videoList`，含剧名、集数、演员、封面（`p3-novel.byteimg.com`）等元数据。
- **实测 `_ROUTER_DATA` 全文搜索不含 m3u8、mp4、main_url、video_model、play_url、spade**——即官方 web 不暴露任何可播放视频地址。在线播放必须跳转 App（扫码/App 内播放）。
- 结论：官方 web 只能作为 **元数据/检索源**，不能用于下载。社区 `rabbitwit/PT-Gen-Refactor` 只实现了这一层。

### 4.2 路径 B：App 原生 API —— CENC AES-128-CTR DRM + X-Gorgon 签名

依据社区逆向仓库 `zhangbaio/hongguo`（MIT，2026-06 逆向复现）的完整链路：

```text
search/tab/v ─→ series_id
  → multi_video_detail ─→ 各集 vid
  → multi_video_model ─→ video_model（需 X-Gorgon/X-Argus 签名，Frida 签名预言机）
      ├─ video_list[].main_url            （CDN 密文直链）
      ├─ video_list[].encrypt_info.spade_a （包装的内容密钥）
      └─ video_list[].video_meta.definition（清晰度）
  → unwrap_spade(spade_a) ─→ content key(16B)（纯 Python，无 KEK/AES）
  → GET main_url ─→ CDN 密文 mp4
  → 从 senc 盒取 base_iv64(8B)
  → AES-128-CTR(key, IV=((base_iv+样本序号)<<64)) 逐样本解密 ─→ 明文 mp4
```

关键事实：
- **接口签名**：`X-Argus/X-Gorgon` 是字节 native 签名，几分钟过期，需要 Frida 预言机（MuMu 模拟器 + app 自己算签名）。
- **视频加密**：标准 CENC **AES-128-CTR**，每集密钥由 `spade_a` 经 `libttmplayer.so` 的纯字节变换算出。
- 下载与解密可纯离线 Python 实现，但「调 API 取 spade+直链」这一步必须依赖运行中的 App 签名环境。
- 该仓库还披露红果内部复用 `com.dragon.read` 的 `VipInfoModel` 类，存在 VIP 解锁 hook（`Squemadylan/squemaFQH`）。

**该路径属于 DRM 破解**，与本仓库 `SECURITY.md`「本项目只处理用户有权下载和分析的公开、非 DRM HTTP(S) 内容」直接冲突。实施必须先正式修订安全边界（见 §7）。

### 4.3 路径 C：macCMS 聚合镜像（`hongguoapp.cn`）—— 非 DRM 但不稳定

- `hongguoapp.cn` 是第三方 macCMS（海洋CMS）站点，播放页嵌入真实 m3u8 直链（`https://v.fengbao8.com/video/{剧名}/第N集/index.m3u8`）。
- 实测该 m3u8 在无头浏览器和 curl 下均返回 404——CDN 域名按剧轮换，且 HyperCDN 屏蔽数据中心 IP，只放行家庭宽带（社区 `wangduoyu001/hongguo-drama-downloader` 实测结论）。
- 该站点用 `bfzym3u8.js`（仅 DPlayer 包装）加载 m3u8；URL 可通过页面内 `player_aaaa` 配置对象提取。
- 结论：可作为**非 DRM 的「网页可下载」来源**，但依赖第三方镜像站的可用性，不能作为官方能力承诺，且不能保证所有剧集。

## 5. 快手与微信视频号调研

### 5.1 快手（kuaishou.com）

- 公开视频 URL 格式：`https://www.kuaishou.com/short-video/{videoId}`（`v.kuaishou.com` 短链需先解析重定向）。
- 社区方案（`x1027966382/video-parser`、`leedreamer4gmail/videodown` 等）依赖解析页面内 `__NEXT_DATA__` / `__INITIAL_STATE__` JSON 提取视频 URL，再配合 `Referer`/`Accept-Language` 请求头。
- **本次实测**：`curl` 直接请求返回 63 字节（需 JS 渲染）；agent-browser 渲染后页面内无 `__NEXT_DATA__`、无 m3u8/mp4，`read` 输出仅 `{"result":2}`——即当前快手页面已不通过页面内 JSON 暴露可下载 URL，实际视频地址需客户端/私有接口获取。
- 结论：快手支持依赖**自研 extractor + 动态接口逆向**，且快手页面频繁变化，实现后需持续维护。You-Get 曾支持 `kuaishou.com` 但该解析路径当前同样失效。

### 5.2 微信视频号（channels.weixin.qq.com）

- 无稳定开源 yt-dlp/you-get extractor；视频播放 URL 需登录态 + 复杂签名（`_signature` 等），且链接短期有效。
- 社区方案多为「微信内置浏览器抓包」或「MITM/协议逆向」，属于高风险、非稳定路径。
- 结论：当前**不建议实现**，维持 `unsupported`；若要实现需独立研究和专用账号会话，风险与维护成本最高。

## 6. 架构方案

### 6.1 分层支持模型

沿用 005 §13 的「已登记 ≠ 已验证」原则，新增平台按能力分四层：

| 层级 | 平台 | 接入方式 | 验证要求 |
| --- | --- | --- | --- |
| L0 已注册且验证 | bilibili、tiktok、niconico、youtube(会话) | 现有 Profile + canary | 真实下载 canary |
| L1 补注册（yt-dlp 已有） | 芒果TV、爱奇艺、搜狐、WeTv | 在 `provider_catalog.py` 增 `_standard` Profile | 真实下载 canary |
| L2 自研非 DRM extractor | 红果聚合镜像、快手（若实现） | yt-dlp plugin（沿用 `app/runner/plugins/yt_dlp_plugins/`） | canary + 插件测试 |
| L3 受控 DRM 路径 | 红果官方 App | 独立 Runner + 独立评估 | 安全评审通过后 |

### 6.2 红果 DRM 路径的隔离设计（参考 005 §5.2 Runner pools）

若正式修订安全边界后实施 L3，红果 DRM 解密组件**必须独立隔离**：

- 独立 `hongguo-runner` 池：与 anonymous/operator Runner 物理分离，不共享 DB/MQ/MinIO/AI 凭据。
- DRM 解密只在独立进程中执行：先调 App 签名 API 取 `spade_a` + 密文直链，再纯 Python `unwrap_spade` + AES-CTR 解密，解密产物再进入现有 inspect/download 校验链路。
- 不把 X-Gorgon 签名逻辑、Frida 预言机或密钥派生逻辑混入核心 `app/runner/` 主链；作为独立子进程/独立镜像承载，输出经过 ffprobe + 大小/时长/哈希校验。
- 权益防火墙：只允许公开短剧；VIP 解锁 hook 明确排除，不通过账号权益借给用户。
- egress 独立；CDN 屏蔽机房 IP 的问题需要家庭带宽出口或受控出口策略。

### 6.3 快手 extractor 插件设计（若实现）

- 沿用 `app/runner/plugins/yt_dlp_plugins/extractor/` 现有插件模式（参考 `douyin_share.py`）。
- `KuaishouIE`：解析短链重定向 → `short-video/{id}` → 页面/私有接口提取视频 URL → 返回标准 yt-dlp info dict。
- 需维护 `__NEXT_DATA__`/私有接口 schema 变化的兼容层；页面变化时降级为 `extractor_regression`，不伪报成功。

## 7. 安全与边界影响（DRM 修订）

### 7.1 现状硬边界

- `SECURITY.md`：「只处理用户有权下载和分析的公开、非 DRM HTTP(S) 内容。不得…规避访问控制、版权保护和平台授权。」
- `AGENTS.md` §安全与运行约束：「仅处理用户有权下载和分析的公开、非 DRM HTTP(S) 内容…DRM 绕过…始终禁止」。
- 005 设计文档 §10：「权益或 DRM…fail closed，不做规避」；`drm_protected` 错误永久拒绝。

### 7.2 若实施红果 App 路径，需修订的文件

| 文件 | 修订内容 |
| --- | --- |
| `SECURITY.md` | 增加「红果 DRM 解密仅限独立隔离 Runner、显式 allowlist 启用」的例外条款，保留默认非 DRM 边界 |
| `AGENTS.md` | 同步安全边界描述，明确 DRM 例外组件与主链隔离 |
| `docs/design/005-多平台Provider策略设计.md` | §10 平台策略表、§11 错误模型（`drm_protected` 对红果的例外）同步 |
| `docs/prd/005`/`docs/plans/005`/`docs/acceptance/005` | 同步验收门禁 |
| `docs/research/003` | §7 引擎边界补充红果专项结论 |
| 相关架构测试 | `tests/unit/domain/test_download_errors.py` 等 DRM 断言需按新策略调整 |

**重要**：安全边界修订是产品/法律级决策，本设计文档只给出可选路径，最终是否修订、修订范围由仓库所有者与安全评审决定。DRM 例外的推荐默认状态是 **默认关闭、仅显式 allowlist、独立 Runner、独立审计**。

## 8. 实施优先级（后续 Plan 参考）

1. **P0 补注册已具备 extractor 的平台**：芒果TV、爱奇艺、搜狐、WeTv 四平台在 `provider_catalog.py` 注册，成本最低、立即可验证（芒果TV 已验证可用）。
2. **P0 修复现有源状态**：为抖音/小红书/微博/优酷/腾讯补全真实样本与错误分类，把 `GET /api/providers` 状态更新为真实值；前端状态页展示「可用/受限/需会话」。
3. **P1 红果非 DRM 层**：接入 hongguoapp.cn 聚合镜像（注册为独立 Provider，标注为镜像源，非官方能力），或接入官方 web 元数据 + 「不支持下载」标注。
4. **P2 红果 DRM 路径**：先完成 §7 安全边界评审与修订，再按 §6.2 隔离 Runner 设计实施。工作量与维护成本最高。
5. **P3 快手/视频号**：快手评估动态接口逆向可行性；视频号维持 `unsupported`，不做不可持续的承诺。
