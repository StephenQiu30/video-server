# 021 媒体封面持久化设计

## 背景与目标

媒体解析及格式凭据默认只保留 15 分钟，但下载任务详情和历史需要长期展示标题、来源、时长、格式与封面。此前封面以内联 Data URL 保存在 `media_inspections.metadata`，详情页又依赖仍未过期的格式查询；格式到期后页面无法取得封面，即使下载制品仍然有效。

本设计把“短期下载凭据”和“长期展示数据”分离。原始媒体 URL、Provider context 与格式提示仍按解析 TTL 失效；封面作为用户私有展示制品持久化到 MinIO，PostgreSQL 仅保存对象引用和完整性元数据。

## 数据与对象模型

`media_thumbnails` 与 `media_inspections` 一对一：

- `inspection_id`：所有权与展示资源关联，删除解析记录时级联删除数据库引用。
- `bucket`、`object_key`：私有 MinIO 对象定位。
- `content_type`：仅允许 AVIF、JPEG、PNG、WebP。
- `sha256`、`size_bytes`：每次读取校验完整性，大小上限 2 MB。
- `created_at`、`updated_at`：记录持久化状态。

对象键使用 `thumbnails/{inspection_id}/{sha256}.{extension}`。内容寻址使重复写入幂等，并避免使用用户标题或 Provider 标识构造对象路径。

## 写入与读取流程

1. Runner 继续通过受控出口读取、压缩并限制封面大小，向 API 返回受支持的 Data URL。
2. API 保存解析结果后验证 MIME、Base64、文件签名与大小，计算 SHA-256 并写入私有 MinIO。
3. MinIO 写入成功后，API 原子 upsert `media_thumbnails`，并移除数据库中的内联 `thumbnail_url`，避免重复保存大块 Base64。
4. 解析、下载详情和下载历史只返回同源地址 `/api/inspections/{id}/thumbnail`。
5. 封面端点执行登录认证和 owner 校验，从 MinIO 读取后校验大小与 SHA-256，并设置 `private` 缓存、ETag 与 `nosniff`。

封面持久化失败不应使媒体解析或下载失败。数据库保留内联封面作为恢复来源；第一次读取封面时执行同一幂等迁移。这样升级前已有任务也可逐步迁移，且不需要一次性读取全部用户数据。

## 生命周期与安全边界

- MinIO bucket 保持匿名访问关闭；API 凭据只新增 `thumbnails/*` 的 Get/Put/Delete 权限。
- 浏览器不接收 MinIO 凭据或长期公开 URL；封面只能通过登录态同源端点读取。
- 封面持久化不会延长原始 URL、格式、Cookie、Provider context 或其他下载凭据的 TTL。
- 当前产品不支持删除下载历史，因此封面与其解析记录长期共同保留。未来增加历史删除时，必须先删除 MinIO 对象，再删除或标记数据库记录，并提供孤儿对象 GC。
- 不信任声明的 MIME：写入前验证文件魔数，读取时重新核对 SHA-256 与大小。

## 兼容与验收

- 新解析：数据库存在 `media_thumbnails`，`metadata` 不再包含内联封面。
- 旧解析：首次访问封面后完成惰性迁移。
- 解析格式过期后，下载详情和历史仍能显示持久化标题、格式和封面。
- 非资源所有者不能读取封面；对象损坏返回稳定的存储不可用错误。
- PostgreSQL 当前态 schema、ORM、OpenAPI、前端类型和最小权限策略必须同步通过门禁。
