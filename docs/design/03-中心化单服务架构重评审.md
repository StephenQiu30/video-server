# DESIGN03 中心化单服务架构重评审

## 1. 背景

PRD10 要求把当前 API + Worker 双服务架构收敛为单业务服务 `app`。本文档定义收敛后的技术方案，包括 runtime 架构、Dockerfile 结构、Compose 结构、数据流、失败路径和迁移影响。

## 2. 目标

1. 定义中心化 runtime 的进程内架构：如何同时运行 API server、队列消费者和下载执行器。
2. 定义 Dockerfile 从多 target 收敛为单 target 的方案。
3. 定义 Compose 从多业务服务收敛为单 `app` 服务的方案。
4. 定义 readiness 检查覆盖范围和失败语义。
5. 定义本地路径隔离和 MinIO 交付边界。

## 3. 非目标

1. 不移除 Redis/RQ。
2. 不让 API 同步执行长耗时下载。
3. 不引入 Kubernetes 或多服务编排。
4. 不在本变更中执行代码改动。

## 4. 架构设计

### 4.1 系统架构

```text
                    ┌─────────────────────────────────┐
                    │           app (单容器)            │
                    │                                   │
                    │  ┌─────────┐  ┌───────────────┐  │
                    │  │ FastAPI  │  │ RQ Worker Loop │  │
                    │  │  :8000   │  │  (消费队列)     │  │
                    │  └─────────┘  └───────────────┘  │
                    │                                   │
                    │  共享：Python runtime、依赖库、     │
                    │  数据库连接、Redis 连接、S3 客户端  │
                    └─────────────────────────────────┘
                              │           │
                    ┌─────────┴───┐  ┌────┴────┐
                    │  PostgreSQL │  │  Redis   │
                    │   (独立容器) │  │ (独立容器)│
                    └─────────────┘  └─────────┘
                              │
                    ┌─────────┴───┐
                    │    MinIO    │
                    │  (独立容器)  │
                    └─────────────┘
```

### 4.2 中心化 runtime 入口

中心化 runtime 入口为 `app.runtime` 模块，职责：

1. 启动 FastAPI server（uvicorn，监听 `:8000`）。
2. 启动 RQ Worker 循环（消费 Redis 队列中的下载任务）。
3. 共享 Python runtime、依赖库、数据库连接池、Redis 连接和 S3 客户端。

进程管理方案：

```python
# app/runtime.py 概念示意
import threading
import uvicorn
from app.worker_loop import start_worker_loop

def main():
    # 在后台线程启动 Worker
    worker_thread = threading.Thread(target=start_worker_loop, daemon=True)
    worker_thread.start()

    # 在主线程启动 API server
    uvicorn.run("app.main:app", host="0.0.0.0", port=8000)

if __name__ == "__main__":
    main()
```

### 4.3 Dockerfile 收敛

从三个阶段收敛为两个阶段：

```dockerfile
# Phase 1: Python Base
FROM python:3.12-slim AS python-base
# ... 系统依赖（ffmpeg 等）

# Phase 2: App (合并 API + Worker)
FROM python-base AS app
COPY apps/api/requirements.txt /app/apps/api/requirements.txt
COPY apps/worker/requirements.txt /app/apps/worker/requirements.txt
RUN pip install --no-cache-dir \
    -r /app/apps/api/requirements.txt \
    -r /app/apps/worker/requirements.txt
COPY apps/api /app/apps/api
COPY apps/worker /app/apps/worker
COPY packages /app/packages
EXPOSE 8000
CMD ["python", "-m", "app.runtime"]
```

## 5. 数据流

```text
用户分享 URL
  → /api/parse (FastAPI, app 容器内)
  → /api/tasks (FastAPI, 创建任务写入 DB)
  → RQ enqueue (Redis)
  → RQ Worker (app 容器内消费)
  → yt-dlp 下载 + FFmpeg 合并
  → 临时文件存放在容器内部 /tmp/video-server/
  → 上传到 MinIO/S3
  → 写入 presigned_url 到 DB
  → 清理临时文件
  → 用户通过 presigned_url 下载
```

### 5.1 本地路径隔离

| 位置 | 是否允许出现本地路径 | 说明 |
| --- | --- | --- |
| `/api/tasks` 响应 | 否 | 只返回 presigned_url |
| 数据库 `tasks` 表 | 否 | 只存储 presigned_url 和对象 key |
| 分享链接 | 否 | 只包含 presigned_url |
| 容器内部 `/tmp/` | 是 | 仅运行时临时使用，任务完成后清理 |

## 6. Readiness 规则

### 6.1 `/ready` 检查项

| 组件 | 检查方式 | 失败时错误标识 |
| --- | --- | --- |
| PostgreSQL | `SELECT 1` | `db: fail` |
| Redis | `PING` | `redis: fail` |
| RQ 队列 | 队列可达性检查 | `queue: fail` |
| MinIO/S3 | bucket 可达性检查 | `storage: fail` |
| 媒体工具 | `ffmpeg -version` + `ffprobe -version` | `media_tools: fail` |
| 下载工作目录 | 目录可写检查 | `download_work_dir: fail` |

### 6.2 `/ready` 响应格式

```json
// 全部就绪 (200)
{
  "status": "ready",
  "checks": {
    "db": "ok",
    "redis": "ok",
    "queue": "ok",
    "storage": "ok",
    "media_tools": "ok",
    "download_work_dir": "ok"
  }
}

// 任一失败 (503)
{
  "status": "not_ready",
  "checks": {
    "db": "ok",
    "redis": "fail",
    "queue": "fail",
    "storage": "ok",
    "media_tools": "ok",
    "download_work_dir": "ok"
  }
}
```

### 6.3 `/health` 响应格式

```json
{"status": "ok", "app": "video-server"}
```

## 7. 失败路径

1. 数据库不可用 → `/ready` 返回 503，API 和 Worker 均无法工作。
2. Redis 不可用 → `/ready` 返回 503，队列消费停止，新任务无法调度。
3. MinIO/S3 不可用 → `/ready` 返回 503，产物无法交付，已有 presigned_url 可能过期。
4. ffmpeg 缺失 → `/ready` 返回 503，视频无法合并。
5. 下载目录不可写 → `/ready` 返回 503，下载任务无法执行。
6. Worker 线程异常 → API 仍可用，但队列消费停止，需要容器重启恢复。

## 8. 迁移/回滚影响

### 8.1 迁移步骤

1. 修改 Dockerfile：删除 `api` 和 `worker` target，新增 `app` target。
2. 修改 `docker-compose.yml`：删除 `api` 和 `worker` 服务，新增 `app` 服务。
3. 创建 `app/runtime.py`：中心化 runtime 入口。
4. 更新健康检查配置。
5. 更新文档和索引。

### 8.2 回滚方案

如果需要回滚：

1. 恢复 Dockerfile 的 `api` 和 `worker` target。
2. 恢复 `docker-compose.yml` 的 `api` 和 `worker` 服务。
3. 删除 `app/runtime.py`。

### 8.3 破坏性变更

- Dockerfile target 名称变更（`api`/`worker` → `app`）。
- Compose 服务名变更（`api`/`worker` → `app`）。
- 容器名变更（`stephen-video-api`/`stephen-video-worker` → `stephen-video-app`）。
