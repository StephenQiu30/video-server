# 006 上线产品能力补全设计

- 状态：In progress
- 更新：2026-09-10
- 范围：账户资源准入、独立服务部署、生产验收边界。

本机部署和验证直接复用已运行的 PostgreSQL、RabbitMQ、Redis 与 MinIO，以及现有 `.env` / `.env.prod`。业务启动不创建第二套基础环境；隔离环境定义仅供 GitHub CI 使用。

## 服务边界

保持独立 Next.js standalone 前端（8101）和 FastAPI API（8111）。同一构建镜像分别启动 Node.js 与 Python 进程。Next.js 承担页面、安全头、普通 HTTP 代理和受限上传代理；FastAPI 承担认证授权、业务用例和状态。WebSocket Upgrade 由部署入口直接交给 FastAPI。此交付方式对应 [Next.js standalone 输出](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)。

FastAPI 路由声明输入、输出和依赖；应用层定义配额策略及错误，数据库适配器在资源创建事务内执行配额检查。任务执行继续交给独立 Worker/Runner，不在 HTTP 进程中运行下载、转码或 AI。

PostgreSQL 结构只由幂等的 `backend/sql/schema.sql` 维护；与 ORM 同步，不引入迁移框架、历史 schema 或兼容 API。公开数据契约仍以 OpenAPI 为唯一来源。

## 用户准入与执行容量

1. Redis 只保存短期限流计数和登录会话。已登录高成本操作按账户与操作限流；管理员跳过业务操作限流。登录、注册和验证码同时按邮箱摘要与真实客户端 IP 限流，避免匿名爆破。`RATE_LIMIT_POLICIES` 支持按操作局部覆盖，未知操作和非正值拒绝启动。
2. PostgreSQL 在创建资源、分析 run 和 outbox 的同一事务内检查账户持久配额。所有入口只取账户事务锁，重放判断先于扣减；并发拒绝时整笔事务回滚。管理员可在用户管理中设置账户豁免或单项覆盖，空值继续使用部署默认值。
3. 全局执行容量由 RabbitMQ 队列、消费者 `prefetch` 和有界 Worker 池控制。API 接受合法任务并返回 `queued`；容量不足时任务留在 RabbitMQ，不再通过全局配额锁返回 503。下载并发为 Worker 实例数乘以 `DOWNLOAD_WORKER_THREADS`，导入与报告 Worker 使用各自的 `WORKER_PREFETCH`。

`QUOTA_LIMITS` 的默认策略如下，部署者可用 JSON 局部覆盖：

| 配额 | 默认 | 计数方式 |
| --- | --- | --- |
| 每账户活跃任务 | 5 | 下载（含视频导入）、文档导入、分析；包含排队、执行、等待重试 |
| 24 小时任务数 | 50 | 下载、两类导入、首次分析及人工分析重试 |
| 24 小时处理字节 | 100 GiB | 按每次准入的输出上界预留 |
| 每账户保留存储 | 100 GiB | 已保存对象加活跃输出预留 |
| 24 小时分析尝试预算 | 60 | 每个首次/人工 run 预留其 `max_attempts` |

管理员账号不受上述账户级活跃任务、滚动 24 小时任务/字节、保留存储和分析尝试预算约束；管理员身份只从已认证会话的数据库角色派生，不能由请求体声明。普通账户可以由管理员设置 `quota_exempt`，或覆盖同时活跃任务、滚动任务/字节、存储和分析尝试中的任意一项。单文件/工作区/执行安全边界、Provider 权限和内容授权判断始终适用。

分析尝试预算是执行工作量上界，不是供应商 token 或金额账单；分段分析和内部模型调用仍受各自分段数、超时及输出上限约束。

`resource_admissions` 仅保存账户哈希、资源或 run ID、类型、预留字节、尝试预算和时间。每天的已准入工作量不会因失败、取消或删除而退还，避免重建任务重复消费；活跃名额和未来输出预留随资源终态释放。幂等重放不重复记账，拒绝的请求不留记录。每日窗口为滚动 24 小时。

下载按最大文件字节加封面上限预留；视频导入按声明字节加封面上限；文档按原始文件加规范化文本 UTF-8 最坏字节；分析按 Markdown/DOCX 合计上限预留。规范化字符数和报告合计字节分别由 `DOCUMENT_NORMALIZED_MAX_CHARACTERS`、`ANALYSIS_REPORT_MAX_BYTES` 控制，API 和对应 Worker 使用同一部署配置。

存储计量包含原始文档、规范化文本、视频、封面，以及所有报告版本。软删除或 `delete_pending` 不释放存储额度；只有物理清理完成才释放。上传隔离区、多段上传和中断执行的孤儿对象由现有导入/报告清理器及隔离区生命周期回收，不属于长期保留制品；上线容量测试必须覆盖这部分临时峰值。

配额拒绝返回稳定的 429 Problem Details 和 `Retry-After`。分片 URL 通过 AWS SDK 签名绑定每片的精确 Content-Length；MinIO 在接收分片时拒绝偏大或偏小的请求。取消已领取的报告发布时，预留仍保留至发布结果转为待删除制品或临时对象清理完成，迟到完成不能恢复任务成功状态。报告超限终结 job/run，并进入清理流程，恢复器不重试确定性失败。

## 无感登录

站内任务详情使用 Next.js 客户端路由，不通过 `window.location` 重载根布局。认证 Provider 只在首次初始化时显示恢复状态；后台网络失败保留现有用户。浏览器使用同源 Web Lock 合并多标签页 Refresh，请求进入锁后先重新检查 `/api/auth/me`。Redis 原子轮换成功后为旧 Refresh 摘要保留 10 秒 tombstone；并发旧请求返回 `refresh_in_progress` 且不清 Cookie，真正过期或撤销才清理会话。

查询、下载现有制品、取消和删除不使用创建入口的限流策略，便于用户自助恢复。

## 配置与代理信任

Compose 从运维 `.env` / `.env.prod` 插值，但不再把整份文件通过 `env_file` 注入业务进程。各角色只接收显式配置：API 的 JWT/管理员/指标密钥不传给 Worker；Outbox 不接收对象存储、Runner 或 URL 解密密钥；Import/Report Worker 不接收 JWT、Runner 或 URL 解密密钥。MinIO 业务凭据仍按仓库规范共用一组。生产校验只要求当前角色实际消费的密钥。

`TRUSTED_PROXY_CIDRS` 保留部署者的外部代理白名单。Compose 使用同一个 `FRONTEND_IPV4_ADDRESS` 同时分配 Next.js 地址并配置 API 的 `TRUSTED_FRONTEND_PROXY_IP`，只增加该单一主机的信任。子网和动态地址池也可配置。不得把全部地址加入可信代理。

API 入口关闭 Uvicorn 自动 `proxy_headers` 改写，保留 TCP 对端供应用解析；仅从可信对端读取 X-Forwarded-For，自右向左选择最近的不可信地址。部署入口应追加实际对端而非透传未校验头。代理边界参照 [FastAPI 代理部署说明](https://fastapi.tiangolo.com/advanced/behind-a-proxy/)。

## 上线验收边界

单元、契约、数据库并发测试和本机浏览器检查是代码交付证据。真实公网 TLS/代理链、容器出口隔离、真实授权素材下载与 AI 完整链路、容量峰值、备份恢复及实际告警接收，必须在目标部署验收。未取得这些证据时，不能将仓库检查通过表述为允许公开上线。

现有账户基线包括注册/登录、轮换会话、角色与禁用管理。管理员可在个人资料中调整自己的角色；降为普通用户或停用管理员时，后端在同一事务内保留至少一位启用的管理员。管理员不能停用或删除自己的账户。新注册邮箱所有权验证见 033，密码恢复和整账户注销尚未交付。面向开放注册的公共 ToC 服务仍需确定并实现相应账户服务及运营支持渠道，不能用本地自托管账户能力替代这项验收。
