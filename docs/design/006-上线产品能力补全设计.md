# 006 上线产品能力补全设计

- 状态：Proposed
- 日期：2026-08-08
- 前置研究：`docs/research/002-上线能力与GitHub开源整合调研.md`
- 说明：本文描述目标设计，未在 Acceptance 通过的部分不得写成当前已实现能力。

## 目标

在保留现有 FastAPI、Next.js、PostgreSQL、RabbitMQ、MinIO、Media Runner 和 AI Worker 主架构的前提下，将 MVP 补全为可安全运营、可升级、可恢复、可观测的公网服务，并为音频、字幕和受限批量下载预留稳定领域模型。

本设计优先解决运行和治理缺口，不以“增加支持站点数量”作为上线完成标准。

## 非目标

- 在普通媒体请求中直接提交 Cookie/账号凭据、未受管会话、私有内容或 DRM 绕过；受控 Provider 会话由 005 单独设计和验收。
- 任意 yt-dlp options、外部 downloader、自定义脚本或输出路径。
- 通过公共第三方解析 API 处理用户源链接。
- 首个公网版本内实现频道无限归档、媒体中心、计费或团队协作。
- 用单次成功样本宣称某个平台永久可用。

## 设计原则

1. 产品输入是受约束的语义意图，不是底层工具参数。
2. Secret 可见性和网络可达性必须由部署拓扑强制，而非依赖进程“自觉不读取”。
3. PostgreSQL 保存需要审计和恢复的长期事实；Valkey 只保存可丢失的短期限流状态。
4. TTL 必须对应实际删除执行器和可观测结果。
5. Provider 可用性是带时间戳的运行数据，不是静态产品文案。
6. 所有高成本操作先获得配额/并发令牌，再创建可执行任务。
7. 数据库升级、备份恢复和回滚证据是发布物的一部分。

## 目标组件与职责

| 组件 | 职责 | 允许访问 | 禁止访问 |
| --- | --- | --- | --- |
| Ingress | TLS、请求体/header/超时限制、安全 header、可信代理链 | API | DB、队列、MinIO、Runner |
| API | 会话/认证、限流、配额预检、资源 API、MinIO 签名 | PostgreSQL、Valkey、Runner、MinIO signing | AI Key、媒体公网直连 |
| Outbox | 持久事件发布 | PostgreSQL、RabbitMQ | MinIO、Runner、AI Key、外网 |
| Download Worker | 下载任务执行、持久进度、上传制品 | PostgreSQL、RabbitMQ、MinIO、Runner | AI Key、媒体公网直连 |
| 宿主机 Analysis Worker | CLI 视觉分析、结果发布 | PostgreSQL、RabbitMQ、MinIO、本机 CLI OAuth | Runner HMAC、媒体 Provider |
| Media Runner | inspect/download/FFmpeg/ffprobe | 共享工作区、egress proxy、Runner HMAC；005 验收后的单 Provider 短时会话 | PostgreSQL、RabbitMQ、MinIO、AI Key、默认公网路由、其他 Provider 凭据 |
| Egress Proxy | DNS/重定向后的出口强制与私网阻断 | 公网媒体 Provider | 业务 Secret、数据库 |
| Lifecycle Worker | 临时对象清理、孤儿对账、手动清理恢复 | PostgreSQL、MinIO | Runner、AI Provider |
| Canary Worker | 受控样本解析、错误分类、Provider 状态 | Runner/API 内部接口 | 用户内容、业务制品 |
| Metrics/Logs | 低基数指标、脱敏事件和告警 | 各内部 metrics/log endpoint | 完整 URL query、模型原文、任务帧、Secret |

## 网络设计

Compose 至少分为以下网络：

- `ingress_net`：Ingress 与 API。
- `db_net`（internal）：API、Outbox、Download/Analysis/Lifecycle Worker 与 PostgreSQL。
- `queue_net`（internal）：Outbox、Download/Analysis Worker 与 RabbitMQ。
- `storage_net`（internal）：API、Download/Analysis/Lifecycle Worker 与 MinIO。
- `quota_net`（internal）：API 与 Valkey。
- `runner_rpc_net`（internal）：API、Download Worker 与 Media Runner，只承载 HMAC 内部 API。
- `runner_egress_net`（internal）：Media Runner 与 Egress Proxy。
- `public_egress_net`：只连接 Egress Proxy；Analysis Worker 如需云 AI，应使用独立的 `ai_egress_net` 或平台级 egress policy。

Media Runner 不连接具有 Docker 默认公网路由的网络。测试必须从 Runner 容器证明：

1. 不能连接 PostgreSQL/RabbitMQ/MinIO/Valkey。
2. 不能直接访问公网 IP/域名。
3. 只能通过配置的无凭据 HTTP(S) proxy 完成媒体请求。
4. 环境中不存在数据库、对象存储、消息和 AI Secret。

## 配置与 Secret 设计

- 不再把同一 `.env.prod` 作为所有进程的运行时环境全集。
- Compose 可继续从一个被忽略的运维文件插值，但每个 service 的 `environment` 只显式传入其白名单字段。
- `Settings` 按角色拆为 API、Outbox、Download Worker、Analysis Worker；Runner 继续使用独立 `RunnerSettings`。
- 生产启动时输出配置键名和来源摘要，不输出值；缺失或跨角色 Secret 直接失败。
- Runner HMAC 支持 key id 与双 key 短期轮换；URL 加密 key 需要版本化解密 keyring，避免单 key 阻断滚动轮换。
- Provider Cookie/POT 不进入通用 env、业务消息或共享工作区；005 验收后只允许 credentialed Runner 通过一次操作级认证加密租约和独占 tmpfs 使用，不保留只读 Cookie 源文件。

## 滥用防护与配额

### 身份维度

首个公网版本继续支持匿名会话。限流键由以下维度组合：

- 可信代理解析后的 IP 前缀哈希。
- 匿名 `owner_hash` 或未来的 `account_id`。
- API key id（若启用）。
- operation 和 Provider key。

不持久化原始 IP；日志只保留短期、带轮换 salt 的哈希。

### 两层限制

1. Valkey + `limits`：秒/分钟窗口、burst、并发令牌、bot challenge token；失败返回 `429` 和 `Retry-After`。
2. PostgreSQL：每日任务数、成功下载字节、AI 分钟/调用、同时活跃任务数和人工封禁状态。

创建 inspect/download/analysis 前必须原子预占额度；幂等重放不能重复扣减。任务创建失败、取消或不可执行失败按冻结规则释放或结算额度。

### 全局 backpressure

- 队列深度、磁盘余量、MinIO 可用性、Provider rate limit 和 AI 配额触发全局保护。
- 保护期间拒绝新高成本任务，但查询、取消、删除和下载已完成制品仍可用。
- API 就绪检查不应因单个 Provider 降级整体下线。

## 数据生命周期

### Artifact GC 状态

```text
active → deletion_pending → deleted
                  ↘ delete_retry
```

- 到期且没有 `analysis_artifact_locks` 的制品进入 `deletion_pending`。
- Worker 先幂等删除 MinIO 对象，再写 `deleted_at`；对象不存在也视为幂等成功。
- 删除失败使用有上限的退避重试并告警，不能无限静默失败。
- 每日孤儿对账比较 DB object key 与 bucket inventory：孤儿对象进入隔离期后删除，缺失对象标记制品不可交付。
- MinIO bucket lifecycle 作为最终兜底，生命周期时间必须长于应用 TTL + 最大分析锁时长。

### 用户删除

`DELETE /api/downloads/{id}` 只允许当前 owner 删除任务。运行中的任务先复用既有取消流程；活动分析制品锁返回 `409`。服务端在事务内锁定任务并先将 artifact 标记为已删除，随后同步校验并删除最终视频、本地上传隔离对象、多段上传和私有封面，全部成功后硬删除任务记录；存储不可用返回可重试错误并保留数据库事实，不形成“界面已删、对象仍在”的假成功。Worker 迟到完成会因失去执行所有权而清理它上传的对象。

剧本文档继续使用 `DELETE /api/documents/{id}`：owner 隔离、活动分析锁保护、原始文件/规范化文本清理和记录删除由服务端统一完成。Web 与原生 App 只在 `204` 后刷新，不自行推断对象键或本地隐藏记录。

### 保留策略

- inspection/formats：短 TTL，可按窗口批量清理。
- artifact：按套餐/配置 TTL，用户删除可提前回收。
- job/analysis metadata：与隐私政策一致的有限保留期。
- analysis result：不得比源 artifact 或账户保留策略更久，除非用户显式保存。
- outbox：发布成功后有限保留，便于审计后再清理。

## 数据库升级与恢复

- 引入 Alembic，当前 schema 作为 `0001_baseline`；已存在环境通过校验后 stamp，新环境执行 upgrade。
- 每个变更同时更新 ORM、migration、schema snapshot、架构/契约测试。
- 生产只允许 expand/contract 两阶段兼容迁移，禁止长事务重写大表。
- 部署前自动备份；迁移失败停止新版本，不自动执行危险 downgrade。
- PostgreSQL 与 MinIO 均有加密备份、保留和季度恢复演练；RabbitMQ 队列不是状态事实源，可从 outbox/DB 恢复。

这项设计实施前必须同步修改 `AGENTS.md` 中“禁止 migrations”的现行约定。

## 可观测性

### 日志

- JSON 结构：timestamp、level、service、request/event id、job id、owner hash 前缀、provider、stage、error code、duration。
- HTTP 请求生成 `trace_id/request_id`；outbox envelope 延续 correlation id 到 Worker 和 Runner。
- 禁止记录完整源 URL、query、Cookie、预签名 URL、任务帧、模型原始响应和 Secret。

### 指标

- API：请求量、延迟、状态码、限流与配额拒绝。
- Job：排队时长、执行时长、阶段时长、重试、取消和终态。
- Provider：inspect 成功率、错误分类、yt-dlp 版本、`last_verified_at`。
- Queue/Worker：深度、consumer、lease recovery、outbox lag、heartbeat 失败。
- Storage：对象数/字节、GC backlog、删除重试、孤儿数、预签名失败。
- AI：音频分钟、provider 延迟/错误、token 用量（不记录内容）。

所有 label 必须是低基数枚举；不得将 URL、job id、owner 或异常文本作为 Prometheus label。

### SLO 初始值

- API 查询类可用性：30 天 99.9%。
- inspect API 服务成功率：排除明确 Provider 访问限制后 99.5%。
- 已完成制品签名 URL 签发：99.9%。
- P95 查询延迟 < 500ms；P95 创建任务延迟 < 1s。
- 管理员发起清理后，符合天数阈值且未被任务锁定的文件进入有界删除流程。

Provider 下载成功率作为分平台 SLI 展示，不并入 API 自身可用性承诺。

## Provider 健康模型

新增内部 canary 结果：

```text
verified | degraded | access_required | rate_limited | blocked | disabled | unsupported | unknown
```

每条记录包含 Provider key、受控样本 id、yt-dlp commit、出口池、检查时间、阶段、稳定错误码和耗时。公开 API 只返回聚合状态、最近验证时间和产品提示，不返回样本 URL、出口或内部错误原文。

真实 canary 为非阻塞定时任务，不放入普通 PR CI。PR CI 只运行固定、无外网的 Provider URL/参数契约测试。

## 媒体能力扩展模型

### 语义计划

将当前只支持视频的 `DownloadPlan` 扩展为显式 kind：

```text
video_muxed | video_only | audio_only | subtitle | bundle
```

- `audio_only` 不要求宽高/video codec，包含音频 codec、语言、bitrate/quality tier 和 container preference。
- `subtitle` 包含语言、人工/自动、format，默认独立文件。
- `bundle` 只由服务端白名单 preset 组合视频、字幕和 metadata，不接受任意 postprocessor。
- 转码与 remux 明确区分；转码必须计入 CPU 配额并显示质量/耗时提示。

### 受限批量

- `BatchJob` 是父资源，每个条目仍生成独立 inspection/download job。
- 默认最多 20 条、最大总时长/总估算字节/并发数均有硬上限。
- inspect 先返回条目摘要并要求用户确认，不自动抓取完整频道。
- 部分成功是合法终态，父任务汇总每个子项错误。

## API 演进

P0/P1 预计新增：

- `GET /api/providers`：公开聚合状态。
- `GET /api/events`：当前 owner 的 SSE 事件，支持 Last-Event-ID；轮询保留为降级。
- `POST /api/downloads/{id}/retry`：从既有语义计划创建新任务，不复活旧终态。
- `DELETE /api/downloads/{id}`：请求删除历史和 artifact。
- `POST /api/batches`、`GET /api/batches/{id}`：受限批量。

所有新建资源继续使用 `201 + Location + Idempotency-Key`。API 不引入版本前缀兼容层；破坏性契约变更在同一发布中同步生成前端客户端，并通过 OpenAPI diff 审核。

## 前端信息架构

- 首页：URL/分享文案、当前 Provider 状态、合法使用确认、解析。
- 解析结果：媒体条目、视频/音频/字幕分类、估算大小、兼容性与转码提示。
- 任务详情：实时状态、取消、重试、删除、持久文件状态和错误恢复建议。
- 历史：任务/批量筛选、保留期、删除、Provider 状态。
- 系统状态：Provider 最近验证、服务公告，不泄露内部基础设施。
- 设置（后续）：账户/API key/配额/通知，不进入匿名 beta P0。

## 供应链与发布

- 工具链版本在 Dockerfile、package engines、CI setup 和 README 中保持一致。
- yt-dlp 固定完整 commit；定时更新 PR 必须运行 extractor 清单、受控 canary 和许可证差异检查。
- 基础镜像固定 digest；生成 CycloneDX/SPDX SBOM，Trivy 扫描依赖、镜像、IaC 与 Secret。
- 发布镜像签名并记录 Git SHA、schema revision、yt-dlp commit、SBOM digest。
- 发布前完成备份、migration dry-run、smoke、回滚演练和变更公告。

## 关键决策门

1. 公网 beta 是否只支持匿名用户，还是上线前引入账户。
2. 首发部署是单机 Compose 还是托管 PostgreSQL/对象存储；两者必须有不同 runbook。
3. 音频 MP3 是否允许转码，及其 CPU/版权提示。
4. 批量最大条目数、总时长和每日配额。
5. 是否允许自托管实例关闭公网滥用控制；官方公网实例不得关闭。

未决项使用最保守默认值不阻塞 P0 基础设施实现，但不得在未确认时扩大产品宣传范围。
