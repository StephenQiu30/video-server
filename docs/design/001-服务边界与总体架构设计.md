## 1. 服务目标

用户粘贴一个有权下载的视频链接，查看可用清晰度，异步生成可下载文件，并可在下载完成后按需提取视频中的语音内容。服务必须能够正式部署、持久化任务、隔离长任务，并保留后续横向扩容能力。

首个版本必须提供：

1. yt-dlp 已适配、非 DRM、公开单视频链接解析。
2. 标准化清晰度选择和异步下载。
3. 必要的 FFmpeg 音视频流合并。
4. PostgreSQL 任务持久化、RabbitMQ/Celery 长任务执行。
5. MinIO 私有文件存储和预签名下载。
6. 可选 faster-whisper + LangChain 内容提取。
7. Swagger、DTO/VO、统一响应和全局异常。

## 2. MVP 非目标

- 不下载、选择、嵌入或烧录字幕。
- 不支持 DRM、付费墙、登录后内容、Cookie 导入、地区规避或权限绕过。
- 不支持播放列表、批量任务、音频下载、视频编辑或增强转码。
- 不提供账号、会员、支付、团队、公开分享或永久媒体库。
- AI 不理解画面、图表、动作或人物。
- 不引入 Redis、Kafka、微服务、Kubernetes、Agent、RAG 或向量数据库。

| 领域 | 选型 |

| API | FastAPI、Pydantic |

## 4. 总体架构

`Web → FastAPI → PostgreSQL / RabbitMQ → Celery Worker → yt-dlp / FFmpeg / faster-whisper / LangChain → MinIO`

- FastAPI：请求校验、同步解析、任务创建、状态查询和下载地址签发。
- PostgreSQL：唯一业务事实来源。
- RabbitMQ：只分发任务，不保存最终业务状态。
- Download Worker：下载、合并、校验和上传。
- AI Worker：语音提取、转写和结构化分析。
- MinIO：私有保存视频和临时媒体文件。

部署单元为 `api`、`worker-download`、`worker-ai`、`scheduler`、`postgres`、`rabbitmq`、`minio`。两个 Worker 与 Celery Beat Scheduler 使用同一服务端镜像。

## 5. 架构原则

- API 不执行长下载或 AI 计算。
- Worker 不直接定义对外响应模型。
- PostgreSQL 状态优先于 Celery Result Backend 或进程内状态。
- MinIO 对象不经过 API 长期转发，由短期预签名 URL 交付。
- 每个功能 Design 只拥有自己的契约；跨功能规则由 005 API Design 统一。
- 设计变更先更新对应 Design，不通过兼容层保留已否决方案。

## 6. 执行验收标准

以下标准与 [全局执行验收基线](README.md#执行验收基线强制) 同为强制项：

| 编号 | 必须证明 | 验证与证据 |
| --- | --- | --- |
| `S001-DAC-01` | `api`、两个 Worker、`scheduler` 及三项基础设施职责和进程完全分离 | 全新环境 Compose 启动记录、容器清单、进程参数和健康状态 |
| `S001-DAC-02` | API 不执行下载、FFmpeg、转写或模型调用，两个 Worker 只消费各自队列 | 架构边界测试、队列路由测试和运行时 Worker inspect |
| `S001-DAC-03` | PostgreSQL、RabbitMQ、MinIO 任一不可用时 readiness 为 503，liveness 不误报；恢复后 readiness 回到 200 | 逐项停启真实依赖的请求、退出码和日志 |
| `S001-DAC-04` | 锁文件可在空环境复现依赖，镜像与 Compose 可重复构建和启动 | `uv lock --check`、`uv sync --frozen`、镜像构建和两次冷启动记录 |
| `S001-DAC-05` | 必要配置缺失时安全失败，源码、镜像、日志和响应均不包含 Secret | 配置负例测试及源码、镜像层、日志和响应扫描报告 |
| `S001-DAC-06` | 质量门禁无降级，新增代码满足全局覆盖率要求 | Ruff、格式、mypy、pytest 全量命令、退出码和覆盖率报告 |
