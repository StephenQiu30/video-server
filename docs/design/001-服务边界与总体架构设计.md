## 1. 产品与系统边界

服务只完成：接收一个公开 HTTP(S) 视频页面链接、解析可用分辨率、创建一个异步下载任务、合并必要音视频流、保存临时文件并交付给当前匿名会话。

“万能”表示复用当前锁定版本 `yt-dlp` 的具名 extractor 覆盖能力，不承诺所有网站永久可用。平台规则变化导致的失效属于显式可观测失败，不通过自研爬虫或绕过措施兜底。

MVP 不包含账号、永久历史、播放列表、批量、字幕、音频单独下载、画质增强、转码编辑、AI、私有/付费媒体 Cookie、代理配置、DRM 绕过或第三方公共下载 API。

## 2. 开源调研与复用决策

| 项目 | 可复用价值 | MVP 决策 |
| --- | --- | --- |
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | 大量站点 extractor、格式选择、Python API、进度 hook | 选为唯一解析/下载引擎；固定精确版本和校验值，禁用运行时自更新 |
| [FFmpeg](https://github.com/FFmpeg/FFmpeg) | 音视频流合并、ffprobe 校验 | 选用 LGPL 配置构建；MVP 只 remux/stream copy，不做质量转码 |
| [MeTube](https://github.com/alexta69/metube) | yt-dlp Web 队列、并发、临时目录和清理经验 | 仅参考运行模式；AGPL-3.0 代码不复制进本项目 |
| [cobalt](https://github.com/imputnet/cobalt) | “粘贴即下载”交互、标准化服务结果 | 仅参考交互；不复制 AGPL-3.0 代码，不调用未经许可的公共实例 |
| [FastAPI Full Stack Template](https://github.com/fastapi/full-stack-fastapi-template) | FastAPI/PostgreSQL/Docker/OpenAPI/测试目录规范；Alembic 从统一 Settings 取得连接 | 参考后端工程和生成客户端做法；不引入模板内账号、邮件和自带前端 |
| [FastAPI Best Practices](https://github.com/zhanymkanov/fastapi-best-practices) | 根级 Alembic、按业务功能垂直组织 `src/` | 采用其可预测的目录原则并按本项目裁剪，不复制示例业务代码 |
| [pydantic-settings](https://github.com/pydantic/pydantic-settings) | 从环境变量和 `.env` 加载、校验类型化配置 | 所有进程共用 `src/core/config.py` 的单一 Settings；缺少必填配置时启动失败 |
| [RabbitMQ](https://github.com/rabbitmq/rabbitmq-server) / [aio-pika](https://github.com/mosquito/aio-pika) | 持久消息、publisher confirm、手工 ack 与自动重连 | 直接使用一个下载队列；不引入 Celery 或第二层任务框架 |
| [MinIO](https://github.com/minio/minio) / [Python SDK](https://github.com/minio/minio-py) | 私有对象、预签名下载 URL、生命周期 | 直接使用 MinIO；不建立存储适配器或本地文件交付方案；单独核对 Server AGPL-3.0 与 SDK Apache-2.0 |
| [Alembic](https://github.com/sqlalchemy/alembic) | SQLAlchemy schema 迁移 | 选为唯一数据库迁移入口；自动生成结果必须人工审核 |
| [aria2](https://github.com/aria2/aria2) | 通用多协议下载 | 不选；不能解析视频页面或生成分辨率，MVP 由 yt-dlp 内建下载完成 |

许可证清单、NOTICE、FFmpeg 构建参数和最终容器 SBOM 必须在实现验收中确认；“开源”不等于可以无条件复制或调用托管服务。

## 3. 确定技术架构

基础设施不存在候选项：关系数据库固定为 PostgreSQL，消息队列固定为 RabbitMQ，对象存储固定为 MinIO。实现阶段不得替换为其他产品，也不得为这些已确定组件建设通用适配层。

`video-web → FastAPI API → PostgreSQL / RabbitMQ → Download Worker → yt-dlp / FFmpeg → MinIO`

- Python、FastAPI、Pydantic、pydantic-settings：HTTP、校验、OpenAPI 与统一环境配置。
- SQLAlchemy 2、Alembic、PostgreSQL：任务和元数据唯一事实来源。
- RabbitMQ、aio-pika：API 直接发布、Worker 直接消费，消息体仅含 `job_id`。
- yt-dlp、yt-dlp-ejs、受支持 JavaScript runtime：页面解析和媒体下载。
- FFmpeg/ffprobe：分离流合并和最终产物校验。
- MinIO Python SDK：上传私有对象并生成短期预签名下载 URL。

不使用 Celery、Redis、存储适配层、微服务拆分、Kubernetes 或自研下载协议。MVP 部署单元为 `api`、`worker-download`、`postgres`、`rabbitmq`、`minio`；只有 Worker 使用本地临时目录。

## 4. 关键调用链

1. Web 调用 inspect；API 校验 URL，使用受限 yt-dlp 元数据解析，保存 15 分钟有效的 source/formats。
2. Web 提交服务端 `source_id + format_id`；API 写入 queued job，再向 RabbitMQ 发布 `job_id`。
3. Worker 锁定 job，从数据库加载服务端生成的选择，不信任消息或用户提供的 selector。
4. Worker 下载；需要时 FFmpeg stream copy 合并；ffprobe 与 checksum 校验后上传 MinIO 私有 Bucket。
5. Web 轮询 job；成功后向 API 换取短期预签名 URL，再直接从 MinIO 下载。默认产物 24 小时后不可访问并清理。

## 5. 未来源码目录

当前只定义结构，不创建目录或源码：

```text
video-server/
├─ src/
│  ├─ main.py
│  ├─ api/
│  │  ├─ dependencies.py
│  │  └─ v1/{router.py,media.py,downloads.py,health.py}
│  ├─ core/{config.py,errors.py,logging.py,security.py}
│  ├─ db/{base.py,session.py}
│  ├─ media/{models.py,schemas.py,repository.py,service.py,formats.py,yt_dlp.py,url_policy.py}
│  ├─ downloads/{models.py,schemas.py,repository.py,service.py,state.py}
│  ├─ minio_client.py
│  ├─ rabbitmq.py
│  └─ worker.py
├─ alembic/
│  ├─ env.py
│  ├─ script.py.mako
│  └─ versions/
├─ alembic.ini
├─ tests/{unit,integration,contract,e2e}/
├─ scripts/
├─ .env.example
├─ Dockerfile
├─ compose.yml
├─ pyproject.toml
└─ uv.lock
```

源码直接位于 `src/`，不再包装 `video_server` 顶层包。按功能垂直组织 `media` 与 `downloads`，共享能力只进入 `core/db`；`minio_client.py`、`rabbitmq.py` 和 `worker.py` 直接放在 `src/`，不再套存储、消息或 Worker 框架目录。API schema、数据库 model 和领域状态不得互相直接替代。

`alembic/env.py` 不是保存环境变量的文件，而是 Alembic 执行迁移的启动脚本：它加载 SQLAlchemy metadata、建立迁移连接并执行 `versions/` 中有顺序的 upgrade/downgrade。`.env` 只能表达键值配置，不能替代数据库结构版本、变更顺序与回滚记录。因此保留标准 `alembic/` 目录，但 `env.py` 必须导入与 API/Worker 相同的 `src/core/config.py`，从 Settings 读取 `DATABASE_URL`；`alembic.ini` 不得保存连接串、账号或密码。

## 6. 配置与零硬编码规范

开发环境由仓库根目录 `.env` 提供部署参数，真实 `.env` 已被 Git 忽略；`.env.example` 只列全部键名和非敏感开发示例，不包含真实凭据。生产环境由容器或进程注入同名环境变量，优先级高于 `.env`。API、Worker、Alembic 与 housekeeping 必须共用一个经 Pydantic 校验的 Settings，不得各自读取环境或维护默认值。

| 配置组 | 唯一环境变量 |
| --- | --- |
| 应用与网络 | `APP_ENV`、`APP_HOST`、`APP_PORT`、`APP_PUBLIC_ORIGIN`、`WEB_ORIGIN`、`LOG_LEVEL` |
| PostgreSQL | `DATABASE_URL` |
| RabbitMQ | `RABBITMQ_URL`、`RABBITMQ_EXCHANGE`、`RABBITMQ_QUEUE`、`RABBITMQ_ROUTING_KEY`、`RABBITMQ_PREFETCH_COUNT` |
| MinIO | `MINIO_ENDPOINT`、`MINIO_PUBLIC_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_SECURE`、`MINIO_BUCKET`、`MINIO_PRESIGNED_URL_TTL_SECONDS` |
| 匿名会话 | `SESSION_SECRET`、`SESSION_COOKIE_NAME`、`SESSION_TTL_SECONDS` |
| 任务与资源限制 | `YTDLP_ALLOWED_EXTRACTORS`、`INSPECT_TIMEOUT_SECONDS`、`INSPECT_TTL_SECONDS`、`DOWNLOAD_TIMEOUT_SECONDS`、`MAX_VIDEO_DURATION_SECONDS`、`MAX_FILE_SIZE_BYTES`、`ARTIFACT_TTL_SECONDS`、`JOB_TOMBSTONE_TTL_SECONDS`、`WORKER_CONCURRENCY`、`WORKER_TEMP_DIR` |
| Worker 运行节流 | `PROGRESS_UPDATE_INTERVAL_SECONDS`、`HOUSEKEEPING_INTERVAL_SECONDS`、`RUNNING_STALE_AFTER_SECONDS` |

连接地址、凭据、Origin、Bucket、Exchange、Queue、routing key、日志级别、超时、TTL、并发数、文件/时长上限和临时目录均禁止写死在 Python、Alembic、Compose 或 Dockerfile 中。缺少、类型错误或越界的必填配置必须在进程启动时失败；日志不得输出 Secret 或含凭据的 URL。

API 路径、状态枚举、RabbitMQ 消息 schema、数据库字段/约束属于跨实例一致的产品契约，保留在代码和迁移中，不放入 `.env`；否则不同实例可能以不同契约运行。这不属于部署参数硬编码。

## 7. 非功能边界

- MVP 配置基线：解析 30 秒、下载 30 分钟、时长 2 小时、最终文件 2 GiB、单 Worker 并发 2；实际值经上述环境变量提供并由 Settings 校验产品上限。
- 解析结果 15 分钟、文件 24 小时、终态任务墓碑 7 天；原始 URL 在任务终态后立即擦除。
- MVP 固定采用受控 Beta 发布方式和匿名会话；公网限流、带宽上限、使用条款与滥用响应均作为部署必备配置，不改变本架构选型。
- 不保证精确文件大小；上游未提供时返回 null。
- 上游站点变化通过依赖升级处理：固定 dated nightly 版本、自动更新 PR、受控站点烟测、禁止容器内 `-U`。

## 8. 演进与回滚

- 横向扩容只增加同版本 Worker；数据库状态与幂等约束保持不变。
- yt-dlp 升级必须独立提交并保留上一镜像；站点回归时回滚镜像，不回滚数据库。
- schema 只经 Alembic 前向迁移；应用回滚不得自动执行 destructive downgrade。
