# 025 微信视频号公开分享链接下载设计

- 状态：Implemented，真实运维会话 canary 待完成
- 日期：2026-08-27
- 对应调研：`docs/research/015-微信视频号公开分享链接服务端解析调研.md`
- 对应需求/计划/验收：`docs/prd/025-微信视频号公开分享链接下载需求.md`、`docs/plans/025-微信视频号公开分享链接下载计划.md`、`docs/acceptance/025-微信视频号公开分享链接下载验收.md`

## 1. 范围

本设计只增加公开微信视频号单作品分享链接下载。腾讯视频 VIP、微信私密/关注可见内容、直播、主页、批量归档和任何加密媒体都不在范围内。公众号文章 discovery 继续由 024 管理；文章中的视频号项仍需未来保存可验证的子来源 URL 后才能复用本 Provider。

支持的唯一输入形态：

```text
https://weixin.qq.com/sph/{4..256 位字母数字_-}
```

禁止 query、fragment、非默认端口和其他路径。已识别但无效的微信域名不能回退 Generic。

## 2. 架构

```text
用户 URL
  → URL Validator / wechat_channels Profile
  → 匿名 Runner：第一方预览页 + 空 generalToken 元数据检查
      ├─ 不公开/失效：provider_link_unavailable
      ├─ 已直接给出批准 clear URL：进入媒体检查
      └─ 仅公开元数据：credential_required
  → Router 选择 wechat_channels Operator Runner
  → 元宝 get_parse_result（Provider 专属 Cookie）
  → 校验 playable_url host/path/query
  → 视频号 get_feed_info(token, eid)
  → 保护材料递归扫描 + 腾讯媒体 host/path allowlist
  → 现有 inspect/FFprobe/语义格式
  → 下载前使用同一 Profile 重新解析
  → 完整下载、FFprobe、大小/时长和 Artifact 校验
```

匿名预检始终先于运维会话，防止 Operator Runner 被用于探测私密或不存在的作品。

## 3. Provider Profile

`wechat_channels` Profile 固定为：

- version：`wechat-channels-public-v1`
- status：`access_required`
- capability：`single_video`、`short_video`
- access mode：`anonymous`、`operator_managed`
- source host：仅 `weixin.qq.com`
- Cookie domain：仅 `yuanbao.tencent.com`
- canary suite：`wechat-channels-public-single-video`
- extractor：仓库可信插件 `WechatChannelsPublicIE`

状态保持 `access_required`，直到真实授权样本完成完整 canary；注册成功或 fixture 通过不自动提升为 `verified`。

## 4. 会话与 Secret

运维在已登录元宝的本机浏览器执行现有导出器。导出器必须同时找到 `hy_user` 与 `hy_token`，过滤其他域 Cookie，写入只读 Netscape Secret。部署配置示例：

```dotenv
RUNNER_OPERATOR_BASE_URLS={"wechat_channels":"http://wechat-channels-operator-runner:19100"}
WECHAT_CHANNELS_COOKIE_SECRET_DIR=./.provider-secrets/wechat_channels
WECHAT_CHANNELS_COOKIE_VERSION=browser-live
WECHAT_CHANNELS_OPERATOR_ACCOUNT_BASELINE_ATTESTED=true
```

`wechat-channels-operator-runner` 由独立 Compose Profile 启动且只挂载该
Provider Secret；不得挂载其他 Provider Secret。会话值、浏览器路径、解析 token
和媒体签名 URL 不写日志、数据库、MQ 或前端响应。

## 5. 提取流程

### 5.1 匿名公开性预检

1. 访问第一方 `finder-preview/pages/sph` 建立公开预览上下文；
2. 用 `shortUri` 和空 `generalToken` 调用 `get_feed_info`；
3. 必须得到成功响应和非空 `feedInfo`；
4. 立即扫描整个响应的保护字段；
5. 预检失败时禁止调用元宝接口。

### 5.2 元宝解析

1. Runner Cookie jar 必须同时含 `hy_user`、`hy_token`；
2. 调用元宝 `api/weixin/get_parse_result`，请求只包含类型、规范化公开 URL 和固定 scene；
3. 不发送硬编码的个人 conversation id、设备 id 或其他用户标识；
4. `playable_url` 必须为批准的视频号预览页，query 恰好为一个 `token` 和一个 `eid`；
5. 元宝错误或结构异常统一视为会话失效/上游变更。

### 5.3 媒体解析

带 `generalToken` 和 `exportId` 再次调用第一方 feed API，只读取 `h264VideoInfo.videoUrl`、`h265VideoInfo.videoUrl` 或受控顶层 `videoUrl`。媒体 URL 必须是 HTTPS、无非默认端口、主机精确为 `finder.video.qq.com`、路径匹配 `/251/.../stodownload`。

格式只声明当次响应真实提供的 H.264/H.265；不虚构清晰度、不承诺无水印。现有下载流水线负责大小、时长、完整文件、轨道与 FFprobe 复验。

## 6. 保护与权益门禁

响应任意层出现有效 `decodeKey`、`drm/has_drm`、`encrypted/encryption` 即返回 `drm_protected`。空字符串、`false`、`0` 可视为未声明，但仍必须通过 FFprobe。禁止：

- 使用 decodeKey、XOR/ISAAC64 或任何保护前缀转换；
- 请求密钥、license 或 App 缓存；
- 将会员/私密身份作为公开作品下载授权；
- 在失败时回退公共 Worker、第三方解析 API、MITM 或浏览器流量拦截。

运维会话只解决第一方匿名接口未返回媒体 URL的问题，不扩大内容可见性。匿名预检不通过的作品没有 operator fallback。

## 7. 稳定错误

| 条件 | 错误 |
| --- | --- |
| 非法路径/query/fragment | `provider_unsupported` |
| 公开预检失败、作品删除 | `provider_link_unavailable` |
| 未部署 operator endpoint/Secret | `provider_auth_required` |
| 元宝 Cookie 失效或 resolver 结构异常 | `provider_session_expired` |
| 保护字段有效 | `provider_drm_protected` |
| 非批准媒体域/路径、无格式 | `provider_link_unavailable` |
| FFprobe/完整性失败 | 现有 `provider_verification_failed`/`media_validation_failed` |

错误只暴露低基数 code，不包含 URL token、Cookie 或上游响应。

## 8. 测试与发布

单元测试覆盖严格 URL、Profile、Cookie 双字段、匿名优先、无会话、失效链接、恶意 playable URL、非腾讯 CDN、decodeKey/DRM 和插件注册。集成测试覆盖 Provider status 和 Inspection 路由。发布还需使用 `agent-browser` 验证桌面/移动 UI、控制台和真实服务错误文案。

能力发布必须同时满足：自动化全绿、Compose 配置校验、授权公开样本真实完整下载 canary、FFprobe clear、无 Secret 泄漏和运维停用演练。缺少真实会话时可合并代码，但状态保持 `access_required`，不得宣称生产下载已验证。
