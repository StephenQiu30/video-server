# 025 微信视频号公开分享链接下载设计

- 状态：Implemented，真实公开媒体 canary 待完成
- 日期：2026-08-29
- 对应需求/计划/验收：`docs/prd/025-微信视频号公开分享链接下载需求.md`、`docs/plans/025-微信视频号公开分享链接下载计划.md`、`docs/acceptance/025-微信视频号公开分享链接下载验收.md`

## 1. 产品边界

C 端服务必须在全新机器上通过 Docker 和显式服务配置运行，不能依赖开发者浏览器、
Keychain、Codex App Server 或某个平台账号。微信视频号当前只保留第一方匿名公开链路；
登录态只能在平台未来提供面向该资产的官方 OAuth/API 后以独立 Connector 接入。

## 2. 解析链路

```text
用户 /sph/ URL
  → 严格 URL normalizer
  → 匿名 Media Runner
  → 第一方预览页 + get_feed_info(shortUri, empty generalToken)
      ├─ 链接无效：provider_link_unavailable
      ├─ 仅元数据：content_entitlement_unknown
      ├─ 存在保护材料：provider_drm_protected
      └─ 直接 clear 媒体：格式和域名校验
  → 现有 inspect / download re-inspect / FFprobe / Artifact
  → 可持续 AI 分析
```

流程不调用元宝、不带 Cookie，也不在失败时回退到浏览器或第三方解析站。

## 3. Provider Profile

- version：`wechat-channels-public-v2`
- status：`degraded`
- capability：`single_video`、`short_video`
- access mode：仅 `anonymous`
- source host：仅 `weixin.qq.com`
- media host：仅 `finder.video.qq.com/251/.../stodownload`
- extractor：仓库可审计插件 `WechatChannelsPublicIE`

`degraded` 表示网络路径已实现，但只有当第一方公开响应实际提供 clear 媒体时才可下载；
它不表示对所有公开分享链接的覆盖承诺。

## 4. 安全与可扩展性

- 匿名 Runner 无 Provider Secret，可按无状态实例水平扩展。
- 不存在微信专用 Operator Runner、Chrome Profile、会话轮询或宿主机获取服务。
- 任意层出现 `decodeKey`、DRM、encrypted 或未知媒体域立即拒绝。
- 媒体 URL、上游响应和用户链接不进入日志或 Provider 状态证据。
- 平台无公开媒体时，统一引导用户上传自有/已授权 clear 文件，后续 AI 链路不受影响。

## 5. 发布门禁

至少一个项目自有或明确授权的真实公开样本完成 metadata、media Range、完整下载、
FFprobe、SHA-256 和 Artifact 验证后，才能考虑从 `degraded` 提升。缺少官方资产授权 API 时，
不得重新引入消费端 Cookie 作为发布回退。
