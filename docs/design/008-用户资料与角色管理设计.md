# 008 用户资料与角色管理设计

- 状态：Accepted
- 日期：2026-08-09

## 目标与边界

账户使用邮箱登录，注册时同时设置唯一用户名。用户可修改自己的用户名；邮箱暂不提供自助修改，避免引入邮件验证和账号接管风险。账户角色只有 `admin` 和 `user`，账号状态只有启用和停用。

生产环境通过根目录 `AUTH_BOOTSTRAP_ADMIN_EMAIL` 指定初始管理员邮箱。该邮箱注册时获得管理员角色，之后管理员可授予其他账号管理员角色。开发和测试环境未配置该值时，首个注册账号成为管理员。

## 权限模型

- JWT 只保存用户 ID，不保存角色或启用状态。
- 每个认证请求从 PostgreSQL 读取最新账户；停用和角色变更立即生效。
- 管理员接口同时经过 FastAPI 依赖和应用服务两层角色校验。
- 管理员不能降级或停用自己的账号；停用其他账号时撤销其全部 Refresh 会话。
- 普通用户只能读取和修改自己的公开资料，不能枚举其他用户。

## 接口与界面

- `PATCH /api/users/me`：修改当前用户名。
- `GET /api/admin/users`：按用户名/邮箱、角色和启用状态查询用户。
- `PATCH /api/admin/users/{user_id}`：修改角色或启用状态。
- 注册页增加用户名字段；个人资料页使用原生 `PageContainer + ProForm`。
- 用户管理页使用原生 `PageContainer + ProTable + ModalForm`，查询字段由 `ProColumns` 生成。
- 页面标题、面包屑、刷新和工具栏操作均使用 Ant Design Pro 原生布局能力。
