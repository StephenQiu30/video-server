# 004 下载历史设计

- 状态：Accepted
- 日期：2026-08-07
- DAC：DAC-004-01 ～ DAC-004-08

## 1. 目标与边界

为当前登录账户提供可分页、可筛选的下载历史。历史读取复用现有下载任务、媒体解析和格式记录，不新增重复业务表，不返回明文 URL、密钥、Provider hint 或对象存储凭据。

当前不包含历史删除、批量操作和重新创建下载任务。

## 2. 数据流与权限

```mermaid
flowchart LR
    B[Browser] -->|HttpOnly JWT cookies| API[GET /api/downloads/history]
    API -->|owner_hash predicate| DB[(PostgreSQL)]
    DB --> API
    API --> B
    B -->|open task / issue URL| API
```

API 使用用户 UUID 派生的稳定 `owner_hash` 过滤 `download_jobs`。历史查询不要求关联的 inspection 或 format 仍未过期；这些记录是任务创建时已经持久化的业务快照，解析资源过期只影响重新解析，不影响历史查看。

## 3. API 契约

`GET /api/downloads/history`

Query：

- `page`：从 1 开始，默认 1，最大 10,000。
- `page_size`：默认 20，范围 1–50。
- `status`：可选 `queued | running | retry_wait | succeeded | failed | cancelled`。
- `search`：可选标题关键词，最多 128 字符；服务端使用参数化模糊匹配。

响应：

```json
{
  "items": [{
    "id": "uuid",
    "title": "视频标题",
    "thumbnail_url": "data:image/...",
    "format_name": "1080p MP4",
    "status": "succeeded",
    "progress": 100,
    "error_code": null,
    "created_at": "2026-08-07T00:00:00Z",
    "updated_at": "2026-08-07T00:03:00Z",
    "finished_at": "2026-08-07T00:03:00Z"
  }],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "summary": {
    "total": 1,
    "succeeded": 1,
    "active": 0,
    "failed": 0
  }
}
```

`summary` 按当前账户和标题关键词统计，不受当前状态筛选影响；`active` 合并 queued、running、retry_wait。

## 4. 验收标准（DAC）

- DAC-004-01：只返回当前登录账户拥有的任务。
- DAC-004-02：默认按 `created_at DESC, id DESC` 稳定排序。
- DAC-004-03：分页、状态和标题筛选组合可用，并限制参数边界。
- DAC-004-04：返回标题、封面、格式、状态、进度和时间，不返回 URL、Provider hint、error_message 或 artifact 内部字段。
- DAC-004-05：inspection 已过期时，历史记录仍可读取。
- DAC-004-06：历史页支持空状态、加载失败、筛选无结果和窄屏布局。
- DAC-004-07：成功任务可打开任务页；任务页已有的短时下载地址流程继续承担文件获取。
- DAC-004-08：任务状态与历史列表来自同一 PostgreSQL 事实源，不能使用浏览器本地存储作为持久化替代。

## 5. 前端实现

历史页使用 Next.js App Router；Radix UI 提供可访问的筛选、菜单、提示与对话框原语，Tailwind CSS 负责响应式布局和状态样式。页面只调用 `@umijs/openapi` 生成的历史查询与任务服务，不复制响应类型，也不直接拼装 API 请求。

页面沿用 009 视觉系统的统一 1200px PageShell、蓝白无边框设计语言和内页标题规则：标题与摘要保持紧凑，不显示“任务记录”等装饰性彩色眉题；“新建下载”使用 Apple 蓝主按钮，刷新、标题搜索和状态筛选组成紧凑工具区。数据区以留白、对齐和浅色分隔线建立层级，不使用厚重表格外框或嵌套卡片。历史在桌面与窄屏均使用 Item/ItemGroup；桌面展开为包含封面、标题、格式、状态、进度和时间的宽行，窄屏重排为同字段的纵向记录，不能通过横向滚动隐藏核心操作。Table 只用于管理员桌面用户列表。

分页、筛选和搜索是受控页面状态，并映射到服务端 `page`、`page_size`、`status`、`search` 参数；刷新复用同一查询入口。加载、空历史、筛选无结果、失败重试和成功记录跳转均有独立可访问状态，状态文案与图标不能只依赖颜色区分。
