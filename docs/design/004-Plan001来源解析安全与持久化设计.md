# Plan 001 来源解析安全与持久化设计

## 1. 本地主体与跨仓边界

Plan 001 默认本地单用户：API 只监听 loopback，以安装时生成的 Bearer token 鉴权；token 映射到不可变 `installation_id`，业务表把该非秘密 ID 保存为 `owner_id`。安装器将 token 与 ID 分别写入 0600 secret；token 不进数据库、日志或 Git，轮换 token 不改变 owner。

配置分离为 `web_origin=http://127.0.0.1:3000`、`web_host=127.0.0.1:3000`、`api_authority=127.0.0.1:8000`。API 校验 authority、token、原始 Web Origin 与 Fetch Metadata；mutation 只接受同源 `application/json`，不启用 credentialed CORS。Server Plan 用独立 contract harness 模拟这些 header，不依赖 Web 实现；BFF 自身行为由 Web Plan 验收。

非 loopback 模式必须配置可验证 `PrincipalProvider`，否则拒绝启动。测试 Provider 创建两个主体，以统一 404 验证资源不可枚举。

## 2. 密钥材料

安装器另建两个独立 0600 secret：32-byte URL KEK keyring 与 32-byte idempotency HMAC key；两者都与 API token 分离并在重启后稳定加载。

URL 与内部格式计划使用 XChaCha20-Poly1305：每行随机 32-byte DEK 和 24-byte nonce，AAD 为 `table:id:owner_id:purpose:v1`；DEK 再由当前 KEK 以独立 nonce/AAD 包裹。行保存 cipher、nonce、wrapped DEK、wrap nonce、`key_id`。KEK 轮换只 rewrap DEK；旧 KEK 保留到所有行 rewrap 完成并通过解密审计。

`idempotency_key_digest` 与 `request_digest` 分别对原始 key、规范化请求做 HMAC-SHA-256。HMAC key 在 Plan 001 安装生命周期内稳定；轮换必须停写、等所有至少保留 24 小时的 idempotency 行到期清除，再更换，不能静默破坏重放语义。

## 3. 持久化模型

| 表 | 关键字段与约束 |
| --- | --- |
| `source_resolution_requests` | `id` PK、owner、`operation`、`idempotency_key_digest`、`request_digest`、`job_id` UNIQUE FK、URL envelope、attestation version/hash/locale/time、`detail_eligible_at/detail_must_purge_by`；UNIQUE(owner, operation, idempotency digest) |
| `rights_statement_catalog` | append-only `(version, locale)` PK、statement、hash、effective/expires/superseded 时点；同一 locale 同时最多一个 current 条目 |
| `source_policy_snapshots` | immutable payload PK、policy/revision UNIQUE、canonical payload hash、signer key、signature、name/official URL、adapter、精确 host/path、decision/permitted operations/user actions/detectors、egress hosts、ACL hash/cert serial、review/expiry |
| `source_policy_lifecycle` | snapshot PK/FK、state=`ACTIVE/REVOKING/REVOKED/EXPIRED`、version、activated/revoking/revoked 时点；唯一可变 policy lifecycle 行 |
| `policy_revocations` | policy/revision UNIQUE、reason、revoked_at、signer 与 signature；不删除历史 snapshot |
| `jobs` | PK、owner、type、status、stage、attempt、progress、error/correlation、时点；终态不可逆 |
| `job_steps` | UNIQUE(job, stage, attempt)、状态与时点 |
| `job_events` | 正数 `GENERATED ALWAYS` bigint identity、job FK、状态/阶段/progress/error；只追加；wire ID 转十进制 string |
| `outbox_messages` | UNIQUE(job, kind)、固定 kind、`job_id/resolution_request_id/owner_id` ID-only 列、claim/publish/attempt/dead-letter 与双保留截止时点；禁止任意 payload |
| `video_sources` | PK、owner、`resolution_request_id` UNIQUE FK（唯一权威关系）、远端 identity hash、标题、平台、时长、parser/policy revision、`expires_at` |
| `source_format_snapshots` | PK、source FK、opaque key UNIQUE、规格、加密内部计划、`expires_at` |
| `resolution_audits` | request/job PK、owner、terminal status/error code、policy revision、attestation version/hash、created/terminal/audit expiry；无 URL、标题、格式或 selector |

创建事务原子写 request、Job、初始 event 和 outbox。成功发布事务以 `video_sources.resolution_request_id` 为唯一权威边原子写唯一 Source/formats、Job `SUCCEEDED/READY` 与终态 event；Resolution 响应由该反向关系取得 `source_id`，request 表不保存第二条 FK。重复 worker 锁 Job 后 no-op。读取始终按 owner 过滤，Source 不跨 owner 复用。

Plan 001 的创建 writer 不接受外部 `operation`，固定写 `probe`；初始 outbox kind 固定为 `SOURCE_RESOLUTION_REQUESTED`。Job、Resolution 等 wire ID 使用带资源前缀、无冒号的稳定 ASCII opaque ID，数据库同时按前缀和安全 alphabet 拒绝可能破坏 envelope AAD framing 的值。URL AAD 固定为 `source_resolution_requests:{resolution_id}:{owner_id}:url:v1`，request 的 ID、owner 与五个 envelope 字段在创建后不可变。

`policy_snapshot_id` 只能在 `source_policy_snapshots` migration 同时建立真实 FK 时加入；在此之前 request 表不保存可伪造的 policy 占位列。加入后初始创建必须为 NULL，resolver 只有在签名 snapshot 与 ACTIVE lifecycle 复核成功后才能绑定。幂等 advisory lock 的线性化点先于 rights 校验：已存在且摘要一致直接 replay，摘要不同直接 conflict；仅不存在时才以与 catalog importer 相同的 locale lock 复核 current rights、生成 attestation 并加密 URL。

每个已提交 Job 快照必须在同一事务拥有唯一匹配 event；event ID 由数据库 `GENERATED ALWAYS`，调用方不可插入负数、乱序或自选 cursor。event 禁止 UPDATE/TRUNCATE；DELETE 只在同一事务删除其完整 aggregate、提交时 parent Job 已不存在的 sweeper 路径允许。后续加入 `policy_snapshot_id` 的 migration 必须原子替换 0002 的 request rewrap trigger，不能先留下无 FK 或不可绑定的中间状态。

## 4. 权利声明与保留期

请求携带 `rights_confirmed=true`、`rights_statement_version` 与 locale；server 按 `schemas/rights-statement-catalog.schema.json` 从 `config/rights-statements.json` 初始化 append-only catalog，按精确 UTF-8 字节验证 SHA-256，并保存 version/hash/locale/time。创建事务再次锁定并验证该条目是 locale 的 current、已生效且未过期版本；false 返回 422，未知、locale 不匹配或已 superseded 的已知版本返回 409，均不创建 Job。文案升级只新增版本并原子 supersede 旧版本；历史条目只供审计还原。

格式的持久化 `expires_at = min(resolved_at + 15m, policy.expires_at)`；GET Source 还必须动态联查 policy 状态，`REVOKING/REVOKED/EXPIRED` 时立即返回 410 并拒绝旧 format key，因此不假设未来 `revoked_at` 已知。

所有保留期从 request `created_at` 计算绝对截止。request（含 URL envelope）、Source、formats、Job、steps、events 以及未发布/dead-letter outbox 的 `eligible_at=created_at+6d22h`、`must_purge_by=created_at+7d`；成功 published outbox 为 `published_at+22h/+24h`。清理明细前 upsert `resolution_audits`，其 `eligible_at=created_at+29d22h`、`must_purge_by=created_at+30d`。sweeper 每小时运行，失败每 5 分钟重试；到 eligible 未清即告警，任何行越过 must-purge deadline 都使隐私健康检查失败。FK 删除顺序和 partition/drop 必须保证 audit 不携带 URL、标题、格式、selector 或密文。

## 5. 签名 policy dossier

Artifact 的完整字段、类型与附加属性禁令由已冻结的 `schemas/source-policy-dossier.schema.json` 定义；payload 使用 RFC 8785 JCS canonicalization，Ed25519 signature 只覆盖 canonical payload。`decision=allow` 还必须列出 `permitted_operations`；Plan 001 只消费 `probe`，绝不把它解释为 `download`。安装 trust store 每个 key 保存公钥、状态、`signer_kind`、允许的 decision/adapter/operation、exact origin/path scope 与有效期；本地 reviewer 私钥仅在 0600 secret。新公钥必须先离线加入 trust 并审计，旧 key 只能在其 active dossier 全部撤销/过期后移除。

operator key 的 trust grant 必须绑定 exact origin/path 和 origin-control proof：CLI 生成一次性 nonce，操作者在该 origin 的 `/.well-known/video-workbench-policy.json` 发布 `{origin,key_id,nonce}`；验证器经仅允许该 exact host 的 bootstrap proxy、禁止 redirect 地读取，保存响应 SHA-256、verified_at 与不超过 30 天的 expires_at。proof 到期或 dossier 超出 grant 一律拒绝。CLI 提供 `policy authorize-origin/sign/import/revoke/list`；import 校验 schema、签名、trust grant、proof、expiry≤30天、精确 host/path 和官方依据，snapshot append-only，新 revision 新增行。

scope 是授权边界：import 使用 IDNA2008 A-label 小写 host，移除尾点与显式 `:443`；只接受无 userinfo/query/fragment 的 HTTPS 默认端口公开 origin。path 先拒绝 encoded slash/backslash、NUL、非法 UTF-8 与 dot segment，再仅解码 unreserved 字符并用大写 percent-hex 重编码。`exact` 按 canonical path 字节相等；`prefix` 必须以 `/` 结尾并按目录前缀匹配。每次 redirect 都重新执行 canonicalization、scope、DNS 与 ACL，不能以字符串 `startsWith` 授权 `/allowedness`。

Plan 001 支持两类生产 dossier：项目签名的公开 canary；持有效 origin-control grant 的安装 reviewer 为 exact origin/path 签名的 operator dossier。首个项目 canary 固定为 W3C HTML5 测试媒体 `https://media.w3.org/2010/05/sintel/trailer.mp4`，依据为 W3C 公开测试页面/邮件；只允许 metadata probe，不预先授权后续下载。operator 正向发布门禁使用 Acceptance 的 `CANARY-OPERATOR-OWNED-1`，缺少真实 origin-control 证明时保持 blocked，不能改用自签占位。

未知、过期、撤销、签名无效、`decision=block`、不含 `probe`、已知禁止或 YouTube dossier 在 extractor 前失败。Plan 001 即使看到 `download` 也只授权 probe；任一 auth-required、download-disabled 或 DRM/加密信号使整个 Resolution 失败，不发布 Source/format。

## 6. Dossier → Smokescreen 强制

Smokescreen ACL 是静态 client-role 配置，不读取数据库。每个 policy revision 对应独立 mTLS role/cert 与 exact-host ACL。`policy import` 先生成 ACL/证书并 reload proxy、验证 `acl_hash`，成功后才在 DB 激活 snapshot；worker 按 snapshot 使用对应 cert。

policy payload/snapshot 永不更新；revoke 先以 lifecycle version CAS 原子把独立 `source_policy_lifecycle` 行置为 `REVOKING`，从该提交点拒绝新 Job、GET Source 立即 410、发布事务的条件更新失败，并把在途 Job 收敛为 FAILED `SOURCE_POLICY_BLOCKED`；再更新 CRL/移除 role并 reload，最后把 lifecycle 置 `REVOKED`。expiry 使用同一 deny-new/publish 守卫。worker 在开始、每次 redirect 和发布事务内复核 ACTIVE lifecycle、cert serial 与 ACL hash；任一不匹配 fail closed。并发 submit/publish/revoke 的线性化点与负向竞态必须测试。

worker 无直接外网路由，只能连接 PostgreSQL、Redis 与 proxy。proxy 除指定 DNS 外只允许 outbound TCP 80/443；Smokescreen 在连接时校验所有 A/AAAA 为公网地址并执行 role hostname ACL。绕 proxy、危险端口、协议降级、userinfo、IPv4-mapped IPv6、redirect/rebinding 和 revoked role 都必须失败。

## 7. 格式归一化

任一 DRM 信号整项失败；之后丢弃 storyboard/image/live/无视频项。codec 先按小写前缀规范化：`avc1/h264→h264`、`hev1/hvc1/hevc→hevc`、`vp09/vp9→vp9`、`av01/av1→av1`、`mp4a/aac→aac`、`opus→opus`、`vorbis→vorbis`，未知保留 `other:<原值小写>`。progressive 独立成候选；video-only 只配一个兼容 audio-only：先精确匹配请求 locale 主语言，再无语言标记，再 `en`，再按 `(abr desc, channels desc, normalized codec, upstream format_id)` 取首个。MP4 family=`mp4,m4v,mov` + `m4a,aac`，WebM family=`webm` + `webm,weba,opus,vorbis`；无兼容音频则丢弃。

以宽高/FPS/dynamic range/video codec family/audio codec family/container/merge 去重，同组依次保留精确大小、总码率最高、上游 video format_id 字节序最小、audio format_id 字节序最小者。大小依次取 filesize、组件和、filesize_approx、`duration×bitrate/8`。

推荐分数依次比较 progressive、MP4、H.264、AAC、最高且不超过 1080p（无则最低超出）、最高且不超过 60fps、已知大小，完全相等时按 canonical candidate fingerprint SHA-256 升序；仅第一项 `recommended=true`。列表排序为推荐优先，再 height/FPS 降序（null 最后）、progressive、容器 `mp4→webm→other`、大小升序，最后按同一 fingerprint 升序。

fingerprint 是以下 exact object 的 RFC 8785 JCS bytes 做 SHA-256：`audio_codec/audio_format_id/container/dynamic_range/estimated_bytes/fps/has_audio/has_video/height/requires_merge/size_is_estimate/video_codec/video_format_id/width`；未知值为 null。progressive 取 `video_format_id=<其 upstream format_id>`、`audio_format_id=""`；merge 分别取 video/audio component ID；任何缺失 ID 都取 `""`。fingerprint 只用于确定性排序且不出 API。label 在 height 为 null 时从 `原始` 开始，否则从 `{height}p` 开始；FPS 非 null 且不等于 30 时追加 `{fps:g}fps`，dynamic range 非 null 且不等于 `SDR` 时追加其大写值，随后总是追加大写 container，merge 时最后追加“需合并”，各段用 ` · ` 连接。

`format_key` 只在快照内稳定，跨快照随机。API 布尔不可空，其余未知为 null。

## 8. Outbox、重试与 SSE

dispatcher 用 `FOR UPDATE SKIP LOCKED` 原子写 `claimed_by/claimed_at/lease_expires_at` 后提交，再发布；lease 固定 60 秒并每 20 秒续租。claim 后 publish 前崩溃由其他 dispatcher 在 lease 到期后 reclaim；旧 claimant 以 compare-and-set token 不能完成新 lease。发布失败最多 10 次、1–30 秒 jitter 退避。耗尽后 outbox 标记 dead-letter，并以 `QUEUE_DELIVERY_FAILED` 原子终止 Job。发布后崩溃允许重复，worker 幂等收敛。

resolver 最多 3 次；timeout、429、5xx 重试，policy/auth/DRM/disabled/unsupported 不重试。DNS 5 秒、connect 10 秒、read 30 秒、总计 60 秒。

SSE 先订阅、再 DB 回放、之后 wake 或每 2 秒 tail，15 秒 heartbeat。丢 wake/Redis 重启不丢终态；wire cursor 为十进制 string。
