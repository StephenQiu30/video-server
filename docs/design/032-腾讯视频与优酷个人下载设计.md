# 032 腾讯视频与优酷个人下载设计

状态：受控路径已实现，真实账号的完整 VIP 下载待验证。个人部署，不增加基础服务。

## 接入与恢复

复用固定版本 yt-dlp 的 VQQVideoIE、YoukuIE，通过仓库插件扩展；不接入 Lux、浏览器流量拦截器或外部解析服务。使用现有任务队列、语义计划、Worker 重解析、FFmpeg 合流和 Artifact 下载入口。两个 Provider 的 profile 升级为 `qqvideo-personal-v1`、`youku-personal-v1`，旧验证记录不能当作本版本成功证据。

腾讯允许单视频 `/x/page/{vid}.html`、`/x/cover/{cid}/{vid}.html`，与优酷一样提供匿名普通视频入口；配置 `RUNNER_OPERATOR_BASE_URLS` 后优先使用对应个人会话。均不自动切账号或在受控失败时降级匿名。

新增两个生产 Compose 可选 profile。会话使用 031 的单平台只读文件、tmpfs 临时副本、稳定 HMAC 版本和轮换隔离；不进入桌面代理的平台枚举。只克隆 Git 不含账号状态；容器重启复用文件，账号过期需要更新文件，不需修改解析器。

## 原始响应与文件校验

- 优酷：提供会话 cna 时复用它作为 UPS utid，避免请求身份与持久会话分离。在 UPS 原始 JSON 归一化之前检查 video.seconds 和 stream.segs。缺失 cdn_url 的质量档被排除；所有质量档不完整则返回 content_preview_only，结构不认识则返回 content_access_metadata_invalid。若返回 milliseconds_video，则与原视频总时长比对。解析 HLS manifest 识别 DRM，排除受保护格式。保留原始总时长，最终 ffprobe 验证实际文件。
- 腾讯：从页面 `__STARTUP_CONFIG__` 读取协议版本，通过仅允许 `vd6.l.qq.com` / `vd.l.qq.com` 的 vinfo_proxy 获取 videoInfo；校验 vid/cid 和原始完整时长。忽略 proxyhttp 的加密响应封装，继续从上游播放接口解析格式。逐响应验证 vl.vi 的 vid/td；preview 是时长字段，非零时需与完整时长一致，不能简单当作布尔试看标记。优先复用播放接口内联 m3u8，核对结束标记和分段总时长；清单留在 Runner 的临时 info JSON 中供原生 HLS 下载器使用。没有内联清单时每种画质最多尝试四个 CDN，取得首个可用清晰流后停止重复探测。清晰 TS 使用 8 KiB Range 前缀在本地识别编码，不能覆盖原始总时长；含密钥、初始化段或字节区间的清单不走前缀探测。腾讯设置 10 秒 socket 超时、最多 4 个并发分段。个人会话线路也允许已签名清晰分段的前缀探测，账号 Cookie 不传给 CDN。这些设置不代表可以消除平台限速；本地匿名样本仍约 1 KB/s，完整下载未通过。账号字段只在 yt-dlp 子进程中转换为固定腾讯 API 的 logintoken，不传入命令行、CDN 请求或业务元数据。继续使用锁定的上游解析逻辑，不新增内容密钥提取或 DRM 解密。
- 仅两个 Provider 的 operator 模式在适配器完整性标记存在时允许会员内容；private、requires_purchase、preview、DRM 仍拒绝。标记代表解析与完整性检查，不代表官方文件导出授权；API 不把这类结果标成 public_free 或 official_download_grant。
- 补充格式的远程探测/本地样本探测不能覆盖完整视频时长。下载后继续校验音视频轨、容器、尺寸、编码和时长，容差沿用现有 max(3 秒, 2%) 默认规则。

## 已知限制

这是依赖平台当前响应的实验接入，不承诺全部 VIP、SVIP、超前点播或画质可用，也不提供账号自动续期。用户提供的腾讯样本目前匿名可取得完整时长与格式；优酷固定公开样本也已通过 Runner 解析。普通样本不能替代 VIP 验收，实际下载结果见验收文档。本批不会自动修改已有部署环境或重启业务容器。
