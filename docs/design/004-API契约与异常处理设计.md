## 1. REST API

| 方法与路径 | operation ID | 输入 | 输出 | HTTP |
| --- | --- | --- | --- | --- |
| `POST /api/v1/media/inspect` | `inspectMedia` | `InspectMediaRequest` | `InspectedMedia` | 200 |
| `POST /api/v1/downloads` | `createDownload` | `CreateDownloadRequest` | `DownloadJob` | 202/200 幂等重放 |
| `GET /api/v1/downloads/{job_id}` | `getDownload` | path | `DownloadJob` | 200 |
| `POST /api/v1/downloads/{job_id}/download-url` | `createDownloadUrl` | path | `DownloadUrl` | 200 |
| `GET /health/live` | `getLiveness` | 无 | `Health` | 200 |
| `GET /health/ready` | `getReadiness` | 无 | `Health` | 200/503 |

不提供列表、删除、取消、重试、字幕、播放列表、站点配置、用户或管理 API。固定提供 `/docs` Swagger UI 和 `/redoc` 供人工审阅/试调，固定提供 `/openapi.json` 作为机器可读契约；代码生成不得读取文档页面 HTML。

## 2. 核心模型

- `InspectMediaRequest`：只有 `url`。
- `InspectedMedia`：`id/title/platform/thumbnail_url/duration_seconds/expires_at/formats[]`。
- `MediaFormat`：只含标准化展示字段和内部 UUID `id`，不含 provider IDs。
- `CreateDownloadRequest`：`source_id/format_id/client_request_id`。
- `DownloadJob`：`id/status/stage/progress_percent/downloaded_bytes/total_bytes/error/artifact/created_at/updated_at`。
- `ArtifactSummary`：`file_name/content_type/size_bytes/sha256/expires_at`，不含 object key。
- `DownloadUrl`：`url/expires_at/file_name`，URL 默认 15 分钟有效且不超过 artifact 期限。

成功响应直接返回资源 JSON，不再包装自定义 `code/message/data`。时间统一 ISO 8601 UTC；字段使用 snake_case；未知字段不作为客户端契约。

## 3. 匿名会话与授权

首次 inspect 时服务端创建或复用 256-bit 随机 `video_session` Cookie：HttpOnly、Secure、SameSite=Lax、Path=/、有效期 24 小时。数据库只存 token SHA-256。

source、format、job 查询和 download URL 签发都必须匹配当前 Cookie；不因 UUID 难猜而省略授权。Cookie 不进入 URL、日志或响应体。MVP 只支持同站 Web，生产 CORS 不允许通配 Origin。

POST 依赖 SameSite Cookie 与严格 Origin 校验防 CSRF。`client_request_id` 只处理同一会话重复提交；相同键不同 payload 返回 409。

## 4. 标准错误

错误使用 `application/problem+json`：

```json
{
  "type": "https://video.example/problems/video-unsupported",
  "title": "暂不支持该视频来源",
  "status": 422,
  "detail": "请更换公开的单视频链接",
  "code": "VIDEO_UNSUPPORTED"
}
```

固定业务码：`URL_INVALID`、`URL_FORBIDDEN`、`VIDEO_UNSUPPORTED`、`VIDEO_DRM_PROTECTED`、`VIDEO_AUTH_REQUIRED`、`VIDEO_PARSE_FAILED`、`INSPECTION_EXPIRED`、`FORMAT_UNAVAILABLE`、`DOWNLOAD_FAILED`、`MEDIA_MERGE_FAILED`、`STORAGE_FAILED`、`QUEUE_PUBLISH_FAILED`、`RESOURCE_LIMIT_EXCEEDED`、`JOB_NOT_READY`、`JOB_EXPIRED`。

- 400：语义参数；403：会话不匹配/地址禁止；404：资源不存在；409：状态或幂等冲突。
- 410：已过期；422：可解析请求但不支持的媒体；429：限流；500：未知错误；503：依赖未就绪。
- 响应不得泄露 URL query、provider 响应、selector、堆栈、SQL、MinIO key、文件路径或密钥。

## 5. OpenAPI 与前端生成

每个 operation 固定 operation ID、tag、请求/响应模型、HTTP 状态和 Problem 示例。`/docs` 仅服务人工阅读；`/openapi.json` 是 video-web 请求类型与 Service 的唯一来源。前端固定使用 Ant Design Pro 的 `@umijs/max-plugin-openapi`，以 `npm run openapi`（`max openapi`）生成 `src/services/video/`，不得手写第二份 API、DTO 或 URL。

破坏性字段、路径、状态或错误变化必须先更新本 Design，再在同一变更中重新生成前端并让契约检查失败；不通过兼容字段或 `any` 隐藏变化。相同服务端版本连续导出 OpenAPI、相同前端版本连续生成 Service 都必须零 diff。

## 6. 健康与可观测性

- liveness 只证明 API 进程可响应，不访问外部依赖。
- readiness 检查 PostgreSQL、RabbitMQ 和 MinIO；任一不可用返回 503。
- 日志结构化记录 request ID、job ID、source host、状态和安全错误码；不记录原始 URL、Cookie、预签名 URL或标题。
- 公网入口按 IP 限制 inspect/download 创建频率；API 根据数据库 running/queued 总量执行全局过载保护。

## 7. Design Acceptance Criteria

| 编号 | 必须证明 | 实现后证据 |
| --- | --- | --- |
| `S004-DAC-01` | 4 个业务接口和 2 个健康接口的方法、路径、模型、状态与 operation ID 完全一致 | 实际 OpenAPI snapshot 与契约测试 |
| `S004-DAC-02` | 所有资源响应无自定义 envelope，所有错误符合 Problem Details 和真实 HTTP 状态 | 成功/错误响应矩阵 |
| `S004-DAC-03` | 匿名 Cookie 能恢复自己任务，跨会话无法查询或签发 URL | Cookie/CSRF/越权集成测试 |
| `S004-DAC-04` | 重复 client_request_id 不重复创建任务，冲突 payload 返回 409 | 幂等并发测试 |
| `S004-DAC-05` | `/docs` Swagger UI 可人工审阅，`/openapi.json` 可由 `npm run openapi` 重复生成 Web Service，前后端无第二份 API/DTO/路径 | 文档与 schema 可用性、生成前后 diff、源码扫描与 Web 类型检查 |
| `S004-DAC-06` | PostgreSQL/RabbitMQ/MinIO 任一故障时 readiness 与业务错误准确，liveness 保持独立 | 逐依赖停启记录 |
| `S004-DAC-07` | 日志与响应不泄露 URL query、Cookie、预签名 URL、selector、key 或路径 | 故障注入与日志/响应扫描 |
