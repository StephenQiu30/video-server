## 2. DTO 与 VO

- Request DTO：Pydantic 输入模型，只负责 API 边界校验。
- Response VO：Pydantic 输出模型，只包含 Web 需要的数据。
- Entity：SQLAlchemy 持久化模型，禁止直接返回。
- Service：接收 DTO 或显式参数并返回 VO 所需结果，不传播无类型 `dict`。

关键字段：

- Inspect Request 只有 `url`；Inspect VO 含 source、标题、平台、缩略图、时长、过期时间和 formats。
- 创建下载只提交 `source_id + format_id`；Job VO 含 ID、status、stage、progress、错误、结果和过期时间。
- Download URL VO 含 URL、文件名和 URL 过期时间。
- AI Request 可选 `output_language`；Analysis VO 只返回语言、摘要、要点和章节。

## 3. 统一响应

所有业务 JSON 成功响应：

```json
{"code":"SUCCESS","message":"success","data":{}}
```

错误响应：

```json
{"code":"VIDEO_PARSE_FAILED","message":"无法解析该视频链接","data":null}
```

保持真实 HTTP 状态：200/201/202 成功，400 业务参数，404 不存在，409 状态冲突，422 DTO 校验，429 限流，500 内部错误，503 依赖未就绪。禁止所有响应均返回 HTTP 200。

MinIO 文件、Swagger、OpenAPI 和 ReDoc 不使用业务包装；预签名 URL 接口仍使用统一响应。

## 4. 全局异常

全局处理：

- `RequestValidationError → VALIDATION_ERROR / 422`。
- 业务异常 → 对应业务 code 与 4xx。
- Starlette/FastAPI HTTP 异常 → 保留 HTTP 状态并统一结构。
- 数据库、Broker、MinIO 等依赖异常 → 安全业务错误或 503。
- 未知异常 → `INTERNAL_ERROR / 500`。

未知异常记录服务端堆栈，但响应不得泄露原始 URL 参数、文件路径、SQL、外部响应或密钥。Celery 异常写入任务记录，由查询 API 以相同错误契约返回。

## 5. Swagger 与前端生成

固定提供 `/docs`、`/openapi.json`、`/redoc`。每个接口声明 tags、稳定 operation ID、DTO、VO、成功状态和错误示例。

OpenAPI 是 `video-web` 服务生成的唯一契约来源。破坏性字段、状态或路径变更必须先更新相关 Design，再重新生成 Web Service；不得维护第二份手写 TypeScript DTO。

## 6. 健康检查

- Liveness 只验证 API 进程可响应。
- Readiness 验证 PostgreSQL、RabbitMQ 和 MinIO。
- 健康接口不执行 yt-dlp、FFmpeg、Whisper 或模型调用。

| 编号 | 必须证明 | 验证与证据 |
