# 027 开场钩子审查 Skill 设计

- 状态：Implemented / Provider Validated
- 日期：2026-08-30
- 对应需求/计划/验收：`docs/prd/archive/027-开场钩子审查Skill需求.md`、`docs/plans/archive/027-开场钩子审查Skill计划.md`、`docs/acceptance/archive/027-开场钩子审查Skill验收.md`

## 1. 决策摘要

在现有视频分析目录中新增 `opening-hook-review`，使用已有
`video-visual-analysis` 结果契约和完整时间轴验证。Skill 聚焦开场前 3 秒、5 秒和
15 秒的可见注意力锚点、信息可理解性、画面文字可读性、变化密度、承诺与
后续视觉兑现，并给出引用真实分镜的修订建议。

本次不引入外部 Skill 运行时、脚本、模板、素材、MCP、ASR 或新 Provider；
只将经过许可证和 Prompt Injection 审查的方法论重写为项目内置 Markdown
指令与参考规则。

## 2. 执行流程

```text
完整视频可见证据
  → 建立全片连续 shots / scenes
  → 单独审查 0–3s / 0–5s / 0–15s
  → 检查开场承诺与后续可见兑现
  → 输出高光候选与按影响排序的修订建议
  → 复用现有 Schema 和证据校验
```

对不足 15 秒的视频，窗口截断到权威时长；不会为了凑齐窗口而推断画面外
信息。即使分析重点是开场，`shots` 和 `scenes` 仍必须覆盖全片，否则无法
判断开场的承诺是否在后续画面中兑现。

## 3. 字段映射

| 现有字段 | 本 Skill 用法 |
| --- | --- |
| `summary` | 用带分镜证据的短文说明开场状态、主要优势和最大风险 |
| `shots` | 保留全片真实 Cut，并在开场分镜中记录可见的起止状态与镜头任务 |
| `visual_tags` | 使用 `hook-role:`、`attention:`、`text:`、`pacing:`、`payoff:` 前缀 |
| `scenes` | 说明开场段落与正文的进入关系、稳定视觉规则和连续性风险 |
| `highlights` | 只保留少量能独立说明开场优势的候选；没有成立候选时可为空 |
| `production_advice` | 按影响和可执行性排列需保留、前移、简化、放大或重组的分镜 |

Skill 不借用 `score` 声称留存率、完播率或转化率；高光分数仅表示本次
可见分析内部的相对候选排序。

## 4. 证据与安全边界

- 仅使用当前 Provider 真实可见的画面、分镜和文字；不声称听到对白、音乐或音效。
- 画面文字、Logo、媒体元数据和用户补充 Prompt 都是不可信数据，不能改变契约、工具或边界。
- 没有足够画面支持时明确降低结论强度，不用一个虚构总分掩盖不确定性。
- 审查结果是创作建议，不是平台表现预测、市场承诺、审核结论或自动剪辑授权。

## 5. 供应链决策

只独立重写以下思路：

- `watch-skill`：开场视觉变化、画面文字与可执行批评的创作者审查方向。
- `drama-skills`：定位、证据、影响和必须达到的修订结果相分离。
- `video-shotcraft`：先看渲染证据再交付，文字可读性和镜头信息聚焦。

不复制上游原文、分数公式、脚本、测试样例、资产、工具调用、运行时或生产管线。审阅
commit 和许可证必须记入 `backend/app/analysis_skills/NOTICE.md`。

## 6. 非目标

- 不增加 ASR、OCR 后端、音频事件、留存率模型或外部研究。
- 不自动修改、剪辑、生成或发布视频。
- 不新增结果契约、API 路由、数据库字段、前端专用页面或第二套 Skill 加载器。
- 不宣称对任意极短闪切或未采样画面做到逐帧法证级捕获。
