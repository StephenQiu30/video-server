# 008 用户资料与角色管理设计

- 状态：Accepted
- 日期：2026-08-09

## 目标与边界

账户使用邮箱登录，注册时同时设置唯一用户名。用户可修改自己的用户名；邮箱暂不提供自助修改，避免引入邮件验证和账号接管风险。账户角色只有 `admin` 和 `user`，账号状态只有启用和停用。

生产环境通过根目录 `AUTH_BOOTSTRAP_ADMIN_EMAIL` 指定初始管理员邮箱。该邮箱注册时获得管理员角色，之后管理员可授予其他账号管理员角色。开发和测试环境未配置该值时，首个注册账号成为管理员。

## 权限模型

- JWT 只保存用户 ID，不保存角色或启用状态。
- 每个认证请求从 PostgreSQL 读取最新账户；停用和角色变更立即生效。
- 管理员接口同时经过 FastAPI 依赖和应用服务两层角色校验。
- 管理员不能降级或停用自己的账号；停用其他账号时撤销其全部 Refresh 会话。
- 普通用户只能读取和修改自己的公开资料，不能枚举其他用户。

## 接口与界面

- `PATCH /api/users/me`：修改当前用户名。
- `GET /api/admin/users`：按用户名/邮箱、角色和启用状态查询用户。
- `PATCH /api/admin/users/{user_id}`：修改角色或启用状态。
- 注册页增加用户名字段；登录、注册和个人资料使用 Next.js App Router 页面、语义化表单、Radix UI 的 Label 等可访问原语与 Tailwind CSS 状态样式。
- 用户管理页使用语义化桌面表格和窄屏记录列表；搜索、角色/状态筛选以及角色调整/停用确认分别由 Radix UI 的 Select、Dialog、Dropdown Menu 等原语组合，危险操作必须明确说明影响并要求确认。
- 认证、资料和管理员请求只调用 `@umijs/openapi` 生成的服务与类型，统一请求层负责凭据携带、Refresh 轮换后的重试和未认证跳转；页面不保存角色真值，也不维护平行 DTO。
- 页面采用 009 的方案 3/Vercel Home 无边框语言：`#FAFAFA` 画布、Geist、近黑前景/主操作、72px 无边框 Header、导航/主体统一的 1376px 隐形网格和 80/32/16px 响应式 gutter。标题、导航账户菜单、刷新与工具栏使用响应式 Geist 层级、无边框填充控件和 Phosphor 图标，页内不显示 PageShell/Card 外壳、装饰 ring 或阴影，只在数据分组需要时使用 1px 发丝 Separator。Dialog、Dropdown Menu、Select 和移动 Sheet 继续保留 Radix 的表面、遮罩、焦点圈定、Escape 关闭和触发器焦点恢复。
- 所有表单错误、启用状态、角色变化和异步结果都有文本反馈、键盘焦点和窄屏布局；前端权限控制只改善交互，不能替代服务端授权。
