## 1. 产品目标与不可破坏的规则

用户提交的工作、已经看见的数据和已经确认的身份，不应因短暂网络异常或页面切换消失。

1. 连接不可用不能被转换为未登录；服务端明确拒绝应用会话才进入重新登录流程。
2. 每种状态只有一个所有者。组件观察状态，不各自推断全局身份、重试与路由。
3. 后台刷新不清空已成功展示的数据；导航不重新初始化应用身份与数据缓存。
4. 任务由服务端持久状态驱动。切页、断开 WebSocket、浏览器关闭均不取消任务。
5. 身份失效必须隐藏私有数据并中止后续操作；保留 UI 不代表放松服务端授权。
6. 第三方平台 Cookie 失效只影响对应平台和任务，不影响帧取登录。
7. 重试必须有明确的责任层、预算和幂等条件；不把无限重试当作恢复。
8. 改造完成的业务路径删除原状态与执行分支，不长期同时维护两套 Web 会话或请求流程。

## 3. 核心架构决策

### 3.1 Web 采用服务端持久会话

建议目标：Web 使用一个无业务含义的随机 HttpOnly 会话 Cookie，FastAPI 在 PostgreSQL 验证其摘要与用户状态。浏览器不再承担 access/refresh 轮换。

| 路线 | 能否实现正确恢复 | 本项目代价与取舍 |
| --- | --- | --- |
| 保留双JWT并重写刷新协调 | 可以；JWT本身不是故障根因 | 必须定义并发轮换、丢失刷新响应、跨标签页同步、凭据代际和重放协议 |
| 服务端持久会话 | 可以；同时移除Web刷新轮换这一类竞态 | 增加会话查询/活动时间维护，承担一次明确的Web重新登录切换 |

选择第二条是基于当前同源 Web、既有 PostgreSQL、每次认证已经查询用户状态和可撤销会话需求。不是因为更换凭据格式能单独解决闪屏。页面状态与请求职责必须一起调整。

- Next.js 负责页面、同源代理与首屏组合，不成为第二个身份签发者。
- FastAPI 唯一签发、验证和撤销 Web 会话。
- PostgreSQL 唯一保存 Web 会话事实；首版不设 Redis 会话镜像或SQL/Redis逐级回退。
- 新增 Web 专属会话实体，按现有 models/services/repositories 目录实现；不复用旧原生刷新记录的不同语义。
- 原生 App 现有 Bearer 协议是独立客户端契约，本轮不改其产品流程；共享依赖必须明确按凭据类型分派，Bearer 失败不得改用 Cookie，Web 失败不得回退旧JWT。
- 原生协议现有存储问题单独登记，不把保留 App 契约当作保留两套 Web 实现的理由。

### 3.2 一个应用会话所有者，一个服务器数据缓存

- 应用级 SessionProvider 持有已确认身份、会话检查结果和客户端身份代际。
- 它不发放权限、不保存原始凭据；身份只来自同源后端。
- HTTP 请求层只处理传输、取消和标准错误，移除业务导航与隐式认证刷新。
- ProtectedRoute 只按统一会话状态决定能否展示；不独立请求用户、不做独立恢复。
- 服务器业务数据采用 TanStack Query 管理，替换各页面重复的请求生命周期；不再额外自建通用缓存框架。
- 当前身份不同时复制到 Query、Context、localStorage 三处。SessionProvider 是前端唯一身份投影，Query 只持有业务数据。
- 路由、表单草稿、服务端任务分别有自己的生命周期，不放进一个万能全局Store。

### 3.3 所有者与边界

| 状态 | 权威来源/所有者 | 其他组件允许做什么 |
| --- | --- | --- |
| 应用会话有效性、角色、禁用 | FastAPI + PostgreSQL | 浏览器读取结论；请求必须再次经过服务端授权 |
| 浏览器中的身份投影与代际 | SessionProvider | 页头、路由、查询读取；登录/退出通过其用例提交 |
| 网络与API可达性 | 请求结果的连接状态投影 | 展示连接反馈；不推断用户退出 |
| 历史、文档、平台、任务快照 | 服务端资源 + Query缓存 | 页面订阅；事件驱动定向失效/更新 |
| 分页、筛选、当前资源 | URL | 浏览器前进后退可恢复 |
| 尚未提交的输入 | 业务草稿 | 切页保留；按账号隔离；不包含Cookie、签名下载地址 |
| 下载/分析执行状态 | PostgreSQL任务及已有Outbox/Worker | HTTP和WebSocket观察，不由页面创建第二份权威状态 |
| 外部平台访问能力 | 035的平台会话与路线状态 | 对应任务进入恢复/待授权，不影响应用身份 |

## 4. Web 会话协议

### 4.1 存储、有效期与部署

Web session 保存 session_id、user_id、token_hash、created_at、last_seen_at、idle_expires_at、absolute_expires_at、revoked_at。Cookie 只包含CSPRNG生成的256位随机值，数据库只存摘要，不记录原值。

- 正常请求不轮换 Cookie。活动时间条件更新，最多每分钟一次；撤销后的记录不能被活动更新重新激活。
- 建议普通账户初始策略为请求闲置7天、绝对30天，均可配置；这是本方案产品默认值，不是上游标准或已验证配置。实际部署需核对当前自定义会话时长，发布明确告知变化。
- 绝对期限不因轮询或心跳无限延长。WS心跳不续会话，隐藏页面暂停非必要查询。
- 登录、重新认证、账号切换生成新会话；敏感权限提升与撤销使用明确的身份变更流程。
- PostgreSQL短时不可用返回503，不伪装401、不删除Cookie。Redis短时不可用不能使已有Web会话丢失；其他依赖功能仍可按职责503降级。
- 数据库和会话配置独立于容器。重建API、前端、Runner不会删除会话；无数据库的新部署不会假装继承旧登录。
- Cookie生产环境使用Secure、HttpOnly、SameSite=Lax、Path=/和host-only作用域；开发HTTP使用明确的开发配置。HTTP-only会话不能依赖JS清除。
- Cookie认证的写操作校验受信任的精确Origin/必要时Referer，禁止把SameSite当作唯一CSRF边界；登录与退出同样覆盖。上传与WebSocket按各自入口验证。代理外部origin必须来自受信配置。
- Web私有响应与会话首屏组合禁止共享缓存。Next进程不得用模块级对象保存用户身份或跨请求QueryClient。

### 4.2 公开操作与错误语义

继续使用现有登录、注册、me、logout资源。具体路由注解和模型仍是唯一OpenAPI来源，本文件不新增手写schema。

| 结果/操作 | 行为 |
| --- | --- |
| 登录/注册成功 | 后端持久创建会话后Set-Cookie，返回用户投影；客户端递增身份代际 |
| GET /api/auth/me 成功 | 返回当前身份；检查没有签发/轮换凭据的副作用 |
| 应用会话缺失、过期或撤销 | 明确401应用认证错误；被禁用按明确账号状态处理 |
| 身份有效但权限不足 | 403；保留登录，不进入refresh或重新登录循环 |
| 网络中断、超时、502/503 | 临时连接/服务错误；保留已确认身份 |
| 外部平台需要授权 | 使用provider专属业务错误和动作，不能透传为帧取401 |
| WebSocket连接失败 | 连接状态降级；先恢复观察，不推断退出 |
| 登出成功 | 撤销提交后清Cookie并204，幂等重复仍成功 |
| 登出响应丢失/断网 | UI立即遮蔽私有内容并停止新操作，但显示退出尚未确认；重试同一退出操作，不能宣称服务端已撤销 |

只在登录/退出/明确凭据失效等身份操作管理Cookie，普通业务响应不携带旧身份的Set-Cookie。取消、退出和账号切换使旧客户端代际失效；迟到的me、列表、任务响应不能恢复旧身份或写回新账号缓存。

跨标签页只广播“身份可能变化/已退出”及非敏感代际通知，不广播用户私有数据或凭据。其他标签页立即隔离旧身份、取消在途请求，然后自行验证共享Cookie。回到前台必须检查错过的身份变化。

## 5. 会话、连接与数据采用正交状态

不要继续扩展一个同时表示所有事情的 loading 布尔值。

### 5.1 身份状态

| 状态 | 含义 | 允许的页面行为 |
| --- | --- | --- |
| unknown | 尚无有效验证结论 | 不展示私有数据、不跳登录；一次有界初始化 |
| authenticated | 后端确认身份 | 展示该身份的数据；后台检查不卸载页面 |
| anonymous | 后端明确没有有效会话 | 私有入口进入登录；公开页正常展示 |
| signing_out | 用户要求退出但服务端结果未确认 | 隐藏私有内容、阻止新操作、完成或重试退出 |

检查状态单独表示 checking / idle / unavailable，不增加“断网游客”之类混合身份。

- authenticated + unavailable：已有内容保持，可标记尚未同步；请求仍由后端鉴权。
- unknown + unavailable：在原路由显示连接恢复与重试，不显示访客营销页或登录页。
- 某旧代际请求返回401：丢弃，不影响当前代际。
- 当前代际业务401：合并到一次会话核对；核对成功则保留身份并呈现原操作结果，明确匿名才进入登录，核对503则保持未知或上次已确认身份。
- 不自动重放任意写操作。单次登录完成后续接下载意图遵循040，不等于重放最后一个POST。
- 账号被切换为另一个用户，即使Cookie有效也不复用前一个用户的输入、任务或查询结果。

### 5.2 网络状态

浏览器online事件只提示“值得重试”，不是服务恢复的证据。网络离线、API不可用、WS降级分别记录，只有对应端点成功才清除对应故障。

网络恢复顺序：核对身份 → 恢复可见且过期的查询 → 恢复任务订阅 → 获取任务最新快照。网络恢复不重建根布局、不自动创建新任务、不全量重新请求所有历史页面。

## 6. 首屏、导航与数据连续性

### 6.1 首屏只确定一次身份

- 首次文档请求若无Web会话Cookie，可直接组合公开身份；存在Cookie则由Next在请求范围内向FastAPI做有界me查询，并传入同一身份快照。
- Cookie存在只是“需要验证”的信号，不能据此授予权限。
- 首屏验证失败使用unknown/unavailable，不降成anonymous；客户端继续有界恢复。
- 已有SSR结论在hydration复用，不能再次以loading初值覆盖；后续软导航不能用迟到的首屏数据覆盖客户端新身份。
- 根布局常驻SessionProvider、QueryClientProvider、导航与连接反馈。路由只替换当前业务内容。
- 保持现有首页“登录后直接工作区”的产品入口；匿名SEO内容仍遵循039，私有内容不进入公开HTML或共享缓存。

### 6.2 数据生命周期

建议浏览器根布局实例化一个QueryClient；SSR如预取则每请求独立创建。业务queryFn直接调用生成API并传递AbortSignal，不添加新的HTTP客户端。

Query key包含身份代际、资源、ID及规范化筛选条件，例如用户A的下载记录与用户B同名查询绝不能共享缓存。身份切换时先取消、清理，再挂载新身份页面。

| 数据 | 建议初始策略 | 展示规则 |
| --- | --- | --- |
| 下载/文档列表 | fresh 30秒，非活跃缓存5分钟 | 返回已访问页面立即展示缓存，过期后台更新 |
| 平台状态 | fresh 15秒，非活跃缓存5分钟 | 保留上次结果与检查时间；失败标注过期 |
| 运行中任务详情 | 版本化快照，WS驱动更新，轮询兜底 | 不因观察失败清空任务；新版本不得被旧响应覆盖 |
| 终态详情 | 较长fresh周期，显式变更后失效 | 不持续高频轮询 |
| 签名媒体/下载地址 | 按有效期临时获取 | 不作长期缓存，不因刷新重复触发下载 |

这些数值是待验收的初始参数，不能代替行为规则。使用非Suspense业务查询以便保留已有视图和取消行为，不把所有查询错误抛到整页错误边界。TanStack默认自动重试与焦点刷新必须显式配置，不能安装库后沿用所有默认值。

分页/筛选写URL；新筛选有新query key，不把旧筛选内容误标为新结果。仅分页等明确允许的同类过渡可保留旧列表，并标注更新中、暂禁不确定的批量操作。

### 6.3 加载反馈

| 场景 | 正确反馈 |
| --- | --- |
| 首次进入且无任何数据 | 与最终结构匹配的局部骨架 |
| 导航目标资源尚未就绪 | 保留当前内容并给导航进度，目标就绪后切换 |
| 已有页面后台更新 | 保留数据，只更新局部状态 |
| 首次读取失败 | 页面内可操作错误，导航仍可用 |
| 已有数据刷新失败 | 保留上次数据，显示持久的同步失败信息 |
| 明确会话失效 | 遮蔽私有数据，带安全returnTo进入重新登录 |

全局loading不承担所有页面的加载。移除当前通用整块占位的前提是导航反馈、首屏和业务骨架边界已经建立；不先删除它制造无反馈等待。客户端导航、预取和错误边界使用Next官方能力；不把所有页面常驻隐藏来伪装无闪屏。

草稿首版按账号保存在应用会话内存，满足软导航往返；普通刷新/关闭后是否保留需明确产品范围。含签名参数的链接与私有输入不能未经选择写入localStorage。已经提交的下载意图使用040服务端持久记录，不依赖草稿。

## 7. 请求、重试与实时恢复

### 7.1 一层负责一次恢复

| 层 | 可以做 | 不可以做 |
| --- | --- | --- |
| Axios传输 | 超时、取消、解包、标准错误 | 跳登录、刷新凭据、任意业务重放 |
| SessionProvider | 合并身份核对、身份代际、退出协调 | 控制所有页面数据或决定任务失败 |
| Query | 合并相同查询、缓存、有限只读重试 | 重试401/403/确定性4xx、自动重放写操作 |
| Mutation/业务用例 | 依据幂等键和服务端结果恢复操作 | 网络超时后推断操作未执行 |
| WebSocket协调 | 连接、版本游标、断线后重订阅 | 删除任务快照、刷新用户、跳转页面 |
| Worker | 既有任务的执行重试与租约恢复 | 因观察端离线取消任务 |

普通只读请求默认最多2次额外重试，指数退避并抖动；429遵守Retry-After与总预算；用户取消不重试。会话初始化/恢复最多3次额外尝试，耗尽后留在原页等待显式重试或新的联网/前台事件，不能无限轮询。

自动重试仅覆盖网络、超时和明确临时5xx；新一轮用户操作或连接恢复事件有单独去重与节流，不叠乘Axios、Query和组件三层次数。

### 7.2 实时任务

- 每个标签页、每个已确认身份最多一条任务通道，订阅按任务引用计数管理。
- 同一用户资料更新不重置socket、不清空订阅；退出/切换用户才整体销毁。
- WS与HTTP认证使用相同Web session验证逻辑；升级连接和存活期间的失效处理都必须覆盖。
- 普通断线保留快照，使用退避重连及低频HTTP兜底；4401触发统一会话核对，不直接退出。
- 任务事件只更新或失效相应query，后端version负责顺序；version缺口与重连后读取权威快照。
- 鉴权依赖暂不可用使用服务暂不可用的连接结论，不能伪装4401。
- 服务端对活跃连接至少每个心跳周期复核会话有效性；明确撤销通过现有通知加速关闭，漏通知仍在下一次复核失效。只读snapshot补偿也必须重新鉴权。
- Worker执行与观察端生命周期彻底分离。取消操作只由用户明确发起并服务端确认。

## 8. 与第三方平台会话恢复的衔接

应用登录回答“谁在使用帧取”，平台授权回答“该任务能以什么身份访问上游”，二者不能共享失败状态。

平台维护失败、Cookie过期、解析器异常分别进入provider维护/任务等待或失败状态。任务保持owner、原链接和明确的下载意图；恢复后由040的服务端流程续接。Web连接恢复只重新观察该意图，不重新授权平台、不再次创建下载。

平台可用性目录、会话自动维护与部署恢复仍由035/038/040负责。本设计仅统一它们与Web身份和页面连续性的接口边界，不再另造第三套平台状态机。

## 9. 实施顺序与删除清单

每一阶段都围绕完整用例交付，不按“先加一层适配器”切割。方案审阅前不开始业务改造。

1. D0 证据基线：记录真实异常与导航时序，区分document重载、RSC导航、根Provider挂载、me/refresh、Query加载与WS断线；不记录Cookie、token或私有响应正文。
2. D1 冻结契约：确定应用401、权限403、服务503、provider动作语义与会话时长；统一路由和Pydantic生成客户端。
3. D2 会话纵向替换：PG Web session、登录/me/logout、HTTP/WS依赖、SSR初始化、SessionProvider与路由一起完成；覆盖退出响应丢失、账号切换和依赖中断。
4. D3 数据纵向替换：先下载记录→详情→返回，再文档和平台页；迁移一条路径即删除其旧局部请求生命周期，保持权限与幂等行为。
5. D4 任务与恢复：统一WS事件进入缓存，删除重复轮询所有权，接040持久意图；不复制任务状态表。
6. D5 一次发布切换：前后端同版，旧Web Cookie不再被接受；明确要求既有Web用户重新登录一次。切换后不再保留Web旧refresh端点与认证回退。原生契约单独回归。
7. D6 在目标环境完成故障注入与重建验收，结果通过后才关闭问题。

必须删除/替换的Web旧路径：

- Axios里的refreshAccessToken、浏览器刷新锁、隐式重放和location登录跳转。
- 把user为空同时表示尚未确认/断网/匿名的状态表达。
- 页面各自维护的重复data/loading/error/轮询循环；业务展示转换保留。
- 同一身份更新即taskSocket.reset的行为。
- 把后台刷新升级成全页loading/error的边界。
- Web认证的Redis→旧SQL回退和旧JWT Cookie读取。
- 不再需要的Web刷新兼容参数与旧客户端生成操作。

发布是明确的协议切换，不靠双读长期兼容。若需回滚，则前后端整套回滚，允许再次登录，不恢复已撤销凭据；数据库变更在现有schema.sql内保持可重复执行，回滚窗口不破坏旧原生数据。

## 10. 验收矩阵与量化证据

以下均为未执行的目标门禁。单元测试通过不能替代真实浏览器/部署证据。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首屏已有Cookie，API503 | 停留原URL；不出现登录页/访客首页；恢复后展示原账号 |
| 已登录页面断网30秒 | 原内容与输入不消失；没有身份退出事件 |
| API恢复、网络恢复 | 合并身份检查与必要查询；不出现请求风暴 |
| 首屏明确没有会话 | 正常匿名/登录流程，不无限尝试恢复 |
| 资源403、404、429或provider授权失败 | 不改变应用身份，各自给正确动作 |
| 真正撤销/到期 | 私有内容及时遮蔽，仅一次有理由的登录导航 |
| 登录/退出/me响应乱序 | 旧代际响应不恢复旧用户 |
| 用户A退出后用户B登录 | A的缓存、草稿、订阅和迟到响应不进入B |
| 两个标签页登录状态改变 | 其他标签页隔离旧身份，核对后展示正确身份 |
| WS断开、恢复、事件乱序 | 不退出；任务快照保留，版本不倒退 |
| WS期间撤销会话 | 后续敏感发送前/规定复核预算内终止访问 |
| 下载记录→详情→返回，重复20次 | 应用壳和身份不重挂；缓存存活时列表不清空；筛选可恢复 |
| 目标路由首次慢加载 | 旧内容保留且有导航反馈；不是整页白屏 |
| 页面业务刷新失败 | 有数据时局部提示，无数据时局部错误 |
| 创建任务响应丢失 | 按已有幂等键恢复结果，不重复创建任务 |
| 前端/API容器重建 | 未到期PG Web session可继续使用；不需要手工恢复登录数据 |
| Redis不可用但PG可用 | Web会话验证正常；依赖Redis的其他功能单独降级 |
| PG不可用 | 会话核对503；不清Cookie、不假装匿名；恢复后可再次验证 |
| 桌面/390px、明暗主题、前进后退 | 交互、焦点、滚动和错误反馈可用，无空白中间帧 |

收集：应用壳挂载次数、document导航次数、身份迁移原因、每次恢复的请求数量、相同资源请求去重、从失败到恢复的时间、连续录屏与DOM状态事件。诊断ID必须脱敏，不能使用原始session/token作关联键。

“彻底修复”的可判定含义：错误的跨状态迁移路径被删除，约定故障场景稳定通过。第三方/网络永不失败不是本方案承诺。

## 11. 代价、约束与尚待核实项

- 服务端Web会话需要每次认证查询；既有用户查询可以合并，但实际数据库负载与写入节流须压测，不宣称免费。
- 首次切换要求Web重新登录一次；后续部署持久性由PG备份恢复和配置稳定性保证。
- 引入TanStack Query只承担服务器数据生命周期，不把它当作身份/草稿/任务执行的统一框架；新增依赖需按锁文件和当前Next版本验证。
- 本轮没有真实用户故障录屏与请求时序，因此“每次闪屏”的完整因果链仍开放。D0必须先完成，必要时调整具体导航边界实现，不能倒推所有闪屏都来自loading文件。
- 当前AGENTS/PROJECT/frontend规范里的Web JWT、请求层认证恢复职责需要在实施切换时同步更新；本目标文档不把旧规范偷偷改写为已交付事实。
- 本轮不扩大到App重构、第三方账号共享、多地域身份平台、离线写队列或全局工作流引擎。
