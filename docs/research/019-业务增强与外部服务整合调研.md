- 日期：2026-09-08；状态：调研完成，增强项尚未实施，候选服务尚未接入。
- 基线：`video-server@1f18f62b58938fd161da6df8e98c6afbca15cdfb`，并检查当前 Web/App 实现；保留上一轮未提交的修复和文档。
- 方法：读取本地服务装配、API、模型、用例、界面与现行设计；使用 GitHub 插件检索官方仓库，核对 README、许可证、默认分支提交及部分 Release；以官方服务文档补充接入限制。未使用 stars 排名或把公开仓库等同于可直接商用的完整服务。
- 产品假设：延续面向创作者、内容研究者的合法视频/剧本分析产品，以小规模托管试用为下一阶段。首发地区、付费模式和具体供应商尚未确定。公网发布门槛仍见 [018 评审](018-业务逻辑评审与ToC最小上线能力.md)。

## 1. 结论

**下一阶段应把“拿到报告”推进到“能核对、能找回、能复用报告”。** 先补时间点回看、账户自助服务、额度解释、任务完成反馈和结果检索，不需要增加一套下载站、任务平台或通用 Agent 框架。

外部能力的优先顺序：

1. **事务邮件：一个邮件通道即可。** 无既有可靠通道时优先验证 Resend；有可用 SMTP 时先复用。用户验证、密码恢复和注销仍由本项目负责。
2. **AI 质量回归：优先评估 promptfoo，运行在开发/验收侧。** 先建授权样本与人工标准，再决定是否引入工具；不进入生产任务的必经链路。
3. **错误归集：Sentry 作为试用期可选服务。** 现有指标和日志仍保留，确有跨版本排障需求时接入，先限制采集范围。
4. **pgvector、Langfuse、Google Drive Connector 有条件再接。** 分别解决语义检索、复杂 AI 诊断和外部交付；目前都不是首次上线的前置依赖。
5. **暂不整合 Keycloak、Novu、Chatwoot、faster-whisper。** 不是判定项目不好，而是当前收益不足以抵消身份迁移、多套基础服务或产品范围扩张。

### 条件满足后再考虑

- **报告外部交付**：先保留已有 Markdown/DOCX 下载；若用户反复手工搬运到 Google Drive，再加一次明确授权的报告导出。跨账号分享链接必须单独设计范围、到期、撤销和删除行为，不能把已有短时对象 URL 当作分享权限系统。
- **少量文件批处理**：只有试用数据证明逐文件操作是主要阻力时，才增加受限选择、逐项状态与取消。023 当前明确不做批处理，应先更新其需求；不顺带开放频道抓取、递归播放列表或无限自动重试。
- **转录/字幕、扫描 PDF**：这是新输入/新结果类型，010/023 当前明确排除 ASR/OCR。可以作为后续产品方向评估，不应为了集成热门项目而恢复已删除的链路。

### 托管 AI 的业务前提

现有 [022 Provider 管理](../design/022-跨平台AI分析Agent与模型Provider配置设计.md) 已有管理员配置与 API Key 路线，不等于尚无模型接入。下一步应从现有适配器中确定一条具有目标服务授权、容量和实际样本验证的托管路线，明确单任务预算、服务不可用时的入口及负责处理的人。010 的宿主机个人登录定位不能自动成为多用户服务承诺；本次没有核验任何个人订阅转售条件，也不建议依赖自动切换多个模型来掩盖容量问题。

“接入成本”是相对工作量判断：低表示边界较窄，中表示新增业务状态/跨端交互，高表示身份迁移、新数据引擎或新处理管线；不是工期报价。许可证描述仅对应已读取的仓库范围，SDK 开源不代表其云服务免费、企业版也开源或已满足本项目运营条件。

### 4.1 事务邮件：只采购传输，不采购整套账户系统

接入位置放在 `backend/app/integrations/`，由账户用例和受限通知消费逻辑调用；复用 Outbox 的持久投递，不在注册 HTTP 请求中等待邮件送达。业务仍须区分“待发送、供应商接受、送达/退信”；接受请求不是进收件箱的证明。

Resend 官方文档要求验证自有域名的 SPF/DKIM，并支持发送幂等键；其去重保留窗口是 **24 小时**，不能替代本项目的持久发送记录。超过窗口且结果不确定时，先核对状态，不无限盲重试。见 [域名配置](https://resend.com/docs/dashboard/domains/introduction) 与 [发送幂等](https://resend.com/docs/dashboard/emails/idempotency-keys)。

首轮验收只需要验证邮件、恢复邮件、可选报告就绪通知三类模板：一次性凭证有期限，旧凭证不能复用，重复消费不会重复创建发送意图，临时失败/退信能定位，邮件商不可用时已有登录与文件获取继续工作。只传收件地址和必要模板内容；报告通知链接到需鉴权的业务页面，不附媒体、报告正文或长期对象地址。供应商地域、实际送达、预算、数据保留和合同仍须在真实目标环境核验，本次没有发信。

### 4.2 质量评测：先定义什么算好，再选择平台

现有 schema 和时间轴校验能证明结构成立，不能证明“高光值得看”“事实来自画面”“改写没有遗漏”。先固定一小组已授权短视频和中英文剧本，记录原文/画面证据、关键结论、不可接受错误以及当前 Skill/模型版本。

promptfoo 的 [Python provider](https://www.promptfoo.dev/docs/providers/python/) 可以复用现有 Python 适配器。结构与证据一致性复用现有校验，内容质量由人工标注或受控 judge 补充；不要另建一个绕过本项目编排的“直接调模型”测试后宣称真实任务通过。真实模型费用、耗时和失败均记录，单次评测有预算；未知 token 数据保留未知，不从运行时长伪造费用。

评测工具不参与生产可用性判定；禁止自动分享用户样本。promptfoo 默认有使用遥测，[官方配置](https://github.com/promptfoo/promptfoo/blob/main/site/docs/configuration/telemetry.md) 提供关闭遥测/更新检查的选项。关闭遥测也不代表云端模型推理不外发输入。第一版可先用现有测试与人工基线，只有多次对照维护开始重复劳动时才引入工具。

### 4.3 错误归集与 AI 追踪：按不同问题选择

Sentry 先解决“哪个版本、哪类错误影响了用户”，现有运行指标继续解决队列、lease 和报告发布问题。只允许脱敏错误码、版本、关联标识和必要堆栈；请求体、URL query、Cookie、局部变量、AI 输入输出、自动日志采集均应逐项验证，不原样复制官方快速开始配置。接收端不可达时不能阻塞任务，使用本地测试 transport 核对实际发送载荷后再开放出站。

Langfuse 适合需要把多次模型调用、实验和反馈串起来的阶段。当前 [DeepSeek 调用](../../backend/app/integrations/ai_api/client.py) 返回结构化结果，统一输出尚无 usage；宿主 CLI 也不能假定可自动取得准确费用。因此接上 Langfuse 不会自动形成计费账本。其 [Compose](https://github.com/langfuse/langfuse/blob/main/docker-compose.yml) 引入 ClickHouse 等额外组件，本轮不部署；以后若采用托管版，也先验证最小元数据是否足以排障，再决定是否值得承担数据外发和费用。

### 4.4 检索与外部交付：结果先留在现有数据边界

先为当前用户可见的标题、标签、报告段落建立有界关键词查询，用实际中文检索问题验证效果。只有关键词无法表达的同义场景搜索具有明确需求时再加入 pgvector。其 [过滤说明](https://github.com/pgvector/pgvector#filtering) 提醒近似索引扫描后的过滤会影响返回数量；上线验证必须同时覆盖 owner 过滤、召回不足、删除同步和重建。先使用精确检索，不默认上 HNSW，也不额外引入 Qdrant/Elasticsearch。

Drive 第一步仅考虑“把我当前报告导出到我授权的位置”，不扫描整个云盘。官方推荐窄范围 [drive.file 权限](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)，并明确 OAuth 配置和撤销边界。导出以用户和报告版本绑定；导出失败不改变原报告，重试不重复创建文件，解绑停止后续访问。账户删除时需明确区分本项目持有副本与用户已主动导出的外部副本；不默认替用户删除云盘文件。

## 6. 最小交付顺序与验收口径

1. **先做 B1 的报告回看，再补 B2/B3 的受控试用与账户闭环。** 回看复用已有播放器；账户只接一个邮件通道。目标是用户能独立完成一次任务，知道限制，并在忘记密码时恢复访问。公开注册继续受 018 门槛约束。
2. **随后做 B4/B6：结果送达、问题反馈和固定质量样本。** 报告就绪与发送结果分开；先记录注册后首个任务完成、报告首次成功获取、任务失败原因、有效反馈。读取报告/制品接口的成功只证明获取成功，不宣称用户已阅读或保存到设备。用现有数据库聚合，不为这几个指标新装产品分析平台。
3. **再做 B5：个人结果库。** 先关键词、收藏和可回看的引用；用检索失败实例决定是否接 pgvector，用真实复制/交付习惯决定是否接 Drive。Langfuse、Novu、Chatwoot 的采用分别由多模型排障、多渠道通知、多人客服需求触发。

每个选定增强沿用 Design → PRD → Plan → Acceptance 推进。006 承接账户/额度，010/028 承接报告证据与质量，023 承接文档及输入范围；跨端接口统一更新 OpenAPI 和两个生成客户端。实现时复用现有用户、任务、权限与用量数据，并遵循现行数据库治理约定。

本次只完成代码事实与外部资料调研、文档整理和链接检查。没有安装候选依赖、修改运行配置、连接第三方账户、发送邮件/用户内容、部署服务或消耗模型额度；没有为文档变更重跑业务测试。服务的实际送达率、目标地区可用性、成本、漏洞状态和数据处理条件均未完成生产验收。上一轮三项 App 修复与 173 项测试记录仍属于 [018](018-业务逻辑评审与ToC最小上线能力.md)，不作为本次候选整合通过证据。
