## 2. 与当前代码对照

- [ProviderCookieFile](../../backend/app/runner/provider_cookie_file.py)逐操作重新打开只读来源，不写回会话更新；[operation_cookie](../../backend/app/runner/provider_session_files.py)清理临时副本。这是安全来源契约，不等于平台会话维护协议。
- [ProviderSessionStore](../../backend/app/runner/provider_sessions.py)以 HMAC 形成文件修订并严格验证 context。自动写回会导致旧引用失效，不能只改挂载权限。
- [MediaInspectionPipeline](../../backend/app/integrations/media_inspection_pipeline.py)在配置 Operator 时优先选择它；目标策略选择需与 endpoint 配置解耦，仍禁止操作中暗中回退。
- [Runner service](../../backend/app/runner/service.py)已有下载前重解析、来源身份和语义计划检查；[命令构建](../../backend/app/runner/yt_dlp_commands.py)已有显式代理与 JS runtime。不能把这些机制写成待从零补齐。
- [当前 pin](https://github.com/yt-dlp/yt-dlp/commit/3a08beaf031ab68f966401ead017ac81fe8486cf)对应 2026.08.19，已含上述 MeTube 案例修复。引擎升级只是待实验变量，不是现成根因。

旧文档局部仍同时保留早期图示/计划与当前实现说明（例如媒体责任链图示与确定性路由文字）。035 明确以源码和最新专项边界为基线，不借旧图示恢复已移除的失败回退，也不在本次顺带重写全部历史文档。

## 3. 尚未解决的外部问题

- [腾讯低速 #8171](https://github.com/yt-dlp/yt-dlp/issues/8171)在调研时仍 open，讨论中的替代工具是线索，不是维护者确认的普遍修复。腾讯完整下载与 VIP 继续保留专项门禁。
- [bgutil 2.0.0 发布](https://github.com/Brainicism/bgutil-ytdlp-pot-provider/releases/tag/2.0.0)包含安全修复与监听行为变更；本项目当时固定 1.3.2。应独立评估升级与网络兼容，不把安全发布等同于九个 Runner DNS 故障的修复。本轮未评估本机可利用性或升级。
- [cobalt session generator](https://github.com/imputnet/yt-session-generator/blob/main/README.md)与 cobalt 当前调用接口不完全一致。仓库 README 不能代替配套版本兼容实验。
- 自动访客建立、账号同主体更新、无桌面视频号路径均没有本项目真实证明；按 035 的 G3 单独裁决。

## 4. 研究结论的强度

可以确认同类项目普遍需要处理平台变化、会话有效性和请求绑定；不能从这些事实推导本项目所有失败都由会话造成。缺服务、引擎回归、来源过期、出口变化和内容限制必须用同条件对照区分。

最小可行方向是保留现有执行面，补访问策略和来源生命周期边界；维护能力逐平台引入。访客与账号自动维护不能默认一起通过。先设计、再获准做隔离实验、再请用户决定实现，是 035 的强制顺序。
