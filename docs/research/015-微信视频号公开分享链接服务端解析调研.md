# 微信视频号公开分享链接服务端解析调研

- 状态：Completed
- 日期：2026-08-27
- 对应设计：`docs/design/025-微信视频号公开分享链接下载设计.md`

## 1. 结论

当前第一方公开预览页可以匿名确认 `weixin.qq.com/sph/{id}` 是否为公开作品，并返回标题、作者与封面，但抽样响应不直接提供媒体 URL。GitHub 中可工作的服务端方案普遍再使用已登录腾讯元宝会话，把公开分享链接解析成视频号预览参数，然后向视频号预览接口读取媒体字段。

本项目采用受限版本：

1. 只接受公开 HTTPS `/sph/{id}` 单视频链接；
2. 必须先匿名调用第一方预览页/接口证明作品公开；
3. 仅在隔离 Runner 中使用项目运维账号的元宝会话；
4. 仅接受批准的腾讯 HTTPS 媒体域和固定下载路径；
5. 出现 `decodeKey`、DRM、加密标记或 ffprobe 无法证明 clear 时拒绝；
6. 不实现客户端抓包、根证书、系统代理、注入、缓存读取、解密或第三方解析站。

这不是微信官方开放下载 API。生产启用前仍需由部署方确认平台条款、账号使用授权和内容权利，并用项目自有/明确授权样本完成真实 canary。

## 2. 第一方接口实测

抽样公开链接会重定向到：

```text
https://channels.weixin.qq.com/finder-preview/pages/sph?id={shortUri}
```

页面匿名请求：

```text
POST https://channels.weixin.qq.com/finder-preview/api/feed/get_feed_info
{"baseReq":{"generalToken":""},"shortUri":"{shortUri}"}
```

有效样本能得到 `feedInfo` 的描述、作者、封面和公开作品标识；无效样本返回空或错误结果。所测匿名响应没有 `h264VideoInfo.videoUrl` 或 `h265VideoInfo.videoUrl`，因此匿名元数据成功不能冒充下载成功。

## 4. 会话最小化

浏览器导出只允许 `yuanbao.tencent.com`，并要求同时存在：

- `hy_user`
- `hy_token`

Cookie 只能进入 `wechat_channels` 专属只读 Secret 和独立 Runner。普通 API、前端、数据库、MQ、日志、canary 响应和其他 Provider 均不得接触原始值。解析得到的 token、export id 与签名媒体 URL也只在一次 Runner 操作内存活。

## 5. 媒体与保护边界

解析结果必须满足：

- `playable_url` 为 `https://channels.weixin.qq.com/finder-preview/pages/feed`；
- query 仅包含单个 `token` 与 `eid`；
- 媒体 URL 为 `https://finder.video.qq.com/251/.../stodownload`；
- 响应树内没有有效 `decodeKey`、DRM、encrypted/encryption 标记；
- 现有媒体检查流水线能够通过 FFprobe 识别标准音视频轨道；
- 下载前重新解析，不能复用旧签名 URL。

任何条件不满足都返回稳定错误，不切换账号、不调用第三方服务、不尝试解密。

## 6. 尚需真实环境验证

自动化 fixture 能验证控制流、域名/路径白名单、会话隔离、错误分类与保护拒绝，但不能证明元宝私有接口长期稳定。发布前需要：

1. 运维在本地安全导出会话，不能把 Cookie 粘贴到工单或聊天；
2. 用自有/授权的公开作品完成 metadata → 最小媒体 → 完整下载 → ffprobe → Artifact canary；
3. 验证无会话、会话过期、链接失效、带 `decodeKey`、非批准 CDN 的负例；
4. 记录接口变更、账号告警、条款变化与紧急停用流程。
