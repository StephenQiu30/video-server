# 内容创作与平台发布能力调研

- 日期：2026-09-15；代码基线：`f547b9e41d101ab4e05988db8842f3642f50069d`。
- 状态：已完成本轮源码与外部资料核对；下述新增创作、配图、转录、投稿能力均未实施、未做真实账号验收。
- 范围：下载/导入 → 证据分析 → 文章与小红书内容制作 → 编辑/导出 → 投稿/发布 → 结果恢复。属于此业务链的设计审查，不声称完成全仓安全、性能或所有平台实测。
- 方法：GitHub 插件读取候选 Skill 与发布实现；Firecrawl developer index 检索维护案例，并实时抓取微信、小红书官方文档；Context7 核对 MCP 工具权限语义和 Tiptap 文档持久化；本地核对 API、SQL、Skill loader、模型适配器与 Web 调用链。
- 后续：[036 设计](../design/036-内容创作与平台发布设计.md) → [需求](../prd/036-内容创作与平台发布需求.md) → [实施 SOP](../plans/036-内容创作与平台发布计划.md) → [验收](../acceptance/036-内容创作与平台发布验收.md)。

## 1. 核心结论

项目已有媒体获取、结构化分析和版本化报告基础，但目前交付物主要是“分析结果”，还不是“用户可以持续编辑、配图并投递到指定账号的内容作品”。增加几个 Skill 名称无法补齐这段业务。

本轮建议的最小完整目标：用户选取已有媒体或输入文字，说明读者和目的，得到有来源依据的文章或小红书图文；修改内容和图片后导出完整包，或向已连接账号创建远端草稿；具备平台权限时再提交发布并核对结果。所有步骤都能在重启后继续查找，某个平台失败不影响已有草稿、文件和其他平台。

三个架构裁决：

1. **保留分析报告作为证据，新增创作草稿与不可变内容版本。** 不覆盖历史报告，也不让文章生产被迫套用分镜分析格式。
2. **Skill 负责写作方法与结构化产物；发布由确定性的业务用例和平台适配器执行。** 模型不能自行选择账号、读 Cookie 或决定对外发帖。
3. **生成完成、远端草稿保存、提交受理、平台发布成功、客户端实际保存分开记录。** 不用一个 `success` 掩盖不同的交付结果。

### 3.1 宝玉 Skills 的具体取舍

核对 [xhs-images Skill](https://github.com/jimliu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-xhs-images/SKILL.md) 后，值得移植的是读者/目的驱动的大纲、卡片信息密度、统一视觉风格、首图与后续页一致、失败页单独再生成。它输出 1–10 页是该 Skill 的工作约定，不是小红书官方图片上限。

`baoyu-article-illustrator`、`baoyu-cover-image`、`baoyu-format-markdown` 作为第二批方法候选，尚未逐文件审查，不能称为已批准可执行依赖。`baoyu-xhs-images` 依赖宿主生图与磁盘工作流，当前 loader 不接受其完整目录；本项目移植方法时保留归属说明，用平台化输入输出契约替代宿主问答及脚本。

公众号 [wechat-api.ts](https://github.com/jimliu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-post-to-wechat/scripts/wechat-api.ts) 的主要提交端点是 `draft/add`，结果为 `media_id`。脚本日志包含 Published successfully，但其 [Skill 完成说明](https://github.com/jimliu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-post-to-wechat/SKILL.md) 明确是草稿保存；本产品必须显示“已保存到公众号草稿箱”。

Firecrawl developer index 找到 [PR #154](https://github.com/jimliu/baoyu-skills/pull/154) 的草稿保存确认与编辑器适配修复案例，说明浏览器路径需要持续维护。本轮结论以当前源码为准，不把 PR 中作者报告的测试当成本项目证据。`danger-gemini-web` 等逆向网页路线不进入本次生产基线。

### 3.2 小红书 MCP 不能原样作为托管发布服务

- [service.go](https://github.com/xpzouying/xiaohongshu-mcp/blob/aad2a3d249a347859975ce3b76d3442c4a027780/service.go) 的图文和视频 `PublishResponse` 包含标题、内容、数量/视频路径、Status，未提供可核验的帖子 ID/链接；动作无错误后返回“发布完成”。这不足以支撑本项目“远端已发布”的验收，不代表上游完全没有页面成功检测。
- [cookies.go](https://github.com/xpzouying/xiaohongshu-mcp/blob/aad2a3d249a347859975ce3b76d3442c4a027780/cookies/cookies.go) 默认当前目录 `cookies.json`，可用 `COOKIES_PATH` 指定；所读版本以 `0644` 写文件、`0755` 建目录。个人工具默认值不满足本项目发布凭据的最小范围与权限，必须由适配层提供隔离的 `0700/0600` 工作区、受限账号来源及清理。
- 上游允许图片 URL/本地绝对路径、视频本地路径。公开业务 API 只能接受 owner-scoped artifact ID；Worker 验证哈希后物化临时文件，不能让模型传入任意服务器路径或私网 URL。
- 不开放搜索、评论、点赞等全部 MCP 工具给写作模型；本需求只需要明确授权的投稿操作。MCP 工具注解是描述性提示，不能代替实际权限校验，见 [MCP tool annotations](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-03-16-tool-annotations.md)。

### 3.3 官方能力边界决定产品文案

**公众号：** 官方 [发布草稿接口](https://developers.weixin.qq.com/doc/subscription/api/public/api_freepublish_submit.html) 要先有草稿 `media_id`，提交取得 `publish_id`；`errcode=0` 仅表示受理，后续仍可能原创/审核失败。页面列明账号类型/认证范围、接口未授权错误和发布结果事件。实际账号必须核验草稿、素材、发布各项权限，不能从“已登录”推导全部可用。产品应支持：本地导出 → 远端草稿 → 已受理 → 已发布/审核失败/结果待核实。发布也不等同向全部粉丝群发，群发不在本轮范围。

**小红书：** 本轮实时读取的 [官方分享平台](https://agora.xiaohongshu.com/doc/ability) 提供客户端 SDK，并利用小红书 App 内发布工具。可以设计“分享到小红书继续发布”，不能把唤起成功标成帖子已发布。文档自身能力页标注更新于 2023-07-04，实施时仍要核验具体 SDK、平台与合作接入资格。本轮没有找到足以确认当前账号具备通用服务端无人值守发帖权限的官方依据；这不是断言所有合作方都没有其他接口。

**其他平台：** 共用内容作品、账号连接和投递协议，但逐平台维护权限、素材限制和回执语义。X、Instagram、Facebook 等不因下载能力已存在就启用投稿；未核验的渠道显示未接入，成熟插件目录不等于运行能力目录。

## 4. 需求取舍与原规范的关系

- 010/023/028 的纯视觉分析继续成立；[019 调研](019-业务增强与外部服务整合调研.md) 当时延后 ASR 是针对分析产品的合理裁决。此次“口播转文章”使转录有新业务价值：036 单独提出创作证据输入，实施时同步契约，不恢复已删除的旧 ASR 链路。
- 现有报告版本、Skill 哈希、Outbox、lease、配额、对象校验都复用。新增的是有实际生命周期差异的作品/投递模型，不另建通用 Agent 平台、Temporal、第二个账号系统或工作流引擎。
- 当前对 GitHub/Firecrawl/Context7 的使用是研发调研工具。把它们加入产品运行时，需要另行配置应用级凭据、成本和数据策略；本轮不假定已接入线上服务。
- 首期覆盖文章和小红书图文制作/导出；公众号官方草稿为首个远端闭环。小红书官方分享与浏览器适配分别验收。定时发布、批量账号运营、评论自动化、实时协作、流量分析不作为本次核心链前置。

## 5. 实施前仍须取得的证据

1. 现有真实内容样本和编辑标准：先用有权处理的公开视频/自有文稿建立基线，不能把抓到网页当转载许可。
2. 目标公众号的实际接口权限、出口 IP 与主体类型；这决定能交付草稿还是可进一步发布。
3. 小红书 SDK 具体接入资格、iOS/Android/JS 适配及回调语义；个人 MCP 路线需专用账号和明确发布操作授权后做实测。
4. 部署模型对中文转录、插图及成本的实测；没有生图 Provider 时仍能上传图片、制作文字卡片和导出。
5. 不停留在“安装成功”：依赖锁定与许可证、严格 schema、中文可读性、平台回执、重启/换机、真实文件分别验收。详细 Go/No-Go 见 036 验收。
