# 005 其他短视频平台接入调研

- 日期：2026-08-12
- 基线：仓库固定 `yt-dlp` commit `5d6b8c8cd19785c3086ae3a9ec618c45e25eb3bc`
- 范围：除当前已验证的 Bilibili、抖音、小红书、快手外，评估其他公开短视频/社交视频平台
- 边界：只处理用户有权下载和分析的公开、非 DRM 内容；不使用公共解析 API、MITM、私有签名生成、账号自动化或客户端逆向

## 1. 结论

当前最合理的扩展顺序不是一次性增加大量域名，而是分四层推进：

1. 先为已经登记的 TikTok、YouTube Shorts、Instagram Reels、Facebook Reels、X、Reddit、Pinterest、Vimeo 和微博补真实完整下载 canary。这些平台已经有 Provider Profile，缺的是可用性证据，不是域名注册。
2. 新平台只继续验证受控 PeerTube 实例。AcFun、Rutube、VK Clips、Dailymotion 和 NicoNico 已由产品决策排除，即使固定引擎存在 extractor 也不接入。
3. 西瓜视频、Snapchat Spotlight、Rumble、Tumblr 和 Bluesky 需要先解决会话、样本失效、出口或 schema 问题，再决定 Profile。西瓜视频的上游实现明确要求 Cookie，即使该 Cookie 不一定代表登录态。
4. Likee、Threads、好看视频和 Kwai 国际版只适合仓库可信插件候选；现有社区实现存在 URL 推导、陈旧 HTML 选择器、多资产语义或地域问题，不能直接复制。微信视频号社区采集路径已被 024 排除，链接保持 `unsupported`，只允许用户导入合法明文文件；ShareChat/Moj/Josh/Roposo/Chingari/Lemon8 等继续保持 `unsupported` 或研究队列。

所有平台最终都必须交付完整视频给现有 AI Agent。抽帧只能作为 Agent 在完整视频上下文内使用的受控工具，不能代替视频输入，也不能据此宣称分镜和高光分析完整。

## 2. 当前系统缺口

当前 Registry 已登记 YouTube、Bilibili、抖音、TikTok、小红书、快手、Vimeo、X/Twitter、Instagram、Facebook、Twitch、Reddit、Pinterest、微博、优酷和腾讯视频。登记只说明 URL 能被归类；除已有验收平台外，其余平台仍需要真实 canary。

固定 yt-dlp 还内置了下列与短视频相关、但没有独立 Profile 的 extractor：

- `AcFunVideo` / `AcFunBangumi`
- `Ixigua`
- `SnapchatSpotlight`
- `likee` / `likee:user`
- `Meipai`
- `Bluesky`
- `Rumble` / `RumbleEmbed`
- `rutube`
- `Tumblr`
- `VK`
- `PeerTube`

extractor 名称存在不代表生产可用，也不代表平台全部内容类型都在产品授权范围内。

## 3. 固定版本只读探测

2026-08-11 使用当前仓库环境执行 `yt-dlp --simulate` 元数据探测。该探测没有下载完整视频，因此只能用于排序，不能把平台升级为 `verified`。

| 平台 | 固定 extractor | 结果 | 观察 | 决策 |
| --- | --- | --- | --- | --- |
| AcFun | `AcFunVideo` | 成功 | 返回完整 HLS 媒体格式与 174.208 秒时长 | 产品范围排除，不接入 |
| Rutube | `Rutube` | 成功 | 返回 HLS 格式与 81 秒时长 | 产品范围排除，不接入 |
| VK | `VK` | 成功 | 返回 720p 媒体格式与 9 秒时长 | 产品范围排除，不接入 |
| PeerTube | `PeerTube` | 成功 | 返回媒体格式与 113 秒时长 | P1，只允许显式实例 allowlist |
| 西瓜视频 | `Ixigua` | 失败 | 明确提示需要 Cookie，且不一定登录 | P1 会话设计，不能标匿名可用 |
| Snapchat Spotlight | `SnapchatSpotlight` | 失败 | 上游测试样本已 404 | P1，先取得授权新鲜样本 |
| Likee | `likee` | 失败 | 当前页面无法提取 `window.data` | P2，独立 schema 研究 |
| 美拍 | `Meipai` | 失败 | 页面未返回可用视频格式 | P3，陈旧实现，不建 Profile |
| Rumble | `RumbleEmbed` | 失败 | 当前出口收到 403 | P2，先区分出口与 extractor 回归 |
| Tumblr | `Tumblr` | 失败 | 当前出口/代理连接失败 | P2，补固定出口 canary |
| Bluesky | `Bluesky` | 失败 | 上游样本的公开 API 返回 400 | P2，取得新鲜样本后复验 |

探测结果说明“上游有测试”与“今天仍可用”是两个不同事实。平台状态 API 必须继续以真实 canary 聚合为准。

## 4. 平台分组

### 4.1 已登记，优先补证据

| 平台 | 现有入口 | 主要问题 | 下一步 |
| --- | --- | --- | --- |
| TikTok | 固定 yt-dlp + Provider Profile | WAF、区域、可选会话、图集与视频需区分 | 公开单视频完整下载 canary |
| YouTube Shorts | YouTube Profile | 当前出口 `access_required`，可能涉及 Cookie/PO Token/IP | 复用 005 的受控会话方案，不另建 Shorts Provider |
| Instagram Reels | Instagram Profile | 登录墙、匿名频控、carousel 多资产 | 单 Reel 成功/登录墙/private 三类 canary |
| Facebook Reels | Facebook Profile | Relay schema、登录墙、CDN 403 | 公开 Reel 完整下载和重解析一致性 |
| X / Twitter | X Profile | guest/auth 分支、敏感内容和 protected 内容 | 公开单 tweet 视频 canary |
| Reddit | Reddit Profile | 匿名 `loid`、processing 延迟、private/quarantine | 公开 `v.redd.it` 单帖 canary |
| Pinterest | Pinterest Profile | 视频 Pin 与图片 Pin 混合 | 视频 Pin 正例、图片 Pin 负例 |
| Vimeo | Vimeo Profile | Referer、密码、登录和数据中心出口 | 只验公开、无密码单视频 |
| 微博 | Weibo Profile | 页面 schema、视频/图文混合 | 公开单视频正例与图文负例 |

这些平台不应重复增加 Profile。应先补 canary、错误分类和状态证据，再根据真实失败决定是否需要可信插件。

### 4.2 已评估的 Profile 候选

| 平台 | 建议入口 | 首期范围 | 硬边界 |
| --- | --- | --- | --- |
| AcFun | `www.acfun.cn/v/ac{id}` | 产品范围排除 | 域名 fail closed，不接入 |
| Rutube | `rutube.ru/video/{id}` / embed | 产品范围排除 | 域名 fail closed，不接入 |
| VK Clips | `vk.com/clip...`、公开 `video...` | 产品范围排除 | 域名 fail closed，不接入 |
| PeerTube | 每个批准实例的 watch/embed URL | 公开单视频 | 禁止通配任意实例，防 SSRF、DNS rebinding 和恶意 manifest |
| Snapchat Spotlight | `snapchat.com/spotlight/{id}` | 公开 Spotlight 单视频，2026-08-12 已完成 metadata + 完整媒体复验 | Story、账号页、过期内容和登录内容不纳入 |

Snapchat 固定 extractor 的官方公开测试样本在 2026-08-12 仍可用，已完成完整媒体、ffprobe 与 hash 复验并新增严格 Spotlight Profile；生产持续探针仍需项目自有或明确授权样本。

### 4.3 需要会话或可信插件

| 平台 | 社区证据 | 风险 | 决策 |
| --- | --- | --- | --- |
| 西瓜视频/头条视频 | yt-dlp 与 Lux 都明确依赖 Cookie | Cookie 新鲜度、短链重定向、图文/视频混合 | 设计 operator-managed 最小会话或第一方匿名 bootstrap；不接收 API 原始 Cookie |
| Likee | yt-dlp 内置实现会通过字符串改写推导另一媒体 URL | schema 已变；“无水印”URL 推导缺少稳定身份约束 | 只接受第一方页面明确给出的 canonical 视频 URL；不复制 URL 改写逻辑 |
| Threads | Lux 读取第一方 embed，但实现把图片和视频聚合为同一 parts 列表 | 单视频与 carousel 语义混合；yt-dlp 无内置 extractor | 独立可信插件只支持恰好一个视频的帖子，多资产先 fail closed |
| 好看视频 | Lux 使用 2022 年 HTML/正则路径 | 维护证据陈旧、当前页面未知 | 获取新鲜样本后独立实现，不把旧正则复制进核心 |
| Kwai 国际版 | yt-dlp 仍无专用 extractor，公开 issue 标注 geo-blocked | 与国内快手域名、页面和地域不同 | 单独 Provider；禁止把 `KuaishouPublicIE` 直接别名为 Kwai |
| Tumblr | 固定 extractor 在 Profile 级 Chrome impersonation 下通过完整媒体验证 | 主页、dashboard、多资产边界 | 已新增公开单视频 Profile；其他入口 fail closed |
| Rumble/Bluesky | 有上游实现，但当前环境分别为 HTTP 403/API 400 | 出口或 API schema | 保持研究状态，不新增已验证状态 |
| LinkedIn/Telegram/Kick | 固定 extractor 与完整媒体复验通过 | 登录/私域、合集、直播/VOD | 只新增公开单视频帖子/频道消息/Kick Clip Profile |

### 4.4 暂不支持

- 微信视频号：社区主流路径仍依赖客户端本地代理、根证书、已登录微信上下文和本地媒体转换，因此不进入产品。链接只做识别并引导合法明文文件导入；当前调研与规范见 014/024。
- ShareChat、Moj、Josh、Roposo、Chingari、Lemon8：本次未在 yt-dlp、Lux、cobalt 或 gallery-dl 中找到满足当前安全和维护门槛的完整视频实现。
- 任何仅提供“去水印 API”、需要把用户 URL 上传到公共解析站、没有清晰许可证或只发布闭源客户端的方案。
- DRM、会员、购买、private、follow-only、地域绕过和直播录制。

“暂不支持”不是永久否定；只有出现许可清晰、第一方公开页、可复现 canary 和完整媒体身份校验后才重新评审。

## 5. 开源方案评估

| 项目 | 许可证与维护 | 可借鉴能力 | 本系统采用方式 |
| --- | --- | --- | --- |
| `yt-dlp/yt-dlp` | Unlicense；仓库固定 2026-08-04 commit | 单视频 extractor、格式合并、字幕、错误语义 | 继续作为主引擎；每个平台仍需 Profile 与 canary |
| `iawia002/lux` | MIT；仓库仍更新，但部分 extractor 最后实质修改在 2022–2024 | Threads、好看、西瓜等第一方页面路径；支持站点矩阵 | 仅作独立验证和设计参考；不新增第二套运行内核 |
| `imputnet/cobalt` | AGPL-3.0；活跃 | Reels、Spotlight、Rutube Shorts、VK Clips、Bluesky 等 URL 路由矩阵 | 不调用公共实例；不复制 AGPL 代码进核心，只参考覆盖面和失败场景 |
| `mikf/gallery-dl` | GPL-2.0；活跃 | Instagram Reels、X、Pinterest、微博、Tumblr 等多资产/时间线 | 将来多资产模型成熟后评估隔离 OCI Runner；不导入核心 |
| `soimort/you-get` | MIT；仍有维护 | 中国站点的交叉验证 | 仅作 canary 对照，不替代 yt-dlp |

cobalt 官方文档明确说明托管 API 不供其他项目直接使用，若需要 API 必须自行部署或取得实例所有者许可。本系统仍坚持不使用公共第三方解析服务。

## 6. 完整视频分析约束

任何新增平台必须复用同一条链路：

```text
授权公开 URL
  → Provider 归类与重定向收敛
  → yt-dlp 或仓库可信 extractor
  → 下载前 re-inspect
  → 完整视频/音频下载与 FFmpeg 合并
  → ffprobe + 时长/轨道/大小 + SHA-256
  → MinIO 视频制品
  → RabbitMQ 异步 Analysis Worker
  → AI Agent 读取完整视频并分析分镜、高光与视觉资产
  → 数据库报告 + MinIO MD/DOCX + WebSocket 状态
```

禁止为快速接入而退化为固定间隔抽帧。Provider 只负责交付完整媒体；Agent 如何在完整视频内选择时间段、关键帧或音轨由分析设计 010/012/015 管理。

## 7. 验证门槛

每个平台从研究队列升级为 `verified` 前至少需要：

1. 当前固定 extractor 或可信插件的 URL、重定向、身份和格式单元测试。
2. 一个项目自有、明确授权或平台公开测试样本的 metadata canary。
3. 一个完整媒体下载 canary，并由 ffprobe 验证视频、音频、容器和时长。
4. 下载前 re-inspect 后格式语义稳定，最终 SHA-256 与制品记录一致。
5. 图片、carousel、private、过期、geo、DRM 和 schema 回归负例。
6. 完整视频进入 RabbitMQ/Agent，报告入库，MD/DOCX 上传 MinIO，WebSocket 状态闭环。
7. 重试复用原 analysis/task 记录，不创建新的业务任务。
8. 后端 lint、format、mypy、pytest、前端检查、Compose smoke 和 CI 全部通过。

## 8. 推荐优先级

1. P0：现有 Profile 的真实 canary——TikTok、Instagram Reels、Facebook Reels、X、Reddit、Pinterest、Vimeo、微博。
2. P1：中国增量——西瓜视频受控会话与短链。
3. P1：全球增量——批准实例 PeerTube。
4. P2：Rumble、Bluesky 的出口/schema 复验；Likee canonical 媒体插件研究。
5. P3：Threads 单视频插件、好看视频新 schema、Kwai 国际版独立 Provider。
6. 保持 unsupported：AcFun、Rutube、VK Clips、Dailymotion、NicoNico 及没有可信第一方实现的封闭 App 平台。微信视频号链接同样保持 `unsupported`；设备文件导入不改变平台状态。
