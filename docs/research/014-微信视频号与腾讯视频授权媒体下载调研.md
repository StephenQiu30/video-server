# 微信公众号文章、视频号与腾讯视频授权媒体下载调研

> 2026-08-27 修订：在产品范围缩小为“仅公开视频号单视频”、并采用匿名公开性预检与隔离运维元宝会话后，视频号最新调研结论见 [015](015-微信视频号公开分享链接服务端解析调研.md)。本文件中全面禁止元宝会话的旧结论已被该受限方案取代；MITM、第三方解析、解密与 VIP 绕过仍然禁止。

- 日期：2026-08-26
- 调研范围：GitHub 源码与许可证、微信公众号文章原生视频/视频号嵌入形态、当前仓库固定 yt-dlp、微信官方组件与运营规则、腾讯视频会员协议、腾讯云 VOD 下载/加密/访问管理文档
- 验证方式：只读源码和文档核验；未运行未知二进制，未向公共解析站提交用户链接，未使用会员账号、付费样本、DRM 许可证或内容密钥
- 对应设计：`docs/design/024-微信视频号与腾讯视频授权媒体接入设计.md`

> 本调研取代早期微信视频号 Provider 调研中关于产品化采集路径的结论。旧调研过程仅通过 Git 历史追溯；其中元宝会话、私有接口、根证书代理、页面注入、`decodeKey` 和受保护前缀转换均不再是产品实现候选。

## 1. 结论摘要

“能解析”和“允许导出”必须拆开。正确实现不等于对所有可播放内容都生成 MP4，而是先确定来源、保护状态和权利依据，再给出稳定、真实的处理结果。

| 来源 | 当前可行性 | 产品结论 |
| --- | --- | --- |
| 微信公众号公开文章中的原生 `wxv_*` 视频 | 条件可行；公开 HTML 的 inline JS 可能包含短时 `mpvideo.qpic.cn` MP4 | 新增文章容器 discovery；仅对无登录、映射无歧义、公开 clear、权利门禁通过的单项提供候选下载，多视频先选择后 inspection |
| 微信视频号公共分享链接 | 未找到官方匿名下载 API；GitHub 主流方案依赖会话、私有接口或本地拦截 | 保持 `unsupported`；只保留无登录、无解密的公共明文 Adapter 研究位 |
| 视频号创作者自有原文件或平台合法导出文件 | 高 | 复用现有浏览器 MP4 导入、quarantine、ffprobe/SHA-256 和 Artifact 链路 |
| 腾讯视频 `v.qq.com` 公开、非 DRM 单视频 | 目标可行；当前实现未过生产门禁 | 暂时把现有 Profile 从 `verified` 降为 `unknown/disabled`；只有取得公开免费正向证据，并完成对现有私有播放接口/`cKey` 机制的法务与安全批准后才恢复 |
| 腾讯视频 VIP、单片付费、会员专享或 DRM | 可识别，不能第三方明文导出 | 返回权益或 DRM 受限结果，引导腾讯视频官方播放/离线缓存 |
| 客户自有腾讯云 VOD 媒资 | 高 | 使用官方 SDK、CAM 最小权限、`SubAppId` 和 `FileId` 导出未加密源文件或处理输出 |
| 加密 HLS、Widevine、FairPlay、私有加密或未知保护 | 不应解密 | 一律 fail closed；官方 SDK 播放或由权利方提供未加密源文件 |

因此，本项目可以完成“视频号与腾讯视频的正确解析和授权下载”，但不能承诺“任意视频号链接”和“腾讯视频会员内容”都可导出为普通 MP4。会员身份赋予的是协议约定的观看/缓存权益，不自动赋予第三方服务导出、转存或再处理权。

## 2. 名词与边界

- **微信公众号文章视频**：`mp.weixin.qq.com` 公开文章可以包含公众号原生 `wxv_*`、腾讯视频 iframe、视频号 snapshot 或未知第三方 embed；它是一个多资产容器，不等同于视频号分享链接。
- **微信视频号**：常见入口包括 `weixin.qq.com/sph/...` 和微信客户端内的视频号页面。
- **腾讯视频消费站**：`v.qq.com`，包括公开、登录、VIP、单片付费和 DRM 内容。
- **腾讯云 VOD**：面向媒资所有者的云点播产品，以云账号、应用/子应用和 `FileId` 管理资产；它不是 `v.qq.com` 的会员下载 API。
- **公开明文媒体**：无需登录、付费、私有权限、地域绕过或解密即可取得，且用户有权保存的 MP4 或 clear HLS。
- **官方离线缓存**：由官方播放器 SDK 管理、可能受设备和许可证控制的缓存；不等于可导出的普通媒体文件。

## 3. 微信公众号文章与视频号 GitHub 调研

### 3.1 微信公众号文章原生视频

[`jj-cheng25/weixin-articles-mcp`](https://github.com/jj-cheng25/weixin-articles-mcp) 在本次核验的 commit `060fb3dd7e41d1c0950a19bc1367d66a6881f915` 是 MIT 项目，源码和测试展示了三类文章内嵌媒体：

- 公众号原生 `<iframe data-mpvid="wxv_*">`；公开文章 HTML 的 `mp_video_trans_info` inline JS 中可能出现多个 `mpvideo.qpic.cn/*.mp4` 短时表示；
- `v.qq.com` iframe，应转交腾讯视频来源分类，而不是由文章 Adapter 直接下载；
- `<mp-common-videosnap>` 视频号嵌入，公开页面通常只足以取得封面/描述，不能当作公众号原生 MP4。

该项目的实现按文档顺序把 native iframe 与 inline MP4 组配，并选择较低清晰度用于关键帧。这能证明页面存在可静态发现的 clear 候选，但“按顺序配对”不足以作为多视频生产身份依据，而且失败日志会包含完整短时 URL；产品不能原样复制。生产 Adapter 必须静态解析、不执行页面脚本，并且只有 `mpvid ↔ media id ↔ representation` 能明确绑定时才允许下载；映射有歧义就返回 `identity_unverified`。

[`bzd6661/wechat-article-for-ai`](https://github.com/bzd6661/wechat-article-for-ai) 在核验 commit `69de9e413cca3fe6b770c40a4dec204afd5b2b3c` 能识别 `<mpvideo>`/iframe，但依赖 Camoufox 的反检测浏览器并在首次运行下载浏览器；抽查 checkout 未发现顶层 LICENSE 文件。它可作为 DOM 形态证据，不作为依赖或生产抓取路线。第三方 `mptext` 下载 API 同样不能进入核心链，因为它会把用户文章 URL 和内容交给外部服务，且不能证明媒体导出权。

可产品化的文章路径必须限制为公开、无需 Cookie 的标准 HTTP 获取：

1. 只接受 `mp.weixin.qq.com/s/{opaque}` 或经严格 query allowlist 的公开文章 URL；不接受付费阅读票据、登录 Cookie 或验证码绕过。
2. 静态解析文章 metadata 和嵌入列表，不运行 inline JS，只解析经 fixture 固定的纯数据结构/转义。
3. 为零个、一个或多个嵌入项返回 discovery；每项标记 `official_account_native/tencent_video/wechat_channels/unknown`。
4. 多视频必须由用户选择 opaque item ref 后再 inspection；不能把文章第一个视频静默当成目标。
5. 原生视频只有在身份映射唯一、CDN host 受批准、无需 Cookie、MP4/BMFF clear、权利声明有效时才可 `downloadable`。
6. 文章需要验证码、登录、关注、付费或页面结构无法验证时 fail closed，并引导用户导入自有文件；不启用 stealth 浏览器。

因此，微信公众号文章原生 clear 视频可以作为独立 `wechat_official_account_article` 候选 Provider；文章只是 discovery 容器，真正的下载身份是选中的嵌入项。该能力仍需用项目自有/明确授权的单视频、多视频和受限文章完成真实 canary，不能仅凭 GitHub fixture 标为已支持。

### 3.2 视频号共同技术事实

当前 yt-dlp 没有微信视频号 extractor。活跃社区项目主要分为两类：

1. **分享链接 + 登录会话**：使用腾讯元宝或视频号网页的登录 Cookie，调用未公开接口，把 `weixin.qq.com/sph/...` 转换为短时媒体 URL；部分媒体还需要本地处理保护前缀。
2. **微信客户端 + 本地代理**：安装本地根证书、修改系统代理、拦截微信页面/API、注入脚本取得短时 URL 和处理参数，再在本机下载或转换。

两类方案都证明“在已有播放会话中，技术上能够取得媒体制品”，但不能证明存在官方、匿名、稳定、允许第三方产品调用的下载接口。公共 Cloudflare Worker 只是把运营者 Cookie 和私有接口隐藏在远端，不是无会话方案。

### 3.4 官方能力和规则

- 微信官方 [`channel-video`](https://developers.weixin.qq.com/miniprogram/dev/component/channel-video.html) 组件提供小程序内播放和无弹窗跳转，需要 `feed-id/finder-user-name` 或 `feed-token`，并对同主体/非同主体有约束；文档没有提供媒体下载 URL 或第三方导出 API。
- [微信视频号运营规范](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=video) 明确要求遵守相关协议，并禁止未经书面许可使用插件、外挂或其他第三方工具接入微信及相关系统。
- 未找到面向普通第三方服务、可匿名输入 `sph` 链接并合法返回完整 MP4 的官方 API，也未找到通用的创作者批量原片导出 API 文档。

因此，当前唯一可直接产品化的视频号制品入口，是用户提供其自有原文件或通过官方功能合法取得的明文文件。若未来获得微信书面授权、内容合作协议或正式开放 API，应作为新的 `official_connector` 单独评审，不能把现有私有接口包装成“官方能力”。

## 4. 腾讯视频 GitHub 调研

### 4.1 当前 yt-dlp Tencent extractor

仓库固定 yt-dlp `2026.07.04`；其 [`Tencent extractor`](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tencent.py) 支持 `v.qq.com/x/page/{vid}`、单集 `x/cover/{cid}/{vid}` 和剧集页：

- 从页面获取元数据，再调用消费端播放信息接口；
- 解析 HLS 或临时 MP4；
- 遍历接口声明的清晰度；
- 把接口中的 DRM 标记转换为 `has_drm`；
- 识别地域版权限制。

它没有腾讯视频登录、会员权益验证、会话刷新或 VIP 下载实现。全局传入 Cookie 也不会把它变成受支持的 VIP 导出器。当前固定版本还会在 extractor 内用硬编码参数生成消费端 `cKey`、请求未公开播放信息接口，并在请求中声明 DRM 能力；输出只提供 DRM 标记，没有可靠的 `public/free/VIP/purchase/preview` 正向权益证据。它曾出现页面 Pinia 结构变化导致失败的 [yt-dlp #8551](https://github.com/yt-dlp/yt-dlp/issues/8551)，也有 CDN 限速问题 [#8171](https://github.com/yt-dlp/yt-dlp/issues/8171)。

因此，仓库当前把 `qqvideo-public-video-v1` 静态标为 `verified` 缺少足够证据，并且与“不生成消费端私有签名”的安全边界冲突。正确的 Phase 0 是先降级或关闭生产下载，而不是在现有 extractor 之上补更多 Cookie、签名或参数复刻。后续只有在法务/安全明确批准上游机制、Provider 能给出公开免费正向证据、完整负例门禁通过时，才把它作为公开视频实现候选恢复。

### 4.2 其他社区实现

- [`iawia002/lux`](https://github.com/iawia002/lux/blob/master/extractors/qq/qq.go) 和 [`soimort/you-get`](https://github.com/soimort/you-get/blob/develop/src/you_get/extractors/qq.py) 主要使用更旧的播放信息/分片接口，没有现代 VIP 权益和 DRM 流程。
- 多个“解析 API”仓库复制旧代码，要求完整会员 Cookie、构造消费端私有参数、依赖外部签名服务，甚至包含示例会话值。抽查文件的实质提交多停留在 2020–2021 年，不适合作为安全或稳定基础。
- GitHub 搜索到的大量同名文件是旧实现的 fork/复制，仓库更新时间不能代表腾讯解析代码本身仍在维护。

可复用的是“固定 URL admission → 元数据 → 格式/保护分类 → 下载前重解析 → 完整性验证”的抽象，而不是旧 Cookie 字段、签名算法或私有接口参数。

## 5. 腾讯官方边界

### 5.1 消费端会员

[腾讯视频系列会员服务协议](https://film.qq.com/weixin/term.html) 把 1080P、内容提前看和缓存等定义为平台内会员权益；协议同时说明，即使内容已下载或缓存到本地，内容下线后仍可能无法观看，并明确排除以破解、转译、转录等方式把会员服务与官方指定程序分离的行为。会员服务是个人、不可转让、非商业和可撤销的服务。

所以产品不能把“用户输入自己的 VIP Cookie”设计成第三方明文下载授权，也不能导出官方 App 的受保护缓存。对 VIP URL 可做公开页面元数据和保护状态解析：`AccessDecision=playback_only`，`EntitlementState=entitlement_required/purchase_required`；若另有 DRM 证据则独立记录 `ProtectionState=drm`。这些维度不能混成一个状态。

### 5.2 腾讯云 VOD 自有媒资

腾讯云为媒资所有者提供正式导出能力：

- [下载媒体文件](https://cloud.tencent.com/document/product/266/84093) 支持源文件、普通转码、自适应码流、截图和封面等处理输出；可通过 `DescribeMediaInfos` 或 `SearchMedia` 获取 URL。
- [`DescribeMediaInfos`](https://cloud.tencent.com/document/api/266/31763) 返回基础信息、元数据、转码和自适应码流等媒资信息。
- [VOD 访问管理](https://cloud.tencent.com/document/product/266/39337) 的资源授权粒度是应用/子应用，不支持细到单个媒体文件；生产连接应使用专用 `SubAppId` 和只读 CAM 策略。
- [下载文档](https://cloud.tencent.com/document/product/266/84093) 明确说明，加密视频下载后仍是加密文件；HLS 需要索引和全部分片，若需要单文件应由资产所有者先生成 MP4 处理输出。
- [MultiDRM 指南](https://cloud.tencent.com/document/product/266/79727) 和播放器能力把 Widevine/FairPlay、私有 HLS 和安全离线播放定义为受保护播放链，而不是明文导出链。
- 官方 [`TencentCloud/tencentcloud-sdk-python`](https://github.com/TencentCloud/tencentcloud-sdk-python) 使用 Apache-2.0，可作为连接器 SDK 候选，但仍需固定版本、SBOM 和最小权限配置。

这条路径只适用于客户自己云账号/子应用内的 `FileId`。`v.qq.com` 的视频 `vid` 不能转换成 VOD `FileId`，也不能使用云 API 导出腾讯视频平台版权内容。

## 6. 保护状态判定

M3U8 不必然等于 DRM，但任何加密或保护状态不明都不能继续下载：

| 证据 | 判定 | 行为 |
| --- | --- | --- |
| 明文 MP4，容器/轨道无加密标记 | `clear` | 经过权利门禁后允许 |
| HLS 无 `EXT-X-KEY/SESSION-KEY`，所有分片为批准的公共 URL | `clear_hls` | 有界下载并 remux |
| HLS AES/SAMPLE-AES、私有加密 | `encrypted` | 拒绝，不请求 key |
| DASH `ContentProtection`、Widevine/FairPlay、BMFF `pssh/encv/enca` | `drm` | 拒绝，不请求许可证 |
| 媒体保护证据不足或 BMFF 有界探针无法完整扫描 | `unknown` | fail closed，不退化为全量下载 |

`preview_only` 属于 `EntitlementState`，不是保护状态；`mpvid/media/representation` 无法唯一绑定属于 `IdentityState=ambiguous/unknown`。只有权益为 `public_free/official_download_grant`、身份为 `verified` 且保护为 `clear/clear_hls` 时才能进入下载。直连 BMFF 可在上述权益/身份正向通过后读取固定预算的 head/tail range 做保护探针，临时字节不进入 quarantine 或 Artifact。

当前仓库 `enforce_media_rights()` 对 DRM 始终拒绝，但 private/premium/member 判定只在 `operator_managed` 路径执行。匿名 `qqvideo` 必须补上等价的 Provider 权益分类，否则可能把试看流或缺少保护证据的格式当作公开正片。仅移动现有判断仍不够：若上游没有提供可验证的公开免费证据，结果必须是 `entitlement_unknown`，不能用“未观察到限制字段”推定可下载。

| 能力 | 当前阶段结论 | 后续条件 |

## 8. GitHub 代码复用结论

1. 固定并继续审计 yt-dlp，但当前 Tencent extractor 只作为研究候选；在私有 `cKey` 机制获批且公开免费证据门禁完成前，不作为生产下载器，不新增腾讯会员 Cookie Runner。
2. 使用腾讯云官方 SDK 实现自有媒资连接器，不使用消费端旧解析 API 代替。
3. 微信公众号文章 Adapter 可参考 `weixin-articles-mcp` 的 DOM/fixture 分类，但必须独立实现身份绑定、URL 脱敏和安全下载；不采用顺序猜测、最低清晰度假定或含签名 URL 的异常日志。
4. 视频号社区仓库只用于维护风险、错误分类、URL 形态和 UX 研究；不复制私有接口、证书、代理、注入或解密代码。
5. 不调用公共解析站、公共 Worker、外部签名服务和来历不明的 DLL/WASM。
6. 任何 vendor 代码都必须固定 commit、确认逐文件许可证/来源、生成 SBOM，并通过独立安全审查。

## 9. 最终判断

- **微信公众号文章原生视频**：可以建设公开文章 discovery 和条件 clear 下载，但必须把文章内原生视频、腾讯 iframe、视频号嵌入分别路由；多视频先选择，身份映射不明、挑战页或受限页面一律关闭。
- **微信视频号**：现阶段无法在安全、稳定、授权清晰的前提下承诺“任意分享链接直接下载”。可立即提供的是创作者自有/合法导出 MP4 的可靠导入；公共明文分享 Adapter 保持研究和 feature flag 状态。
- **腾讯视频公开内容**：目标上可以支持，但当前固定 extractor 不能继续按 `verified` 发布；必须先解决私有签名边界并把公开、试看、VIP、购买、地域、DRM 和未知保护严格分开。
- **腾讯视频 VIP**：正确实现是解析并返回受限原因，然后交给官方播放/离线缓存；不是上传 Cookie 后导出明文。
- **客户自有腾讯媒资**：腾讯云 VOD 官方 API 是完整、可维护、可审计的下载路径，也是本设计中“付费/受控内容”唯一可以自动导出的腾讯路径，前提是客户本身是媒资所有者或获得合同授权。
