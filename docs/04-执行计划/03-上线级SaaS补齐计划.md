# 上线级 SaaS 补齐计划

更新时间：2026-05-02

## 1. 执行边界

本计划只管理“小范围内测 SaaS”的生产化补齐，不替代 M1 本地 MVP 计划。M1 未完成项继续由 OpenSpec 变更 `bootstrap-mvp-foundation` 收尾；上线级 SaaS 补齐由 OpenSpec 变更 `production-saas-readiness` 管理。

当前上线基线：

- 小范围内测 SaaS。
- 免费配额，不接入支付。
- 单机 Docker Compose + Nginx/TLS。
- 不做 AI 摘要、平台专用解析、Cookie 托管、支付会员、K8s。

## 2. P0：收尾 M1 未完成项

目标：确保本地 MVP 主链路真实可验收，再进入生产化补齐。

任务：

- 补齐至少 3 个合法公开视频解析样例。
- 保留至少 1 个小文件完整下载样例，并记录 ffprobe 校验证据。
- 验证 DRM、付费墙、私密链接、Cookie 托管、平台绕过能力未实现。
- 保持后端测试、API smoke、Worker smoke、前端 lint/build 和 OpenSpec validation 通过。

退出标准：

- `bootstrap-mvp-foundation` 中 M1 验收项均有验证证据。
- docs 中能追溯样例 URL、执行命令、返回结果和失败边界。

## 3. P1：SaaS 内测能力

目标：让公网小范围内测可控，不被开放注册和下载资源消耗拖垮。

任务：

- 增加注册开关或邀请码。
- 增加用户免费配额：每日任务数、并发数、最大文件大小、保留时间、总存储占用。
- 增加接口限流和配额超限错误。
- 增加最小管理员能力：用户列表、任务列表、配额调整、禁用用户、滥用任务查看。
- 前端展示配额、剩余额度、任务失败原因和下载链接过期状态。

退出标准：

- 普通用户无法越权访问其他用户任务。
- 配额触发后返回明确错误。
- 管理员可以禁用异常用户并调整配额。
- 前端能解释配额不足、任务失败、链接过期和未登录状态。

## 4. P2：单机上线部署

目标：形成第一版可重复部署的生产基线。

任务：

- 补齐 Web、API、Worker、PostgreSQL、Redis、MinIO 的单机 Compose 编排。
- 补齐 Nginx 反向代理和 HTTPS/TLS 配置说明。
- 补齐生产环境变量模板和危险默认值检查。
- 补齐 PostgreSQL 备份恢复、Redis 持久化、MinIO 生命周期清理。
- 补齐 API、Worker、对象存储、数据库和队列的健康检查。

退出标准：

- 一台服务器可以按文档启动完整服务。
- HTTPS 入口能访问前端和 API。
- `/health`、`/ready`、Worker 日志和对象存储检查均可验证。
- 生产密钥、数据库密码、MinIO 凭证未替换时不得作为上线通过。

## 5. P3：上线门禁与运维

目标：让每次上线都有自动化和人工验收依据。

任务：

- 增加 CI/CD：后端测试、前端 lint/build、OpenSpec validation、Compose config 校验。
- 增加结构化日志和敏感字段脱敏检查。
- 增加基础运行指标：API 健康、队列深度、任务失败数、存储占用、清理结果。
- 增加服务条款、隐私说明、滥用举报和内容投诉处理边界。
- 增加合规负向样例验收。

退出标准：

- 每次上线前能通过测试、构建、OpenSpec 和部署配置校验。
- 出现下载失败、配额超限、队列异常或存储异常时，有日志和排查入口。
- 合规禁止能力均有负向验收记录。

## 6. 执行规则

- 所有生产化实现先进入 `production-saas-readiness` 任务，不直接改 M1 范围。
- 每个阶段必须有可执行验收命令或可观察证据。
- 如果某一项无法验证，不能标记为完成。
- 未经项目负责人确认，不得新增支付、会员、K8s、复杂团队权限、Cookie 托管或平台专用解析。
