# 执行计划

更新时间：2026-05-02

## 1. 当前阶段

当前阶段已完成“调研、边界确认、技术选型确认”。下一阶段可以进入 M1 MVP 骨架，但仍必须遵守合规边界和已确认技术栈。

## 2. 总体里程碑

| 阶段 | 目标 | 主要产物 | 退出标准 |
| --- | --- | --- | --- |
| M0 调研与确认 | 明确市场、范围、合规、技术候选 | docs、AGENTS、.codex 角色定义 | 已完成：关键选型已由项目负责人确认 |
| M1 MVP 骨架 | 初始化前后端、任务模型、下载 Worker | 可运行的最小服务 | 本地可粘贴公开视频链接并创建任务 |
| M2 下载闭环 | 完成解析、格式选择、下载、进度、历史 | Web 工作台 + API | 至少 3 个公开样例跑通 |
| M3 稳定性 | 错误分类、重试、限流、日志脱敏 | 验收脚本、错误手册 | 可解释大多数失败原因 |
| M4 增强能力 | 字幕、音频提取、AI 摘要、素材库 | 插件化能力 | 用户能完成下载后的内容整理 |
| M5 生产化 | 鉴权、配额、对象存储、多 Worker | 部署手册、监控 | 可受控公网或私有部署 |

## 3. M0 详细任务

- 完成市场调研和竞品对照。
- 明确首版产品定位和非目标范围。
- 列出关键技术候选并完成项目负责人确认。
- 写入项目协作规范。
- 写入角色定义和执行策略。
- 技术栈已由项目负责人确认，详见 `docs/03-架构设计/02-技术选型候选.md`。

## 4. M1 详细任务

前置条件：技术栈已确认。

- 初始化代码结构。
- 定义下载任务数据模型。
- 定义 API 合同：解析、创建任务、查询任务、取消任务、下载文件。
- 封装下载内核适配层。
- 建立本地 Docker 运行方式。
- 建立基础测试和格式化命令。

## 5. M2 详细任务

- 链接解析和平台识别。
- 解析视频元数据与格式列表。
- 选择格式后创建下载任务。
- Worker 执行下载、合并、落盘。
- 前端展示任务状态和进度。
- 下载完成后提供文件。
- 失败原因分类：不支持平台、网络错误、格式不可用、文件过大、处理超时。

## 6. M3 详细任务

- 限制任务大小、时长、并发、超时。
- 增加重试策略。
- 增加日志脱敏。
- 增加清理任务：过期文件自动删除。
- 增加验收样例集。
- 编写部署和排障文档。

## 7. M4 详细任务

- 字幕提取与导出。
- 音频提取。
- AI 摘要、章节、问答。
- 下载历史和本地素材库。
- 文件命名模板。
- 批量下载，但必须有并发和频率限制。

## 8. 角色协作策略

角色协作策略已拆分到 [02-角色协作策略.md](02-角色协作策略.md)，并与 `.codex/agents/` 保持一致。

## 9. 风险检查清单

进入实现前必须确认：

- [x] 技术栈已经由项目负责人确认。
- [x] UI 组件库已经由项目负责人确认。
- [ ] MVP 不包含未经确认的平台专用解析。
- [ ] 合规声明已经进入产品文案和接口错误。
- [ ] 下载任务有大小、并发、时长和过期清理限制。
- [ ] 日志不会泄露 Cookie、token、签名 URL。
- [ ] 失败原因可以被用户理解。
- [ ] 项目不承诺支持所有平台。

## 10. 下一步建议

下一步进入 M1 初始化和 MVP 骨架：

1. 初始化 React + Umi + TypeScript 前端，并接入 Ant Design Pro。
2. 初始化 FastAPI + Python 3.12 后端。
3. 初始化 RQ Worker、Redis、PostgreSQL、MinIO / S3 兼容对象存储。
4. 定义解析、任务、下载、鉴权的最小 API 合同。
5. 建立 Docker Compose 本地运行方式。
6. 按 OpenSpec `bootstrap-mvp-foundation` 推进 M1 proposal、design、specs、tasks。
