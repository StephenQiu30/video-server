更新时间：2026-05-02

## 1. 当前阶段

当前阶段已完成“调研、边界确认、技术选型确认”。M1 已开始后端骨架实现，当前已落地 FastAPI API、RQ Worker、PostgreSQL、Redis、MinIO / S3 私有存储、JWT 用户系统、本地开发脚本和 Docker 部署基线。

当前没有新增产品需求需要再确认。后续执行应继续围绕已确认的 M1 范围推进，不新增平台专用解析、不新增 Cookie 托管、不新增 AI 摘要、不新增支付或会员能力。

## 4.2 直接执行计划

在没有新增需求的前提下，下一步直接按以下顺序执行：

1. 补齐至少 3 个合法公开视频解析样例，并验证 `POST /api/parse`。
2. 补齐后端负向自动化：重复邮箱、密码错误、未登录、跨用户访问、队列不可用、过期文件。
3. 做前后端联调验收：启动 API、Worker 和 Web，完成登录、解析、创建任务、查看任务、获取下载链接。
4. 做 M1 闭环验收：本地完成 API smoke、前端基本操作、任务状态流转、对象存储下载链接和合规负向样例检查。
5. 更新 OpenSpec 任务状态：只勾选已经通过验证的任务，未跑通的端到端链路保持未完成。
6. 前端和后端本地闭环稳定后，再单独规划 Docker 部署模式；当前 M1 不把上线容器验收作为阻塞项。

## 5. M2 详细任务

- 链接解析和平台识别。
- 解析视频元数据与格式列表。
- 选择格式后创建下载任务。
- Worker 执行下载、合并、落盘。
- 前端展示任务状态和进度。
- 下载完成后提供文件。
- 失败原因分类：不支持平台、网络错误、格式不可用、文件过大、处理超时。

- 增加日志脱敏。
- 增加清理任务：过期文件自动删除。
- 增加验收样例集。
- 编写部署和排障文档。

## 11. 上线级 SaaS 补齐计划

上线级 SaaS 内测版不并入 M1 本地 MVP 计划，单独由 OpenSpec 变更 `production-saas-readiness` 管理。详细计划见 [03-上线级SaaS补齐计划.md](03-上线级SaaS补齐计划.md)。

已确认边界：

- 小范围内测 SaaS。
- 免费配额，不接入支付。
- 单机 Docker Compose + Nginx/TLS。
- 不做 AI 摘要、平台专用解析、Cookie 托管、支付会员、K8s。

执行时必须先收尾 M1 未完成验收项，再进入注册控制、免费配额、管理员兜底、部署、监控和合规门禁。
