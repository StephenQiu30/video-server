# PLAN03 平台画像注册与识别

## 1. 背景

首版需要把"支持哪些平台"变成稳定可测的系统能力，而不是只在 README 里写一句话。

当前代码已实现 10 个平台画像注册（`PLATFORM_PROFILES`）和平台识别（`find_platform_profile`），本计划以此为准进行规范化。

## 2. 目标

1. 固化 10 个正式支持平台画像，覆盖三类平台分类。
2. API 使用统一 `platform_id`、`platform_category`、`compliance_note` 字段。
3. 水印提示规则与平台分类绑定。

## 3. 非目标

- 不承诺所有已识别平台都能成功下载。
- X（Twitter）和 Instagram 暂不列入首版。

## 4. 核心内容

### 4.1 平台画像注册表

`apps/api/app/services/platforms.py` 中的 `PLATFORM_PROFILES` 包含 10 个平台画像：

| 分类 | platform_id | display_name |
| --- | --- | --- |
| long_video | bilibili | B 站 |
| long_video | youtube | YouTube |
| long_video | vimeo | Vimeo |
| long_video | dailymotion | Dailymotion |
| domestic_short_video | douyin | 抖音 |
| domestic_short_video | kuaishou | 快手 |
| domestic_short_video | xiaohongshu | 小红书 |
| domestic_short_video | ixigua | 西瓜视频 |
| domestic_short_video | weibo | 微博 |
| short_video | tiktok | TikTok |

### 4.2 平台识别逻辑

1. `find_platform_profile(url)` 根据 URL hostname 匹配平台画像。
2. `validate_supported_download_url(url)` 在匹配失败时检查是否为 blocked host。
3. 未匹配的公开 host 允许 yt-dlp best-effort 处理。

### 4.3 适配器路由

| 适配器 | 覆盖平台 |
| --- | --- |
| DomesticShortVideoAdapter | douyin, kuaishou, xiaohongshu, ixigua, weibo |
| BilibiliAdapter | bilibili |
| YtDlpAdapter（fallback） | youtube, vimeo, dailymotion, tiktok 及其他 |

### 4.4 合规提示分组

| 合规提示 | 适用平台 |
| --- | --- |
| BILIBILI_COMPLIANCE_NOTE | bilibili |
| DOMESTIC_SHORT_VIDEO_COMPLIANCE_NOTE | douyin, kuaishou, xiaohongshu, ixigua, weibo |
| DEFAULT_COMPLIANCE_NOTE | youtube, vimeo, dailymotion, tiktok |

### 4.5 水印提示

| 提示 | 平台 |
| --- | --- |
| "可能含平台水印" | douyin, kuaishou, tiktok |
| "优先可用源" | bilibili, youtube, vimeo, dailymotion |
| "不可确认" | xiaohongshu, ixigua, weibo |

## 6. 验收门禁

- 10 个正式支持平台均可被识别。
- 平台画像字段（id、display_name、category、compliance_note）稳定。
- API 返回的 platform_id、platform_category、compliance_note 与画像一致。
- 水印提示与平台分类正确绑定。

## 7. 风险与边界

平台域名和跳转链接形式可能变动，测试样例应覆盖常见 URL 形态。

## 8. 待确认问题

- X（Twitter）和 Instagram 是否在后续版本加入正式支持清单。
