# 子计划 2：解析安全与错误语义

## 1. 背景

PRD001 要求系统在入口处拒绝无效 URL、本机地址、内网地址和保留地址，并将解析失败按业务错误码分类，同时确保错误响应不泄露敏感参数。

当前 `apps/api/tests/test_url_normalization.py` 已覆盖基本的 trim、协议补全和非法 scheme 拒绝，`apps/api/tests/test_parse_error_classification.py` 已覆盖登录、DRM、限流和不支持 URL 的错误分类。

本计划补充内网/保留地址拒绝、错误码完整性、敏感参数脱敏等安全边界。

## 2. 目标

```gherkin
Given 用户输入包含内网地址、保留地址或敏感参数的 URL
When 系统执行 URL 校验或错误分类
Then 无效 URL、本机地址、内网地址和保留地址被拒绝
And 登录、会员、验证码、限流、暂不支持和普通解析失败映射到清晰业务错误码
And 错误响应不泄露 token、signature、auth、cookie、key、access_token、session 等敏感参数
```

### 2.1 验收标准

- 无效 URL、本机地址、内网地址和保留地址被拒绝。
- 登录、会员、验证码、限流、暂不支持和普通解析失败映射到清晰业务错误码。
- 错误响应不泄露 token、signature、auth、cookie、key、access_token、session 等敏感参数。
- 先提交失败测试，再提交最小实现，验证命令通过。

## 3. TDD 执行计划

### 3.1 红灯阶段（test:）

扩展 `apps/api/tests/test_url_normalization.py`：

1. **本机地址拒绝**：断言 `http://localhost/video` 和 `http://127.0.0.1/video` 被拒绝。
2. **内网地址拒绝**：断言 `http://10.0.0.1/video`、`http://172.16.0.1/video`、`http://192.168.1.1/video` 被拒绝。
3. **保留地址拒绝**：断言保留 IP 段被拒绝。

扩展 `apps/api/tests/test_parse_error_classification.py`：

4. **会员内容分类**：断言 "members only" / "premium" 映射到 `platform_restricted`。
5. **验证码分类**：断言 "captcha" / "verification" 映射到 `platform_rate_limited`。
6. **敏感参数脱敏**：断言包含 `token=xxx`、`access_token=yyy` 的 URL 在错误响应中被脱敏。

### 3.2 绿灯阶段（impl:）

调整 `apps/api/app/utils/url.py`：

1. 在 `normalize_user_url` 中增加内网地址、本机地址和保留地址检测。

调整 `apps/api/app/services/download_adapter.py`：

2. 在错误分类逻辑中补充会员、验证码的错误码映射。
3. 在错误响应生成时对敏感参数进行脱敏。

### 3.3 重构阶段

- 在测试保护下提取内网检测为独立工具函数。
- 确保脱敏逻辑集中在一处，避免分散。
