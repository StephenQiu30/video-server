# PLAN06 取消、重试与事件流

## 1. 背景

如果没有事件流、取消和重试能力，用户只能被动等待失败，系统也缺少可追踪过程。

## 2. 目标

1. 支持取消和重试。
2. 关键状态流转写入 `task_events`。

## 3. 非目标

- 不实现 SSE 推送。

## 4. 核心内容

### 4.1 取消流程

1. API 接收 `POST /api/tasks/{task_id}/cancel` 请求。
2. 调用 `get_owned_task` 校验任务存在性和所有权。
3. 调用 `cancel_task` 执行取消逻辑：
   - 校验状态：仅 `queued` 和 `running` 允许取消
   - 设置 `state = CANCELED`，`failure_reason = "用户已取消任务"`
   - 清除 `failure_code`（取消不是失败）
   - 写入 `task_events` 记录
4. Worker 侧需定期检查任务取消标志（通过数据库轮询或 Redis 标志）。

### 4.2 重试流程

1. API 接收 `POST /api/tasks/{task_id}/retry` 请求。
2. 调用 `get_owned_task` 校验任务存在性和所有权。
3. 调用 `retry_task` 执行重试逻辑：
   - 检查 `retry_superseded`：同一任务不能重复重试
   - 校验状态：`failed`、`canceled` 可直接重试；`succeeded` 仅当产物已过期
   - 检查并发限制：`assert_concurrency_allowed`
   - 创建新任务：`retry_of_task_id` 指向原任务，`attempt_no + 1`
   - 保留字段：`source_url`、`title`、`cover_url`、`duration_seconds`、`format_id`、`format_label`
   - 写入 `task_events`（新任务和原任务各一条）
4. 新任务入队 Redis Queue。

### 4.3 事件流机制

1. `add_task_event(db, task, state, message)` 写入 `task_events` 表。
2. 每条事件包含：`task_id`、`state`、`message`、`created_at`。
3. 事件按 `created_at` 升序排列，不可修改。
4. API 通过 `GET /api/tasks/{task_id}/events` 暴露事件列表。

### 4.4 关键实现文件

| 文件 | 职责 |
| --- | --- |
| `apps/api/app/routers/tasks.py` | 取消和重试端点 |
| `apps/api/app/services/tasks.py` | `cancel_task`、`retry_task`、`add_task_event` |
| `apps/api/app/models.py` | `TaskEvent` ORM 模型 |

### 4.5 TaskEvent 数据库模型

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 自增主键 |
| `task_id` | FK → download_tasks | 所属任务 |
| `state` | string | 事件发生时的状态 |
| `message` | string nullable | 事件描述 |
| `created_at` | datetime | 事件时间 |

### 4.6 重试任务数据继承

| 字段 | 是否继承 | 说明 |
| --- | --- | --- |
| `source_url` | 是 | 原始视频 URL |
| `title` | 是 | 视频标题 |
| `cover_url` | 是 | 封面 URL |
| `duration_seconds` | 是 | 视频时长 |
| `format_id` | 是 | 格式 ID |
| `format_label` | 是 | 格式显示名 |
| `user_id` | 是 | 任务所有者 |
| `retry_of_task_id` | 新设 | 指向原任务 |
| `attempt_no` | 新设 | 原任务 + 1 |
| `state` | 新设 | `queued` |
| `progress` | 新设 | 0 |
| `failure_code` | 否 | 清空 |
| `failure_reason` | 否 | 清空 |
| `object_key` | 否 | 清空 |

## 6. 验收门禁

- 失败任务可重试。
- 可取消状态清晰可测。
- 关键事件可追踪。
- 重试创建新任务，不覆盖原任务。

## 7. 风险与边界

取消和重试如果没有状态约束，容易导致重复消费或数据污染。

## 8. 待确认问题

- 重试是复用原任务还是新建任务。
