# PLAN09 本机开发与依赖复用

## 1. 背景

研发阶段更需要快速调试，而不是每次都拉起整套容器。

## 2. 目标

1. 复用已有 Redis、Postgres、MinIO，无需额外容器。
2. 支持本机启动 API（含热重载）与 Worker。
3. 缺失依赖时给出可操作提示。

## 3. 非目标

- 不在本计划中完善 Docker Compose。

## 4. 核心内容

1. 本机环境变量来自 `.env`，首次启动时 `scripts/start.sh` 自动从 `.env.example` 复制创建。
2. 依赖安装：`npm run dev:install` 执行 `scripts/dev_install.sh`，通过 pip 安装 `apps/api/requirements.txt`。
3. PYTHONPATH 设置：API 需要 `apps/api:packages/shared`，Worker 额外需要 `apps/worker`。由 `scripts/dev_api.sh` 和 `scripts/dev_worker.sh` 自动导出。
4. 依赖探测：`npm run check:local` 执行 `scripts/check_local_services.sh`，读取 `.env` 中的 `DATABASE_URL`、`REDIS_URL`、`S3_ENDPOINT_URL` 并打印连接信息。
5. 端口冲突检测：`scripts/start.sh local` 启动前通过 `lsof`/`ss`/`netstat` 检查 `API_PORT` 是否被占用，冲突时给出提示并支持 `API_PORT=8001` 覆盖。
6. 启动命令：`npm run dev`（仅 API）或 `npm run dev:all`（API + Worker），底层调用 `scripts/start.sh local` / `scripts/start.sh local:worker`。
7. 验证：`curl http://127.0.0.1:8000/health` 检查 API 存活，`curl http://127.0.0.1:8000/ready` 检查全部组件就绪。

## 6. 验收门禁

- 本机开发路径可复用已有依赖成功启动。
- 缺失依赖时有明确提示。

## 7. 风险与边界

如果本机路径和 Docker 路径配置不一致，后续排障成本会很高。本计划只覆盖本机开发路径，Docker Compose 路径由 PLAN10 负责。
