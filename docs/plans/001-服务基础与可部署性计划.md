# Plan 001 服务基础与可部署性计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[001](../design/001-服务边界与总体架构设计.md)。
- PRD：[001](../prd/001-服务基础与可部署性需求.md)。
- 目标：建立后续功能共享的服务骨架、配置、健康检查、进程入口和本地部署基线。
- 依赖：无；这是服务端首个执行 Plan。

## 1. 任务边界

包含 Python 工程、FastAPI、配置、日志、依赖客户端、Celery 入口、Docker 镜像、Compose 和健康检查。不实现业务表、下载、AI 或完整业务 API。

## 2. 执行拆分

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | 配置缺失和非法值测试先失败 | Pydantic Settings 与环境示例 | 可验证配置契约 |
| 2 | App 创建、路由前缀和生命周期测试先失败 | FastAPI 工厂与模块结构 | API 骨架 |
| 3 | Liveness/Readiness 成功和依赖失败测试先失败 | PostgreSQL、RabbitMQ、MinIO 探针 | 健康接口 |
| 4 | Celery route 与 Worker 队列测试先失败 | Celery app、download/ai Worker 入口 | 独立 Worker |
| 5 | Compose 配置、冷启动和重启持久性检查先失败 | Dockerfile、Compose、持久卷和依赖健康检查 | 可重复启动环境 |
| 6 | Secret/日志泄露检查先失败 | 结构化日志与安全配置输出 | 安全启动行为 |

## 3. 预期文件边界

- `pyproject.toml`、锁文件、`.env.example`。
- `src/video_server/` 下 app、config、logging、health、infrastructure、worker 入口。
- `tests/` 下配置、健康、路由和进程入口测试。
- `Dockerfile`、`compose.yaml`；不创建第二套部署目录。

## 4. 验收映射

- S001-DAC-01、S001-DAC-02：任务 2、4、5 的进程、架构边界与队列运行证据。
- S001-DAC-03：任务 3 的三项真实依赖逐项停启与恢复证据。
- S001-DAC-04：任务 1、5 的锁文件、镜像构建和两次冷启动证据。
- S001-DAC-05：任务 1、6 的配置负例和 Secret 扫描。
- S001-DAC-06：完整质量命令和覆盖率报告。
- S001-AC-01、S001-AC-04：独立 API、Worker、Scheduler 进程与队列测试。
- S001-AC-02：依赖故障下的 liveness/readiness 集成测试。
- S001-AC-03：配置、镜像和日志 Secret 扫描。
- S001-AC-05、S001-AC-06：Compose 验证及服务清单检查。

## 5. 验证命令

- 依赖复现：`uv lock --check`、`uv sync --frozen`。
- 质量：`uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy --strict src`。
- 测试：`uv run pytest --cov=video_server --cov-branch --cov-fail-under=90`。
- 容器配置：`docker compose config`。
- 运行时：启动依赖后调用 `/health/live`、`/health/ready`，再逐一停止依赖验证 503。

## 6. 提交顺序

`test: 配置与应用骨架约束 → impl: 服务骨架 → test: 健康与队列约束 → impl: 依赖和进程入口 → test: 部署约束 → chore: 容器基线`

## 7. 风险与非目标

- Docker 环境和端口冲突可能阻塞运行时验证；必须记录真实依赖状态。
- 不在本 Plan 顺手实现数据库业务表、下载适配器、AI 或 Web。

## 8. 完成条件

S001-DAC-01 至 DAC-06 与 S001-AC-01 至 AC-06 必须全部 `passed`，Compose 可重复冷启动，完整质量门禁通过且工作区无生成物后，本 Plan 才可进入 Acceptance。
