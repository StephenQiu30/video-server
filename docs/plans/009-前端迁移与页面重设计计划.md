# 009 前端迁移与页面重设计计划

- 状态：Completed
- 日期：2026-08-09
- 关联 Design：`docs/design/009-Next前端与蓝白视觉系统设计.md`
- 关联 PRD：`docs/prd/009-前端体验重构需求.md`

## 实施原则

迁移以一个可独立验收的目标前端替换旧前端，不长期并行维护 Umi 与 Next。先固定契约、路由和视觉基准，再建立基础设施，随后按用户主流程迁移页面，最后切换静态托管并删除旧结构。任何阶段都不得用手写 DTO、临时兼容页面或跳过权限校验来换取表面可运行。

第二轮属于已完成迁移之上的视觉与组件收敛：不改动路由、API、权限和静态交付决策，仅以 [Vercel 首页](https://vercel.com/home)、[Geist 排版](https://vercel.com/geist/typography)、[shadcn Radix 组件](https://ui.shadcn.com/docs/components)和 [Radix Accessibility](https://www.radix-ui.com/primitives/docs/overview/accessibility) 统一画布、网格、留白和交互原语。本计划不包含部署或发布操作。

## 路由迁移清单

| 旧路由 | 目标路由/处理 | 必须保留的能力 |
| --- | --- | --- |
| `/` | `/` | URL 解析、格式选择、幂等创建任务 |
| `/history` | `/history` | 搜索、状态筛选、刷新、分页、取件/查看 |
| `/downloads/:jobId` | 308 → `/downloads/detail?jobId=<id>` | 下载轮询、取消、取件、AI 分析、思维导图 |
| `/account` | `/account` | 当前资料、用户名更新 |
| `/admin/users` | `/admin/users` | 管理员查询、筛选、分页、角色与启用状态 |
| `/user/login` | `/user/login` | 登录、Refresh Cookie、站内返回 |
| `/user/register` | `/user/register` | 用户名/邮箱注册、站内返回 |
| `*` | `not-found.tsx` / `404.html` | 真实 404 和返回首页 |

## 实施顺序

### 1. 冻结基线与契约

1. 记录当前全部路由、API 调用、权限、轮询终态、表单校验和测试覆盖，以上表格作为不得遗漏的迁移清单。
2. 将方案 2 原图作为首页视觉基准，记录其 1487×1058 原始视口；确定可重复的解析成功测试数据和 390×844 移动视口。
3. 从 FastAPI 应用导出 OpenAPI，增加“每个公开操作都有且仅有一个全局唯一 `operationId`”契约测试；先修正契约再生成客户端。
4. 在开始删除旧代码前运行当前前后端测试，区分迁移引入的失败与已有问题。

### 2. 建立 Next 静态应用骨架

1. 将前端 package scripts 切换为 Next 开发、lint、格式、测试、OpenAPI 生成与生产构建；直接依赖 `@umijs/openapi`，加入 Radix UI、Tailwind CSS 和统一图标库。
2. 建立 `src/app/layout.tsx`、路由组、`not-found.tsx`、全局 metadata、Tailwind 配置与 `globals.css` token。
3. `next.config` 启用 `output: "export"`、`trailingSlash: true` 和无需运行时图片优化的配置。此阶段即验证空页面能生成 `out/`，避免在全部页面完成后才发现静态导出不兼容。
4. 建立 `components/ui/` 的 Button、Field、Select、Dialog、Dropdown Menu、Progress、Tooltip、Toast 和 Skeleton 封装；组件源以 shadcn `radix-nova` registry 为准，保留 Radix 原生语义与焦点行为。

完成门禁：最小 App Router 构建通过，`out/index.html` 与 `out/404.html` 存在，生产依赖图中没有 Umi/Ant Design。

### 3. 解耦 OpenAPI 与请求层

1. 新增 `openapi2ts.config.ts`，schema 地址允许通过环境变量覆盖，生成路径固定为 `src/services/video/`，请求库固定为 `src/lib/request.ts`。
2. 迁移 Axios 同源实例、统一错误映射、Cookie 携带、并发 Refresh 合并和安全登录跳转；生成模板只调用该封装。
3. 运行 `npm run openapi` 重新生成全部服务；以生成类型替换旧手写接口类型，保留的业务适配层只负责输入标准化、幂等键和展示错误。
4. 增加 `openapi:check`：从当前 FastAPI 应用获取临时 schema、生成客户端并执行 `git diff --exit-code -- src/services/video`。临时 schema 不提交。

完成门禁：认证、解析、下载、历史、分析、资料和管理员调用均来自生成客户端；生成目录没有人工补丁。

### 4. 建立全局壳与认证边界

1. 实现无侧栏的 64px 发丝线 Header、品牌、历史入口、Avatar 账户 Dropdown Menu 和 Footer；管理员入口只对管理员出现，390px 下导航进入 Sheet。
2. 实现 Auth Provider/Auth Boundary，会话恢复期间使用不跳动的骨架；401 合并刷新并只重试一次。
3. 实现站内 `redirect` 校验、认证页已登录跳转、管理员角色守卫和登出。
4. 为全局 loading、toast、error summary、focus ring、skip link 和 reduced motion 建立统一行为。

完成门禁：直接刷新每个静态页面时不泄露用户数据，登录前后返回地址正确，普通用户无法渲染管理员内容。

### 5. 按主流程迁移页面

1. 首页：先实现方案 2 的 Header、Hero、URL Bar 和步骤，再迁移解析、格式单选、媒体预览、幂等创建与全部规定状态。
2. 详情：实现静态 `/downloads/detail`，从查询参数读取 `jobId`；迁移下载轮询、取消、取件、AI 分析、结果和思维导图，并清理离页轮询。
3. 历史：迁移搜索、状态筛选、刷新与分页；桌面与移动端的 Item/ItemGroup 任务列表复用同一查询状态，仅改变排列密度。
4. 登录/注册：迁移校验、错误摘要、密码可见性、提交状态和安全返回。
5. 个人资料：迁移用户名编辑与导航同步。
6. 用户管理：迁移查询、筛选、分页和 Radix Dialog 编辑，落实普通用户/自我修改限制。
7. 404：实现品牌化静态错误页和返回首页操作。

每完成一个页面即补充组件测试、键盘路径、加载/空/错误状态与 390px 布局，不把响应式集中到最后处理。

### 6. 切换 FastAPI 静态托管

1. 根 Dockerfile 改为复制 `frontend/out/`，运行镜像仍只启动 FastAPI。
2. 更新静态服务：优先处理 API/健康/文档保留路径；正确服务导出的目录索引、哈希资源和 `404.html`。
3. 在静态挂载前增加旧 `/downloads/{jobId}` 308；对 ID 做 URL 编码，排除 canonical `/downloads/detail`，并确保 `/api/downloads/*` 不被命中。
4. 增加浏览器刷新和 HTTP 集成测试：每个有限路由 200，未知 UI 404，API 未知地址返回 JSON 404，旧详情地址 308 后可加载任务。
5. 验证 HTML 与哈希静态资源缓存头，确认认证 Cookie 和 Secret 不进入导出内容。

完成门禁：统一镜像内无 Next 运行进程，FastAPI 同源完整覆盖页面、API、旧链接和真实 404。

### 7. 删除旧栈并收口规范

1. 删除 Umi config、旧 `src/pages`、旧 `app.tsx/access.ts`、Ant Design Pro 布局、Less、旧生成插件和无引用类型/测试夹具。
2. 清理 package lock、TypeScript aliases、测试配置、CI 命令、README、AGENTS 与 Docker 注释，确保只描述目标架构。
3. 用 `rg` 检查 `@umijs/max`、`antd`、`@ant-design`、`.less`、Umi 路由和旧 `/downloads/${id}` 内部导航没有残留；`@umijs/openapi` 是允许保留的唯一 `@umijs/*` 依赖。

完成门禁：没有平行页面、兼容入口或死依赖，仓库规范与实际结构一致。

### 8. 功能、无障碍与设计 QA

1. 执行前端 lint、格式、类型、单元/组件测试、OpenAPI 漂移检查和生产构建；执行后端静态服务/契约测试。
2. 在真实浏览器验证登录、注册、解析、格式选择、创建下载、详情轮询/取消/取件、分析、历史、资料和用户管理。
3. 在 1487×1058 解析成功态把方案 2 与实现截图放入同一比较输入，记录并修复 P0/P1/P2。
4. 在 390×844 逐路由验证无横向溢出、软键盘、长标题、列表替代表格、Dialog、44px 触控和 200% 缩放。
5. 使用 axe 与纯键盘验证主流程，人工复核焦点恢复、错误关联、live region 和 reduced motion。
6. 重新截图并更新根 `design-qa.md`，只有 `final result: passed` 才进入交付。
7. 构建统一镜像并解析本地/生产 Compose；必要时以容器验证同源页面与 API。

### 9. 第二轮 Vercel/Geist 视觉与官方组件收敛

1. 在不改变业务状态机的前提下，统一 `#FAFAFA` 画布、白色内容表面、Apple 蓝 primary `#0071E3`/hover `#0068D1`/focus `#007AFF`、Geist 字体、最高 56px 首页 H1、10px 圆角和 1px 发丝线；移除重阴影、不必要渐变与卡片嵌套。
2. 将 Header 固定为 64px 高，与最大 1200px 内容网格共用对齐线；页面以 4px 基准、24/32px 内容组和 48/64/96px 段落留白收敛纵向节奏。
3. 从 shadcn `radix-nova` 官方 registry 引入并统一 Card、Table、Sheet、Tooltip、Avatar、Field、InputGroup、Item、Empty、Pagination、AlertDialog 和 AspectRatio；保留已有 Button、Select、Dialog、Dropdown Menu、Progress 等的 Radix 交互语义。
4. 首页使用 Field/InputGroup 构成主输入，使用 Item 表达格式选项，使用 AspectRatio 稳定媒体；保留方案 2 的标题、三步和两栏优先级。
5. 历史在桌面与 390px 均使用 Item/ItemGroup；只有用户管理在桌面端使用 Table，390px 下切换为 Item 列表。空数据使用 Empty，分页使用 Pagination，移动导航使用 Sheet。
6. 登录/注册使用单层 Card 和 Field/InputGroup，账户页使用 Avatar、Field 与 InputGroup；下载详情使用连续内容区与 Separator。AlertDialog 仅用于取消下载/分析，管理员编辑使用普通 Dialog，图标补充说明使用 Tooltip。
7. 按 [Radix Composition](https://www.radix-ui.com/primitives/docs/guides/composition) 复核 `asChild`、props/ref 透传和可聚焦触发器；以键盘验证 Sheet、Tooltip、Dialog、AlertDialog 的焦点进入、退出与恢复。
8. 在 1280px 和 1487×1058 桌面视口核对排版/网格，在 390×844 核对无溢出、移动 Sheet、Item 列表、分页、16:9 媒体与 44px 触控目标；重新运行视觉、axe、键盘、测试和静态构建门禁。

完成门禁：代码中官方组件与页面语义映射一致，桌面与 390px 证据完整，业务、权限、OpenAPI 和 FastAPI 静态交付回归无退化。本阶段只产生本地实现和验收证据，不表示已部署。

## 风险与控制

| 风险 | 控制 |
| --- | --- |
| Next 静态导出无法枚举任务 ID | 使用 `/downloads/detail?jobId=` 静态页，旧动态地址由 FastAPI 308 |
| 认证逻辑误依赖 SSR/Middleware | 客户端 Auth Boundary + FastAPI HttpOnly Cookie；构建检查禁止服务端运行时能力 |
| OpenAPI 生成仍隐式依赖 Umi | 直接调用 `openapi2ts`，锁定 config、请求导入与漂移检查 |
| 无边框导致层级或可用性丢失 | 保留输入边界、行分隔、焦点环与状态文字，只移除装饰性容器 |
| 桌面表格在 390px 溢出 | 同一数据源提供移动任务列表/摘要行，不使用横向滚动兜底 |
| 视觉实现偏离方案 2 | 固定参考尺寸和测试状态，同图比较并阻断 P0/P1/P2 |
| 追求 Vercel 外观导致品牌与内容可读性丢失 | 只复用网格、留白、发丝线和 Geist 排版；保留 Apple 蓝，不复制黑色主题 |
| 官方组件被业务样式破坏无障碍 | 锁定 `radix-nova`，遵循 Radix composition，用键盘/axe 验证覆盖层与触发器 |
| 大爆炸替换导致功能遗漏 | 按路由清单逐页迁移并过门禁，最终一次性删除旧入口而非长期双轨 |
