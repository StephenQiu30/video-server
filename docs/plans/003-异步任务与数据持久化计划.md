## 1. 任务边界

实现四表 PostgreSQL schema、Alembic、状态机、仓储、RabbitMQ 发布/消费、幂等、heartbeat 与 housekeeping。不实现媒体下载细节或 HTTP 路由。

## 2. Test-first 执行拆分

| 顺序 | 先失败的约束 | 最小实现 | 主要产出 |
| --- | --- | --- | --- |
| `S003-T01` | 空库 upgrade、重复 upgrade、约束/索引和表数量测试 | Base、四个 model、单一初始 migration | 可重复 schema |
| `S003-T02` | 合法/非法状态矩阵与乐观并发测试 | `downloads/state.py` 与 repositories | PostgreSQL 状态事实 |
| `S003-T03` | 会话组合 FK、client_request_id 和唯一 artifact 并发测试 | 事务化 job 创建/更新 | 业务幂等 |
| `S003-T04` | exchange/queue/routing/message 捕获先失败 | aio-pika 声明、confirm publisher | 最小 RabbitMQ 拓扑 |
| `S003-T05` | 重复消息、终态消息、running 重投递与 manual ack 测试 | Worker consumer 与行锁 | 幂等消费 |
| `S003-T06` | 发布前崩溃、失联 heartbeat、到期对象和墓碑可控时间测试 | 单一 housekeeping | 故障收敛 |
| `S003-T07` | PostgreSQL/RabbitMQ/MinIO/Worker 逐项重启测试 | 启动恢复与补发 | 重启恢复证据 |

## 5. 验证命令

- `uv run alembic upgrade head`，对新空库重复执行并导出 schema/索引/约束。
- `uv run pytest tests/unit/state tests/unit/repositories -q`。
- `uv run pytest tests/integration/postgres tests/integration/rabbitmq tests/integration/recovery -q`。
- 捕获 RabbitMQ 声明与消息体，逐一重启 PostgreSQL、RabbitMQ、MinIO、Worker。
- 运行完整 `pytest --cov=src --cov-branch --cov-fail-under=90`、Ruff、格式和 mypy。

## 6. 提交顺序

`test: schema与状态约束 → impl: models和migration → test: 幂等与RabbitMQ约束 → impl: 发布消费状态机 → test: 崩溃清理恢复 → impl: housekeeping和恢复`
