# PRD002-01 清晰度预设计划

## 1. 背景

PRD002 要求解析结果稳定返回推荐、最高 1080p、720p、480p、360p 五类清晰度预设，每个预设包含 `quality_label`、`available` 和 `note` 字段。当前代码已实现基础预设逻辑，需要验证和补齐测试覆盖。

## 2. 目标

```gherkin
Given 平台提供 1080p 和 720p 视频流
When 调用解析接口
Then 返回五类预设，推荐/1080p/720p 的 available 为 true
And 480p 和 360p 的 available 为 false（yt-dlp selector `bv*[height<=480]`/`bv*[height<=360]` 不匹配任何格式）
And 480p 和 360p 的 note 提示"该来源未提供此清晰度的视频流"
And 每个预设包含 quality_label、available 和 note

Given 平台仅提供 360p 视频流
When 调用解析接口
Then 360p 的 available 为 true
And 推荐/1080p/720p/480p 的 available 为 true，note 提示"该来源最高可用 360p，将自动降级下载"

Given 平台不提供任何视频流
When 调用解析接口
Then 所有预设的 available 为 false
And note 提示"该来源未提供此清晰度或更低的视频流"
```

## 3. 非目标

- 不做后端转码。
- 不新增平台专用解析器。
- 不修改 yt-dlp 调用参数。

## 4. 任务拆解

### 4.1 TDD：先提交失败测试

- [ ] 在 `test_download_adapter.py` 中新增测试用例，覆盖三类场景：
  - 平台提供多清晰度源（可用 + 降级）。
  - 平台仅提供低清晰度源（降级）。
  - 平台不提供视频流（不可用）。
- [ ] 测试验证每个预设包含 `quality_label`、`available` 和 `note`。
- [ ] 运行验证命令确认测试失败。

### 4.2 实现：补齐预设逻辑

- [ ] 确认 `_build_resolution_presets()` 逻辑已覆盖三类场景。
- [ ] 如有缺失，调整 `download_adapter.py` 中的预设构建逻辑。
- [ ] 确认 `VideoFormat` schema 包含所有必要字段。

### 4.3 验证：测试通过

- [ ] 运行验证命令，确认所有测试通过。
- [ ] 检查测试覆盖率。

## 5. 验证命令

```bash
PYTHONPATH=apps/api:apps/worker:packages/shared pytest apps/api/tests/test_download_adapter.py -q
```

## 6. 验收标准

- 解析结果稳定返回推荐、最高 1080p、720p、480p、360p。
- 每个预设包含 `quality_label`、`available` 和 `note`。
- 平台未提供对应清晰度时提示不可用或自动降级，不做后端转码。
- 先提交失败测试，再提交最小实现，验证命令通过。

## 7. 风险与依赖

- 依赖 yt-dlp 格式元数据的完整性。
- 部分平台可能缺少 `height` 信息，导致预设全部不可用。
