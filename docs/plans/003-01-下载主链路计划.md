# 子计划 1：下载主链路

## 1. 背景

下载主链路是万能视频下载器的核心用户路径。本文档定义从任务入队到主视频文件归档的完整技术计划，覆盖状态机、Worker 流程、失败分类和 TDD 验收标准。

关联 PRD：`docs/prd/003-下载任务与产物归档.md`

## 2. 目标

```gherkin
Given 用户通过 POST /api/tasks 提交合法下载请求
When Worker 执行下载 → 校验 → 上传流程
Then 任务状态从 queued → running → succeeded，progress 从 0 → 100
And 主视频文件存储于 S3，object_key / object_size / expires_at 正确写入
And 用户可通过 GET /api/tasks/{id}/download-link 获取短期预签名 URL
```

## 3. 非目标

- 不涉及增强产物（字幕、封面、AI 摘要）的处理逻辑（见子计划 2）。
- 不修改前端 UI 或落地页。
- 不调整用户配额管理逻辑（已有独立实现）。

## 4. 核心计划

### 4.1 任务状态机

**实现文件**：`packages/shared/video_downloader_shared/states.py`

| 状态 | 值 | 触发条件 | 目标状态 |
|------|----|----------|----------|
| QUEUED | `queued` | `create_task` 入队 | RUNNING, CANCELED |
| RUNNING | `running` | Worker `_mark_running()` | SUCCEEDED, FAILED, CANCELED |
| SUCCEEDED | `succeeded` | 主视频上传完成 | — (终态) |
| FAILED | `failed` | 任意主链路异常 | — (终态，可 retry) |
| CANCELED | `canceled` | 用户调用 cancel 端点 | — (终态，可 retry) |

**活跃状态**：`ACTIVE_TASK_STATES = (QUEUED, RUNNING)` — 用于并发检查和过期任务对账。

**进度语义**：
- `0`：任务创建
- `5`：Worker 开始处理
- `5-95`：下载阶段，按 `downloaded/total * 90 + 5` 线性映射
- `95-100`：校验+上传阶段
- `100`：任务成功

### 4.2 Worker 流程

**实现文件**：`apps/worker/worker/jobs.py`

`process_download_task(task_id)` 流水线：

```
1. _should_skip_task()     — 跳过已取消/已成功/已在运行的任务
2. _mark_running()         — state=RUNNING, progress=5, 记录事件
3. _assert_media_tools()   — 检查 ffmpeg/ffprobe 在 PATH 上
4. download_task_artifact() — yt-dlp 下载（progress 5→95）
5. 取消检查                 — 重新读取 DB 检查用户是否已取消
6. _assert_size()           — 校验文件大小 ≤ min(system_max, user_max)
7. ffprobe 校验             — 验证输出为有效媒体文件
8. upload_artifact()        — 上传至 S3
9. 最终取消检查             — 如已取消则删除已上传的 artifact
10. _mark_succeeded()       — state=SUCCEEDED, progress=100, 写入 object_key/size/expires_at
11. process_ai_pipeline()   — 异步 AI 流水线（不阻塞主任务）
12. _mark_failed()          — 异常处理器，分类失败码
```

### 4.3 下载器

**实现文件**：`apps/worker/worker/download_runner.py`

`download_task_artifact()` 关键配置：

| 选项 | 值 | 说明 |
|------|----|------|
| `format` | 用户选择的 `format_id` 或 `"best"` | 格式选择 |
| `noplaylist` | `True` | 仅下载单个视频 |
| `max_filesize` | `min(system_max, user_max)` | 文件大小上限 |
| `socket_timeout` | 30 | 连接超时（秒） |
| `retries` | 3 | 下载重试次数 |
| `fragment_retries` | 3 | 分片重试次数 |
| `continuedl` | `True` | 支持断点续传 |
| `merge_output_format` | `"mp4"` | 强制合并为 MP4 |
| `ffmpeg_location` | 解析后的 ffmpeg 路径 | 合并工具 |

**输出路径解析**：`resolve_output_path()` 优先使用 prepared filename，回退到目录中最新文件。

### 4.4 对象存储

**实现文件**：`apps/worker/worker/artifact_storage.py`、`apps/api/app/services/storage.py`

| 操作 | 函数 | 说明 |
|------|------|------|
| 上传 | `upload_artifact(task, artifact)` | 对象键 `users/{uid}/{tid}/{filename}`，返回 `StoredArtifact` |
| 预签名 | `presign_download_url(object_key)` | GET 请求，TTL 900 秒 |
| 删除 | `delete_artifact(object_key)` | 取消后清理 |
| 过期清理 | `cleanup_expired_task_outputs(db)` | 惰性触发，清理 `expires_at <= now` 的任务 |

### 4.5 失败分类

**实现文件**：`apps/worker/worker/failures.py`、`apps/worker/worker/domain.py`

12 个失败码，4 个可重试（`download_failed`、`storage_failed`、`task_timeout`、`platform_rate_limited`）。

分类逻辑：
1. `JobFailure` 带已知码 → 直接使用
2. 异常消息模式匹配（正则） → 映射到对应失败码
3. 默认回退 → `download_failed`

**错误消息**：用户友好的中文描述，自动脱敏 URL。

### 4.6 任务 API

**实现文件**：`apps/api/app/routers/tasks.py`

| 端点 | 方法 | 关键逻辑 |
|------|------|----------|
| `/api/tasks` | POST | URL 校验 → 并发/配额检查 → 入队 |
| `/api/tasks` | GET | 列表 + 过期清理 + `is_latest_attempt` 注解 |
| `/api/tasks/{id}` | GET | 详情 + 过期清理 |
| `/api/tasks/{id}/cancel` | POST | 仅 QUEUED/RUNNING 可取消 |
| `/api/tasks/{id}/retry` | POST | 创建新 attempt，链接原任务 |
| `/api/tasks/{id}/download-link` | GET | 权限校验 → 预签名 URL |
| `/api/tasks/{id}/events` | GET | 审计事件列表 |
| `/api/tasks/stream` | GET | SSE 实时推送 |

### 4.7 过期任务对账

**实现文件**：`apps/api/app/services/tasks.py`

`reconcile_active_tasks(db)` — 找到 QUEUED/RUNNING 超过 `max_task_runtime_seconds`（默认 7200s）的任务，标记为 `FAILED` + `task_timeout`。

## 7. 验收标准

- [ ] 主视频成功后任务为 `state=succeeded` 且 `progress=100`。
- [ ] 下载链接只对任务拥有者可用，并使用短期预签名 URL。
- [ ] FFmpeg 缺失、文件过大、上传失败等主链路失败有 `failure_code` 和 `failure_reason`。
- [ ] 先提交失败测试，再提交最小实现，验证命令通过。
- [ ] 过期任务自动清理 S3 对象并标记 `retention_expired`。
- [ ] 重试创建新 attempt 并正确链接原任务。

## 8. 风险与边界

1. **yt-dlp 版本兼容性**：不同版本的 yt-dlp 对平台支持不同，需要锁定版本。
2. **ffmpeg 环境依赖**：Docker 镜像必须预装 ffmpeg，否则所有下载失败。
3. **S3 连通性**：本地开发需要 MinIO 或兼容 S3 的存储服务。
