# Plan 001：URL 异步解析与清晰度目录

## 1. 交付边界

已验证邮箱用户通过数据库会话提交已确认权利的 URL，owner 固定为 `users.id UUID`。API 原子创建 Resolution、Job、初始事件和 outbox；resolver worker 只能经 egress proxy 检查 policy dossier 并以 yt-dlp `download=False` 解析，最后保存真实格式快照。客户端可通过 resolution 查询与 SSE 恢复终态。

本 Plan 不下载媒体，不调用 FFmpeg、MinIO 或 AI，不生成缩略图、思维导图或 PDF，不支持源站 Cookie、DRM、直播、播放列表、团队空间和无鉴权部署。浏览器身份 Cookie 属于 Plan 000 的前置能力，不是源站凭据。

## 2. 前置门禁

- Design 001–005 与 PRD 001 重新评审并为 `accepted`。
- Plan 000 为 `done`，`AC-AUTH-001/002`、`AC-DATA-001`、`AC-REDIS-001`、`AC-MAIL-001`、`AC-OBJ-001`、`AC-DR-001`、`AC-CONTRACT-001` 全部 `passed`。
- 本 Acceptance 文档为 `accepted/result: pending`。
- 已提交的 JSON Schema、rights catalog 与 fixture manifest 是输入基线；Acceptance 冻结 W3C/operator canary、ACL 和预期结果。签名 policy/trust、可执行服务与 compose 是 Red 后实施输出，门禁不声称它们预先存在。

## 4. Red / Green 门禁

Red 必须由验收行为测试失败，而不是只证明文件不存在：未验证邮箱仍可提交、跨 UUID owner 可读取、false rights 仍可提交、私网可连接、同 key 异请求未冲突、Job/outbox 不原子、格式 fixture 未归一化、SSE 丢 wake 后无终态。

Green 必须证明：12 个真实网络 fixture 全部解析，8 个 normalization case 逐字段一致；负向策略/SSRF 全部阻断且 extractor 未运行；owner、幂等、outbox、状态和事件可恢复；p95 达标且无敏感 URL 泄漏。

## 5. 完成定义

- Plan 000 的 `AC-AUTH-001/002`、`AC-DATA-001`、`AC-REDIS-001`、`AC-MAIL-001`、`AC-OBJ-001`、`AC-DR-001`、`AC-CONTRACT-001` 保持 `passed`；Plan 001 的 `AC-POL-001/002`、`AC-SRC-001/002/003`、`AC-SEC-001`、`AC-OBS-001`、`AC-API-001` 全部 `passed`，含 production canary、attestation 与清理时钟。
- migration 可从空库升级，并在无数据损失时安全降级。
- API、dispatcher、resolver worker 和 proxy 有健康信号。
- OpenAPI 与 server-owned schema/fixture 可重复生成且无 diff；Web 客户端一致性由 Web Plan 验收。
- 没有实际下载、第三方缩略图、AI 或 PDF 越界实现。

## 6. 风险与回滚

yt-dlp 与站点变化会造成解析回归。固定版本和 policy-backed canary 保护升级；可禁用 dossier/Adapter 回滚，不删除历史 Job/事件。任何 egress proxy 或政策组件不健康时 fail closed。
