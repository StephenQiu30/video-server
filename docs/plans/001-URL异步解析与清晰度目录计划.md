# Plan 001：URL 异步解析与清晰度目录

## 1. 交付边界

本地单用户通过安装令牌提交已确认权利的 URL。API 原子创建 Resolution、Job、初始事件和 outbox；resolver worker 只能经 egress proxy 检查 policy dossier 并以 yt-dlp `download=False` 解析，最后保存真实格式快照。客户端可通过 resolution 查询与 SSE 恢复终态。

本 Plan 不下载媒体，不调用 FFmpeg、S3 或 AI，不生成缩略图、思维导图或 PDF，不支持 Cookie、DRM、直播、播放列表、公开 SaaS 和无鉴权公网部署。

## 2. 前置门禁

- Design 001–004 与 PRD 001 为 `accepted`。
- 本 Acceptance 文档为 `accepted/result: pending`。
- 已提交的 JSON Schema、rights catalog 与 fixture manifest 是输入基线；Acceptance 冻结 W3C/operator canary、ACL 和预期结果。签名 policy/trust、可执行服务与 compose 是 Red 后实施输出，门禁不声称它们预先存在。

- [ ] 建立 PostgreSQL、Redis、Celery、Smokescreen 和 HTTPS fixture 集成环境。

PostgreSQL 17 测试基线与 rights catalog migration/import 已完成 Red/Green；其余业务表、Redis/Celery、Smokescreen 与 HTTPS fixture 尚未建立完整集成环境，因此第三项继续保持未完成。

### 3.2 主体、数据与可靠投递

- [ ] 原子创建 request + Job + event + outbox；实现 claim/publish、重复投递 no-op 与有限重试。

### 3.3 政策与出站安全

- [ ] 校验 scheme、userinfo、IDNA、IP literal 与端口；missing/false rights 不创建 Job。

- [ ] 独立 Tester/Reviewer 无 blocker 后才将 Plan 标为 `done`。

## 4. Red / Green 门禁

Red 必须由验收行为测试失败，而不是只证明文件不存在：false rights 仍可提交、跨 owner 可读取、私网可连接、同 key 异请求未冲突、Job/outbox 不原子、格式 fixture 未归一化、SSE 丢 wake 后无终态。

Green 必须证明：12 个真实网络 fixture 全部解析，8 个 normalization case 逐字段一致；负向策略/SSRF 全部阻断且 extractor 未运行；owner、幂等、outbox、状态和事件可恢复；p95 达标且无敏感 URL 泄漏。

## 5. 完成定义

- `AC-POL-001/002`、`AC-ID-001`、`AC-SRC-001/002/003`、`AC-SEC-001`、`AC-OBS-001`、`AC-API-001` 全部 `passed`，含 production canary、attestation 与清理时钟。
- migration 可从空库升级，并在无数据损失时安全降级。
- API、dispatcher、resolver worker 和 proxy 有健康信号。
- OpenAPI 与 server-owned schema/fixture 可重复生成且无 diff；Web 客户端一致性由 Web Plan 验收。
- 没有实际下载、第三方缩略图、AI 或 PDF 越界实现。

## 6. 风险与回滚

yt-dlp 与站点变化会造成解析回归。固定版本和 policy-backed canary 保护升级；可禁用 dossier/Adapter 回滚，不删除历史 Job/事件。任何 egress proxy 或政策组件不健康时 fail closed。
