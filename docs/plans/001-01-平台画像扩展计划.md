# 子计划 1：平台画像扩展

## 1. 背景

PRD001 要求系统识别 10 个主流视频平台并返回平台画像信息。当前 `apps/api/app/services/platforms.py` 已定义 `PlatformProfile` 数据类和 `PLATFORM_PROFILES` 注册表，测试文件 `apps/api/tests/test_platform_profiles.py` 已覆盖国内短视频平台和 B 站。

本计划确保所有 10 个平台均有稳定的画像断言，并满足 TDD 红绿重构流程。

## 2. 目标

```gherkin
Given 平台画像注册表包含 10 个平台定义
When 测试调用 find_platform_profile 传入各平台 URL
Then 每个平台返回正确的 id、display_name、category
And 高风险平台返回 compliance_note
And 未知公共 host 不被拒绝，返回 None 进入 yt-dlp best-effort
```

### 2.1 验收标准

- 抖音、快手、小红书、西瓜、微博、B 站、YouTube、TikTok、Vimeo、Dailymotion 均有稳定平台画像断言。
- 每个平台返回 `id`、`display_name`、`category`，高风险平台返回 `compliance_note`。
- 未知公共 host 不被平台画像误拒绝，仍可进入 yt-dlp best-effort。
- 先提交失败测试，再提交最小实现，验证命令通过。

## 3. TDD 执行计划

### 3.1 红灯阶段（test:）

扩展 `apps/api/tests/test_platform_profiles.py`：

1. **覆盖全部 10 个平台**：在现有国内短视频和 B 站测试基础上，补充 YouTube、TikTok、Vimeo、Dailymotion 的画像断言。
2. **断言字段完整性**：每个平台断言 `id`、`display_name`、`category` 三个必填字段。
3. **高风险平台合规提示**：对需要 `compliance_note` 的平台断言该字段非空。
4. **未知 host 降级**：断言未知公共 host（如 `example.com`）返回 `None`，不抛异常。

### 3.2 绿灯阶段（impl:）

调整 `apps/api/app/services/platforms.py`：

1. 在 `PLATFORM_PROFILES` 中补充 YouTube、TikTok、Vimeo、Dailymotion 的画像定义。
2. 确保 `find_platform_profile` 函数对未匹配 host 返回 `None`。

### 3.3 重构阶段

- 在测试保护下优化 `PLATFORM_PROFILES` 结构（如按 category 分组）。
- 确保 `matches_host` 方法的 host 匹配逻辑清晰可读。

## 4. 验证命令

```bash
PYTHONPATH=apps/api:apps/worker:packages/shared pytest apps/api/tests/test_platform_profiles.py -q
```
