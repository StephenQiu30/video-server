## 1. 任务边界

建立直接 `src/` 工程、锁定依赖、统一 Settings、进程入口、结构化日志、基础设施客户端、容器和质量门禁。不创建业务表、解析逻辑、下载状态机或业务 API。

## 2. Test-first 执行拆分

| 顺序 | 先失败的约束 | 最小实现 | 主要产出 |
| --- | --- | --- | --- |
| `S001-T01` | 目录、依赖和禁止项扫描 | `pyproject.toml`、`uv.lock`、直接 `src/`/`tests/` 骨架 | 可重复工程 |
| `S001-T02` | 缺失、非法、越界、环境覆盖和脱敏测试 | `src/core/config.py` 与完整 `.env.example` | 单一类型化 Settings |

## 3. 预期文件边界

- 根目录：`pyproject.toml`、`uv.lock`、`.env.example`、`Dockerfile`、`compose.yml`。
- `src/main.py`、`src/worker.py`、`src/core/{config,logging,security,errors}.py`。
- `src/db/{base,session}.py`、`src/rabbitmq.py`、`src/minio_client.py`。
- `tests/unit/`、`tests/integration/` 中仅基座、配置、进程、容器和依赖连接测试。

## 5. 验证命令

- `uv lock --check`、`uv sync --frozen`。
- `uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy --strict src`。
- `uv run pytest tests/unit tests/integration --cov=src --cov-branch --cov-fail-under=90`。
- `docker compose config --quiet`，随后执行两次 `docker compose up -d --build` 冷启动和 `docker compose ps`。
- 逐项移除必填变量并扫描镜像、配置、日志、依赖与许可证。

## 6. 提交顺序

`test: 工程与配置约束 → impl: 工程和统一配置 → test: 进程与依赖约束 → impl: 进程和客户端 → test: 容器与供应链约束 → chore: 容器和锁定基线`

## 7. 完成条件

全部映射标准为 `passed`，完整质量命令零失败，冷构建可重复且无 Secret/模板垃圾后，在已定义的 Acceptance 001 中填写证据与结论；未授权实现时保持 Ready。
