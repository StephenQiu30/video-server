# Plan 005 API 契约与异常治理计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[005](../design/005-API契约与异常处理设计.md)。
- PRD：[005](../prd/005-API契约与异常治理需求.md)。
- 目标：建立共享响应/异常/OpenAPI 基座，并在功能完成后统一核验全部正式接口。
- 依赖：基础阶段依赖 Plan 001；最终契约阶段依赖 Plan 002、003、004。

## 1. 执行方式

本 Plan 分两次执行但保持一个验收闭环：先完成所有功能依赖的 API 基座，再由各功能 Plan 添加 endpoint，最后回到本 Plan 做 OpenAPI 全量核验。不得为并行开发复制响应或异常模块。

## 2. 基座阶段

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | 泛型成功/空 data 序列化测试先失败 | `ApiResponse[T]` | 统一成功结构 |
| 2 | 业务/校验/HTTP/未知异常测试先失败 | 异常类型与 handlers | 统一错误结构 |
| 3 | 敏感信息泄露测试先失败 | 安全错误映射和日志 | 脱敏边界 |
| 4 | operation ID、tags、docs URL 测试先失败 | Router/OpenAPI 配置 | Swagger 基座 |
| 5 | Health VO 与 503 测试先失败 | Health Router | 探针契约 |

## 3. 功能与收口阶段

- Plan 002 负责 inspect、download job、artifact URL endpoint 及 DTO/VO。
- Plan 004 负责 AI job/result endpoint 及 DTO/VO。
- 本 Plan 最终对 Design 005 的完整路径、HTTP 状态、错误示例和 operation ID 做 schema snapshot。
- 使用生成出的 `/openapi.json` 驱动 video-web Plan 005，禁止维护手写副本。

## 4. 验收映射

- S005-DAC-01、S005-DAC-04：任务 4、6 的完整 OpenAPI snapshot、文档和 operation ID 检查。
- S005-DAC-02、S005-DAC-03：任务 1、2、3 的统一响应、无 request_id、异常与泄露矩阵。
- S005-DAC-05：任务 5 与 Plan 001 的真实依赖健康故障证据。
- S005-DAC-06：真实 schema 驱动 Web 生成、扫描、类型和构建证据。
- S005-DAC-07：全部功能完成后的跨接口成功/失败全量契约回归。
- S005-AC-03、S005-AC-04、S005-AC-05：基座阶段响应、异常和泄露测试。
- S005-AC-07：Plan 001 健康实现与本 Plan Schema 测试。
- S005-AC-01、S005-AC-02、S005-AC-06：功能完成后的完整 OpenAPI snapshot、docs 可用性和 Web 生成 smoke。

## 5. 验证命令

- `uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy --strict src`。
- `uv run pytest --cov=video_server --cov-branch --cov-fail-under=90` 执行 response、exception、OpenAPI、health 目标测试及全量测试。
- 导出 `/openapi.json` 并与受控 snapshot 比较。
- 在 `video-web` 运行官方 OpenAPI 生成命令，确认无手工修补和无 `any` 逃逸。

## 6. 提交顺序

`test: 统一响应异常约束 → impl: API 基座 → test: OpenAPI 基础约束 → impl: docs 配置 → test: 完整 schema → docs/refactor: 契约收口`

## 7. 风险与非目标

- 这是跨功能 Plan，最终 Acceptance 必须等待 002/004 endpoint 完成；基座完成不等于 PRD 005 完成。
- 不加入 GraphQL、SSE、WebSocket、鉴权或第二种响应 envelope。

## 8. 完成条件

S005-DAC-01 至 DAC-07 与 S005-AC-01 至 AC-07 必须全部 `passed`，Web 从实际 OpenAPI 零补丁生成并通过完整构建，且不存在 `request_id`、敏感泄露或手写 DTO 后进入 Acceptance。
