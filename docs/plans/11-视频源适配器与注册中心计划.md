# PLAN11 视频源适配器与注册中心

## 1. 背景

PRD06 定义了视频源接入从条件判断转向 Adapter/Strategy/Registry/Factory 的产品边界。当前 `download_adapter.py` 已有 `PlatformAdapter`、`AdapterRegistry`、`YtDlpAdapter`、`BilibiliAdapter`、`DomesticShortVideoAdapter` 等实现，需要将这些实现规范化为可扩展的适配器体系。

## 2. 目标

1. 固化 `PlatformAdapter` 接口契约：`supports()`、`parse()`、`map_parse_error()`。
2. 固化 `AdapterRegistry` 注册与匹配规则：专用适配器优先，`YtDlpAdapter` 作为最终回退。
3. 统一所有适配器的失败语义映射。
4. 确保新增平台只需添加 `PlatformProfile` 和 `PlatformAdapter`，不修改 router 或主流程。

## 3. 非目标

- 不引入动态插件加载或远程 adapter 机制。
- 不修改 `/api/parse` 路由签名或 `ParseResponse` 结构。
- 不实现 Worker 下载执行或 MinIO 归档逻辑。

## 4. 核心内容

### 4.1 PlatformAdapter 接口契约

```python
class PlatformAdapter:
    name: str

    def supports(self, parsed_host: ParsedHost) -> bool:
        """判断是否支持该 URL"""
        ...

    def parse(self, url: str) -> ParseResponse:
        """解析 URL 并返回统一响应"""
        ...

    def map_parse_error(self, exc: Exception) -> AppError:
        """将异常映射为统一错误码"""
        ...
```

### 4.2 AdapterRegistry 注册规则

1. 默认适配器列表顺序：`DomesticShortVideoAdapter` → `BilibiliAdapter` → 其他专用适配器 → `YtDlpAdapter`。
2. `get_adapter(url)` 按顺序调用 `supports()`，返回第一个匹配的适配器。
3. 若无匹配，返回列表最后一个适配器（`YtDlpAdapter`）。

### 4.3 现有适配器映射

| 适配器 | name | 支持平台 | 回退策略 |
| --- | --- | --- | --- |
| `DomesticShortVideoAdapter` | `short-video` | douyin, kuaishou, xiaohongshu, ixigua, weibo | 专用 |
| `BilibiliAdapter` | `bilibili` | bilibili | 专用，自定义错误消息 |
| `YtDlpAdapter` | `ytdlp-fallback` | 所有其他 | 最终回退 |

### 4.4 失败映射策略

所有适配器的 `map_parse_error()` MUST 映射到统一错误码：

| 异常特征 | 错误码 | HTTP |
| --- | --- | --- |
| login/sign-in/members-only/private/premium/paid/drm/copyright/geo | `platform_restricted` | 403 |
| too many requests/429/rate limit/captcha | `platform_rate_limited` | 429 |
| unsupported url/no suitable extractor/no video formats | `unsupported_platform` | 422 |
| timed out/timeout/connection reset/network unreachable | `platform_unavailable` | 503 |
| 其他 | `parse_failed` | 422 |

### 4.5 测试计划

| 测试场景 | 验证内容 |
| --- | --- |
| 已注册平台 URL 匹配正确适配器 | `BilibiliAdapter.supports()` 对 bilibili URL 返回 True |
| 未注册平台 URL 回退到 YtDlpAdapter | `YtDlpAdapter.supports()` 对任意 URL 返回 True |
| 受限内容异常映射到 `platform_restricted` | `map_parse_error()` 对 login-required 异常返回正确错误码 |
| 限流异常映射到 `platform_rate_limited` | `map_parse_error()` 对 429 异常返回正确错误码 |
| 超时异常映射到 `platform_unavailable` | `map_parse_error()` 对 timeout 异常返回正确错误码 |
| 适配器注册顺序正确 | `AdapterRegistry` 默认列表中专用适配器在 `YtDlpAdapter` 之前 |

## 6. 验收门禁

- `PlatformAdapter` 接口契约明确且可测试。
- `AdapterRegistry` 注册顺序和匹配规则明确。
- 所有适配器的失败映射统一。
- 新增平台不修改 router 或主流程。

## 7. 风险与边界

1. 适配器注册顺序影响匹配结果，需要有明确的优先级文档。
2. `YtDlpAdapter` 作为回退可能掩盖真正的平台不支持问题。
3. 平台页面结构变动可能导致适配器失效，需要定期维护。

## 8. 已解决问题

| 问题 | 结论 | 决策依据 |
| --- | --- | --- |
| 是否引入动态适配器加载 | 否，静态注册足够 MVP 需求 | 避免过度设计，PRD06 明确为非目标 |
| 是否为每个适配器定义独立超时 | 否，统一使用 yt-dlp 默认超时 | 简化实现，后续可扩展 |
