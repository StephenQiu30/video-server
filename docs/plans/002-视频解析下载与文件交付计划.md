# Plan 002 视频解析、下载与文件交付计划

## 状态与输入

- 状态：Ready；尚未开始实现。
- Design：[002](../design/002-视频解析下载与文件交付设计.md)。
- PRD：[002](../prd/002-视频解析下载与文件交付需求.md)。
- 目标：完成安全解析、格式标准化、异步下载、FFmpeg 合并、校验、MinIO 上传和文件交付闭环。
- 依赖：Plan 001、003、005 的 API 基座阶段完成。

## 1. 任务边界

只实现单链接视频下载链路及对应 API。字幕、播放列表、Cookie、登录、批量、音频下载和转码不在范围内。

## 2. 执行拆分

| 顺序 | Test-first 约束 | 最小实现 | 产出 |
| --- | --- | --- | --- |
| 1 | URL 协议、私网、重定向和超时测试先失败 | URL 安全校验器 | SSRF 边界 |
| 2 | yt-dlp 元数据 fixture 与失败分类测试先失败 | Extractor Adapter | 解析能力 |
| 3 | 格式过滤、排序、null 大小和过期测试先失败 | Format Normalizer | 标准化 formats |
| 4 | Inspect/Create Job API 契约测试先失败 | 解析与任务 Service/Router | 业务 API |
| 5 | 单文件、分离流、超限和清理测试先失败 | Download Task + yt-dlp Adapter | 下载 Worker |
| 6 | FFmpeg 参数与 ffprobe 校验测试先失败 | Media Adapter | 无损合并与校验 |
| 7 | MinIO 上传、幂等、预签名和过期测试先失败 | Artifact Service | 文件交付 |
| 8 | PostgreSQL/RabbitMQ/MinIO/FFmpeg 集成场景 | 最小端到端串联 | 下载闭环 |

## 3. 测试策略

- 单元测试使用固定 yt-dlp 元数据 fixture，不依赖外网平台。
- FFmpeg 测试生成短小本地音视频流，验证输出同时含视频和音频。
- MinIO、PostgreSQL、RabbitMQ 使用隔离测试资源和唯一 job ID。
- 真实站点只作为显式 smoke，不进入无凭据的稳定 CI 门禁。

## 4. 验收映射

- S002-DAC-01：任务 2、3 和真实受控 URL 解析/过期证据。
- S002-DAC-02：任务 1 的 URL、重定向、来源与权限负例矩阵。
- S002-DAC-03、S002-DAC-04：任务 5、6 的单文件/分离流、stream copy、ffprobe 和无字幕证据。
- S002-DAC-05：任务 7 的真实 MinIO、checksum 和双重过期证据。
- S002-DAC-06、S002-DAC-07：任务 4、5 的资源、清理、故障和重试矩阵。
- S002-DAC-08：任务 8 的完整真实依赖端到端证据。
- S002-AC-01、S002-AC-03：Extractor、Normalizer 与 Inspect API 测试。
- S002-AC-02：URL 安全与重定向测试。
- S002-AC-04、S002-AC-08：单文件、分离流、ffprobe 和无字幕断言。
- S002-AC-05、S002-AC-06：MinIO 对象、数据库元数据、预签名和过期测试。
- S002-AC-07：资源与错误码参数化测试。

## 5. 验证命令

- `uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy --strict src`。
- `uv run pytest --cov=video_server --cov-branch --cov-fail-under=90` 执行全量及下载目标测试。
- 启动 PostgreSQL、RabbitMQ、MinIO 后执行下载集成测试。
- `ffmpeg -version`、`ffprobe -version` 记录运行依赖。
- 使用受控公开样例完成解析、下载、合并、MinIO URL 获取和 checksum 比对；该项不可用 Mock 替代。

## 6. 提交顺序

`test: URL 与解析约束 → impl: 解析格式 → test: 下载媒体约束 → impl: 下载合并 → test: 存储交付约束 → impl: MinIO 交付 → test/feat: API 闭环`

## 7. 风险与非目标

- 平台提取规则会变化，错误分类必须保留原始内部日志但不泄露给用户。
- 不为通过特定网站 smoke 添加站点专用业务分支。

## 8. 完成条件

S002-DAC-01 至 DAC-08 与 S002-AC-01 至 AC-08 必须全部 `passed`，真实端到端、临时文件清理、OpenAPI 与 Web 契约同步均有证据后进入 Acceptance。
