# 006 上线产品能力补全计划

- 状态：In progress

## 当前拆分状态（2026-08-14）

报告持久化、分析重试、实时状态、异步分析、RabbitMQ 可靠性和制品保留已经分别由 012–015、018、020 完成并归档，不再作为本计划的执行项。剩余工作收敛为生产网络与滥用防护、配额、备份恢复、可观测性/发布治理、用户删除以及音频/字幕/受限批量；实施时应为每个可独立验收的能力建立新编号，并同步缩减 006 的完成定义。
- 日期：2026-08-08
- 关联 Design：`docs/design/006-上线产品能力补全设计.md`
- 关联 PRD：`docs/prd/006-上线产品能力补全需求.md`

## 执行规则

1. 按阶段交付，每个阶段使用独立任务、测试和 Conventional Commit。
2. P0 未完成前不并行扩展新 Provider、音频、字幕或播放列表。
3. 先写失败测试/验收脚本，再修改实现；每阶段结束更新 Acceptance 证据。
4. 任何迁移、删除、网络隔离和 Secret 变更先在临时数据卷/受控环境验证。
5. Provider 会话只按 005 的独立 Plan/Acceptance 实施；本计划不顺带加入 Cookie、任意 yt-dlp 参数或公共解析服务。

## Phase 0：冻结基线与决策

### 交付

- 修复当前 Ruff E501 和 3 个 format drift，恢复后端全门禁。
- CI、Dockerfile、package engines 和 README 统一 Node 24/npm 11.19；统一并固定 uv 版本。
- 为生产部署选择“单机 Compose”或“托管依赖”基线，并记录 ADR。
- 冻结 Public Beta 是否匿名、AI 是否首发、默认配额、artifact TTL 和 ingress 方案。
- 输出当前 OpenAPI、schema、Compose、镜像和受控 E2E 基线摘要。

### 验证

- 后端/前端全门禁、Compose 两种模式 config、镜像 build 全部返回 0。
- CI 与 Docker 使用相同 Node/npm/Python/uv 主版本。

## Phase 1：网络与 Secret 边界

### 交付

- 按服务拆分 Settings 和显式环境白名单，移除全量 env 注入。
- 增加 `ingress_net/app_net/runner_egress_net/public_egress_net` 网络分段。
- Media Runner 只保留 HMAC、工作区、固定 binary 和 egress proxy 配置。
- Egress Proxy 成为 Runner 唯一公网路径；阻断 Runner 横向访问业务依赖。
- 增加 Runner HMAC/URL encryption key rotation 设计所需 key id/keyring。

### 验证

- 容器内 `env` 白名单快照不含越权 Secret。
- Runner 到 DB/RabbitMQ/MinIO/Valkey/公网直连全部被拒绝。
- Runner 经 Squid 对受控公网样本 inspect/download 成功；私网、字面量 IP、重定向和 DNS rebinding 测试被拒绝。

## Phase 2：数据库迁移与恢复

### 交付

- 修改 `AGENTS.md`、backend README 和运维文档，允许并规范 Alembic。
- 以当前 schema 创建 `0001_baseline`，保留 `schema.sql` 作为新环境快照。
- CI 验证空库 upgrade、当前基线 stamp/upgrade、model/schema/migration 一致性。
- 增加 PostgreSQL/MinIO 加密备份、校验、保留、恢复 runbook。
- 明确 RabbitMQ 丢失后的 outbox/recovery 重建流程。

### 验证

- 空库、带现有 MVP 数据的库均迁移成功。
- 备份恢复后 owner 隔离、任务、artifact、analysis evidence 与 SHA 一致。
- 记录实际 RPO/RTO；失败演练有可执行修复项。

## Phase 3：Artifact 生命周期

### 交付

- 新增 artifact deletion 状态/队列和 Lifecycle Worker。
- 实现 TTL 扫描、analysis lock 保护、幂等对象删除、有上限重试和告警。
- 新增用户删除 API、历史删除状态和前端确认流程。
- 增加 bucket lifecycle 兜底与 DB/MinIO 每日孤儿对账。
- 清理过期 inspection/formats、已发布 outbox 和过期匿名 metadata。

### 验证

- 到期、锁竞争、对象不存在、MinIO 暂停、重复删除和 Worker 崩溃场景通过。
- 跨 owner 删除返回 404；预签名 URL 在删除后失效。
- GC 指标和告警可观察 backlog、重试与孤儿。

## Phase 4：限流、配额和生产入口

### 交付

- 引入 Valkey + `limits`，实现 IP/owner/API key/operation 多维限流。
- 在 PostgreSQL 实现每日任务/字节/AI 分钟和活跃并发配额。
- 幂等请求复用原配额结算，失败/取消按规则释放。
- 支持全局 backpressure 和 Provider kill switch。
- 加入受支持 ingress，冻结 TLS、安全 header、body/header/timeout 和可信代理配置。
- 可选接入 Turnstile；机器客户端使用 API key，不用浏览器 challenge token。

### 验证

- 单实例、多 API 实例和 Valkey 重启下限流语义一致。
- 伪造 forwarded headers 不能绕过限制。
- 并发竞争不超卖；返回 `429 + Retry-After`；查询/取消/删除不被全局暂停误伤。
- TLS/header/body limit 通过自动化浏览器和协议测试。

## Phase 5：可观测性与运营面

### 交付

- 统一 JSON 日志、request/trace/correlation id 和脱敏过滤器。
- 增加 FastAPI RED、任务、Provider、队列、outbox、lease、MinIO、GC、AI 指标。
- 配置 Prometheus/Grafana 或托管等价能力，产出 dashboard 和告警。
- 增加 Provider canary Worker、聚合状态表、`GET /api/providers` 和前端状态页。
- 建立 runbook：队列堆积、Provider 验证、存储满、数据库慢、AI 限额、GC 失败。

### 验证

- 敏感 fixture 不出现在日志、metrics、trace 或告警 payload。
- metrics label 基数测试阻止 URL/job/owner/exception message 成为 label。
- canary 失败能降级对应 Provider，不影响 API readiness 或其他 Provider。

## Phase 6：可靠性、容量与供应链

### 交付

- 建立真实 PostgreSQL/RabbitMQ/MinIO/Runner/浏览器 E2E 套件。
- 补 muxed、分离音视频、格式漂移、重定向、取消、超时和磁盘上限样本。
- 建立 Worker/Runner/RabbitMQ/MinIO 故障注入和重复投递测试。
- 完成真实 CLI 视觉模型 shot evidence E2E；未完成则通过 feature flag 关闭 AI 创建。
- CI 加入 Trivy、Secret scan、依赖审计、SBOM、基础镜像 digest 与 yt-dlp 更新策略。
- 建立容量模型：API RPS、最大活跃任务、队列水位、每任务磁盘/内存、日带宽和 AI 成本。

### 验证

- 所有 P0 故障场景有可重复命令、结果和清理步骤。
- 发布镜像可追溯到 Git SHA、schema revision、yt-dlp commit 和 SBOM digest。
- 目标容量下 SLO 达标，过载时有序拒绝而非资源耗尽。

## Phase 7：治理与 Public Beta

### 交付

- 产品页增加合法使用确认、Provider 边界、保留/删除提示。
- 发布隐私、服务条款、投诉/下架、安全报告和状态页入口。
- 完成值班、事故、滥用封禁、数据删除、发布/回滚 runbook。
- 执行 production-like staging 演练、备份、migration、smoke、回滚和公告。
- Public Beta 使用 allowlist/限额逐步放量，观察 14 天错误预算。

### 验证

- `docs/acceptance/006-上线产品能力补全验收.md` 的 P0 全部勾选并附证据。
- 14 天无 P0 事件、无不可恢复数据丢失、核心 SLO 未耗尽。

## Phase 8：Stable v1 产品能力

按独立小任务依次实施：

1. `DownloadPlan.kind` 与 audio-only，先原生 M4A/Opus，再评估 MP3 转码。
2. 字幕 inspection、独立制品和受控嵌入。
3. 失败/取消任务重试、用户删除与历史生命周期 UI。
4. owner-scoped SSE，轮询作为退避降级。
5. 受限 batch/playlist 父子任务和部分成功。
6. AI 历史、JSON/Markdown 导出与视觉 fixture 扩展。
7. a11y、国际化和移动端完整 E2E。

每项都需要新增 Design/PRD 或在本编号中先冻结详细验收，不一次性暴露所有 yt-dlp 能力。

## 暂不实施

- 账户/团队/计费、频道订阅、Webhook/Apprise、扩展、媒体中心与 SponsorBlock。
- 未受管 Cookie、私有媒体、任意底层参数、自定义脚本、公共解析中转；005 定义的受控 Provider 会话不在本计划内。

这些候选在 Public Beta 数据证明有需求后另立编号，不能顺带进入上述阶段。

## 建议提交拆分

```text
fix(ci): 统一前端工具链并恢复质量门禁
refactor(config): 按进程拆分生产配置
fix(runner): 强制媒体流量只能经过出口代理
feat(db): 建立数据库迁移基线
feat(worker): 增加制品生命周期清理
feat(api): 增加限流与使用配额
feat(observability): 增加服务与任务指标
feat(provider): 增加真实来源健康状态
test(e2e): 增加下载与分析真实依赖验收
docs(operations): 补充上线与灾难恢复手册
```

实际提交仍按一个可独立验证的小任务拆分，不把示例机械合并为十个大提交。
