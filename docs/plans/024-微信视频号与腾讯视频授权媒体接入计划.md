## 1. 范围与交付策略

024 取代 019 中元宝 Cookie、私有 finder、MITM、页面注入、`decodeKey` 和受保护媒体转换路线。023 已完成的本地 MP4 隔离上传、验证和 Artifact 晋升子门禁继续复用，不依赖其无关的剧本模型质量验收。

交付顺序固定为“先关闭错误能力，再建立统一决策，然后分别交付文章 discovery、视频号明文导入和官方资产连接器”。不可变门禁：

1. 只有 `access_decision=downloadable` 能产生可选格式和获取任务。
2. `entitlement/protection/identity=unknown` 一律 fail closed。
3. 权利声明不能覆盖 private、VIP、purchase、preview、geo、encrypted 或 DRM。
4. 公共 Runner、文章 discovery/native media、官方 Connector 和文件导入使用独立执行器、消息、凭据和 canary。
5. 每次 attempt 都重新解析、重新授权、重新分类，不复用过期短时 URL。
6. 任何执行模式都不能回退到 Cookie、Generic、外部签名、公共解析服务、代理或解密。
7. fixture、HTTP 200、metadata 或 M3U8 成功不能替代授权完整媒体 E2E。

## 2. 开工前输入

- 法务、安全、供应链和内容权利评审责任人。
- 项目自有或明确授权的公众号原生单视频/多视频公开文章、视频号 MP4。
- 公众号挑战/验证码/登录/付费/无视频/身份歧义的可重复负例或脱敏 fixture。
- 若要恢复 `qqvideo`：对当前未公开接口/`cKey` 机制的书面审批，以及可证明 `public_free` 的授权公开样本。
- 独立腾讯云 VOD 测试 `SubAppId`、最小权限 CAM、clear MP4/clear HLS/encrypted/DRM 测试资产。
- Secret backend、一次性 Secret Ingress、workload identity、内部 PKI/证书、备份恢复和运维责任人的 ADR 决策。
- 权利声明版本、隐私说明、投诉/删除责任人和 Provider 发布批准人。

缺少某阶段输入不阻塞前序安全加固，但对应能力必须保持关闭；不建立“临时 Cookie/环境变量 Secret/第三方解析服务”替代路径。

## 4. Phase 1：微信公众号文章 discovery 与原生 clear 视频

### 024-P1-01 静态文章 Adapter

- [x] 新增 `wechat_official_account_article`，只用标准 HTTP、固定普通 UA、人类阅读速率和有界响应。
- [x] 支持 `/s/{opaque}` 与严格 query allowlist；拒绝 ticket、Cookie、未知参数和非默认端口。
- [x] 静态解析公开 metadata、`data-mpvid/mpvideo`、腾讯 iframe、视频号 snapshot 和 unknown embed，不执行脚本。
- [x] 挑战/验证码/登录/关注/付费/异常 HTML 返回 `article_access_restricted`，不启动 headless/stealth。

门禁：响应/日志无原始 HTML、inline data、ticket、signed URL；限流与挑战页负例通过。

### 024-P1-02 Discovery 控制面和选择

- [x] 建立 `source_discoveries/source_discovery_items`、owner/TTL/opaque item ref 和 source fingerprint。
- [x] 实现 `POST/GET /api/source-discoveries`，返回零/单/有界多项安全 metadata。
- [x] item 分类为 `official_account_native/tencent_video/wechat_channels/unknown`；多项和单项都需用户确认。
- [x] 子 inspection 只接受同 owner、未过期的 discovery/item ref。

门禁：零项、多项、重复请求、过期、跨 owner、unknown embed 和默认第一项负例通过。

### 024-P1-03 原生媒体身份与下载

- [x] 独立解析经 fixture 固定的 `mp_video_trans_info` 纯数据，不运行 JS。
- [x] 只有 `mpvid ↔ internal media id ↔ representation` 一一绑定才返回 candidate；禁止 DOM 顺序猜测。
- [ ] 短时 `mpvideo.qpic.cn` URL 只存在于当次 resolve/attempt 内，每跳执行 allowlist/DNS/IP。
- [ ] 下载前重取文章并验证 article/item/media identity、权益、RightsBasis 和保护。
- [ ] 同一媒体多清晰度映射成语义格式；不得固定选择最低清晰度或虚构格式。

门禁：数量错配、重复 id、映射歧义、文章变更、URL 过期、CDN 越界和 signed URL 泄漏负例通过。

### 024-P1-04 执行器、消息与 Import Intake

- [ ] 新增 `article_native` execution/source kind、`article_media.requested` outbox/quorum queue/DLQ 和独立 Article Media Worker。
- [ ] Worker 只按内部 id 读取同 owner discovery/item，重取文章后写 quarantine；MQ/DB/日志无文章/CDN URL。
- [ ] 扩展共享 `ImportIntakePort`，按 `source_kind + source_request_id` 幂等创建 `media_imports/media_import_attempts`，再由无外网 Import Worker 复验。
- [ ] Download Worker 不 claim article job，Article Worker 不访问 Generic/消费端 Cookie/官方连接 Secret。

门禁：重复消息、并发 claim、过期 discovery、任务取消、Worker 崩溃和 quarantine 孤儿均不产生重复 import/Artifact。

### 024-P1-05 真实发布门禁

- [ ] 项目自有/授权的单视频和多视频文章完成 discovery → item 选择 → inspection → 完整下载 → Artifact → Analysis → MD/DOCX → WebSocket。

- [ ] 供应链记录固定参考 commit/许可证，但生产代码独立实现且无 Camoufox/第三方 API。

- Phase 0 回滚不得恢复旧 qqvideo verified 或匿名权益缺口。
