# PLAN04 创建任务与状态查询

## 1. 背景

异步下载主链路的第一步是把"接单"和"查单"稳定下来，让 API 与 Worker 解耦。

## 2. 目标

1. 支持创建任务、列表和详情查询。
2. 入队前写入 `download_tasks` 初始记录。

## 3. 非目标

- 不在本计划中实现下载执行。

## 4. 核心内容

### 4.1 任务创建流程

1. API 接收 `POST /api/tasks` 请求，校验认证和限流。
2. 调用 `normalize_user_url` 规范化 URL。
3. 调用 `validate_supported_download_url` 校验平台支持。
4. 调用 `assert_concurrency_allowed` 检查并发和配额限制。
5. 创建 `DownloadTask` 记录，`state = QUEUED`，`progress = 0`。
6. 写入 `task_events` 记录（"任务已创建，等待下载"）。
7. 调用 `enqueue_download_task` 入队 Redis Queue。
8. 入队失败时将任务标记为 `FAILED`，`failure_code = "queue_unavailable"`。

### 4.2 任务列表查询

1. API 接收 `GET /api/tasks` 请求。
2. 调用 `reconcile_stale_active_tasks` 清理超时任务。
3. 调用 `cleanup_expired_task_outputs` 清理过期产物。
4. 按 `created_at` 降序返回用户任务列表。
5. 支持 `state` 参数过滤和 `limit` 参数限制数量。

### 4.3 任务详情查询

1. API 接收 `GET /api/tasks/{task_id}` 请求。
2. 调用 `get_owned_task` 校验任务存在性和所有权。
3. 调用 `annotate_latest_attempts` 标记是否为最新尝试。
4. 返回 `TaskRead` 响应，包含完整任务信息。

### 4.4 关键实现文件

| 文件 | 职责 |
| --- | --- |
| `apps/api/app/routers/tasks.py` | API 端点定义 |
| `apps/api/app/schemas.py` | Pydantic 请求/响应模型 |
| `apps/api/app/services/tasks.py` | 业务逻辑（创建、查询、限流检查） |
| `apps/api/app/services/queue.py` | Redis Queue 入队 |
| `apps/api/app/services/rate_limit.py` | 限流实现 |
| `apps/api/app/models.py` | SQLAlchemy ORM 模型 |

### 4.5 数据库模型

`download_tasks` 表关键字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID string | 主键 |
| `user_id` | FK → users | 任务所有者 |
| `source_url` | string | 原始视频 URL |
| `state` | string | 任务状态（5 选 1） |
| `progress` | integer | 进度 0-100 |
| `failure_code` | string nullable | Worker 失败码 |
| `failure_reason` | string nullable | 用户可读失败原因 |
| `object_key` | string nullable | MinIO 对象路径 |
| `retry_of_task_id` | FK nullable | 重试来源任务 |
| `attempt_no` | integer | 尝试次数 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 最后更新时间 |

## 6. 验收门禁

- 创建任务返回任务 ID 和 `queued` 状态。
- 列表与详情能读出任务基础信息。
- 限流和配额检查正确拦截超限请求。
- URL 校验拒绝不支持的平台。
