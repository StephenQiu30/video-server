# PRD005-02 限流配额与合规负向计划

## 1. 背景

公网部署必须启用鉴权、限流和配额（见 `docs/06-运维合规/02-风险与合规边界.md`）。当前后端已有基础限流能力（见 `docs/03-架构设计/06-后端可靠性与Redis防滥用设计.md`），但需要补齐：

1. 生产配置校验门禁。
2. 合规负向输入检查（无效 URL、保留域名、内网地址）。
3. 限流和任务额度的完整测试覆盖。

## 2. 目标

```gherkin
Given 生产环境启动
When `scripts/validate_prod_env.py` 执行
Then 检查 JWT_SECRET_KEY、数据库连接、Redis 连接等必填配置
And 拒绝 CHANGE_ME 占位值和 localhost 生产连接
```

```gherkin
Given 用户提交 `http://127.0.0.1:8000/api/tasks` 作为下载 URL
When 合规负向检查执行
Then 返回 `invalid_url` 错误码，拒绝任务创建
```

```gherkin
Given 用户在 1 分钟内第 21 次调用 `/api/tasks`
When 限流检查执行
Then 返回 429 状态码和 `rate_limited` 错误码
```

## 3. 非目标

- 不引入 Kubernetes、Prometheus 服务端或复杂网关。
- 不改变已有 API 成功响应结构。
- 不在本阶段实现成功响应 envelope。
- 不把真实平台 smoke 测试纳入默认 CI。

## 4. 实现计划

### 4.1 生产配置校验

扩展 `scripts/validate_prod_env.py`，覆盖以下检查项：

| 检查项 | 失败条件 | 错误等级 |
| --- | --- | --- |
| `JWT_SECRET_KEY` | 缺失或长度 < 32 | error |
| `JWT_SECRET_KEY` | 值为 `CHANGE_ME` 或 `change-me` | error |
| `APP_ENV` | 生产部署时不是 `production` | error |
| 数据库连接 | 指向 `localhost`/`127.0.0.1`/`0.0.0.0` | warning |
| Redis 连接 | 指向 `localhost`/`127.0.0.1`/`0.0.0.0` | warning |
| MinIO 连接 | 指向 `localhost`/`127.0.0.1`/`0.0.0.0` | warning |
| 域名 | 值为 `your-domain.example` | error |
| 注册模式 | 开放注册但未配置邀请码 | warning |

### 4.2 合规负向检查

新增或扩展 `apps/api/app/services/compliance_check.py`：

```python
from enum import StrEnum
import ipaddress
from urllib.parse import urlparse


class ComplianceErrorCode(StrEnum):
    INVALID_URL = "invalid_url"
    RESERVED_DOMAIN = "reserved_domain"
    PRIVATE_NETWORK = "private_network"
    PLATFORM_RESTRICTED = "platform_restricted"
    DRM_PROTECTED = "drm_protected"


def check_url_compliance(url: str) -> ComplianceErrorCode | None:
    """检查 URL 是否符合合规要求。

    返回 None 表示通过，返回错误码表示拒绝。
    """
    # 协议检查
    parsed = urlparse(url)
    if parsed.scheme not in ("http", "https"):
        return ComplianceErrorCode.INVALID_URL

    # 保留域名检查
    hostname = parsed.hostname or ""
    reserved_domains = {"localhost", "127.0.0.1", "0.0.0.0", "::1"}
    if hostname in reserved_domains:
        return ComplianceErrorCode.RESERVED_DOMAIN
    if hostname.endswith(".local") or hostname.endswith(".internal"):
        return ComplianceErrorCode.RESERVED_DOMAIN

    # 内网地址检查
    try:
        ip = ipaddress.ip_address(hostname)
        if ip.is_private or ip.is_loopback or ip.is_link_local:
            return ComplianceErrorCode.PRIVATE_NETWORK
    except ValueError:
        pass  # 不是 IP 地址，跳过

    return None
```

### 4.3 限流配置

限流策略沿用 `docs/03-架构设计/06-后端可靠性与Redis防滥用设计.md` 中的设计：

| 接口 | Scope | 身份维度 | 默认策略 |
| --- | --- | --- | --- |
| `/api/parse` | `parse` | user id | 60 次 / 分钟 |
| `/api/tasks` | `create_task` | user id | 20 次 / 分钟 |
| 登录 | `login` | email hash + IP | 失败 5 次锁 15 分钟 |
| 注册 | `register` | IP | 10 次 / 小时 |

实现策略：

- `RedisRateLimiter` 使用 Redis key + TTL 计数。
- `InMemoryRateLimiter` 保留为 local/testing fallback。
- 生产环境默认使用 Redis；Redis 不可用时默认 fail-open 并记录告警。
- 关键 key 统一命名：`video:ratelimit:{scope}:{identity}`。

### 4.4 任务额度

沿用现有资源限制：

| 维度 | 限制 |
| --- | --- |
| 单任务最大文件大小 | 2GB |
| 单任务最大运行时长 | 2 小时 |
| 全局下载并发数 | 2 |
| 单用户下载并发数 | 1 |
| 文件保留时间 | 24 小时 |

### 4.5 Smoke 脚本

新增 `scripts/smoke_compliance_negative.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

BASE_URL="${BASE_URL:-http://127.0.0.1:8000}"

echo "=== 合规负向 Smoke 测试 ==="

# 测试 1: 无效协议
echo "[1] 无效协议 URL..."
RESP=$(curl -s -o /dev/null -w "%{http_code}" -X POST "$BASE_URL/api/tasks" \
  -H "Content-Type: application/json" \
  -d '{"url": "ftp://example.com/video.mp4"}')
[ "$RESP" = "422" ] && echo "  PASS: 返回 422" || echo "  FAIL: 期望 422, 实际 $RESP"

# 测试 2: localhost
echo "[2] localhost URL..."
RESP=$(curl -s -o /dev/null -w "%{http_code}" -X POST "$BASE_URL/api/tasks" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://localhost:8000/api/tasks"}')
[ "$RESP" = "422" ] && echo "  PASS: 返回 422" || echo "  FAIL: 期望 422, 实际 $RESP"

# 测试 3: 内网地址
echo "[3] 内网地址 URL..."
RESP=$(curl -s -o /dev/null -w "%{http_code}" -X POST "$BASE_URL/api/tasks" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://192.168.1.1/video.mp4"}')
[ "$RESP" = "422" ] && echo "  PASS: 返回 422" || echo "  FAIL: 期望 422, 实际 $RESP"

# 测试 4: .local 域名
echo "[4] .local 域名..."
RESP=$(curl -s -o /dev/null -w "%{http_code}" -X POST "$BASE_URL/api/tasks" \
  -H "Content-Type: application/json" \
  -d '{"url": "http://myserver.local/video.mp4"}')
[ "$RESP" = "422" ] && echo "  PASS: 返回 422" || echo "  FAIL: 期望 422, 实际 $RESP"

echo "=== 合规负向 Smoke 测试完成 ==="
```

## 7. 风险与边界

- Redis fail-open 会降低防滥用强度，但能避免 Redis 抖动导致全站不可用。
- 合规负向检查的内网地址范围需要支持 IPv4 和 IPv6。
- 限流默认值可能需要根据实际使用情况调整。
- Smoke 脚本依赖运行中的服务实例，不适合默认 CI。
