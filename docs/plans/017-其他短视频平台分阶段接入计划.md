## 1. 已完成代码工作

1. 建立 append-only Provider metadata/media/analysis 证明模型与动态状态聚合。
2. 实现 PeerTube 精确实例白名单，并在 API、下载 Worker、Canary 与 Media Runner 启动时装配同一 Registry。
3. 从产品平台注册表移除 AcFun、Rutube、VK Clips、Dailymotion 和 NicoNico，并对相关域名 fail closed。
4. 实现完整视频 analysis attestation：反查下载、制品、Agent run、严格结果、数据库报告、MinIO MD/DOCX 与 WebSocket 事件。
5. 实现 `PROVIDER_VERIFIED_KEYS` 显式发布批准，批准与三阶段证据缺一不可。
6. 保持 RabbitMQ 异步分析、报告持久化、登录态 refresh session 持久化、WebSocket 恢复和原任务多 run 重试能力。

## 2. 运维执行顺序

1. 在未跟踪的 Secret 环境中，为项目自有或明确授权视频配置相同 `target_id` 的 metadata/media 目标。
2. 启动 canary，确认 metadata/media 结果和稳定错误分类。
3. 使用正常产品 API 下载完整视频并创建分析，等待 RabbitMQ、Agent 与报告 Worker 全部成功。
4. 执行：

   ```bash
   python -m app.workers.canary.attest \
     --target-id <authorized-target-id> \
     --analysis-job-id <existing-analysis-job-uuid>
   ```

5. 确认命令只输出 target/provider/stage/outcome/稳定错误码，不包含 URL。
6. 在证据窗口满足后，将对应 key 加入 `PROVIDER_VERIFIED_KEYS`，滚动重启 API。
7. 通过 `/api/providers`、桌面/移动页面和监控确认状态；任何失败立即撤销批准或按状态机降级。
8. 归档前执行 `python -m app.workers.canary.archive` 只读复核；只有退出码为 0，且 Acceptance 已完成证据并显式标记 `acceptance: accepted`，才执行 `python -m app.workers.canary.archive --apply`。
