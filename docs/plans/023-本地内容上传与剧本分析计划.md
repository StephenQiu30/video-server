## 1. 交付策略

按“先统一边界与上传基础设施，再交付本地视频，随后交付剧本文档和 Skill”的顺序实施。每个阶段必须有独立 feature flag、自动化和回归证据；未完成剧本能力不能阻塞已验证的 MP4 上传，后续 `019` Edge Agent 也只能复用本计划的上传/验证端口。

本计划不创建新仓库、平行前端、第二套任务系统或运行时 Skill 安装器。数据库、API、Worker、Web 和文档均在现有 `video-server` 职责内完成。

Phase B 消息切片证据（2026-08-14）：新增严格的 `content.import.verify.requested` v1 payload/parser，只允许 `resource_id/content_kind/attempt/version`；RabbitMQ 初始化建立独立只读 import 用户、`video.import` quorum 主队列与 quorum DLQ、5 次 delivery limit、at-least-once dead-letter、TTL/长度/字节上限和受控回灌白名单。Import consumer 使用 manual ack，非法消息直接 dead-letter，执行异常与显式 retry 只允许一次客户端重投后进入 DLQ，shutdown cancellation 会 requeue。真实 RabbitMQ 4 已确认队列类型/策略/权限，并通过 Outbox 身份 publisher confirm 发布、Import 身份读取、严格解析和 ack；Phase C 聚合切片进一步证明 repository 在状态事务中只写一条验证事件，因此该消息基础项完成。consumer 的业务 lease/heartbeat、执行恢复和孤儿协调仍留在下一项。

## 12. 开工前输入

Phase A–F 可使用仓库自建 fixture 开始。真实验收前需要：

- 项目自有或明确授权的短 MP4；
- 可提交为 fixture 的合成中/英文短剧本，以及不能入库但可本地验收的完整剧本；
- 内容权利声明和 AI 云端处理披露文本；
- 外部 Skill 来源 commit、许可证和 NOTICE 责任人确认；
- 足够完成中英双向真实调用的活动 AI Provider 配额。

缺少真实完整剧本或 Provider 配额时，代码和自动化可以推进，但 Acceptance 中的中英双向 E2E 必须保持未通过，四件套不得归档。
