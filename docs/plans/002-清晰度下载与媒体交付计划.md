# Plan 002：清晰度下载与媒体交付

## 1. 前置门禁

Plan 000/001 状态均为 `done` 且 Acceptance 全部通过；邮箱 UUID owner、格式快照、Job 事件和 MinIO `ObjectStorage` Port 契约稳定。Design/Acceptance 必须先冻结 `download` operation 的签名 policy、current rights 和错误契约。

## 2. 范围

- 创建下载时重新读取 current rights statement 并要求显式确认；锁定 current ACTIVE signed policy，只有 `decision=allow` 且 `permitted_operations` 含 `download` 才创建 Job。
- 下载前重新解析并验证远端视频身份、DRM/download-disabled 信号和 `format_key`；Plan 001 的 probe-only dossier 必须 fail closed。
- Celery media queue 执行 yt-dlp 下载、必要的 FFmpeg stream copy 合流。
- 进度、取消、有限重试、磁盘/时长/字节配额和失败清理。
- ffprobe 验证分辨率、时长、音轨、容器和非空输出。
- MinIO 私有 multipart 上传；PostgreSQL 资产状态按 `PENDING → UPLOADING → READY`，只有 HEAD/大小/SHA-256 校验一致后 READY，失败进入 `FAILED` 并由 orphan sweeper 清理。
- PostgreSQL 保存 owner、opaque key、object version、SHA-256 与保留期；MinIO 只保存二进制。下载使用最长 15 分钟的签名 GET，24 小时生命周期由应用与对象层共同执行。
- SSE 断线恢复和刷新后的任务恢复。

## 3. 非目标

主动升频、默认转码、AI、PDF、Cookie、DRM、直播、播放列表和永久媒体库。

## 4. 核心验收

- 选择规格与最终媒体一致率 100%。
- 已知总量进度单调；未知总量不伪造百分比。
- 取消后 2 秒内更新状态、5 秒内停止继续拉取。
- 重试不生成重复资产；大文件不经过 API 或 Next.js。
- 签名链接过期可重签，不重复下载。
- 跨 UUID owner 访问统一 404；Redis 清空或 worker 重投不生成重复 MinIO object/READY 资产。
- MinIO 上传中断、HEAD/hash 不一致、PG commit 失败和孤儿 multipart 都有可复现补偿证据。
- probe-only policy 100% 返回 canonical `SOURCE_DOWNLOAD_NOT_AUTHORIZED` 且不创建 Job；operator-owned `download` grant 有真实 origin-control 正向 canary。
