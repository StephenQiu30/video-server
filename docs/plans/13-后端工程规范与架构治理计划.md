# PLAN13 后端工程规范与架构治理

## 1. 背景

视频下载后端已积累 router、service、core、schemas、models、worker 等多层职责，但缺少显式的依赖边界约束和架构治理规范。本计划承接 PRD08，将后端分层边界、依赖方向、单一事实来源和文档门禁固化下来。

## 2. 目标

1. 固化后端分层架构边界和依赖方向。
2. 建立架构边界测试防止回归。
3. 创建 PRD08 和 PLAN13 文档补齐治理链路。
4. 更新验证脚本检查文档完整性。

## 3. 非目标

- 不做大规模代码重构或目录迁移。
- 不引入新的 `repositories/`、`sources/`、`tasks/` 目录。
- 不改动前端工程规范。
- 不改动 Worker 内部实现。

## 4. 核心内容

### 4.1 OpenSpec 变更

创建 `openspec/changes/backend-architecture-governance/` 目录，包含：

- `proposal.md`：后端工程规范治理提案
- `design.md`：目录职责与架构设计
- `specs/backend-layer-boundaries/spec.md`：分层边界规范
- `tasks.md`：执行任务拆解

### 4.2 架构边界测试

创建 `apps/api/tests/test_architecture_boundaries.py`，使用 AST 分析验证：

1. router 层不直接导入 `yt_dlp`、`minio`、`redis` 等外部 SDK。
2. router 层不直接导入 `SessionLocal`（应通过 `Depends(get_db)`）。
3. service 层不从 router 导入。
4. core 层不从 service/router 导入。

### 4.3 文档更新

1. 创建 `docs/prd/08-后端工程规范与架构治理.md`
2. 创建 `docs/plans/13-后端工程规范与架构治理计划.md`
3. 更新 `docs/README.md` 添加 PRD08 和 PLAN13 索引
4. 更新 `scripts/validate-repository.sh` 检查 PRD08/PLAN13 存在性

### 4.4 规范推广

将 `backend-layer-boundaries` spec 推广到 `openspec/specs/backend-layer-boundaries/spec.md` 作为基线。

## 5. 执行顺序

1. 创建 OpenSpec change artifacts（proposal、specs、design、tasks）
2. 创建 PRD08 和 PLAN13 文档
3. 创建架构边界测试（红灯）
4. 更新文档和脚本
5. 推广 spec 到基线
6. 运行验证测试（绿灯）
