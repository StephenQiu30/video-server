# PLAN13 后端工程规范与架构治理

## 1. 背景

PRD08 定义了后端分层架构、SOLID 边界、shared 真相源和测试优先治理要求。PLAN13 将这些要求转化为可执行的渐进治理任务，不追求一次性重排全部代码，而是通过每次真实变更逐步收敛。

## 2. 目标

1. 将 PRD08 的分层架构定义落到可验证的目录结构和依赖约束。
2. 建立 shared 真相源，将分散的错误码和常量迁移到 `packages/shared/`。
3. 建立架构边界测试，防止跨层依赖引入。
4. 建立复杂度控制检查，防止单文件/单函数过度膨胀。

## 3. 非目标

- 不一次性重写全部已有模块。
- 不引入 CI 自动化架构扫描工具（如 import-linter），留待后续评估。
- 不覆盖 Worker 层的独立 repository 抽取（由后续 PLAN 处理）。

## 7. 风险与边界

渐进治理意味着短期内新旧代码风格并存。Phase 1-2 建立骨架和真相源，Phase 3-4 建立防护，后续每次真实变更时逐步将已有代码迁移到治理结构中。不要求一次性迁移所有已有模块。
