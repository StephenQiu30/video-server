日期：2026-09-22。状态：尚未开始业务实施。本文接管 BACKLOG P9 的执行细节，保留 P9.01–P9.14 编号；本次文档拆分不关闭任何业务任务。

[PRD](../prd/044-开源部署无感解析PRD.md) 定义 FR／NFR／AC；[Design](../design/044-开源部署无感解析需求与系统设计.md) 定义技术方案；[BACKLOG P9](../../BACKLOG.md#p9-开源部署无感解析执行计划044) 只提供入口和任务导航。**任务状态、承接者、阻塞和证据仅在本文维护**，不在 BACKLOG 复制勾选项。

## 1. SDD 工作方式

1. 从目标任务读取 PRD 条目、Design 章节和依赖；核对当前代码、工作区已有改动及调用方。未通过开始条件，不进入依赖实现。
2. 先为业务规则、故障或安全边界建立可判定的测试／验证场景，再实现最小闭环；代码生成只基于服务端 OpenAPI。
3. 按任务列出的开发步骤实现；新事实改变需求时先改 PRD，改变技术决策时先改 Design，同步本文的影响范围与验收。
4. 运行任务验证和所触及模块的仓库门禁；记录预期／实测、commit、版本和脱敏证据。代码完成不等于平台实测完成。
5. 检查全部关联 FR、NFR、AC 后更新唯一状态；发布依赖跨任务门禁，不能因一个后端任务完成就删除客户端仍依赖的接口。

开始条件（DoR）：依赖产物可用且必要验收通过；本任务 FR／NFR／AC 无未归属项；现有代码和未提交原型已盘点；真实样本、环境、预算与承接者已确定。遇到外部阻断记录事实和可继续的独立工作，不用假数据替代平台通过。

完成条件（DoD）：实现和被替代路径处理符合 Design；契约及受影响客户端同步；全部关联验收通过；必要运行手册更新；最小充分检查和脱敏证据完整。仅“已验收”可勾选。

状态使用：未开始 → 进行中 → 代码完成待验收 → 已验收；阻塞时写明阻塞点、恢复条件与负责人。每个任务标题下的勾选项及状态字段是唯一事实；步骤编号只标识开发顺序，不另建进度表。估时与日期在承接者和环境明确后填写，不用未经评估的日期承诺进度。

## 6. 验收记录与变更管理

每个任务完成步骤或遇到阻塞时，在该任务“执行记录”处维护以下信息；不要创建另一张状态表。无需为尚未执行的步骤预填“通过”。

```text
承接者 / 当前状态 / 更新日期：
关联步骤、FR / NFR / AC：
实际变更与提交（跨仓库时分别列出）：
环境、架构、镜像、schema、平台/出口/上下文版本：
验证命令或操作 / 时间 / 脱敏证据位置：
预期 / 实测 / 通过或失败 / 未测：
资源、耗时、样本量与统计口径：
阻塞或剩余风险 / 责任人 / 恢复条件：
需求或设计调整及影响任务：
验收结论与复核者：
```

代码与确定性测试链接到对应 commit；可公开的短实测结论记录在任务下，运行指导进入 `docs/operations/`。大体积录制保存在受控制品位置并附稳定引用；Cookie、完整签名 URL、个人媒体、原始日志和临时报告不得提交。证据失效、版本变化或复核失败时重开受影响任务，不能保留错误“已验收”。

PRD、Design、Plan 的有效内容持续维护，不因本次文档提交就删除。需求变更先更新 PRD，再审查 Design 和依赖任务；开发步骤变化只改 Plan。版本替代和已失效过程稿通过 Git 历史追溯，不复制多份当前规格。
