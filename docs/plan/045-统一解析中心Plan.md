## 3. 测试数据和场景

为测试账号建立：链接 ready/handed_off/action_required/failed/expired；视频 AI running/retry_wait/succeeded；剧本文档 uploading/verifying/ready/failed；剧本 AI 分析与改写各一项；同一剧本两次不同配置；源已删除但报告存在；分析已软删除；另一 owner 的同名数据。

关键回归：页面重载与跨浏览器不增加写请求；三页翻页中插入新记录不重复；后台任务终态后列表停止轮询；删除后旧链接不给其他结果；账号 A 请求延迟到 B 登录后返回不得显示；运行历史每条都属于所查任务与 owner。

受控 UI 夹具只能证明交互。真实 AI 和真实报告验证使用用户有权处理的短视频与小剧本，检查既有模型凭据可用性并按正常任务授权执行；不能用 fixture 或 HTTP 200 代替结果验收。无需为本功能重做全平台下载矩阵。

## 4. 检查入口

后端按 AGENTS：Ruff check/format、mypy、pytest；接口契约测试包含 discriminator 全覆盖、分页筛选、响应敏感字段过滤。SQL 有变更才增加空库/已有库幂等门禁。

前端按 AGENTS：pnpm format:check、pnpm lint、pnpm test、pnpm build；从运行源 OpenAPI 重生成请求与类型并核对差异。浏览器覆盖桌面和 390px、明暗、键盘返回焦点、筛选 URL、空/错/刷新失败，记录真实测试与夹具边界。

性能数据固定十万条混合记录、10 并发、热身后至少 1,000 次列表请求，记录环境、分布、p50/p95、错误率及 SQL EXPLAIN；首次页、深游标、状态筛选、标题搜索分开测，不用平均值掩盖慢查询。

## 5. 工作量估算与发布边界

以现有执行能力复用为前提，单工程师 Web/Backend 预计 7–10 个工作日：基线与契约 1 日，查询/测试 1.5–2 日，详情/运行历史 1.5–2 日，列表交互 1.5–2 日，联调/性能/发布 1.5–3 日。此为规划估算；老客户端升级、历史关联损坏或运行环境差异可能延长。App 另估 2–4 日并以真实设备条件校准。

第一交付切片 S2–S4 解决“记录缺失和结果找错”，S5–S7 完成可发布解析中心。切片合入不是整体验收，不能只加两个页签就关闭任务。
