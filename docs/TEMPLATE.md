# 文档标题

## 1. 背景与事实

记录可验证的现状、问题信号和输入来源。不要把历史实现当作现行需求。

## 2. 目标

列出具体、可衡量、有边界的目标。

## 3. 非目标

明确本轮不解决的事项。

## 4. 核心决策

按文档层级记录需求边界、技术方案、执行步骤或验收标准。

## 5. 契约与失败路径

说明数据、接口、状态、权限、安全、失败处理及迁移或回滚影响；不适用时说明原因。

## 6. 验证

列出可复现的命令、场景、期望结果和证据形式。

## 7. 风险与待确认项

记录残余风险、依赖和必须由人确认的决策。
