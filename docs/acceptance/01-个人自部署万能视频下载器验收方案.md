# MVP 验收方案

## 1. 背景

新版项目范围已经收束为个人自部署主链路，验收方案必须围绕“输入安全、平台识别、异步任务、MinIO 交付、自部署运行”五条线建立。

## 2. 目标

1. 为 5 个 PRD 提供统一的验收门禁。
2. 同时覆盖成功路径和失败路径。
3. 覆盖本机开发与 Docker Compose 两种运行方式。

## 3. 非目标

- 不覆盖 AI 摘要、PDF 报告或字幕增强能力。

## 4. 核心内容

### 4.1 功能验收

- PRD01：非法 URL、本机地址、内网地址和保留地址被拒绝。
- PRD02：5 个正式支持平台可识别并返回统一平台字段。
- PRD03：任务支持创建、列表、详情、取消、重试。
- PRD04：主视频成功归档后可获取短期有效下载链接。
- PRD05：本机开发和 Docker Compose 两条路径都能跑通。

### 4.2 失败路径验收

- 平台受限、限流和普通下载失败具有稳定错误码。
- MinIO 上传失败会让任务进入 `failed`。
- 封面缺失不影响主视频任务成功。

### 4.3 部署验收

- 已有 Redis/Postgres/MinIO 环境可复用。
- Docker Compose 可启动完整系统。
- 健康检查可区分 API、Redis、Postgres、MinIO 问题。

## 6. 验收门禁

- 至少 3 个正式支持平台公开样例可成功下载。
- 所有关键状态和失败语义可查询。
- 本机开发和 Docker Compose 两条路径有可执行验证步骤。

## 7. 风险与边界

真实平台样例会随时间变化，验收样例需要定期刷新，但验收结构不应依赖具体单一链接。
