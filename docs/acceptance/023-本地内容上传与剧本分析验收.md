## 1. 验收边界

验收分为上传基础设施、本地视频、剧本文档、Skill/供应链、剧本分析、剧本改写、安全、API/UI 和真实运行九个门禁。任一自动化或 fake Provider 成功不能替代真实 MP4、真实文本解析和中英双向模型 E2E。

本编号只验收浏览器本地上传；设备配对、Edge Import、微信视频号和红果继续由 `019` 独立验收。本地 MP4 成功不能提升任何 Provider canary。

## 2. 上传基础设施

- [ ] 浏览器 multipart 直传不经过 API 完整文件内存/磁盘中转。
- [ ] 上传会话只允许 owner 对应资源、attempt 和确定 quarantine key，无法更换 bucket/key、扩大大小或延长权限。
- [ ] quarantine 对公开下载、Analysis Worker 和其他 owner 不可读，短 lifecycle 生效。
- [ ] complete 的对象 HEAD、资源状态和 `content.import.verify.requested` outbox 原子提交。
- [ ] 过期会话、缺 part、错误 ETag、重复 complete、重复消息和并发 complete 状态稳定。
- [ ] Worker 在下载、验证、晋升、数据库提交和清理前后崩溃均无重复最终资源或假成功。
- [ ] 成功、失败、取消、过期和中断均有界 abort multipart 并清理 quarantine、part、最终孤儿和工作区。
- [ ] 队列使用 quorum、publisher confirm、manual ack、DLQ、有界回灌、lease/heartbeat 和恢复扫描。

## 3. 本地视频上传与拉片

- [ ] 有效本地 MP4 创建 `browser_import` download job，inspection/format 为空且 SQL CHECK 正确。
- [ ] 服务端重算大小/SHA-256，并验证 BMFF、视频轨、正时长、codec、尺寸和配置上限。
- [ ] 合法无声 MP4 可以通过；系统不转码、不修复、不改变原始字节。
- [ ] 假扩展名、损坏容器、无视频轨、外部引用、多文件、playlist、超大小/时长和哈希不一致 fail closed。
- [ ] 成功只生成一个现有 Artifact，来源显示“本地视频上传”，不写 Provider canary。
- [ ] 上传视频完成 `director-breakdown`：完整视频 Agent、结构化结果、PostgreSQL、MinIO MD/DOCX、WebSocket 和浏览器 E2E。
- [ ] Analysis 失败、取消或删除不改变 upload/download 成功和原始 Artifact 状态。
- [ ] 原 URL inspection、格式选择、下载、历史、取消、重试和五个视频 Skill 全量回归通过。

## 4. 剧本文档导入

- [ ] DOCX、可提取文字 PDF、TXT、Markdown、Fountain 各有中/英文有效 fixture 并进入 ready。
- [ ] Document 独立于 download job/video artifact，原始与 normalized 对象各自有稳定 SHA-256、状态和保留期。
- [ ] 同一原始字节重复规范化得到相同 UTF-8 文本 SHA-256、场景顺序和 scene ID。
- [ ] 场景标题、动作、人物、括注和对白的中英文 fixture 解析符合人工真值。
- [ ] 无明确场景但有正文时产生单场景质量警告；空文本、乱码超限和不可恢复结构失败。
- [ ] DOCX zip bomb、路径穿越、宏、外部关系、超多条目和超解压大小均被拒绝。
- [ ] 加密/附件/扫描/空文字/低质量 PDF 被拒绝，不自动 OCR、不执行脚本或外部资源。
- [ ] TXT/Markdown/Fountain 的 NUL、控制字符、超长行、非法编码和超字符数被拒绝。
- [ ] 文档详情只显示有界纯文本预览，不渲染上传 HTML/OOXML/PDF 活动内容。
- [ ] 文档不可原地替换；上传修订稿创建新的 Document 和 SHA-256。

## 5. Analysis 联合输入与生命周期

- [ ] 现有 Analysis 数据幂等回填为 video；数据库拒绝双输入、无输入和 kind/外键不一致。
- [ ] 视频只使用 Artifact，screenplay 只使用 Document normalized SHA-256。
- [ ] Document owner、ready、expiry、deleted 和 hash 漂移检查 fail closed，跨 owner 返回 404。
- [ ] `analysis_document_locks` 在运行、可重试和报告发布期间阻止输入清理，终态后按策略释放。
- [ ] 视频/剧本共享 lease、heartbeat、retry wait、取消、原任务重试、删除、报告发布和 WebSocket 语义。
- [ ] 创建时 Skill 指令、指令 SHA-256、result contract、output language、custom prompt 和 input SHA-256 固定；配置变化不改变重试。
- [ ] 视频与剧本 result 使用当前带 `kind` discriminator 的联合 OpenAPI，不存在 legacy 双轨 parser。
- [ ] Markdown 预览、Markdown 下载和 DOCX 内容来自同一 canonical Markdown。

## 6. Skill 与供应链

- [ ] `GET /api/analysis-skills?input_kind=video` 只返回五个视频 Skill；`screenplay` 只返回三个剧本 Skill。
- [ ] 现有视频 Skill 已迁移到标准 frontmatter，视频分析结果无行为回归。
- [ ] `screenplay-analysis`、`screenplay-structure-review`、`screenplay-rewrite` 的 ID、显示名、默认提示和顺序稳定。
- [ ] Skill 只能绑定 allowlisted input kind 和 result contract，用户 Prompt/正文不能改变。
- [ ] 重复 ID、非法名称、未知 metadata、绝对/穿越引用、符号链接、未知 contract 和输入类型均使服务启动/CI fail closed。
- [ ] 外部 scripts、allowed-tools、MCP、插件和网络要求不会进入子进程。
- [ ] 每个受 GitHub 启发的 Skill 有来源 URL、固定 commit、许可证/NOTICE 和本地修改记录。
- [ ] 固定 commit 更新会触发重新审查、fixture 和真实 E2E，不存在运行时 clone/pull/install 路径。

## 7. 剧本分析

- [ ] 中文和英文完整剧本分别完成一次 `screenplay-analysis` 真实 Provider E2E。
- [ ] `screenplay-structure-review` 对人工植入的节拍、场景推进、转折、连续性和节奏问题给出可执行结论。
- [ ] 结果包含 logline、synopsis、结构/转折/节奏、人物、场景、对白、优点和优先修改项。
- [ ] 每个人物、场景、对白和修改建议只引用存在的源 scene ID，无悬空、重复或模型自造源场景。
- [ ] 未知字段、超长字符串、超大数组、非法 ID、悬空引用和超大 JSON 被拒绝且不保存部分结果。
- [ ] 超过单次预算的 fixture 使用“场景级 → 全局摘要”父 Worker 编排，最终结论仍覆盖全部场景。
- [ ] fake CLI 覆盖正常、非法 JSON、Schema 失败、限流、额度、超时、取消和进程树清理。

## 8. 中英文改写

- [ ] 中文剧本完成中→英，英文剧本完成英→中，另有一次同语言润色真实 Provider E2E。
- [ ] glossary 覆盖主要人物名、地点、专有名词、称谓和保留术语，并通过 schema 校验。
- [ ] 每个输出块携带正确 scene ID、part、源 SHA-256 和 target language。
- [ ] 合并前 scene/chunk 覆盖率为 100%，无缺失、重复、顺序漂移和跨源哈希复用。
- [ ] 同一人物与保留术语在全部场景中遵循 glossary；冲突会阻止报告发布或返回明确质量失败。
- [ ] 单场景超限时按动作/对白段落细分，合并后仍保持一个源场景的相对顺序。
- [ ] 任一块失败时不发布部分改写；原任务重试保持同一输入、Skill、语言和 glossary 规则。
- [ ] 完整改写正文只确定性合并一次，公开 JSON 没有第二份全文，Markdown/DOCX 内容一致。
- [ ] 输出页面明确标注 AI 改写和目标语言，不宣称法律、行业或逐字翻译准确性。

## 9. 安全、隐私与资源

- [ ] 剧本文本、metadata、文件名和 Prompt Injection 无法联网、读取 Home/仓库/相邻任务/Secret 或扩大工具权限。
- [ ] 剧本执行器没有 FFmpeg、通用 Shell、MCP、插件、浏览器和 subagent；视频权限保持当前最小边界。
- [ ] CLI 子进程环境没有数据库、RabbitMQ、MinIO、签名或无关 Provider Secret。
- [ ] 上传/解析/分析的 CPU、内存、pids、磁盘、文件数、文本、chunk、输出和 wall-clock 上限均有故障注入证据。
- [ ] 取消、超时、lease 丢失、Agent shutdown 和 Worker 崩溃终止完整进程组并清理 workspace/chunks。
- [ ] API、WebSocket、RabbitMQ、数据库普通字段、日志、trace 和指标扫描无完整正文、Prompt、预签名 URL、模型原始响应、人物名和场景内容。
- [ ] 创建 AI 任务前披露剧本文本和必要上下文会发送到活动云端模型 Provider。
- [ ] 删除/过期清理 quarantine、原始文档、normalized 文本、chunks、result 和报告，不越过活动任务锁。

## 10. API、前端与可访问性

- [ ] 所有新公开操作 operationId 唯一稳定；创建资源返回 `201 + Location`；严格 schema 拒绝额外字段。
- [ ] OpenAPI 生成前端服务无手工漂移，认证、幂等键、错误映射和重试入口一致。
- [ ] 首页“链接解析 / 本地上传”可键盘切换，不破坏现有首页网格、格式选择和返回路径。
- [ ] MP4 上传成功进入现有下载详情；剧本文档进入 `/documents/detail`，直接访问和站内返回均稳定。
- [ ] 文档列表/详情覆盖 loading、empty、uploading、verifying、ready、failed、cancelled、expired 和 retry。
- [ ] 剧本分析/改写覆盖 Agent 离线、执行、分块进度、失败、取消、重试、成功、导出和删除。
- [ ] 所有文本按纯文本或安全 Markdown 呈现，不执行上传 HTML、脚本、命令和外部链接指令。
- [ ] 1280px、1024px、390×844 无页面级横向溢出；长文件名、错误、glossary 和正文安全换行/局部滚动。
- [ ] 唯一 h1、顺序标题、label、按钮、焦点环、Escape/焦点恢复、44px 目标、对比度和 aria-live 满足 WCAG 2.2 AA。
- [ ] 明暗主题、上传进度、覆盖层滚动锁、导航固定槽位和 reduced motion 无视觉回归。

## 13. 当前结论

当前仓库已完成 Phase A 的枚举、feature flag、下载来源形态、Analysis 联合输入/结果契约、旧数据回填和 OpenAPI 基线，但尚无浏览器 Artifact Import、Document 聚合、剧本执行器或三个剧本 Skill。本验收保持 `pending`；不得宣称本地上传或剧本中英文改写已可用，也不得归档 `023` 四件套。
