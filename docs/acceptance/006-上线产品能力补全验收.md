## 判定规则

- Public Beta 只有在 P0 全部通过、无 Critical/High 未接受风险时才能发布。
- 自动化 fake 不能替代真实依赖、真实容器网络和受控媒体 E2E。
- 单个 Provider 成功不能替代 Provider 状态/canary 机制。
- “字段存在”不能替代物理删除、备份恢复或网络阻断的执行证据。
- 任何失败项必须保留失败输出和后续修复记录，不得只修改勾选状态。

## B. Secret 与网络隔离

- [ ] B1：每个服务只有显式环境白名单，快照不包含越权 Secret。
- [ ] B2：Media Runner 环境不含 DB/RabbitMQ/MinIO/Valkey/AI 凭据。
- [ ] B3：Runner 不能连接 PostgreSQL、RabbitMQ、MinIO 或 Valkey。
- [ ] B4：Runner 不能绕过 egress proxy 直接访问公网。
- [ ] B5：Runner 经 egress proxy 可完成受控公开样本 inspect/download。
- [ ] B6：私网、loopback、link-local、云元数据、字面量 IP、重定向与 DNS rebinding 被阻断。
- [ ] B7：Download Worker/Analysis Worker/Outbox/API 也不持有超出职责的 Secret。
- [ ] B8：网络/Secret 测试在 CI 或 production-like staging 容器内执行，不是静态文本断言。

## C. 限流、配额与入口

- [ ] C1：IP/owner/API key/operation 多维限流在多 API 实例下原子一致。
- [ ] C2：inspect/download/analysis 使用不同成本策略和并发上限。
- [ ] C3：每日任务、字节、AI 分钟和活跃任务配额不会竞争超卖。
- [ ] C4：幂等重放不重复扣费；失败/取消按规则释放或结算。
- [ ] C5：超限返回 Problem Details、429 和正确 `Retry-After`。
- [ ] C6：伪造 forwarded headers 不能改变限流身份。
- [ ] C7：全局 backpressure 拒绝新高成本任务，但查询/取消/删除/取文件仍可用。
- [ ] C8：TLS、安全 header、body/header/timeout 和可信代理链通过协议测试。
- [ ] C9：管理/metrics/Swagger 的生产暴露符合冻结策略。
- [ ] C10：bot challenge/API key 失败、过期、重放和撤销路径通过。

## D. 数据生命周期

- [ ] D1：到期且无分析锁的 artifact 在目标窗口内删除 MinIO 对象并写 `deleted_at`。
- [ ] D2：有分析锁的 artifact 不会被删除，终态释放后可再次清理。
- [ ] D3：对象已不存在时重复删除幂等成功。
- [ ] D4：MinIO 不可用时删除退避重试、达到阈值告警且不丢任务。
- [ ] D5：用户删除运行中、成功、失败和已过期任务的行为符合契约。
- [ ] D6：跨 owner 查询/取消/重试/删除始终返回 404。
- [ ] D7：孤儿对象和 DB 缺失对象对账可检测、隔离和处理。

- [ ] D9：inspection/formats/outbox/job/analysis 的保留和清理与隐私策略一致。

## 当前结论

2026-08-08 已完成 P0 基础代码的一部分并保留本地证据；真实容器网络阻断、迁移/备份恢复、长期配额、可观测性、Provider canary、用户删除和 P1 媒体能力仍未验收。当前结论保持 Pending，项目不得基于本验收文档宣称已经满足公网生产上线条件。
