## 1. 冻结前置条件

- [ ] 测试数据至少包含一个管理员、一个普通用户、两个视频来源、六种下载状态、UTC 边界任务与空白日。
- [ ] `media_inspections` 仍使用 URL 密文包，`download_jobs.inspection_id` 外键可关联来源，没有新增重复来源列或分析事实表。
- [ ] 后端契约/聚合测试、前端组件测试和生产构建可执行；PostgreSQL 口径与浏览器证据在本文保持待验收，不预先标记通过。

## 2. 逐项验收

- [ ] A1：未登录请求分析 API 返回 401；普通用户返回 403 且无桌面/移动入口；管理员返回 200 并可直接刷新 `/admin/analytics`。
- [ ] A2：`GET /api/admin/downloads/analytics` 默认使用 30 天；`days=7`、`30`、`365` 可用，`6`、`366`、非整数返回 `ProblemDetails` 422。
- [ ] A3：多来源/多状态样本的 summary（包括 `unique_users`、`downloaded_bytes`、`average_duration_seconds`）、UTC 每日 `total/succeeded/failed/cancelled` 分桶与来源分布和数据库任务/制品事实一致，任务不因幂等重放重复计数。
- [ ] A4：成功率按 `succeeded / (succeeded + failed) * 100` 计算为 0–100 百分比并保留 1 位小数；后端值为 88.9 时前端显示 88.9%，不显示 8890%；分母为 0 时显示 0%。
- [ ] A5：每日数组升序且空白日补零，来源按任务数降序并稳定打破平局；无任务时摘要为零、数组结构合法，页面显示 Empty 而非空白。
- [ ] A6：inspection 解析 TTL 过期后，已创建任务仍能按来源聚合；查询不解密 URL，API/DOM 不出现 URL、`owner_hash`、`provider_media_id`、`provider_hints`、`error_message`、用户资料或对象存储字段。
- [ ] A7：OpenAPI 包含唯一 `getDownloadAnalytics` 操作、单一 `admin` tag、`days` 边界和严格响应 schema；响应字段为 `period_days/start/end/summary/daily/sources`，重新生成前端客户端无漂移。
- [ ] A8：页面只在 7/30/90 天快捷值之间切换且请求参数正确；刷新复用当前窗口；快速切换时旧请求最后返回也不覆盖新数据。
- [ ] A9：加载骨架、数据态、空数据、请求失败、重试和刷新状态都有明确文本；图表有可读标题和等价表格/列表，数值不只靠颜色或 Tooltip 传达。
- [ ] A10：桌面 1280px 和移动 390×844 下页面符合 009 的 72px Header、1376px 隐形网格、80/32/16px gutter、无可见 Card 外壳和发丝 Separator 规范，无横向溢出；键盘、明暗主题、200% 缩放和 reduced motion 下仍可读。
- [ ] A11：后端 ruff/format/mypy/pytest、前端 lint/format/Vitest/build、OpenAPI 漂移检查与本地/生产 Compose 解析的实际结果已记录；任一失败都不得标记验收通过。
