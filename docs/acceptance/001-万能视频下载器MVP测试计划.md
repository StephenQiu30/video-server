# 万能视频下载器 MVP 测试计划

## 1. 背景

本测试计划承接 PRD 001-005 和 MVP 执行计划，强调 TDD 红绿流程：每个功能点先用失败测试定义验收，再实现最小代码通过测试，最后在测试保护下重构。

## 2. 目标

1. 为解析、格式选择、下载归档、AI/PDF 和合规治理提供可执行测试入口。
2. 明确哪些能力必须自动化验证，哪些平台样例允许通过 smoke 或手工证据补充。
3. 保证主下载链路和增强产物链路分层验收。

## 3. 非目标

- 不把一次性调试日志作为长期验收证据。
- 不要求所有互联网平台样例在 CI 中联网验证。
- 不用手工验证替代核心业务规则的单元或契约测试。

## 4. 红绿测试矩阵

| 功能 | 红灯测试 | 绿灯实现 | 回归命令 |
| --- | --- | --- | --- |
| 链接解析与平台识别 | 新增样例 URL 平台画像断言，先观察失败 | 补平台 profile 或错误分类 | `pytest apps/api/tests/test_platform_profiles.py apps/api/tests/test_parse_error_classification.py` |
| 分辨率与无水印优先 | 断言推荐档位、高级格式、水印提示字段 | 扩展解析响应和格式构建 | `pytest apps/api/tests/test_download_adapter.py apps/api/tests/test_openapi_contract.py` |
| 下载任务与产物归档 | 断言增强产物失败不影响主任务成功 | 扩展 Worker 产物处理和事件 | `pytest apps/api/tests/test_worker_jobs.py apps/api/tests/test_task_endpoints.py` |
| AI 摘要与 PDF | 断言 skipped/completed/failed 和 PDF 权限 | 调整 AI pipeline 与 PDF 导出 | `pytest apps/api/tests/test_ai_intelligence.py apps/api/tests/test_finalize_features.py` |
| 自部署 Cookie 与合规 | 断言浏览器名校验和负向合规配置 | 收紧配置、错误和 smoke 脚本 | `pytest apps/api/tests/test_production_config.py apps/api/tests/test_worker_reliability_modules.py` |

## 5. 端到端验收场景

```gherkin
Given 用户已登录并粘贴公开视频链接
When 用户解析链接并选择推荐格式
Then 系统创建下载任务并在 Worker 完成后返回下载链接
And 任务事件展示下载、上传和增强处理进度
```

```gherkin
Given 平台只提供带水印或不可确认水印状态的视频源
When 用户查看格式列表
Then 系统提示无水印源不可确认或不可用
And 不提供主动去水印能力
```

```gherkin
Given 自部署用户配置了浏览器 Cookie 来源
When 配置值不是 chrome、chromium、edge、firefox、safari 或关闭值
Then Worker 返回浏览器登录态配置无效
```

## 6. 必跑命令

开发阶段按 issue 运行最小命令，PR 收口前运行：

```bash
npm test
```

涉及 Docker 生产配置时额外运行：

```bash
set -e; cp .env.production.example .env.production; npm run docker:config; rm -f .env.production
```

涉及公网合规和平台 smoke 时按需运行：

```bash
bash scripts/smoke_compliance_negative.sh
bash scripts/smoke_parse_platforms.sh
bash scripts/smoke_download_task.sh
```

## 7. 验收证据要求

- 自动化测试必须记录命令和结果。
- 联网平台 smoke 必须记录样例来源、时间、成功/失败结果和失败语义。
- 失败但可接受的增强产物必须记录事件或状态，而不是静默吞掉。
- PR 描述必须包含 Test-first Evidence、Tests added、Commands run 和 Result。

## 8. 残余风险

- 平台样例可能因地区、风控或页面结构变化而失效。
- AI provider 成本和限流不适合纳入默认 CI。
- 浏览器 Cookie 读取依赖自部署机器环境，CI 只验证配置和错误语义。
