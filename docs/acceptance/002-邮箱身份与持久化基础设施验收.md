## 4. 身份与会话细化矩阵

- register/request/forgot 对命中与未命中邮箱返回相同 status、content type、schema 和账户相关 header。固定本地服务预热后各采样 200 次，分别比较 median 与 p95；两组差值都必须 ≤`max(25ms, 较慢组的10%)`，并附原始分布。`check_deliverability=false` 且测试证明无 DNS 查询，只有成功验证邮件能把 `is_verified` 置真。
- 规范化邮箱唯一且大小写变体不能创建第二个用户；不执行供应商 dot/plus folding。数据库和 API UUID 类型一致，不接受文本 installation owner。
- Argon2id hash/rehash 由 pwdlib 执行；明文密码、hash、session/verify/reset token 不出响应、日志、trace、event、Celery message 或 MinIO metadata。CSRF raw token 只允许出现在专用 no-store bootstrap JSON 与请求 header，禁止其他响应面和全部日志/持久化面。
- `GET /auth/csrf` 返回 200、no-store、正文 raw token 与 `HttpOnly` 签名配对 Cookie，且不读取账户状态；login 成功 204 并设置生产 `__Host-video_session`、清除旧 CSRF 配对。route dependency 用 fastapi-csrf-protect 校验 raw header、签名 Cookie 与 1 小时有效期；缺失、篡改、过期、旧 header 对缺失或轮换后 Cookie、错误 Origin/Host 或 Fetch Metadata 均在业务写入前失败。不得记录为数据库 session binding。
- Redis 限流不可用时 register/login/verification request/forgot fail closed 为可重试 503；已有合法会话的只读 `me` 仍由 PostgreSQL 验证。Redis 恢复后限流无无限放大窗口。
- logout、用户禁用、密码重置和 7 天绝对到期均使旧 Cookie 不可用；不存在/跨 owner 资源统一 404。reset command 在 commit 前故障时 hash/session/intent/audit 必须全部回滚，commit 后故障时四类事实必须全部提交且旧 Cookie 不可用；verify 的用户状态/intent/审计满足同一原子规则。

## 5. 邮件与 outbox 细化矩阵

- 故障注入一必须复现“注册用户已提交、callback 未写 intent/outbox”，证明 scanner 只基于未验证用户补建 current 验证 generation。故障注入二必须先提交已验证用户的 forgot `auth_mail_intent`，再令 callback 崩溃，证明 reconciler 不依赖 `is_verified=false` 即可对同一 intent 补建唯一 outbox；不得用测试事务掩盖 gap。
- callback command commit 前故障必须同时不存在 outbox 与 ENQUEUED，commit 后故障必须二者同时存在；数据库约束拒绝任何部分状态。并发/重复请求按 generation 串行化，新 generation 使旧未消费 token digest 与未发送 outbox 失效，旧 token 不能重置密码。
- dispatcher/worker 只接收 `mail_id`；STARTTLS/TLS 证书错误 fail closed。SMTP 4xx/timeout 可重试，5xx 按策略终止；attempt 11 不发送，dead-letter 可审计和人工重放但不重复已成功 generation。
- verification/reset token digest 必须等于原始 token UTF-8 bytes 的 SHA-256 lowercase hex，且不复用 AES key；token material 用 cryptography `>=49.0,<50` AES-256-GCM v1 envelope 在 PG 加密。随机 nonce 不复用，format/key ID 在 exact AAD 中，篡改 ciphertext/nonce/AAD/key ID 均 fail closed；重复 key material 配置拒绝启动。覆盖 active/旧 key 解密、新 key 写入、引用行重加密，`SENT/SUPERSEDED` material 立即全清、`DEAD_LETTER`/未投递行最迟 expiry 全清、部分 material 被约束拒绝，旧 key 只有零引用才可移除；过期/已使用/错误 purpose 均 `AUTH_TOKEN_INVALID`。邮件模板没有远程图片、脚本或用户可控 HTML。
- production `PUBLIC_WEB_ORIGIN` 只接受 exact HTTPS origin，development 只允许 loopback HTTP；`TRUSTED_API_AUTHORITY` 只接受部署配置的单一 `host[:port]`。任意 hostile/重复 `Host` 或 `Forwarded/X-Forwarded-*/Origin` 都不能改变门禁或固定 fragment 链接，缺失/非法配置必须启动失败。
- register/request/forgot 不因邮箱存在性、SMTP 瞬时失败或 dead-letter 返回可枚举差异；管理员健康检查可见 `EMAIL_DELIVERY_UNAVAILABLE`，用户 detail 不含收件地址。

## 6. Redis/outbox 故障矩阵

- 事务回滚无消息；claim lease/fencing 阻止旧 claimant 完成新 lease；publish 后崩溃允许重复但 worker no-op；poison message 有有限重试和 dead-letter。
- 在 Redis AOF/RDB 均删除后重启：PG 行数/hash/终态不变；reconciler 为无有效 worker lease 的非终态 Job 创建新 delivery attempt；旧 event 不改写，SSE cursor 从 PG 连续恢复。
- Redis 禁止保存唯一 session、Job、资产状态或邮件意图；cache key 过期/丢失只影响性能。启动检查拒绝 `allkeys-*` eviction、无认证的非 loopback Redis 或错误 namespace。

## 7. MinIO Saga 与生命周期矩阵

- `PENDING → UPLOADING → READY` 只有 HEAD 的 version/size/MIME/SHA-256 全匹配才能完成；任一不符进入安全 FAILED，不签发 URL。重复 complete 只返回同一资产。
- multipart 中断可续传或 abort；complete 后 PG 崩溃产生的孤儿由 inventory/reconciler 删除；PG 成功而对象缺失使健康检查失败且资产不可读。
- bucket/list/object 默认私有，key/metadata 不含邮箱、owner、文件名、Source URL；presigned GET/PUT 最长 15 分钟且不能跨 owner 重签。
- 删除从 PG `DELETING` 驱动，清除源/副本全部版本并 HEAD 404 后才 `DELETED`；旧 presign 随对象删除失效。时钟分别推进 24h、7d、用户删除和 backup+30d 验证清理。
- 本地全部通过后仍只记录“开发集成 passed”；生产 AC 在三选一门禁完成并用批准 digest 重跑复制、故障与恢复前保持 blocked。

## 8. 备份恢复证据

在隔离环境创建带两个 owner、会话、Job/event、mail outbox、READY/DELETED 对象的 manifest 和 SHA-256；记录故障时点，执行 pgBackRest base+differential+WAL PITR、MinIO 副本恢复、Redis 空库重建。恢复后逐行/逐对象对账，验证 FK、session revoke、outbox fencing、event cursor、object version/hash、删除/retention，再开放 API。

RPO 从最后可恢复业务提交到故障时点计算，RTO 从宣告灾难到健康门禁全部通过并恢复服务计算；默认分别 ≤5 分钟和 ≤2 小时。没有异故障域、只复制 volume、未记录起止时点或手工改数据均不能 passed。
