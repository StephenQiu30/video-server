# URL 解析与清晰度目录验收

## 1. 通过规则

下列全局 AC 全部 `passed` 且独立 Functional Review 无 blocker 时，Plan 001 才能标为 `done`。每项必须附精确命令、环境、提交 SHA、关键输出和证据路径；缺少证据不得通过。

## 2. 固定环境与数据

- Python 3.13；锁定的 PostgreSQL、Redis、Celery、Smokescreen、yt-dlp 与 HTTPS fixture 镜像。
- `DS-P1-RESOLVE-12`：逐项输入与期望由版本化 JSON manifest 冻结；测试记录 fixture origin、TLS 与 manifest SHA。
- `DS-P1-FORMAT-8`：纯 normalization manifest 冻结多候选排序、去重、locale/fallback audio、null、incompatible family、codec/label 与 fingerprint tie；public wire fields 除随机 format_key 外逐字段断言，`components/fingerprint_sha256` 只作内部 oracle 并必须证明不出 API/OpenAPI。
- `CANARY-W3C-SINTEL-1`：项目签名 dossier 对 W3C 公开测试媒体执行真实 metadata probe；记录 W3C 依据、响应和 parser 版本。
- `CANARY-OPERATOR-OWNED-1`：真实受控 HTTPS origin 完成 well-known nonce、trust scope、operator 签名/import 与 probe；无 origin-control 证据不得通过。
- 负向集覆盖 rights statement、签名/trust/revoke/expiry/ACL、auth/disabled/DRM、Host/Origin、协议/IP/端口、全部 A/AAAA、redirect/rebinding、metadata 与 proxy bypass。
- 性能为 warm worker、cold format cache、并发 1、30 次；从 POST 被 API 接收到 Source 首次可读计算，p95 ≤8 秒。

## 4. AC-API-001 细化矩阵

- 状态属性测试覆盖所有允许/禁止迁移、终态不可逆、attempt 单调和失败保留 stage。
- outbox 覆盖事务回滚不投递、claim 后 publish 前崩溃的 60 秒 lease/reclaim、stale claimant CAS、10 次退避、发布后崩溃只重复不丢失、dead-letter `QUEUE_DELIVERY_FAILED`。
- SSE 覆盖 Last-Event-ID 回放、replay/live 竞态、重复/乱序、丢 wake、Redis 重启、2 秒 tail、heartbeat、stream-reset 和终态刷新。
- migration 从空库 `upgrade head`；无数据时 `downgrade base`；API/dispatcher/worker/proxy 健康信号通过。
- 生成 `openapi/openapi.json` 后再次生成无 diff，并通过 schema/fixture 契约测试。
- Source 快照到期或 policy 进入 REVOKING/REVOKED/EXPIRED 均立即 410，原 Job/Resolution 不回退，旧 format key 不可继续使用；并发发布不能越过 revoke 线性化点。
- 从 request.created_at 推进绝对时钟，逐表验证 request/Source/format/Job/step/event/unpublished/dead-letter 不越过 7d、published outbox 不越过 published_at+24h、audit 不越过 30d；注入首轮清理失败后在 must-purge deadline 前恢复，越界触发隐私健康失败，日志/DB 无明文 key、URL 或 selector。
