# 部署与运行规划

更新时间：2026-05-02

## M1 后端运行方式

当前项目支持“本地开发”和“生产 Docker 部署”两套运行方式，并提供统一启动入口：

```bash
./scripts/start.sh local
./scripts/start.sh prod
```

### 本地开发方式（推荐）

本地开发只启动项目进程，不安装、不启动 Redis、PostgreSQL、MinIO / S3 这类基础设施：

- Python：默认运行 FastAPI API；需要验收队列下载链路时再启动 RQ Worker。
- PostgreSQL：由 `.env` 指向已有服务；本地一键启动不负责安装或启动。
- Redis：只在本地启动 Worker / 队列下载验收时需要；本地一键启动默认不启动 Worker。
- MinIO / S3：由 `.env` 指向已有服务；本地一键启动不负责安装或启动。
- FFmpeg / ffprobe：M1 本地验收阶段必须在本机可执行，用于音视频合并和媒体校验。

本地一键启动命令：

```bash
./scripts/start.sh local
```

如果需要本地验收队列下载链路，并且已有可用 Redis：

```bash
START_WORKER=true ./scripts/start.sh local
```

分步启动命令：

```bash
cp .env.example .env
pip install -r apps/api/requirements.txt
./scripts/check_local_services.sh
./scripts/dev_api.sh
./scripts/dev_worker.sh
```

说明：

- 当前队列选型是 `RQ + Redis`，本地不需要 RabbitMQ。
- 本地普通开发不强制启动 Redis；Redis 只在启动 Worker 或验收异步下载链路时需要。
- macOS 本地开发默认使用 `RQ_WORKER_MODE=simple`，避免 RQ fork 子进程触发系统级崩溃；生产环境可使用默认 fork Worker。
- `/Users/stephenqiu/Desktop/Docker` 继续集中管理 PostgreSQL、Redis、MinIO 等基础设施服务，不新增独立 FFmpeg 服务。
- 如果后续改用 RabbitMQ，需要重新提交技术选型 ADR。

### 生产 Docker 部署方式

Docker 配置区分默认环境和生产环境：

- 默认 Compose：`infra/docker/docker-compose.yml`，只定义 `web` 和 `api`，不启动 PostgreSQL、Redis、MinIO，不启动 Worker；API 容器通过 `.env` 中的 `DOCKER_DATABASE_URL`、`DOCKER_REDIS_URL`、`DOCKER_S3_ENDPOINT_URL` 复用本机已有 brew PostgreSQL、brew Redis 和 MinIO，前台启动命令为 `./scripts/start.sh docker`，后台一键启动命令为 `./scripts/start.sh docker:detached` 或 `npm start`，停止命令为 `npm stop`。
- 生产 Compose：`infra/docker/docker-compose.yml` + `infra/docker/docker-compose.prod.yml`，读取 `.env.production`，同时启动 Web、API、Worker、PostgreSQL、Redis 和 MinIO。

生产服务包含：

- Compose 项目名：固定为 `stephen-video`。
- 容器名：固定为 `stephen-video-web`、`stephen-video-api`、`stephen-video-worker`、`stephen-video-postgres`、`stephen-video-redis`、`stephen-video-minio`，线上排障时不依赖 Compose 自动生成的 `-1` 后缀。
- `api`：FastAPI 服务，默认端口 `8000`。
- `worker`：RQ 下载 Worker。
- `web`：Umi / Ant Design Pro 前端，默认通过 `3000` 端口访问。
- `postgres`：PostgreSQL 16，仅在 Compose 内部网络暴露。
- `redis`：Redis 7，仅在 Compose 内部网络暴露。
- `minio`：MinIO / S3 兼容对象存储，默认宿主机 API 端口 `19000`，控制台端口 `19001`，避免和本机已有 MinIO 冲突。

API 和 Worker 镜像统一使用多阶段 Dockerfile，内置 FFmpeg / ffprobe：

- `infra/docker/python.Dockerfile`

Web 静态产物只在生产 Docker 配置中构建，由生产 Web 镜像内置 Nginx 托管 Umi 构建产物。Nginx 配置不作为独立文件维护，避免把线上静态托管细节暴露到独立配置文件中：

- `infra/docker/web.prod.Dockerfile`

生产启动命令：

```bash
cp .env.production.example .env.production
# 替换 CHANGE_ME、域名、密钥和密码
./scripts/start.sh prod
```

前端访问：

```bash
open http://localhost:3000
```

后端健康检查：

```bash
curl http://localhost:8000/health
curl http://localhost:8000/ready
```

## 部署原则

- 默认使用 Docker 或项目本地环境运行，避免污染宿主系统。
- 首版优先单机可运行。
- MVP 即引入 Redis、PostgreSQL 和 MinIO / S3 兼容对象存储；生产化阶段再扩展多 Worker、对象生命周期和监控。
- FFmpeg / ffprobe 属于 API / Worker 运行时依赖，不作为独立基础设施服务拆出。
- M1 阶段只验收本地可用性；Docker、staging、production、acceptance 的上线阻断规则后续进入部署验收计划。

## 运行目录

后续实现时使用以下目录和对象存储分工：

- 临时工作目录：`DOWNLOAD_WORK_DIR` 指向 Worker 本地临时目录，仅用于 yt-dlp 下载、FFmpeg 合并和 ffprobe 校验；上传 MinIO 后会清理任务临时目录。
- 成品文件：写入 MinIO / S3 私有 bucket `video-downloads`，任务只保存对象 key，不依赖本地临时目录交付。
- 日志目录：API 和 Worker 分别输出结构化日志。
- 元数据：任务、用户、状态、对象 key 写入 PostgreSQL。
- 清理归档：由 Worker 或定时清理任务删除超过保留时间的对象。

## 资源限制

- 单任务最大文件大小：2GB。
- 单任务最大运行时长：2 小时。
- 全局下载并发数：2。
- 单用户下载并发数：1。
- 文件保留时间：24 小时。
- 预签名下载 URL 有效期：15 分钟。

上述默认值已分别写入：

- `.env.example`：本地开发，普通进程使用 `127.0.0.1`，默认 Docker API 使用 `host.docker.internal` 对应的 `DOCKER_*` 地址访问宿主机已有环境。
- `.env.production.example`：生产 Docker 部署占位模板，使用 Compose 服务名连接 PostgreSQL、Redis 和 MinIO。

生产环境必须替换 `JWT_SECRET_KEY`、MinIO 账号密码和数据库密码。

生产启动前由 `scripts/validate_prod_env.py` 执行失败前置检查，至少覆盖：

- 必填变量缺失。
- `CHANGE_ME`、`change-me`、`your-domain.example` 等占位值。
- `APP_ENV` 不是 `production`。
- `JWT_SECRET_KEY` 长度不足 32 位。
- 生产连接指向 `localhost`、`127.0.0.1` 或 `0.0.0.0`。
- 开放注册但未配置邀请码。

## MinIO / S3 访问策略

- bucket 默认私有，不开启公共读取。
- bucket 名称默认 `video-downloads`。
- 对象 key 使用 `users/{user_id}/tasks/{task_id}/{filename}`。
- 用户下载文件时由后端校验任务归属后生成短期预签名 URL。
- 前端不直接持有 MinIO 管理密钥。

## 第一版上线部署基线

第一版上线采用“小范围内测 SaaS + 免费配额 + 单机 Docker Compose + Nginx/TLS”。

部署组成：

- Nginx：负责 HTTPS/TLS、反向代理、静态资源入口和基础安全头。
- Web：React + Umi + Ant Design Pro 前端。
- API：FastAPI 后端。
- Worker：RQ 下载 Worker。
- PostgreSQL：用户、任务、事件、文件元数据。
- Redis：RQ 队列和限流辅助。
- MinIO / S3：私有 bucket 存储下载结果。

第一版不采用 K8s、服务网格、多地域高可用或复杂云原生编排。后续如果需要升级部署方式，必须新增 ADR 和 OpenSpec 变更。

## 生产环境变量要求

生产环境必须显式替换：

- `JWT_SECRET_KEY`
- PostgreSQL 用户名、密码和数据库名。
- Redis 连接地址和认证信息。
- MinIO / S3 endpoint、access key、secret key、bucket。
- API 外部访问域名。
- Web 外部访问域名。
- CORS 允许域名。
- 文件大小、任务并发、文件保留时间和预签名 URL TTL。

生产环境不得使用示例密钥、空密码或本地开发默认值作为上线配置。

## 备份与清理

生产环境必须具备：

- PostgreSQL 定期备份和恢复演练说明。
- MinIO / S3 生命周期清理或后台清理任务。
- Redis 持久化策略或明确说明 Redis 仅保存可恢复队列状态。
- 下载临时目录清理策略。
- 过期文件和过期任务的清理记录。

## 公网部署要求

公网部署前必须启用：

- 鉴权。
- 任务配额。
- 接口限流。
- 文件过期清理。
- 日志脱敏。
- 滥用黑名单。
- Nginx HTTPS/TLS。
- 生产密钥替换检查。
- 备份恢复和对象生命周期清理。
