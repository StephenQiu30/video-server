# 部署与运行规划

更新时间：2026-05-02

## M1 后端运行方式

当前后端支持“本地开发”和“Docker 部署”两套运行方式。

### 本地开发方式（推荐）

本地开发默认复用开发机已有服务，不强制 Docker：

- Python：运行 FastAPI API 和 RQ Worker。
- PostgreSQL：本地服务，默认 `127.0.0.1:5432`。
- Redis：本地服务，默认 `127.0.0.1:6379`，供 RQ 使用。
- MinIO / S3：本地或远端 S3 兼容服务，默认 `127.0.0.1:9000`。

本地启动命令：

```bash
cp .env.example .env
pip install -r apps/api/requirements.txt
./scripts/check_local_services.sh
./scripts/dev_api.sh
./scripts/dev_worker.sh
```

说明：

- 当前队列选型是 `RQ + Redis`，本地不需要 RabbitMQ。
- 如果后续改用 RabbitMQ，需要重新提交技术选型 ADR。

### Docker 部署方式

Docker 主要用于上线部署或需要完整隔离环境时使用，默认读取 `.env.docker.example`。服务包含：

- `api`：FastAPI 服务，默认端口 `8000`。
- `worker`：RQ 下载 Worker。
- `postgres`：PostgreSQL 16。
- `redis`：Redis 7。
- `minio`：MinIO / S3 兼容对象存储，API 端口 `9000`，控制台端口 `9001`。

本地启动命令：

```bash
docker compose -f infra/docker/docker-compose.yml up --build
```

后端健康检查：

```bash
curl http://localhost:8000/health
```

## 部署原则

- 默认使用 Docker 或项目本地环境运行，避免污染宿主系统。
- 首版优先单机可运行。
- MVP 即引入 Redis、PostgreSQL 和 MinIO / S3 兼容对象存储；生产化阶段再扩展多 Worker、对象生命周期和监控。

## 运行目录

后续实现时使用以下目录和对象存储分工：

- 临时下载目录：Worker 本地临时目录，仅用于下载和合并过程。
- 成品文件：写入 MinIO / S3 私有 bucket `video-downloads`。
- 日志目录：API 和 Worker 分别输出结构化日志。
- 元数据：任务、用户、状态、对象 key 写入 PostgreSQL。
- 清理归档：由 Worker 或定时清理任务删除超过保留时间的对象。

## 资源限制

- 单任务最大文件大小：2GB。
- 单任务最大运行时长：2 小时。
- 全局下载并发数：2。
- 单用户下载并发数：1。
- 文件保留时间：24 小时。
- 预签名下载 URL 有效期：15 分钟。

上述默认值已分别写入：

- `.env.example`：本地开发，使用 `127.0.0.1`。
- `.env.docker.example`：Docker 部署，使用 Compose 服务名。
- `.env.production.example`：生产部署占位模板。

生产环境必须替换 `JWT_SECRET_KEY`、MinIO 账号密码和数据库密码。

## MinIO / S3 访问策略

- bucket 默认私有，不开启公共读取。
- bucket 名称默认 `video-downloads`。
- 对象 key 使用 `users/{user_id}/tasks/{task_id}/{filename}`。
- 用户下载文件时由后端校验任务归属后生成短期预签名 URL。
- 前端不直接持有 MinIO 管理密钥。

## 公网部署要求

公网部署前必须启用：

- 鉴权。
- 任务配额。
- 接口限流。
- 文件过期清理。
- 日志脱敏。
- 滥用黑名单。
