# 多平台受控会话运行手册

> 默认路径是部署方按 Provider 管理的只读来源，普通客户端不安装浏览器扩展、不运行本机 Agent，也不向服务端提交 Cookie。个人自托管可显式启用本机浏览器连接器，把已获授权的单平台状态导入同一来源契约；它不是 ToC 客户端前置。视频号仍使用专用元宝来源，腾讯视频/优酷仍使用受控文件来源。重启与换机步骤见[个人部署手册](008-个人部署重启与换机手册.md)。

本手册只适用于用户有权处理的公开、非 DRM 内容。受控会话不能扩大内容权益，不能用于 private、好友可见、会员、付费、地域限制或平台保护媒体。

## 1. 唯一运行模型

会话平台由 `ProviderKey`、`ProviderSessionVersion`、`ProviderCookieDomain` 和 `ProviderSessionSource` 统一登记。浏览器来源标识为 `browser`，文件来源使用受控版本及文件修订；不接受自由字符串、active/retained、旧格式或降级兼容路径。

每个平台使用一个独立 Runner 和并发上限 1。API、下载 Worker 与 Canary 根据 Provider key 路由，不允许一个 Runner 同时处理多个平台会话：

```dotenv
RUNNER_OPERATOR_BASE_URLS={"youtube":"http://youtube-operator-runner:19100","douyin":"http://douyin-operator-runner:19100","reddit":"http://reddit-operator-runner:19100","wechat_channels":"http://wechat-channels-operator-runner:19100"}
PROVIDER_SOURCE_ENCRYPTION_KEY=<部署侧稳定密钥，不在终端日志或附件展示>
```

每个 Operator Runner 还必须使用共享 Redis 的凭据租约配置：
`RUNNER_CREDENTIAL_LEASE_REDIS_URL` 指向与其他 Operator 副本相同的 Redis 数据库，默认 TTL 为
120 秒、心跳为 30 秒。租约 key 为
`video:provider-credential-lease:{provider}:{credential_version}`；Redis 不可用时 Runner
不会通过 readiness，也不会退化为无协调的多副本运行。单进程 `Semaphore(1)` 仍只负责
本副本排队，不能替代跨副本租约。

已配置受控 Runner 的平台按部署默认访问策略或显式准入进入该 Runner，任务冻结同一访问上下文，download 不得切回匿名或切换其他账号。未配置受控 Runner、且 Profile 允许匿名访问的平台只进入匿名 Runner。

## 2. 会话来源

### 2.1 部署级单平台来源（默认）

YouTube、抖音、Reddit 的 Operator Runner 从单平台命名卷读取 `provider-sources` 发布的短期租约来源，并在容器内只读挂载为 `/run/provider-source/cookies.txt`。来源由现有 PostgreSQL 加密持久记录恢复，首次登记与撤销见 [008](008-个人部署重启与换机手册.md)；普通 Web 客户端只提交链接。Runner 每次操作重新打开来源，因此原子轮换不需要重建容器；来源内容不进入环境变量、API、RabbitMQ、日志或 Git。

每个平台独占一个目录、Runner 和访问策略；不得把多平台状态合并为共享文件。生产环境应由 secret controller 原子投影 `0600` 文件，并保留上一份已验证版本，候选只有在 metadata、完整 media 和制品校验通过后才进入默认路由。多主机部署确实需要集中分发时，再实现认证的短租约 Broker；单机和单集群不为此预先引入全局凭据平台。

来源缺失或失效只降级对应平台，不影响 API readiness 和其他平台。平台会话、设备验证、出口信誉仍由第三方控制，部署级托管消除的是每台客户端安装和手工复制流程，不承诺绕过登录、验证码、DRM、会员、地域或平台限制。

### 2.2 本机浏览器导入器（个人部署可选）

个人自托管者可显式安装 macOS Agent 与浏览器连接器，把当前 Chrome 中某一 Provider allowlist 的已授权状态导入部署来源。该路径只解决本机读取责任主体和导入体验，不能成为普通用户下载的必经步骤：

```bash
cd backend
uv run python -m app.workers.runner.provider_cookie_agent install \
  --runtime-root "$HOME/Library/Caches/FrameFetch/provider-cookie-agent"
uv run python -m app.workers.runner.provider_cookie_agent doctor \
  --provider youtube \
  --source current_chrome
```

浏览器连接器通过 Chrome 官方 Cookie API 按 Provider allowlist 读取，并经 Native Messaging 写入本机加密快照；后台不读取 Chrome SQLite。只有部署管理员显式启用本地导入时，状态页才可创建一次性授权事务。普通解析、普通重试以及任意远端客户端都不会探测或唤醒扩展。禁止把命令输出、浏览器目录或 Cookie 内容加入工单、日志、Git 或普通备份。

### 2.3 显式文件采集（初始化/灾备）

YouTube、抖音、Reddit 可显式采集为三个互不共享的只读文件，用于个人部署初始化或灾备。标准开发/生产 Compose 直接消费这些部署级来源；后台 LaunchAgent 不继承终端的 macOS TCC 权限，不能作为普通 Chrome 来源的日常读取者：

```bash
cd backend
for provider in youtube douyin reddit; do
  uv run python -m app.workers.runner.provider_session_setup capture-chrome \
    --provider "$provider" --directory "../.provider-sessions/$provider"
done
```

采集命令只读取对应平台白名单域和最小必需 Cookie，校验后原子发布 `0600` 文件；失败不替换上一版。它是部署侧来源初始化工具，不是终端用户操作，也不代表上游接受会话或媒体可完整下载。

视频号使用用户明确批准的本机专用元宝目录，不复制普通 Chrome。首次从 `backend/` 执行 `uv run python -m app.workers.runner.yuanbao_session login` 并由用户登录，然后安装动态来源代理：

```bash
uv run python -m app.workers.runner.provider_cookie_agent install
uv run python -m app.workers.runner.provider_cookie_agent status
```

视频号 Runner 在每次 inspect/download 开始时生成仅存在于内存的一次性 X25519 私钥，请求只写入 `provider + browser + ephemeral public key`，不含 URL、Cookie 或账号。代理按需启动专用浏览器，读取元宝限定身份和动态头，用 X25519/HKDF/ChaCha20-Poly1305 加密单次租约后关闭。目录保留，登录与导出互斥；权限、撤销和新机流程见个人部署手册。

### 无凭据响应探测与升级

视频号 Runner readiness 使用与业务相同的加密队列发送 `probe:<provider>` 请求，最长等待 2 秒。文件来源 Runner 则校验只读文件与隔离租约 Redis；两者不可互相回退。
代理回送绑定该请求临时公钥的固定响应，不读取 Chrome、导出 Cookie 或请求平台。
`.agent-installed` 只证明安装存在；无响应、畸形响应或错误队列不能证明就绪。
代理先处理当前 probe 快照，再处理会话刷新；繁忙时探测可能超时，容器按既有重试窗口重新检查。
就绪不代表登录仍有效，登录失效继续由实际业务稳定错误和平台探针识别。

启用新 Runner 镜像前，先更新宿主代理所使用的代码和依赖；刷新请求格式保持原有三行协议。
代理定义使用 `ThrottleInterval=1`，使按需唤醒适配 2 秒 probe 预算；launchd 默认的 10 秒启动节流会造成连续探测失败。升级到此定义，或代理安装路径、Python 环境发生变化时，重新执行 install，沿用原 `--runtime-root` 和 `--profile`。确认响应后再滚动更新 Runner；
不要仅凭 status 命令的 installed 输出认定受控媒体已恢复。目标环境升级和重启设计见 [030 运行故障隔离与恢复设计](../design/030-运行故障隔离与恢复设计.md)。

卸载代理：

```bash
cd backend
uv run python -m app.workers.runner.provider_cookie_agent uninstall
```

卸载只移除 LaunchAgent 和空队列目录，不删除视频号专用登录目录，也不撤销平台账号。专用来源停用与清理由用户按个人部署手册操作，平台侧会话撤销仍需在第一方完成。

## 3. 启动

开发 Compose 按实际平台启用对应 Profile，例如：

```bash
docker compose --env-file .env -f docker-compose.yml \
  --profile youtube-operator --profile douyin-operator \
  --profile reddit-operator \
  --profile wechat-channels-operator up -d --build --wait
```

生产 Compose 的隔离 Runner 按 `COMPOSE_PROFILES` 选择；YouTube、抖音、Reddit、优酷和腾讯视频先由部署方准备单平台来源及匹配的受控路由，普通客户端无需任何安装：

```bash
docker compose --env-file .env.prod -f docker-compose-prod.yml config --quiet
docker compose --env-file .env.prod -f docker-compose-prod.yml \
  up -d --build --force-recreate --remove-orphans --wait --wait-timeout 300
```

生产 API、下载 Worker 和 Canary 不等待媒体 Runner 健康，避免单个平台阻断核心服务启动。
API readiness 检查 PostgreSQL 结构、MinIO、RabbitMQ 和 Redis；平台故障由对应请求和 Provider 探针表达。
下载 Worker/Canary 只等待共享目录初始化；下载 Worker 和 Runner 停止宽限为 90 秒，覆盖 Worker 的 60 秒有限排空。
停止预算不能代替断电、租约回收和目标环境重启验收。

每个受控 Runner 不得获得数据库、RabbitMQ、MinIO、AI 凭据或 Docker socket，也不发布宿主机端口；仅可通过 `runner_rpc_net` 访问无持久化、无宿主端口的 `provider-lease-redis`，不能借此绕过受控出口。文件来源 Runner 只读挂载本 Provider 的来源，视频号只挂载无凭据的动态队列。操作 jar 位于独占 tmpfs `/run/provider-session`，权限为 `0600`，操作结束立即销毁。

## 4. 验证与故障

固定矩阵必须覆盖每个平台的 metadata 和完整 media：

```bash
cd backend
uv run python -m app.workers.canary.fixed_matrix
```

验证内容包括最终媒体下载、ffprobe、SHA-256、对象存储、浏览器下载文件名和任务冻结的访问上下文。Vimeo 的 DRM 样例必须返回 `provider_drm_protected`；请用非 DRM 样例验证 Vimeo 下载，不能绕过 DRM。

稳定错误处理：

- `provider_auth_required` / `provider_session_expired`：服务端托管平台由部署方轮换对应单平台来源并重新跑 canary；普通用户只需稍后重试。视频号由部署者重新运行专用元宝登录流程。个人自托管且显式启用本地导入器时，才使用本机 Agent 辅助更新来源。
- `provider_session_source_missing`：项目找不到已配置的 Profile 或 Cookies 数据库；修复来源路径/配置，不要求用户重复登录一个不存在的来源。
- `provider_session_permission_denied`：宿主操作系统拒绝读取来源；修复或更换项目独立来源。不要把它当成登录过期，也不要默认要求给通用 Shell/解释器广泛磁盘权限。
- `provider_session_unavailable`：文件来源检查只读挂载、文件安全与 Runner tmpfs；视频号检查专用代理和加密队列。不要静默切换匿名路径。
- `provider_verification_failed`：检查第一方验证码、账号风险和受管出口；不要通过公共代理规避。
- `provider_drm_protected` / `provider_content_restricted`：永久终止，不换账号扩大权益。

发生账号警告、Cookie 泄漏、权益漂移或撤销指令时，移除该平台的默认策略和受控路由，停止对应 Runner，并在第一方平台撤销会话。视频号专用目录、普通 Chrome 和只读文件来源分别清理，不处理其他平台来源。
