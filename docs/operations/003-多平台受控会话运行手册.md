# 多平台受控会话运行手册

本手册只适用于用户有权处理的公开、非 DRM 内容。受控会话不能扩大内容权益，不能用于 private、好友可见、会员、付费、地域限制或平台保护媒体。

## 1. 唯一运行模型

会话平台由 `ProviderKey`、`ProviderSessionVersion`、`ProviderCookieDomain` 和 `ProviderSessionSource` 统一登记。当前来源标识固定为 `browser`，不接受自由字符串，也不存在文件版本、active/retained、旧格式或降级兼容路径。

每个平台使用一个独立 Runner 和并发上限 1。API、下载 Worker 与 Canary 根据 Provider key 路由，不允许一个 Runner 同时处理多个平台会话：

```dotenv
RUNNER_OPERATOR_BASE_URLS={"youtube":"http://youtube-operator-runner:19100","douyin":"http://douyin-operator-runner:19100","xiaohongshu":"http://xiaohongshu-operator-runner:19100","x":"http://x-operator-runner:19100","instagram":"http://instagram-operator-runner:19100","facebook":"http://facebook-operator-runner:19100","reddit":"http://reddit-operator-runner:19100","pinterest":"http://pinterest-operator-runner:19100","wechat_channels":"http://wechat-channels-operator-runner:19100"}
PROVIDER_COOKIE_AGENT_RUNTIME_DIR=
```

已配置受控 Runner 的平台会在 inspect 时直接进入该 Runner，任务冻结同一访问上下文，download 不得切回匿名或切换其他账号。未配置受控 Runner、且 Profile 允许匿名访问的平台只进入匿名 Runner。

## 2. macOS Chrome 会话代理

在 Chrome `Default` Profile 完成相应平台登录，然后安装一次统一代理：

```bash
cd backend
uv run python -m app.runner.provider_cookie_agent install
uv run python -m app.runner.provider_cookie_agent status
```

Runner 在每次 inspect/download 开始时生成仅存在于内存的一次性 X25519 私钥，请求只写入 `provider + browser + ephemeral public key`，不含 URL、Cookie 或账号。代理按中央域名和必需 Cookie 规则从 Chrome 数据库读取最小集合，用 X25519/HKDF/ChaCha20-Poly1305 加密给该次请求。队列只短暂保存无法脱离该次私钥解开的密文，Runner 领取后立即确认删除；请求读取在独立进程组内执行，15 秒超时会回收整个进程组。

普通 Chrome `Default` Profile 用于 YouTube、抖音、小红书、X、Instagram、Facebook、Reddit 和 Pinterest。微信视频号依赖元宝页面的 localStorage 身份和动态请求头，因此用户也必须在正常 Chrome `Default` 中完成元宝登录。每次视频号操作只复制当前元宝 localStorage 到随机临时目录，注入本次读取的元宝 Cookie，计算动态头后立即关闭临时 Chrome 并销毁目录。项目不创建或保留专用浏览器 Profile。

卸载代理：

```bash
cd backend
uv run python -m app.runner.provider_cookie_agent uninstall
```

卸载只移除 LaunchAgent 和空队列目录。项目没有可保留的 Cookie Secret 或独立 Chrome 状态；账号撤销在第一方平台或正常 Chrome 中完成。

## 3. 启动

开发 Compose 按实际平台启用对应 Profile，例如：

```bash
docker compose --env-file .env -f docker-compose.yml \
  --profile youtube-operator --profile douyin-operator \
  --profile xiaohongshu-operator --profile x-operator \
  --profile instagram-operator --profile facebook-operator \
  --profile reddit-operator --profile pinterest-operator \
  --profile wechat-channels-operator up -d --build --wait
```

生产 Compose 固定启动九个隔离 Runner，不使用 Profile 条件：

```bash
docker compose --env-file .env.prod -f docker-compose-prod.yml config --quiet
docker compose --env-file .env.prod -f docker-compose-prod.yml \
  up -d --build --force-recreate --remove-orphans --wait --wait-timeout 300
```

生产 API、下载 Worker 和 Canary 都等待匿名 Runner 与九个受控 Runner 健康。readiness 会逐个探测已配置 endpoint，不能在受控 Runner 未启动时错误报告就绪。

每个受控 Runner 不得获得数据库、RabbitMQ、MinIO、Valkey、AI 凭据或 Docker socket，也不发布宿主机端口。Runner 只挂载无凭据的请求/响应队列；解密后的操作 jar 位于独占 tmpfs `/run/provider-session`，权限为 `0600`，操作结束立即销毁。

## 4. 验证与故障

固定矩阵必须覆盖每个平台的 metadata 和完整 media：

```bash
cd backend
uv run python -m app.workers.canary.fixed_matrix
```

验证内容包括最终媒体下载、ffprobe、SHA-256、对象存储、浏览器下载文件名和任务冻结的访问上下文。Vimeo 的 DRM 样例必须返回 `provider_drm_protected`；请用非 DRM 样例验证 Vimeo 下载，不能绕过 DRM。

稳定错误处理：

- `provider_auth_required` / `provider_session_expired`：在正常 Chrome `Default` 的对应第一方平台重新登录，然后重新触发该平台任务。
- `provider_session_unavailable`：检查统一代理状态、加密队列挂载和 Runner tmpfs；不要切换匿名路径。
- `provider_verification_failed`：检查第一方验证码、账号风险和受管出口；不要通过公共代理规避。
- `provider_drm_protected` / `provider_content_restricted`：永久终止，不换账号扩大权益。

发生账号警告、Cookie 泄漏、权益漂移或撤销指令时，从 `RUNNER_OPERATOR_BASE_URLS` 删除对应 key，停止对应 Runner，并在第一方平台撤销会话。应用没有长期会话文件需要轮换或保留；其他平台 Runner 不受影响。
