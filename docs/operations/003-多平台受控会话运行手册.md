# 多平台受控会话运行手册

本手册适用于公开、非 DRM、用户有权处理，但匿名请求被第一方平台要求最小登录态的单视频。它不用于 private、好友可见、会员、购买/租赁、付费或地域绕过内容，也不允许用户通过普通 API 上传 Cookie。

## 1. 部署模型

每个 endpoint 只能持有一个 Provider 的 Cookie Secret。API、下载 Worker 与 Canary 通过 Provider key 显式路由：

```dotenv
RUNNER_OPERATOR_BASE_URLS={"wechat_channels":"http://wechat-channels-operator-runner:19100","tiktok":"http://provider-operator-runner:19100","douyin":"http://douyin-operator-runner:19100","xiaohongshu":"http://xiaohongshu-operator-runner:19100","reddit":"http://reddit-operator-runner:19100"}
WECHAT_CHANNELS_COOKIE_SECRET_DIR=./.provider-secrets/wechat_channels
WECHAT_CHANNELS_COOKIE_VERSION=
WECHAT_CHANNELS_RETAINED_SESSION_VERSIONS={}
WECHAT_CHANNELS_OPERATOR_ACCOUNT_BASELINE_ATTESTED=true
OPERATOR_PROVIDER_KEY=tiktok
OPERATOR_COOKIE_SECRET_DIR=./.provider-secrets/tiktok
OPERATOR_COOKIE_VERSION=2026-08-11-v1
OPERATOR_RETAINED_SESSION_VERSIONS={}
OPERATOR_ACCOUNT_BASELINE_ATTESTED=true
```

本地视频号版本留空时使用 `browser-live`。首次授权执行
`./scripts/authorize-provider-session.sh wechat_channels`；隔离元宝窗口只在该命令运行
期间存在，Secret 自动生成后窗口退出。业务 Compose 和下载运行期不启动、监控或
读取 Chrome。生产版本必须显式配置。

Session 文件路径为 `<secret-dir>/<version>.cookies.txt`，必须是小于等于 1 MiB 的普通 Netscape 会话文件。Runner 会按 Profile 拒绝跨域行、symlink、空文件、错误 header 和未登记 Provider。Runner 在实际请求时读取并验证快照，不以“首次尚未登录”作为进程启动失败。

## 2. 启动与检查

```powershell
docker compose --env-file .env -f docker-compose.yml \
  --profile wechat-channels-operator --profile provider-operator \
  --profile douyin-operator \
  --profile xiaohongshu-operator --profile reddit-operator config --quiet
docker compose --env-file .env -f docker-compose.yml \
  --profile wechat-channels-operator --profile provider-operator \
  --profile douyin-operator \
  --profile xiaohongshu-operator --profile reddit-operator up -d --build
docker compose --env-file .env -f docker-compose.yml \
  --profile wechat-channels-operator --profile provider-operator \
  --profile douyin-operator \
  --profile xiaohongshu-operator --profile reddit-operator ps
```

operator Runner 不得获得数据库、RabbitMQ、MinIO、Valkey、AI 凭据或 Docker socket，也不发布宿主机端口。源 Secret 只读；操作副本位于 Runner 独占 tmpfs，权限为 `0600`，并发固定为 1。

## 3. Provider 范围

当前受控会话 allowlist 为 YouTube、TikTok、抖音、小红书、Vimeo、X、Instagram、Facebook、Reddit 与微信视频号。视频号只允许公开 `weixin.qq.com/sph/...` 单视频，Secret 只允许 `yuanbao.tencent.com` 域；一次性授权流程自动生成兼容 Runner 的最小会话，不依赖人工 Cookie 字段，也不保留浏览器进程。不得用于私密、付费、直播或受保护媒体。视频号、抖音、小红书与 Reddit 均有专用 Profile 和物理隔离服务；`provider-operator` profile 一次只承载一个其他 Provider。并行平台必须给 `RUNNER_OPERATOR_BASE_URLS` 配置不同内部 endpoint，不得把多个 Provider 会话塞入同一 Runner。

## 4. 验收与撤销

启用前必须用项目自有或明确授权样本分别完成 metadata、完整下载、ffprobe、SHA-256、MinIO、完整视频 Agent、数据库报告、MD/DOCX 和 WebSocket 证据。只有完成 canary 并显式批准后才能修改 Provider 状态。

出现账号警告、Cookie 泄漏、权益漂移、跨 Provider、会话过期或平台规则变化时，先从 `RUNNER_OPERATOR_BASE_URLS` 删除对应 key，再停止隔离 Runner、撤销第一方会话并移除 active/retained 文件。失败任务保留原业务任务与 attempt 轨迹，恢复后在原任务上重试。
