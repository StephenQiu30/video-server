# 运行与部署手册

## 1. 背景

项目首版面向个人自部署，必须同时支持研发本机调试和部署者一键拉起完整服务。

## 2. 目标

1. 定义本机开发和 Docker Compose 两条运行路径。
2. 明确依赖复用、环境变量和健康检查规则。

## 3. 非目标

- 不覆盖云平台、Kubernetes 或 SaaS 运维。

## 4. 核心内容

### 4.1 本机开发

1. 优先复用已有 Redis、Postgres、MinIO。
2. 启动前确认依赖地址和凭证。
3. 启动 API 与 Worker 后验证健康检查接口和最小任务链路。

### 4.2 Docker Compose

1. 使用 Compose 拉起 API、Worker、Redis、Postgres、MinIO。
2. 保持与本机路径一致的环境变量命名和行为。
3. 提供启动、停止和清理命令。

### 4.3 健康检查

1. API 健康检查必须可用。
2. 缺失 Redis、Postgres、MinIO 时要有可操作报错。
3. 健康检查应区分配置错误和服务不可达。

## 6. 验收门禁

- 本机和 Compose 两条运行路径均有可执行步骤。
- 环境变量来源和默认行为清楚。
- 健康检查和排障入口清楚。

## 7. 风险与边界

如果运行手册只描述理想路径，不描述已有依赖复用和失败排障，个人自部署体验会显著下降。
