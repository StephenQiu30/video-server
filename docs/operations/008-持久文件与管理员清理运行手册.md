# 持久文件与管理员清理运行手册

## 1. 存储规则

下载视频、本地导入视频、剧本文档原件、规范化剧本文本、Markdown 报告和 DOCX 报告均持久保存，不设置业务 TTL，也不由后台 Worker 自动删除。最终制品表不设计过期字段；清理只能由管理员显式发起。

以下临时状态仍必须过期，因为它们属于访问或并发协议，不属于用户文件保留期：

- 登录会话、访问令牌和短时预签名下载地址；
- multipart 上传会话、quarantine 对象与未完成分片；
- Worker lease、heartbeat、outbox lock 和解析结果缓存。

## 2. 管理员文件列表

管理员进入 `/admin/files` 查看所有尚未清理的持久文件。列表按创建时间倒序分页，默认每页 20 项，展示视频、剧本文档和分析报告三类逻辑资源及其对象数、总字节数和创建时间，不公开 MinIO bucket、object key 或签名地址。

对应接口为：

- `GET /api/admin/files?page=1&page_size=20`
- `page` 范围为 `1..10000`，`page_size` 范围为 `1..50`

## 3. 手动清理

管理员点击“清理历史文件”，输入要清理的天数并二次确认。默认值为 30 天，可选范围为 `1..3650` 天；服务端删除创建时间早于当前 UTC 时间减去该天数的最终对象并标记数据库记录已删除。

对应接口为：

```http
POST /api/admin/files/cleanup
Content-Type: application/json

{"older_than_days": 30}
```

响应返回清理的逻辑资源数、对象数、释放字节数与失败资源数。清理是不可恢复的管理操作；对象存储删除失败的资源不会被标记为已删除，可在排除存储故障后再次执行。

正在被分析任务锁定的视频或剧本文档会被跳过，避免清理影响运行中的任务。清理窗口只根据最终资源的创建时间计算，不根据短时下载 URL、最近访问时间或上传会话时间计算。
