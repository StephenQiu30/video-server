# CI 与主分支门禁运行手册

## 1. 结论与责任

当前设计适合本项目：服务端两个并行 Job 负责确定性代码、契约、业务和构建检查；Flutter 仓库分别执行质量/Android 构建与 iOS 模拟器构建。它们能发现可编码的规范回归，但不能自动证明全部设计规范、目标部署和真实用户流程正确。

定义分别在本仓库 `.github/workflows/ci.yml` 与 App 仓库 `.github/workflows/flutter-quality.yml`。2026-09-21 查询 GitHub：两仓 `main` 均无传统分支保护、也无 ruleset。当前推送触发的是事后检测，不是进入 main 前的强制门禁；已有远端失败运行也证明不应把“已推送”理解为“通过 CI”。

如改为强制合并门禁，应在 GitHub 配置 required status checks，使用下表稳定的 Job 名称，并确认管理员/机器人绕过策略。由于当前采用直接 main 推送，本轮不擅自改变这项协作方式。依据：[GitHub protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。

## 2. 标准覆盖矩阵

| 标准 | 自动检查 | 边界 |
| --- | --- | --- |
| 后端依赖、格式、类型 | `Backend tests`：uv frozen、Ruff lint/format、strict MyPy | 不以本机已有依赖替代锁文件安装 |
| 后端目录与依赖方向 | architecture 测试：根目录、services 与底层模块导入约束、路由不导入 main | 不能判断所有职责划分、事务所有权和代码是否过度设计 |
| 数据与业务契约 | 全量 pytest：PostgreSQL 17.5、模型、SQL 静态约束、隔离 schema 的集成测试、队列/配额/鉴权、Redis 租约互斥/过期接管/心跳 | 测试表多数由 ORM create_all 创建；不能宣称对完整 schema.sql 的空库与已有库真实执行均已验收 |
| 前端依赖、格式、类型、行为 | `Frontend tests`：pnpm frozen、Biome、tsc、Vitest、Next.js build | 不代表浏览器/设备视觉验收 |
| REST 唯一契约 | 从当前后端注解离线导出 OpenAPI，重新生成 src/api，检查 tracked 和 untracked 漂移 | 自动生成一致性不等于接口真实集成成功 |
| 前端目录与请求分层 | Vitest architecture 检查固定 src 目录；组件/Hook 不直接 import Axios/request 或调用 fetch/XMLHttpRequest | AST 检查常见直接绕过，不是完整静态数据流或安全扫描；共享上传编排仍需评审 |
| CI 必跑命令 | contract 测试检查触发分支、只读权限、工具版本、完整命令及常见跳过/忽略失败配置 | Workflow 与测试同时被删除或恶意绕过仍需 PR 审查和远端保护 |
| Flutter 依赖与生成代码 | App：pub enforce-lockfile、冻结 OpenAPI 快照重生成、路由/本地化重生成、tracked/untracked 漂移 | 冻结快照不等于追踪服务端最新 main；跨仓同步需要明确版本与集成验收 |
| Flutter 静态质量与产物 | `Quality and Android debug build`：format/analyze/test/APK；`iOS simulator build`：模拟器构建 | 不含 iOS 签名、商店发布、真机和真实后端 integration_test |
| 根 `design.md` 的唯一视觉标准、交互与可访问性 | 当前有部分语义组件测试 | 桌面/390px、明暗主题、焦点、真实上传/播放继续浏览器/设备检查，自动测试不能完整评判审美 |

后端/前端 Job 任一失败会使 Workflow 失败，不增加重复汇总 Job。Actions 使用完整提交 SHA，权限为 contents: read；超时和并发取消用于限制重复运行。提交标题约定服务于协作，不单独阻断 CI。

## 3. 本地复现

后端在 `backend/`：

```bash
uv sync --frozen --dev
uv run --frozen ruff check app tests
uv run --frozen ruff format --check app tests
uv run --frozen mypy app
uv run --frozen pytest -q
```

复用当前 PostgreSQL，测试使用独立 schema 并自动清理；不新建本机基础服务，也不覆盖已有数据。

前端在 `frontend/`：

```bash
pnpm install --frozen-lockfile
pnpm format:check
pnpm lint
pnpm test
pnpm build
```

CI 的 OpenAPI 导出命令见 Workflow。`OPENAPI_SCHEMA_URL` 可以指向离线 JSON 文件；在干净检出执行 `pnpm openapi:check`。比较包括生成器新增但尚未跟踪的文件，不能只依赖 git diff。

Flutter 在 App 仓库使用 `flutter pub get --enforce-lockfile`、`dart run tool/openapi.dart --from-snapshot --check`、`flutter gen-l10n` 与 `dart run build_runner build`，再执行格式/分析/测试与平台构建；生成过程需要 Java、Maven 和固定版本生成器依赖，无需在线业务 API。

## 4. 本轮发现与修复

- 远端服务端运行 `35521170699`：前端下载工作区 import 排序与后端五个文件格式失败。修复格式，不降低或绕过门禁。
- SEO 的 `SITE_INDEXABLE` 新配置需要同步 backend Compose 配置白名单；保留白名单门禁并补齐合法字段。
- Web 生成 API 检查原先只用 git diff，漏掉新生成且未跟踪的文件；现同时检查 untracked。
- CI 自身原先只验证测试/build 与 Action SHA；现保护完整质量命令、权限与触发边界，并用删除命令、条件跳过、continue-on-error 三类变异验证检测有效。
- App 原先只重生成路由与本地化，没有从冻结 OpenAPI 重生成客户端；现补齐离线生成漂移检查与依赖锁强制执行，同时禁止 checkout 保留凭据。
- 四个会话维护单元测试未显式传测试 revision secret，干净环境会误读部署 RunnerSettings 并失败；补齐测试注入，不放宽生产配置。
- `.gitattributes` 原先将 frontend 全目录强制作为文本，导致 PNG/ICO 在干净检出比较时进入换行转换；改为自动检测文本，并添加二进制资源规则回归检查。
- 运维文档旧版仍写 npm，已与 pnpm 工作流一致。
- 远端运行 `35559152876` 虽通过，但三项 Redis 租约测试因 runner 缺少 redis-server 而跳过；Backend Job 显式安装并检查 redis-server/redis-cli，测试使用临时端口且禁用持久化，不启动完整业务 Compose。MinIO 上传边界测试仍需单独提供隔离对象存储验收。

## 5. CI 之外的验收

真实 Provider 会话、AI 服务、完整 Compose 启停、网络出口、备份恢复、对象存储和设备 E2E 依赖外部环境，按相关变更在本地或发布前验收。外部依赖公告审计单独执行，不让公告变化替代每次提交的确定性系统测试。

镜像/Compose 变化按需解析、构建并检查健康；SQL 变化必须补充真实空库与已有库执行证据。搜索收录、GEO 引用率、线上 Core Web Vitals 也不属于普通单元 CI 的通过结论。CI 失败先复现并修复根因，不通过删除测试、设置 continue-on-error 或重复重跑掩盖问题。
