## 1. 任务边界

从锁定 Ant Design Pro v6 simple 建立可重复 Web 工程、冻结路由、精简全局布局、合法提示、响应式/可访问基线和质量工具。不连接真实 API，不加入 Mock 成功数据或空白占位功能。

## 2. Test-first 执行拆分

| 顺序 | 先失败的约束 | 最小实现 | 主要产出 |
| --- | --- | --- | --- |
| `W001-T01` | 官方仓库来源、锁定 tag/commit、`npm run simple` 初始化记录、lockfile、`.env` 缺失/覆盖和依赖禁止项检查 | Ant Design Pro simple 工程、`package-lock.json`、`.env.example` | 可追溯、可重复脚手架与配置 |
| `W001-T02` | 根重定向、两业务路由和 404 测试 | `config/routes.ts` 与真实页面容器 | 冻结路由 |
| `W001-T03` | 菜单、标题、合法提示和唯一主内容测试 | `app.tsx`、Layout、LegalNotice | 最小全局体验 |
| `W001-T04` | Demo/账号/AI/无关依赖和资源扫描 | 删除模板示例并修复引用 | 干净上下文 |
| `W001-T05` | 1440/768/375、键盘焦点、语义和不可信文本测试 | Token/CSS/响应式容器 | 可访问基线 |
| `W001-T06` | 存储、路由、日志和错误上报敏感字段扫描 | 全局安全约束 | 无持久化泄露 |
| `W001-T07` | lint、format、type、unit、coverage、build 先失败 | 项目脚本和 CI 门禁 | 可执行质量基线 |

页面容器必须承载真实布局和状态入口，不创建“敬请期待”或 Mock 业务页；具体业务状态由后续 Plan 填充。

`W001-T01` 的执行顺序固定为：记录 Ant Design Pro 官方仓库与选定 tag/commit → 在仓库外临时目录检出该版本 → 按官方方式安装依赖并执行 `npm run simple` → 删除模板 `.git` 与剩余 Demo/Mock/无关能力 → 将精简结果合入当前 `video-web`，不得覆盖已有 `docs` 与仓库治理文件 → 生成并验证 `package-lock.json`。不得用 Vite、Create React App 或自写配置替代此步骤。

## 3. 预期文件边界

- `package.json`、`package-lock.json`、`.env.example`、TypeScript、Biome、Vitest、Umi 配置。
- `config/{config,routes,proxy}.ts`。
- `src/app.tsx`、`src/components/LegalNotice.tsx`、全局样式、`src/pages/404.tsx`。
- `src/pages/Download/index.tsx` 与 `DownloadJob/index.tsx` 仅放真实页面容器和安全初始状态。
- `tests/unit/` 中路由、布局、响应式和安全基线测试。
