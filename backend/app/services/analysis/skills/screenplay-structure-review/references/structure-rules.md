# 结构审阅清单

## 场景推进

- 记录场景进入时的目标或压力、阻碍如何升级、离开时发生了什么不可忽略的变化。
- 结果可以是成功伴随新代价、失败并恶化、重新定义目标或迫使人物选择；无变化需明确标记。
- 情绪反应场应把上一结果转化为困境和决定，为下一行动建立因果，不是简单复述。

## 转折与连续性

- 转折必须改变人物可用信息、策略、关系或风险，不以突发事件的表面强度代替结构作用。
- 检查重要信息和道具的首次出现、人物何时获知、后续使用及兑现。
- 对矛盾只描述文本可验证的两端，并同时引用相关源场景。

## 节奏与建议

- 比较冲突升级、转折密度、重复信息和连续同强度场景，定位节奏问题的起止场景。
- 修改建议优先采用合并、前移、后移、删减重复、强化选择或补足因果等可执行动作。
- 保留作者已有故事目标；不要用单一结构模板取代文本本身。

## Coverage 与生产线索

- 把每个源场景和其中可识别的对白、动作、人物、地点、道具线索看成待覆盖的叙事事实；不要把“适合拍摄”写成“已经有镜头”。
- 如果某个必要事实没有被后续场景或镜头化动作承接，优先写成 `priority_revisions`，说明缺口、影响和证据场景。
- 场景、对白、资产和镜头是不同层次：当前 Skill 只输出结构审阅结果，不能输出 VibeReels/Lanverse 的候选决策、主选或 stale 状态对象。
- 源场景长度、段落数和对白行数不等于未来镜头数量；需要镜头化时只列出必须被覆盖的可见动作、空间、状态与对白事实，不预先制造 Shot/Cut。
- 连续性问题应区分信息缺失、文本矛盾和有意留白；只有前两者有足够证据时才提出修改建议。
