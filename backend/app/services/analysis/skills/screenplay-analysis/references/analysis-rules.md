# 剧本文本分析规则

## 全局阅读

- 用一句话概括主角、目标、主要阻力和利害关系，形成可由正文验证的 logline。
- synopsis 应覆盖开端、升级、关键转折与结局，不添加未出现的因果。
- 结构按文本实际组织，不强行套固定幕数；幕与转折必须能从已提供的文本解释。

## 人物与场景

- 人物弧光检查“欲望或目标—阻力—选择—结果—变化”的文本因果链；不要把性格标签当作弧光。
- 把“人物自述是什么样的人”和“压力下实际作了什么选择”分开写；若正文没有展示选择，只能说明弧光尚未建立。
- 每场说明它带来的新信息、压力或选择。若一场没有可见转变，应明确指出这一判断及其原因。
- 比较场景开头与结尾的关系、风险或可用信息；即使没有逆转，也检查是否完成了必要的铺垫，不机械要求每场翻转。
- 节奏判断结合场景长度、信息重复、冲突升级和转折间距，不只根据对白多少判断。

## 对白与修改

- 对白检查角色声音区分、言下之意、关系变化、信息倾倒和多重功能。
- 对白诊断先问角色想通过这句话让对方做什么、对方实际如何回应；同一句台词不能仅凭措辞推断潜台词。遮住说话人姓名仍难区分时，指出可观察的用词或行动差异。
- strengths 说明有效机制而非泛泛称赞；priority_revisions 先处理会影响后续多场的结构或人物问题。
- 文本信息不足时明确说明范围限制，不得为凑结论补造情节。

## 面向生产的事实线索

- 场景中的地点、人物、道具、服化、状态变化和可视化动作可以作为后续资产/镜头生产的线索，但当前结果不创建 Asset、Shot 或人工 Decision 对象。
- 对白、动作和场景功能分别判断覆盖需求：对白主要对应 audio，动作/场景标题主要对应 visual；不能因为一个镜头有画面就声称已经覆盖了对白事实。
- 连续性问题至少说明“前一场已建立的状态”和“后一场出现的冲突”；缺少一端文本事实时只能标记为待确认。
- 候选、建议和已确认事实必须分开用词：可以说“建议作为候选”，不能说“已选定”“已入库”或“已生成”。
- `source_scene_id` 只标识规范化文本场景，不代表一个镜头、一个 Cut 或一个固定生产单元；不得按场景长度、对白行数或段落数推断镜头数量。
