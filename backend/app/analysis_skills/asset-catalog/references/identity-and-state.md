# 资产身份与状态规范

## 一、身份归并顺序

对候选依次比较：

1. **稳定形态**：轮廓、结构、面部/发型、服装主件、空间布局、产品形状、Logo 图形或文字内容。
2. **上下文连续**：相邻镜头的动作、位置、手持关系和进入/退出方向是否支持同一对象。
3. **区别特征**：颜色强调、纹理、破损、配件、标记、家具布局或界面结构。
4. **冲突证据**：同时出现在同一画面、结构明显不同或状态变化无法由连续动作解释时，不得强行合并。

角度、裁切、远近、景深、色温和短时遮挡通常不是新身份。证据不足时使用“人物 A”“室内场景 A”“深色手持物”等保守标签。

分析分镜边界与资产身份边界相互独立：物理 Cut 或 `transition_in=continuous` 都不自动产生新资产；反过来，同一资产持续存在也不能成为把不同空间、动作或状态阶段合成一个超长分镜的理由。

## 二、身份与状态分离

`description` 使用：

`稳定特征：……；可见状态：……；状态变化：Shot … 从……变为……；连续性风险：……`

状态包括服装增减、污损/破损、开合、内容更新、道具持有关系、灯光开启、空间布置变化等。只有画面证据支持时才记录变化，不生成不存在的版本 ID。

## 三、证据等级

- **主证据**：清晰、无遮挡、能看见区别特征的镜头。
- **连续证据**：通过连续动作或空间关系支持同一身份的镜头。
- **弱证据**：远景、强遮挡、运动模糊、反光或仅见局部的镜头。

每项资产至少包含一条主证据；若只有弱证据，在描述中标明“不足以确认”，并避免具体命名。

## 四、类型边界

- `person`：可见人物身份候选，不推断真实身份。
- `location`：有稳定空间布局的场景；同一地点不同机位通常合并。
- `object`：道具、服饰配件、家具或通用物件。
- `product`：画面明确作为产品主体展示；无法确认时用 `object`。
- `logo`：独立图形/品牌标记，仅记录可见内容，不推断权属。
- `on_screen_text`：标题卡、字幕、界面文字或图形文字；内容更新可写为状态变化。

## 五、完成检查

合并后再次按分析分镜时间线检查：是否存在一物多名、同名异物、首次出现错误、状态前后矛盾、证据分镜不存在、边界阶段遗漏或类型越界。
